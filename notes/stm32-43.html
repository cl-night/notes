[12-3] 读写备份寄存器&实时时钟 — 学习笔记

一句话结论

两个独立工程：BKP 工程验证掉电保持，VBAT 用飞线接 ST-Link 的 3.3V；RTC 工程新建 MyRTC 模块，核心是 MyRTC_Init 八步的顺序。时间用 mktime/localtime 与秒计数器互转，掉电保持靠 BKP_DR1 存 0xA5A5 标志。

本集定位

  • 模块 12 的代码课，两个独立程序，都从复制 OLED 显示屏工程起步。
  • 程序① 12-2 读写备份寄存器：BKP ＋ PB1 按键，验证掉电保持特性。
  • 程序② 12-2 实时时钟：RTC，新建 MyRTC 模块放在 System 目录。
  • 结尾 52:00 是 RTC_GetDivider() 的线性变换扩展演示，无下集预告。

图 1：接线图——STM32 最小系统板 ＋ ST-Link ＋ OLED ＋ 按键（PB1 处红笔标注）；红框标出板子右上角的 VBAT 引脚用飞线接到 ST-Link 的 3.3V 输出

1. 接线与工程准备

  • 12-2 读写备份寄存器：OLED 接 I2C、PB1 接按键、VBAT 飞线接 ST-Link 的 3.3V 输出。
  • 为什么用 3.3V 模拟备用电池：套件里没配纽扣电池，实际产品一般用 3V 纽扣电池。
  • 绝不能接 5V：ST-Link 有 3.3V 和 5.0V 两组输出，VBAT 不支持 5V 供电。
  • 12-2 实时时钟：同样 VBAT 接 3.3V、不用按键；32.768kHz 外部低速晶振板载自带，不用接线。
  • 工程：复制 OLED 显示屏工程，改成对应名字后编译。

2. 程序①：读写备份寄存器（BKP）

2.1 编程思路

  1. 开启 PWR 和 BKP 的时钟。
  2. 用 PWR 函数使能对 BKP 和 RTC 的访问。
  3. 调用 BKP 的写入函数 / 读取函数。

2.2 BKP 与 PWR 库函数

函数 作用
BKP_DeInit(void) 恢复缺省配置——可手动清空 BKP 所有数据寄存器
BKP_TamperPinLevelConfig(uint16_t BKP_TamperPinLevel) 配置 TAMPER 引脚有效电平
BKP_TamperPinCmd(FunctionalState NewState) 是否开启侵入检测功能
BKP_ITConfig / BKP_GetFlagStatus / BKP_ClearFlag / BKP_GetITStatus / BKP_ClearITPendingBit 中断、标志位相关
BKP_RTCOutputConfig(uint16_t BKP_RTCOutputSource) RTC 时钟输出配置
BKP_SetRTCCalibrationValue(uint8_t CalibrationValue) 写 RTC 校准寄存器
BKP_WriteBackupRegister(uint16_t BKP_DR, uint16_t Data) 写备份寄存器：第一个参数写哪个 DR，第二个是 16 位整型数据
BKP_ReadBackupRegister(uint16_t BKP_DR) 读备份寄存器：返回值就是该 DR 里存的值
  • BKP_DRx 的 x 范围：参数可写 BKP_DR1～BKP_DR42，但只有大容量和互联型才有 42 个 DR。
  • 中/小容量（含 F103C8T6）只有 DR1～DR10。
  • stm32f10x_pwr.h 只需要 PWR_BackupAccessCmd：内部是 *(__IO uint32_t *) CR_DBP_BB = (uint32_t)NewState;，即置 PWR_CR 的 DBP 位。
  • PWR 和 BKP 都是 APB1 外设，两个时钟都要开：只开 BKP 不行，必须先开 PWR 时钟。
  • 读函数的完整原型是 uint16_t BKP_ReadBackupRegister(uint16_t BKP_DR)，返回值就是该 DR 的值。

图 2：stm32f10x_bkp.h 库函数声明表——BKP_DeInit、BKP_TamperPinLevelConfig（高亮）、BKP_TamperPinCmd、BKP_ITConfig、BKP_RTCOutputConfig、BKP_SetRTCCalibrationValue、BKP_WriteBackupRegister、BKP_ReadBackupRegister 等

图 3：PWR_BackupAccessCmd 源码——注释「Enables or disables access to the RTC and backup registers」，函数体 assert_param(IS_FUNCTIONAL_STATE(NewState)); *(__IO uint32_t *) CR_DBP_BB = (uint32_t)NewState;，即置 PWR_CR 的 DBP 位

2.3 初版代码与现象

uint16_t ArrayWrite[] = {0x1234, 0x5678};
uint16_t ArrayRead[2];

int main(void)
{
    OLED_Init();

    /* ① 开时钟：PWR 和 BKP 都是 APB1 外设，两个都要开 */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_BKP, ENABLE);

    /* ② 使能对 BKP 和 RTC 的访问（置 PWR_CR 的 DBP 位） */
    PWR_BackupAccessCmd(ENABLE);

    /* ③ 写 / 读备份寄存器 */
    // BKP_WriteBackupRegister(BKP_DR1, 0x1234);
    OLED_ShowHexNum(1, 1, BKP_ReadBackupRegister(BKP_DR1), 4);

    while (1) { }
}
  • 三句关键调用：RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);、RCC_APB1PeriphClockCmd(RCC_APB1Periph_BKP, ENABLE);、PWR_BackupAccessCmd(ENABLE);，也可合并成 RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR/BKP, ENABLE)。
  • 初版只读不写：写操作 // BKP_WriteBackupRegister(BKP_DR1, 0x1234); 先注释掉，读用 OLED_ShowHexNum(1, 1, BKP_ReadBackupRegister(BKP_DR1), 4)（写全分号即 OLED_ShowHexNum(1, 1, BKP_ReadBackupRegister(BKP_DR1), 4);）。
  • 数组声明 uint16_t ArrayWrite[] = {0x1234, 0x5678};、uint16_t ArrayRead[2];（图里手写成 uint16_t ArrayRead（2）;）。
  • 现象：下载后 OLED 显示 1234。
  • 不带备用电池时上电 BKP 是 0；复位不会清空，数据仍是 1234；断 VDD 后仍是 1234。
  • 把 VBAT 也拔掉 → BKP 清零，符合实验预期。

图 4：BKP main.c 初版——uint16_t ArrayWrite[] = {0x1234, 0x5678};、OLED_Init();、两个 RCC_APB1PeriphClockCmd、PWR_BackupAccessCmd(ENABLE);、注释掉的 BKP_WriteBackupRegister(BKP_DR1, 0x1234) 与 OLED_ShowHexNum 读取

2.4 完善版：按键写入 ＋ 持续读取

uint8_t KeyNum;

int main(void)
{
    OLED_Init();
    Key_Init();
    OLED_ShowString(1, 1, "W:");      /* 写入的数据 */
    OLED_ShowString(2, 1, "R:");      /* 读取的数据 */

    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_BKP, ENABLE);
    PWR_BackupAccessCmd(ENABLE);

    while (1)
    {
        KeyNum = Key_GetNum();
        if (KeyNum == 1)
        {
            ArrayWrite[0] ++;
            ArrayWrite[1] ++;
            BKP_WriteBackupRegister(BKP_DR1, ArrayWrite[0]);
            BKP_WriteBackupRegister(BKP_DR2, ArrayWrite[1]);
            OLED_ShowHexNum(1, 3, ArrayWrite[0], 4);
            OLED_ShowHexNum(1, 8, ArrayWrite[1], 4);
        }
        /* 无按键时也不断读取刷新显示 */
        ArrayRead[0] = BKP_ReadBackupRegister(BKP_DR1);
        ArrayRead[1] = BKP_ReadBackupRegister(BKP_DR2);
        OLED_ShowHexNum(2, 3, ArrayRead[0], 4);
        OLED_ShowHexNum(2, 8, ArrayRead[1], 4);
    }
}
  • OLED 两行标签是 W: 与 R:；按键用 Key_Init()、Key_GetNum()。
  • 按键分支：if (KeyNum == 1) { ArrayWrite[0]++; ArrayWrite[1]++; BKP_WriteBackupRegister(BKP_DR1, ArrayWrite[0]); BKP_WriteBackupRegister(BKP_DR2, ArrayWrite[1]); }
  • 两个 DR 一起写，说明读写多个 DR 也没问题。
  • 现象：上电时 W 后面不显示、读出的是 00000000。
  • 按一下按键 → 写入 1235、5679（写入前就已经自增，不是数组默认的 1234/5678），读到的和写入一致。

图 5：BKP main.c 主循环——KeyNum = Key_GetNum();、if (KeyNum == 1) 里两个 ArrayWrite[0] ++、两次 BKP_WriteBackupRegister、两次 OLED_ShowHexNum 写入行

图 6：BKP 现象——OLED 显示 W:1235 5679 / R:1235 5679，写入与读取完全一致；字幕「读取的数据，和写入一样，1235、5679」

3. 程序②：实时时钟（RTC）

3.1 建模块与初始化流程

  • 复制工程改名 12-2 实时时钟，新建 MyRTC 模块（放 System 目录）。
  • 初始化流程：① 开 PWR＋BKP 时钟、使能访问 ② 启动 RTC 时钟（计划用 LSE，为了省电默认是关闭的）。
  • ③ 配置 RTCCLK 数据选择器（在 RCC 模块里） ④ 调用两个等待函数（等同步、等上次写完）。
  • ⑤ 配置预分频器 PRL，保证输出给计数器的是 1Hz ⑥ 配置 CNT 的值（初始时间） ⑦ 可选配置闹钟/中断。
  • RTC 比较简单：库函数没有用结构体配置，也没有 RTC_Cmd 这样的函数，开启时钟就能自动运行。

3.2 RCC 侧与 rtc.h 库函数

函数 作用
RCC_LSEConfig(RCC_LSE_ON) 配置 LSE（参数有 RCC_LSE_ON/OFF/BYPASS；BYPASS＝时钟旁路，可从外部直接输入时钟）
RCC_GetFlagStatus(RCC_FLAG_LSERDY) 等待 LSE 启动完成，必须等 LSERDY 置 1
RCC_RTCCLKConfig(RCC_RTCCLKSource_LSE) 选择 RTCCLK 的时钟源（LSE / LSI / HSE÷128）
RCC_RTCCLKCmd(ENABLE) 使能 RTC 时钟
函数 作用
RTC_ITConfig / RTC_GetFlagStatus / RTC_ClearFlag / RTC_GetITStatus / RTC_ClearITPendingBit 中断与标志位
RTC_EnterConfigMode / RTC_ExitConfigMode 置/清 RTC_CRL 的 CNF 位，写 PRL/CNT/ALR 的函数内部自带
RTC_GetCounter 获取 CNT 计数器的值（秒数）
RTC_SetCounter(uint32_t CounterValue) 写入 CNT 计数器的值
RTC_SetPrescaler(uint32_t PrescalerValue) 写入预分频器 PRL
RTC_SetAlarm(uint32_t AlarmValue) 写闹钟值 ALR
RTC_GetDivider 读 DIV 余数寄存器，一般用来得到更细致的时间（厘秒/毫秒）
RTC_WaitForLastTask 等待上次操作完成：循环等 RTOFF＝1
RTC_WaitForSynchro 等待同步：等 RSF＝1
  • 带分号的调用形式：RCC_RTCCLKConfig(RCC_RTCCLKSource_LSE);、RTC_WaitForSynchro();。
  • 写寄存器的内部流程是 EnterConfigMode → 写 → 退出，所以用户代码里看不到进出配置模式。

图 7：stm32f10x_rtc.h 函数声明表——RTC_ITConfig、RTC_EnterConfigMode、RTC_ExitConfigMode、RTC_GetCounter、RTC_SetCounter、RTC_SetPrescaler、RTC_SetAlarm、RTC_GetDivider（高亮）、RTC_WaitForLastTask、RTC_WaitForSynchro 等

3.3 MyRTC_Init（八步，顺序就是核心）

void MyRTC_Init(void)
{
    /* ① 开 PWR / BKP 时钟，② 使能对 BKP 和 RTC 的访问 */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_BKP, ENABLE);
    PWR_BackupAccessCmd(ENABLE);

    /* ③ 启动 LSE，④ 等待 LSE 就绪 */
    RCC_LSEConfig(RCC_LSE_ON);
    while (RCC_GetFlagStatus(RCC_FLAG_LSERDY) != SET);

    /* ⑤ 选择 RTCCLK 时钟源，⑥ 使能 RTC 时钟 */
    RCC_RTCCLKConfig(RCC_RTCCLKSource_LSE);
    RCC_RTCCLKCmd(ENABLE);

    /* ⑦ 等同步 + 等上一步写完 */
    RTC_WaitForSynchro();
    RTC_WaitForLastTask();

    /* ⑧ 预分频 32768 → 1Hz；设置初始时间（Unix 时间戳） */
    RTC_SetPrescaler(32768 - 1);
    RTC_WaitForLastTask();

    RTC_SetCounter(1672588795);
    RTC_WaitForLastTask();
}
  • 预分频写 32768 - 1：LSE 频率 32.768kHz＝32768Hz，分频计数值包含 0，写 32767 才是 32768 分频 → 1Hz。
  • 每个写操作后都要 RTC_WaitForLastTask()：写进去的值不会立刻生效。
  • 配置模式不用手动进出：RTC_SetCounter/RTC_SetPrescaler 内部自动置/清 CNF。
  • 初始时间 RTC_SetCounter(1672588795) 是 PPT 的例子（2023-1-1 15:59:55 伦敦时间），不预设就当 0，time.h 解析出来是 1970 年。
  • 两个等待函数是「安全保障措施」，防止时钟不同步造成 bug。

图 8：MyRTC_Init 前半（MyRTC.c）——两个 RCC_APB1PeriphClockCmd、PWR_BackupAccessCmd(ENABLE);、RCC_LSEConfig(RCC_LSE_ON);、while (RCC_GetFlagStatus(RCC_FLAG_LSERDY) != SET);、RCC_RTCCLKConfig、RCC_RTCCLKCmd(ENABLE);、两个等待函数

图 9：MyRTC_Init 尾部——RTC_SetPrescaler(32768 - 1);、RTC_WaitForLastTask();、RTC_SetCounter(1672588795);、RTC_WaitForLastTask();；字幕「接下来我们要做的就是」

3.4 main 初测与现象

#include "MyRTC.h"

int main(void)
{
    OLED_Init();
    MyRTC_Init();
    OLED_ShowNum(1, 1, RTC_GetCounter(), 10);   /* 1 行 1 列显示 CNT */
    while (1) { }
}
  • main 里只有一句 OLED_ShowNum(1, 1, RTC_GetCounter(), 10)，把 CNT 直接显示出来。
  • 现象：数字按 1 秒间隔自增，说明 RTC 正常运行。
  • 坑：有些板子 RTC 晶振起振不了，程序会卡在 while (... LSERDY ...) 那里。
  • 备选方案：改用 LSI，RCC_LSICmd(ENABLE) ＋ 等 RCC_FLAG_LSIRDY ＋ RCC_RTCCLKSource_LSI ＋ RTC_SetPrescaler(40000-1)。
  • LSI 频率 40kHz，所以写 40000-1（等价于 RTC_SetPrescaler(40000 - 1)）才能 40 分频到 1Hz。
  • 根治起振问题要从硬件下手（换晶振、调起振电容）。
  • 读时间统一走 MyRTC_ReadTime，把秒数换算成年月日时分秒。

3.5 MyRTC_SetTime / MyRTC_ReadTime

uint16_t MyRTC_Time[] = {2023, 01, 01, 23, 59, 55};   /* 年 月 日 时 分 秒 */

void MyRTC_SetTime(void)
{
    time_t time_cnt;
    struct tm time_date;

    time_date.tm_year = MyRTC_Time[0] - 1900;
    time_date.tm_mon  = MyRTC_Time[1] - 1;
    time_date.tm_mday = MyRTC_Time[2];
    time_date.tm_hour = MyRTC_Time[3];
    time_date.tm_min  = MyRTC_Time[4];
    time_date.tm_sec  = MyRTC_Time[5];

    time_cnt = mktime(&time_date);      /* 日期时间 → 秒数（当地） */

    RTC_SetCounter(time_cnt);
    RTC_WaitForLastTask();
}

void MyRTC_ReadTime(void)
{
    time_t time_cnt;
    struct tm time_date;

    time_cnt = RTC_GetCounter();                    /* 读秒数 */
    time_date = *localtime(&time_cnt);              /* 秒数 → 日期时间 */

    MyRTC_Time[0] = time_date.tm_year + 1900;
    MyRTC_Time[1] = time_date.tm_mon + 1;
    MyRTC_Time[2] = time_date.tm_mday;
    MyRTC_Time[3] = time_date.tm_hour;
    MyRTC_Time[4] = time_date.tm_min;
    MyRTC_Time[5] = time_date.tm_sec;
}
  • MyRTC.c 里 #include <time.h>，MyRTC_Time 数组顺序是年/月/日/时/分/秒，整个用 uint16_t：年份 2023 超过了 uint8_t 的范围。
  • SetTime 三步：① 填 struct tm ② mktime 得到秒数 ③ 写入 CNT；年和月要减，即 tm_year = MyRTC_Time[0] - 1900、tm_mon = MyRTC_Time[1] - 1。
  • 代码原文每行带分号：tm_mon = MyRTC_Time[1] - 1;、tm_mday = MyRTC_Time[2];、tm_hour = MyRTC_Time[3];、tm_min = MyRTC_Time[4];、tm_sec = MyRTC_Time[5];。
  • 图 11 截图里是全角括号版：tm_mon = MyRTC_Time（1） - 1;、tm_mday = MyRTC_Time（2）;、tm_hour = MyRTC_Time（3）;、tm_min = MyRTC_Time（4）;、tm_sec = MyRTC_Time（5）;。
  • 换算两句：time_cnt = mktime(&time_date)、RTC_SetCounter(time_cnt)；读回 time_cnt = RTC_GetCounter()、time_date = *localtime(&time_cnt)。
  • ReadTime 是反过程：读 CNT → localtime → 回填数组（年加 1900、月加 1）。
  • MyRTC.h：#ifndef __MYRTC_H / #define __MYRTC_H、全局数组声明要加 extern、三个函数原型、#endif。

图 10：MyRTC.c 开头的全局数组 uint16_t MyRTC_Time[] = {2023, 01, 01, 23, 59, 55};，回车位置有红叉，正是因为 09 这类前导 0 会报错；字幕「十进制数前面，千万不要随意补0」

图 11：MyRTC_SetTime 完整——time_t time_cnt; struct tm time_date;、time_date.tm_year = MyRTC_Time[0] - 1900;、tm_mon 减 1、tm_mday/tm_hour/tm_min/tm_sec 依次赋值、time_cnt = mktime(&time_date);、RTC_SetCounter(time_cnt);

图 12：MyRTC.h——#ifndef __MYRTC_H / #define __MYRTC_H、全局数组声明（int16_t MyRTC_Time[];，此处还需加 extern）、void MyRTC_Init(void);、void MyRTC_SetTime(void);、void MyRTC_ReadTime(void);、#endif

}
  • 三行模板串：OLED_ShowString(1,1,"Date:XXXX-XX-XX");、(2,1,"Time:XX:XX:XX");、(3,1,"CNT :");。
  • 现象：Date:2023-01-01、Time:23:59:55（这是伦敦时间，localtime 在 STM32 上默认 0 时区）、CNT:1672588795。
  • 数组里的时间没被用到（初始化时没调 MyRTC_SetTime），显示的是 RTC_SetCounter 的初始秒数。

4. 代码修正过程

4.1 前导 0 是八进制

  • 数组里写 {2023, 01, 01, 23, 09, 55} 会报错：C 语言里 0 开头的数字是八进制，八进制没有 9。
  • 即使不报错也容易错：0123 是八进制 123（十进制 83），所以 if (123 == 0123) 不成立。
  • 作者之前 51 单片机教程里「密码判断不正确」的 bug 就是这个原因。
  • 建议写 {2023, 1, 1, 23, 59, 55}，十进制数前面千万不要随意补 0。

4.2 函数定义在调用之后会报错

  • 在 MyRTC_Init 里调用 MyRTC_SetTime()，但它的定义写在后面 → 编译报错（函数未声明）。
  • 两种办法：① 前置声明 ② 调整顺序。

4.3 时区偏移

  • STM32 上没有系统时区：localtime 和 gmtime 都按 0 时区（伦敦）处理，裸机上 time() 也不能用。
  • 读取时：在秒数上加 8 * 60 * 60（28800 秒） → time_cnt = RTC_GetCounter() + 8*60*60; 再 localtime。
  • 写入时：先把秒数减 8 * 60 * 60 再写入 CNT；加减的量就是 8*60*60 秒。
  • 不能在「小时」上直接 +8：要考虑进位（跨天、跨月），在秒数上加减才严谨。
  • 偏移后现象：Date:2023-01-02、Time:00:00:12、CNT:1672617615，与 PPT 的北京时间↔时间戳对应关系一致。

图 14：时区偏移后的现象——OLED 显示 Date:2023-01-02 / Time:00:00:12 / CNT :1672617615，与 PPT 的北京时间↔时间戳对应关系一致

4.4 掉电保持：用 BKP_DR1 存标志

  • 问题：每次复位都会调 MyRTC_Init → 里面有 MyRTC_SetTime() → 时间被重置。
  • 做法：用 BKP_DR1 存标志值 0xA5A5，判断「是不是刚上电或完全断电过」。
  • 上电先 BKP_ReadBackupRegister(BKP_DR1)；不等于 0xA5A5 → 完整初始化，最后 BKP_WriteBackupRegister(BKP_DR1, 0xA5A5)。
  • 等于 0xA5A5 → 不重复初始化，只调 RTC_WaitForSynchro() ＋ RTC_WaitForLastTask()。
  • 验证：复位、断主电源时间继续走；完全断电后 DR1 清零 → 重新初始化。

图 15：MyRTC_Init 八步集中可见（整段高亮）——PWR/BKP 时钟、PWR_BackupAccessCmd(ENABLE)、LSE 配置与 LSERDY 等待、RCC_RTCCLKConfig、RCC_RTCCLKCmd(ENABLE)、两个等待函数、RTC_SetPrescaler(32768 - 1)，最后调用 MyRTC_SetTime();

4.5 DIV 线性变换（扩展）

  • 主循环加 OLED_ShowString(4, 1, "DIV :") 与 OLED_ShowNum(4, 6, (32767 - RTC_GetDivider()) / 32767 * 999, 10)。
  • 原理：RTC_GetDivider() 返回 DIV（32767→0 递减），32767 - DIV 变成 0→32767，再 / 32767 * 999 缩放到 0～999（算式本体 (32767 - RTC_GetDivider()) / 32767 * 999）。
  • 这样能得到比「秒」更细的时间（厘秒/毫秒级）。

图 16：DIV 线性变换——OLED_ShowString(4, 1, "DIV :"); 与 OLED_ShowNum(4, 6, (32767 - RTC_GetDivider()) / 32767 * 999, 10);

坑与易错点

  1. 两个程序别混：12-2 读写备份寄存器与12-2 实时时钟是两个独立工程。
  2. VBAT 用 ST-Link 的 3.3V 模拟，绝不能接 5V，产品用 3V 纽扣电池。
  3. PWR 和 BKP 时钟都要开：PWR_BackupAccessCmd 依赖 PWR 时钟。
  4. BKP_DRx 只有 DR1～DR10（F103C8T6 中容量），1～42 是全部型号上限。
  5. RTC 没有结构体和 RTC_Cmd：开 RTCCLK 后计数器自动运行。
  6. LSE 默认关闭：要 RCC_LSEConfig(RCC_LSE_ON) 并等 LSERDY，否则卡住。
  7. 预分频写 32768-1：计数值含 0，写 32768 就是 32769 分频了。
  8. 每个 RTC 写操作后都要 RTC_WaitForLastTask()，写值不会立刻生效。
  9. 不用手动 Enter/ExitConfigMode：RTC_SetCounter/SetPrescaler 内部自带。
  10. C 前导 0 是八进制：09 报错、0123 != 123，十进制常量别补 0。
  11. 函数定义在调用之后会报错：前置声明或调序；头文件里数组要 extern。
  12. MyRTC_Time[] 用 uint16_t：2023 超过 uint8_t；顺序是年/月/日/时/分/秒。
  13. tm_year 要 -1900、tm_mon 要 -1（写时），读回来要 +1900、+1。
  14. localtime/gmtime 都是 0 时区：显示北京时间要在秒数上 ±8×3600。
  15. 每次复位重置时间：用 BKP_DR1 存 0xA5A5 标志判断是否完整初始化。
  16. RTC_GetDivider() 的 DIV 是 32767→0 自减：(32767-DIV)/32767*999 映射到 0～999。
