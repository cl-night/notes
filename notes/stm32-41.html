[12-1] Unix时间戳 — 学习笔记

一句话结论

Unix 时间戳是从 1970 年 1 月 1 日 UTC 起经过的秒数，全时区共用一个秒计数器，按小时的时区偏移得到当地时间。STM32 的 RTC 计数器本质就是这样一个秒计数器，C 语言则用 time.h 做各种换算。

本集定位

  • 模块 12（RTC 实时时钟）的第一节，对应参考手册第 16 章；本集零 STM32 代码。
  • 00:00 先翻手册交代位置 → 01:27–06:36 只演示两个成品程序的现象（12-1 读写备份寄存器、12-2 实时时钟）→ 06:36 起讲 Unix 时间戳、UTC/GMT、闰秒 → 23:39 起在 Dev-C++ 里逐个演示 time.h 的函数。
  • 两个任务：了解 Unix 时间戳是什么、会用 time.h 做时间戳转换；这套知识不专用于 STM32。
  • 结尾 44:24「那我们下一小节，再见」；BKP/RTC 外设结构在 [12-2]、代码在 [12-3]。

1. 片头：两个成品程序的现象

1.1 现象①：BKP 备份寄存器（12-1 读写备份寄存器）

  • 手册 16.1 要点：RTC 与时钟配置系统（RCC_BDCR）位于后备区域，系统复位或从待机模式唤醒后 RTC 的设置和时间维持不变。

  • 系统复位后对后备寄存器和 RTC 的访问被禁止（防止对 BKP 的意外写），要访问需置 RCC_APB1ENR 的 PWREN、BKPEN 位（电源接口和后备接口时钟），再置 PWR_CR 的 DBP 位。

  • 硬件：在 ST-Link 上引一根线，模拟电池电源（VBAT）。

  • 程序：按键后往两个备份寄存器分别写入 0x1234、0x5678 再读出来显示（OLED 的 W: 与 R: 两行）。

  • 访问前要开时钟与后备访问：RCC_APB1PeriphClockCmd(RCC_APB1Periph_BKP, ENABLE);、RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);、PWR_BackupAccessCmd(ENABLE);。

  • 显示用 OLED_ShowString(1, 1, "W:"); 与 (2, 1, "R:"); 两行。

  • 写入和读出一样——BKP 和上一节的 Flash 类似，都是存数据的地方。

  • 只要 VBAT 有电池供电，即使 STM32 主电源断电，BKP 的值仍维持原状，重新上电读出来和断电前一样。

  • 按下复位键 BKP 的数据也不复位；但把 VBAT 也断开（彻底没电）后数据就清零——BKP 本质上并不能做到完全掉电不丢失。

  • 结论：BKP 更多是为了服务 RTC 的（用它保存配置/状态）。

1.2 现象②：RTC 实时时钟（12-2 实时时钟）

  • OLED 显示年月日时分秒，靠 VBAT 电池维持。
  • 按复位键：时间继续走、不复位。
  • 拔掉系统主电源：时间仍然继续走（VBAT 供电），就像手机一样。
  • 这说明 RTC 是真正掉电不丢时间的，本质上是借 BKP 后备区域实现的。

  • 有的芯片 VBAT 的电源还会微弱地给整个系统供电，导致拔掉主电源后系统还有残留供电（现象不明显但存在）。

2. Unix 时间戳

2.1 定义

  • Unix 时间戳：从 UTC/GMT 的 1970 年 1 月 1 日 0 时 0 分 0 秒开始所经过的秒数，不考虑闰秒。
  • 时间戳存储在一个秒计数器里，秒计数器为 32 位/64 位的整型变量。
  • 世界上所有时区的秒计数器相同，不同时区通过添加偏移得到当地时间。
  • 最早在 Unix 系统使用，之后 Linux、Windows、安卓等系统都继承了这套规定。
  • 对计算机：一个永不进位的秒数，存储和计算都非常方便；对人：一长串秒数难记难理解，所以要能双向转换。

2.2 秒计数器 vs 日期时间（对照表）

秒计数器 日期时间（伦敦） 日期时间（北京）
0 1970-1-1 0:0:0 1970-1-1 8:0:0
1000000000 2001-9-9 1:46:40 2001-9-9 9:46:40
1672588795 2023-1-1 15:59:55 2023-1-1 23:59:55
  • 年月日时分秒计时系统每 60 秒进 1 分钟、每 60 分钟进 1 小时，再进位到日、月、年。
  • 秒计数器则永不进位：60 秒就是 60、100 秒就是 100，千秒万秒一亿秒都直接加下去。

图 5：PPT「Unix时间戳」定义页，字幕「之后继续进位，就是日、月、年了」

2.3 为什么用秒计数器

  • 好处①简化硬件电路：设计 RTC 时放一个大秒寄存器即可，不用考虑年月日寄存器、进位、大月小月、平年闰年。
  • 好处②时间间隔计算方便：两个时刻的秒数相减，再除一小时的秒数，就能算出间隔。
  • 好处③存储方便：存一个比较大的变量即可。
  • 坏处：比较占用软件资源——给人看的时候，软件要做一遍复杂的换算。

2.4 存储格式与溢出风险

  • 秒计数器可用 32 位或 64 位整型存储；以 32 位有符号为例，最大值 2^32/2 − 1 = 2147483647，约 21 亿多秒。
  • 这个数只够用到 2038 年前后，业界称 2038 问题，可能导致很多不健全的程序出错。
  • 现代手机/电脑多用 64 位时间戳，能存的时间范围非常非常大。
  • 本课程 STM32 的 RTC 计数器是 32 位的（详见 [12-2]）。

图 6：32 位溢出，字幕「2^32/2−1，大家可以拿计算器算一下」

2.5 时区与时间轴

  • 地球分 24 个时区，每差一个时区 ±1 小时；所有时区共用一个秒计数器，各自加小时偏移得到当地时间。
  • 秒计数器 0 对应伦敦 0 点，中国在东 8 区，对应北京就是 8 点。
  • 起点是人为规定的伦敦时间 1970 年 1 月 1 日 0 点；1970 年之前的时间戳无法表示。
  • 时间戳有两种表现形式：① 永不进位的秒计数原值；② 由它计算出的年月日时分秒。
  • 后一种要算一年多少秒、一天多少秒、现在是第几天第几时几分几秒，还要考虑大小月、平年闰年——计算麻烦但步骤固定，所以直接用现成的库函数 time.h。

3. UTC 与 GMT、闰秒

3.1 GMT（格林尼治标准时间）

  • 英文全称 Greenwich Mean Time，中文译「格林尼治标准时间」，也译格林威治标准时间，都是一个意思。
  • 格林尼治是英国伦敦的一个地名，可以简单理解为伦敦标准时间。
  • 以地球自转为基础：把地球自转一周的时间间隔等分为 24 小时，以此确定计时标准。
  • 这种计时方法很符合直觉（一天就定义为地球自转一周），以前全球计时都用 GMT，不同时区再加小时偏移。

3.2 GMT 的缺陷与 UTC 的引入

  • 地球自转一周的时间其实不固定：由于潮汐、地质活动等原因，地球目前越转越慢。
  • 如果用「一天」来定义时间基准，秒长就会不断变长，光速、音速这类常数就固定不了。
  • 于是提出 UTC（Universal Time Coordinated，协调世界时），以原子钟为基础：规定铯 133 原子基态的两个超精细能级间在零磁场下跃迁辐射 9,192,631,770 周所持续的时间为 1 秒。

3.3 为什么要闰秒

  • 用恒定的秒计时，而地球自转越来越慢，两者会逐渐出现偏差；时间长了中午 12 点太阳可能不在正上方。
  • 所以在原子钟基础上加入闰秒：当原子钟计时的一天与地球自转一周的时间相差超过 0.9 秒时，UTC 执行闰秒，多打一秒去追上地球自转。
  • 闰秒示例：上一次闰秒是北京时间 2017 年 1 月 1 日 7 时 59 分 59 秒，下一秒时钟出现 7 时 59 分 60 秒，这一分钟总共 61 秒。
  • 副作用：闰秒可能造成一些程序 bug；时间戳对闰秒没有适应性，每次闰秒就会与授时中心的标准时间差 1 秒。
  • 日常生活中 GMT 与 UTC 可以看成一样：手机/电脑里写 GMT+8 或 UTC+8 都表示东 8 区时间。

4. C 语言 time.h 与三种数据类型

4.1 七个函数

函数原型 作用

4.2 三种数据类型

(1) 秒计数器类型 time_t

  • time_t 是 typedef 重命名的类型；在 Dev-C++（MinGW）里展开后是 time64_t，实际上就是 int64，64 位有符号整型。
  • 如果没有特别声明（如 _USE_32BIT_TIME_T），默认用 64 位，不用担心溢出；它存的就是一直自增的秒数。

(2) 日期时间类型 struct tm

  • 定义在 time.h 里，是封装好的结构体类型，用 struct tm 两个词作类型名；9 个成员：
成员 含义 取值范围
tm_sec 秒 0～59（有些实现含闰秒到 61）
tm_min 分 0～59
tm_hour 时（从午夜起） 0～23
tm_mday 日 1～31
tm_mon 月（从 1 月起的偏移） 0～11（0 是 1 月）
tm_year 年（从 1900 年起的年数） 如 123 表示 2023 年
tm_wday 星期（从周日起的偏移） 0～6（0 是周日）
tm_yday 一年中的第几天 0～365
tm_isdst 是否使用夏令时 +1 使用 / 0 不使用 / −1 不知道
  • 两个偏移要特别注意：tm_year 的偏移是 1900（时间戳起点是 1970，两者不一样），真实年份＝tm_year+1900；tm_mon 从 0 开始，真实月份＝tm_mon+1。
  • 夏令时（tm_isdst）：欧美不少国家还在用，我国曾经用过、现在已经不用；本集只解释含义，不展开实现。
  • 写法差异：time.h 里是 struct tm { ... };（没加 typedef），而 STM32 库函数习惯 typedef struct { ... } 新名字;，效果一样，只是使用时类型名要写 struct tm。

(3) 字符串类型 char*

  • char* 是 char 型数据的指针，用来指向一个表示时间的字符串（如 ctime/asctime/strftime 的输出）。

图 10：struct tm 定义原文，字幕「然后tm_wday，表示从周日开始的星期几」

5. Dev-C++ 实操（PC 端 C 程序，不是 STM32 工程）

5.1 准备

  • 打开 Dev-C++（任何 C 编译器都可以），建一个 HelloWorld 工程，在 main.c 里 #include <stdio.h> + #include <time.h>。
  • 定义三个全局变量：time_t time_cnt;（秒计数器）、struct tm time_date;（日期时间）、char *time_str;（字符串）。
  • 这些函数大量涉及指针操作，指针不熟的建议先补指针教程。

5.2 time()：获取系统时间

time_cnt = time(NULL);      /* 用返回值 */
time(&time_cnt);            /* 或用输出参数，效果一样 */
printf("%d\n", time_cnt);   /* 打印当前时间戳秒数 */
  • 参数不需要时可以给 NULL；返回值就是当前时间戳，类型 time_t。
  • time 的两种用法：time(NULL) 与 time(&time_cnt) 等价，代码里写 time_cnt = time(NULL); 或 time(&time_cnt);，结果存进 time_cnt。
  • 用在线时间戳转换工具可以验证这个数对不对。
  • 重点：这个函数在电脑里可以直接读电脑时间，但在 STM32 里用不了——STM32 是裸机系统，不知道现在是啥时间，要靠 RTC 计数器自己维护。

5.3 gmtime()：秒 → 格林尼治日期时间

time_cnt = 1672588795;                  /* 手动给一个秒数做测试 */
time_date = *gmtime(&time_cnt);         /* 返回值是指针，赋值给结构体要加 * */
printf("%d\n", time_date.tm_year + 1900);
printf("%d\n", time_date.tm_mon + 1);
printf("%d\n", time_date.tm_mday);
/* …tm_hour / tm_min / tm_sec / tm_wday 同理 */
  • gmtime 返回 struct tm*（指针），而左边 time_date 是结构体变量，指针不能直接赋给变量，所以要在右边加 * 取内容（也可以把左边定义成指针）。
  • 打印时年份要 +1900、月份要 +1（即 tm_year + 1900、tm_mon + 1），否则会打印出 123 年、0 月。
  • 结果：1672588795 → 伦敦时间 2023-1-1 15:59:55、星期日，与 PPT 对照表一致。

图 12：gmtime 代码，字幕「好，这样，我们的转换实际上就已经完成了」

5.4 localtime()：秒 → 当地日期时间

  • 用法和 gmtime 完全一样，只是函数名换成 localtime。
  • 区别：localtime 会根据本机时区自动添加小时的偏移——东 8 区得到 2023-1-1 23:59:55（比伦敦多 8 小时），与 PPT 对照表一致。

5.5 mktime()：日期时间 → 秒（必须传当地时间）

time_cnt = mktime(&time_date);   /* 传入日期时间结构体的地址 */
printf("%d\n", time_cnt);
  • 是上面两个函数的逆过程；参数是日期时间结构体指针。
  • 必须传当地时间：把 localtime 得到的结果转回去，秒数和最初的 1672588795 完全一样。
  • 反例：换成 gmtime 的结果（伦敦时间）再 mktime，得到的秒数就和最初不一样，说明 mktime 按当地时间解析。
  • 参数没有 const：因为 mktime 算秒数时会回填 tm_wday（星期）和 tm_yday（一年第几天），传进去的星期实际上不作为输入。

5.6 ctime() / asctime()：转成默认格式字符串

time_str = ctime(&time_cnt);   printf(time_str);   /* time_t → 字符串 */
time_str = asctime(&time_date); printf(time_str);  /* struct tm → 字符串 */
  • 两者输出完全相同的默认格式字符串，例如 Sunday January 1 23:59:55 2023（结构是 Sunday January … 这种「星期 月 日 时 分 秒 年」顺序）。
  • 这是西方国家的习惯格式，中国一般不用，所以这两个函数用得不多，了解即可。

5.7 strftime()：自定义格式

char str[50];
strftime(str, 50, "%H:%M:%S", &time_date);
printf("%s\n", str);
  • 四个参数：① 字符数组 ② 数组长度 ③ 格式字符串 ④ 日期时间结构体指针，即 strftime(char 数组, 长度, "%H:%M:%S", &time_date)。
  • 格式占位符参照菜鸟教程：%H 小时、%M 分钟、%S 秒；占位符会被替换成具体值，其他符号保留原样。
  • 结果就是 23:59:55 这种「小时-分钟-秒」格式。

5.8 重点掌握哪两个

  • 不太重要的函数：clock（计算程序执行了多长时间）、difftime（计算两个时间之间的差值），了解即可。
  • 必须重点掌握的是 localtime 与 mktime 这两个，其他了解即可。

坑与易错点

  1. gmtime/localtime 返回指针：赋给结构体变量要加 *（time_date = *gmtime(&cnt);），否则编译不过。
  2. 打印年份要 +1900、月份要 +1：tm_year 从 1900 起算、tm_mon 从 0 开始。
  3. tm_year 的偏移是 1900，与时间戳起点 1970 不是一回事，别混。
  4. localtime 与 gmtime 用法相同但结果差 8 小时（东 8 区），前者自动加时区偏移。
  5. mktime 必须传当地时间：传 gmtime 的结果换算回去会得到不同的秒数。
  6. mktime 参数没有 const：它会回填 tm_wday/tm_yday，传入的星期不作为输入。
  7. 32 位有符号秒计数器最大约 21 亿秒（2^32/2−1），存在 2038 问题；现代系统多用 64 位。
  8. 时间戳不考虑闰秒：每次闰秒会与授时中心标准时间差 1 秒，程序要注意。
  9. BKP 不能完全掉电不丢失：VBAT 断了就清零，它主要是为 RTC 服务。
  10. RTC 才是掉电不丢时间：靠 VBAT 后备区域供电，复位/主电源断开时间都继续走。
  11. time() 不能直接用在 STM32 裸机上：没有系统时间可读，要用 RTC 计数器自己维护秒数。
  12. GMT 与 UTC 日常可视为一样：写 GMT+8 / UTC+8 都表示东 8 区。
  13. clock/difftime 本集未演示：只需知道用途（程序运行时间、两时间差）。
  14. 夏令时 tm_isdst：+1 使用 / 0 不使用 / −1 不知道；我国现已不用。
