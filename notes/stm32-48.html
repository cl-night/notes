[15-1] FLASH闪存 — 学习笔记

一句话结论

FLASH 是下载程序的那块非易失存储，分程序存储器 0x08000000、系统存储器 0x1FFFF000、选项字节 0x1FFFF800 三部分；读靠指针，写要解锁（KEY1/KEY2）→ 擦除 → 半字编程 → 等 BSY；C8T6 主存 64K。

本集定位

  • 理论课：00:40–04:05 只演示 15-1 读写内部FLASH、15-2 读取芯片ID 两个已写好工程的现象，无写码；04:05–46:20 全是 PPT + 手册；
  • ⚠ FLASH 库函数本集一个都没出现：FLASH_Unlock/FLASH_ErasePage/FLASH_ProgramHalfWord 都没有，片头代码里只有作者自定义的 Store_Data()/Store_Clear()；
  • 库函数详解与代码在 [15-2]；结尾 46:12「我们下小节来学习闪存的代码部分」；
  • 主线：简介 → 存储器映像 → 存储器组织 → FPEC → 解锁 → 指针访问 → 三条流程 → 选项字节 → 电子签名。

1. 片头两个成品程序

1.1 程序①：15-1 读写内部FLASH

  • OLED 显示 Flag:A5A5（标志位，思路同 RTC 备份寄存器）与 4 个字节的 Data；
  • 按 Key1 变换数据并存入内部 FLASH、按 Key2 全部清零；断电重启、按复位键数据都不丢。

1.2 程序②：15-2 读取芯片ID

  • 用指针直接读指定地址，得到闪存容量（0x0040＝64K）与 96 位 UID（每片不同）。

1.3 两个用途与 ICP / IAP

  • 用途①存用户数据：用程序存储器的剩余空间保存掉电不丢失的数据（C8T6 只有 64K，简单程序只占前面很小一部分），选区域时绝不能覆盖原有程序，一般选最后几页；
  • 用途②IAP 自我更新：在程序中编程，效果相当于 OTA；
  • ICP（在线编程）：只留几个引脚、不用拆芯片，用 JTAG/SWD（就是 ST-Link）或系统加载程序（Bootloader，串口下载）更新程序存储器的全部内容，每次下载都是整体覆盖；
  • IAP（在程序中编程）：可用微控制器支持的任一种通信接口下载程序，可做远程升级——自写 Bootloader 放在不被覆盖处，接收数据后写入程序正常运行的地方，再跳回/复位；
  • 比芯片自带的系统 Bootloader 灵活（后者写死、只能串口、只能靠 BOOT 引脚触发）；本课程不涉及 IAP 实现。

2. 存储器映像回顾

  • 闪存是非易失性存储器（掉电不丢失），本节特指 STM32 内部闪存——就是下载程序存放的那块。
区域 起始地址 介质 特性
ROM 区（程序存储器 Flash） 0x08000000 FLASH 掉电不丢失
ROM 区（系统存储器） 0x1FFFF000 FLASH 原厂 Bootloader，不允许修改
ROM 区（选项字节） 0x1FFFF800 FLASH 配置读/写保护
RAM 区（运行内存 SRAM） 0x20000000 SRAM 掉电丢失、可读可写
RAM 区（外设寄存器） 0x40000000 SRAM 外设寄存器
RAM 区（内核外设寄存器） 0xE0000000 SRAM 内核外设
  • 看起始地址就能判断区域与特性：0x08 开头是程序存储器、0x20 是 SRAM、0x40 是外设、0xE0 是内核外设。

3.1 闪存的五项特性（与 W25Q64 一致）

  1. 写入前必须先擦除；
  2. 擦除以最小单位（页）进行；
  3. 擦除后数据位全变为 1；
  4. 数据只能 1 写 0，不能 0 写 1；
  5. 擦除和写入后都要等待忙（查 BSY）。

4. FLASH 基本结构与解锁

4.1 FLASH 基本结构（FPEC）

  • 核心是闪存存储器接口 / 闪存编程和擦除控制器（FPEC）；
  • 它对程序存储器做「擦除和编程」、对选项字节做「擦除和编程」；
  • 选项字节还能配置程序存储器的读/写保护；
  • FPEC 不能操作系统存储器（Bootloader 由原厂固化）。

4.2 三个键值

键 值 作用
RDPRT 键 0x000000A5 解除读保护（写到 RDP 选项字节位置）
KEY1 0x45670123 解锁第一道锁
KEY2 0xCDEF89AB 解锁第二道锁
  • 「KEY」＝钥匙/密钥寄存器；键值可以随便定义，只要不容易被翘锁（都是 1/0 交替的刁钻组合）。

4.3 解锁与加锁（两把锁）

  • 大锁（FPEC / FLASH_CR）：复位后 FPEC 被保护、不能写 FLASH_CR；在 FLASH_KEYR 先写 KEY1、再写 KEY2 解锁；
  • ⚠ 错误的操作序列会在下次复位前锁死 FPEC 和 FLASH_CR——只有复位能恢复；
  • 加锁：操作完成后尽快置 FLASH_CR 的 LOCK 位；
  • 小锁（选项字节）：另有一把小锁，要在 FLASH_OPTKEYR 写 KEY1、KEY2，且先置 FLASH_CR 的 OPTWRE 位才能擦/写选项字节；
  • 读不需要解锁、写必须解锁：闪存在程序运行时只读。

图 8：PPT「FLASH解锁」——三个键值 RDPRT、KEY1、KEY2；解锁＝FLASH_KEYR 先 KEY1 后 KEY2；错误序列会锁死；加锁＝置 LOCK 位

图 9：同页 + KEY1 行高亮——强调*先 KEY1 再用 KEY2 才能解开两道锁*

4.4 使用指针访问存储器

uint16_t Data = *((__IO uint16_t *)(0x08000000));      /* 读 */
*((__IO uint16_t *)(0x08000000)) = 0x1234;             /* 写 */

#define __IO volatile
  • 三步：①写地址（地址做加减时必须加括号，否则运算符优先级出错）②强制类型转换（16 位 uint16_t *、8 位 uint8_t *、32 位 uint32_t *、浮点 float */double *）③用 * 取值或赋值；
  • 写 SRAM（0x20000000）可以直接写——SRAM 不受 FPEC 保护。

4.5 volatile 的两个作用

  • 目的：防止编译器优化；Keil 默认最低优化等级，加不加无影响；提高优化等级后有两类问题：
    1. 用变量计数空循环做延时会被优化掉；
    2. 变量被缓存到寄存器——中断里改了原变量，缓存值不同步，判断出错；
  • 加 volatile 就是告诉编译器「每次都执行到位、不要用缓存优化」；
  • 读写与硬件相关的存储器时必须加（库函数里到处都是 __IO）。

图 10：读 uint16_t Data = *((__IO uint16_t *)(0x08000000));；写 *((__IO uint16_t *)(0x08000000)) = 0x1234;；并给出 #define __IO volatile

图 11：同页 + 红圈 __IO 与 volatile、红框标出「中断函数」——讲 volatile 防止变量被缓存到寄存器

5. 三条流程图

5.1 程序存储器全擦除

  1. 读 FLASH_CR 的 LOCK 位；
  2. 若 =1，执行解锁过程（FLASH_KEYR 写 KEY1、KEY2）——库函数里没有这个判断，直接无条件解锁；
  3. 置 FLASH_CR 的 MER（Mass Erase）位 =1；
  4. 置 STRT 位 =1（这是触发条件）；
  5. 内部电路自动执行全擦除；
  6. 查 FLASH_SR 的 BSY 位循环等待；
  7. 「读出并验证所有页的数据」——测试程序才做。

5.2 程序存储器页擦除

  1. 读 FLASH_CR 的 LOCK；
  2. 解锁；
  3. 置 FLASH_CR[PER]=1（PER＝Page Erase）；
  4. 在 FLASH_AR（Address Register）写入要擦除的页地址；
  5. 置 FLASH_CR[STRT]=1；
  6. 等待 BSY=0。
  • 擦除最小单位就是一页＝1K＝1024 字节。

5.3 程序存储器编程

  1. 读 FLASH_CR 的 LOCK；
  2. 解锁；
  3. 置 FLASH_CR 的 PG（Programming）位 =1；
  4. 在指定地址写入半字——这句本身就是触发条件，不需要置 STRT；
  5. 等待忙。
  • 写入前芯片会检查该地址是否已擦除：未擦除则不编程（除非写入的全是 0）；
  • 只能以半字（16 位）写入：字 Word＝32 位、半字 HalfWord＝16 位、字节 Byte＝8 位；
  • 写 32 位分两次；写 8 位很麻烦——只能「整页读到 SRAM → 随意修改 → 整页擦除 → 整页写回」；写入大量数据就循环调用该流程。

图 12：页擦除流程（红笔标注）——读 LOCK → 解锁 → FLASH_CR（PER）=1、FLASH_AR 写页地址、FLASH_CR（STRT）=1 → 查 BSY 循环 → 验证

6. 选项字节

  • 地址 0x1FFFF800，共 16 字节，成对存储：RDP/nRDP、USER/nUSER、Data0/nData0、Data1/nData1、WRP0/nWRP0～WRP3/nWRP3；
字节对 含义
RDP / nRDP 读保护（写入 RDPRT 键 0x000000A5 解除）
USER / nUSER 硬件看门狗、停机/待机是否产生复位等零碎位
Data0 / nData0 芯片未定义功能，用户可自定义
Data1 / nData1 同上
WRP0 / nWRP0 … WRP3 / nWRP3 写保护
  • 带 n 的必须是反码：芯片检测到两者不是反码关系则数据无效、对应功能不执行；反码由 FPEC 硬件自动计算（库函数已封装）；
  • 去掉带 n 的只剩 8 个字节：RDP、USER、Data0、Data1、WRP0～WRP3；
  • 读保护：不解除 RDPRT 时闪存处于读保护状态，无法通过调试器读取程序；
  • 写保护粒度：中容量每 1 位保护 4 个存储页，4 字节 32 位 → 4×32＝128 页（WRP0 管页 0～31、WRP1 页 32～63、WRP2 页 64～95、WRP3 页 96～127）；
  • 小容量每 1 位保护 4 页（1K/页）→ 4 位共保护 32K（WRP0 管第 0～31 页）；
  • 大容量每 1 位保护 2 页（2K/页），4 字节不够 → 规定 WRP3 的位 7 保护第 62～255 页，共 512K；
  • ⚠ 写保护位是反逻辑：0 ＝实施写保护、1 ＝不实施写保护（默认是 1，因为擦除后全是 1）；
  • 选项字节擦除/编程：擦除——①解锁闪存 ②检查 FLASH_SR 的 BSY ③解锁 FLASH_CR 的 OPTWRE 位（FLASH_OPTKEYR 写 KEY1、KEY2）④置 OPTER=1 ⑤置 STRT=1 ⑥等 BSY=0；编程——检查 BSY → 解小锁 → 置 OPTPG=1 → 指针写入半字 → 等待忙；
  • 当闪存由「保护」变为「未保护」时会自动执行整片擦除。

图 13：手册 2.5 选择字节说明 WRPx——小容量每比特位保护 4 页（1K/页）、0＝保护 1＝不保护；中容量四位保护 128K；大容量每比特位 2 页（2K/页）、WRP3 位 7 保护第 62～255 页，共 512K

7. 器件电子签名

  • 存放在闪存存储器模块的系统存储区域、出厂时编写、不可更改、用指针读指定地址即可获取；
  • 闪存容量寄存器 F_SIZE：基地址 0x1FFFF7E0，大小 16 位（以 K 字节为单位，0x0080＝128K、0x0040＝64K）；
  • 产品唯一身份标识寄存器（UID）：基地址 0x1FFFF7E8，大小 96 位；
  • 用途：序列号、密码（与加密算法结合提高代码安全性）、激活带安全机制的自举过程；
  • 任何情况下唯一、不能修改；可按字节（8 位）/半字（16 位）/全字（32 位）读取，偏移 0x00；
  • 96 位每片都不同 → 程序多处加 ID 判断，程序被盗到别的设备上也难运行。

图 14：FLASH 基本结构——左侧 FPEC；右侧 C8T6 程序存储器 0x0800 0000 页0(1K)、0x0800 0400 页1、0x0800 0800 页2、0x0800 0C00 页3…0x0800 F400 页61、0x0800 F800 页62、0x0800 FC00 页63；下方 0x1FFF F000 Bootloader(2K)、0x1FFF F800 选项字节(16)

图 15：电子签名在系统存储区域、出厂编写不可更改，指针读地址即可；F_SIZE 基地址 0x1FFFF7E0、16 位；UID 基地址 0x1FFFF7E8、96 位

图 16：手册 28.2 产品唯一身份标识寄存器（96 位）——位 15:0 为 F_SIZE（31:16 保留，以 K 字节为单位）；UID 用途：序列号、密码、激活自举；只读、偏移 0x00

8.1 手册结构

  • 《STM32F10xxx 闪存编程》PM0042：ICP/IAP 简介、2.3.1 小/中/大容量、2.3.2 Code 接口、2.3.3 预取缓冲区、2.4.1 FPEC、2.4.2 主闪存编程；
  • 寄存器章节：FLASH_ACR（与内核执行代码有关，不用深究）、FLASH_KEYR（闪存锁）、FLASH_OPTKEYR（选项字节小锁）、FLASH_SR（重点 BSY）、FLASH_CR（重点 LOCK/STRT/OPTER/OPTPG/MER/PER/PG）、FLASH_AR（配合页擦除指定页）、FLASH_OBR（加载选项字节内容）、FLASH_WRPR（写保护）。

8.2 坑①：任何读写闪存都会让 CPU 暂停

  • 原因：执行代码本身要读闪存，闪存忙时 CPU 无法运行 → 任何读写闪存的操作都会使 CPU 暂停到本次编程结束；
  • 后果：对时间敏感的频繁中断会卡顿/闪烁——点阵屏用定时器中断扫描刷新时，读写闪存会让屏幕快速闪烁；
  • 结论：程序里有对时间要求严格的频繁中断时，慎用内部闪存存用户数据。

8.3 坑②：由保护变未保护会自动整片擦除

  • 当闪存由「保护」变为「未保护」时，会自动执行整片擦除——解除读保护要小心数据全丢；
  • 另：写/擦除时必须打开 HSI 时钟（SystemInit 里已配好，不要动它）。

坑与易错点

  1. 纯理论课：片头只演示两个成品工程，FLASH 库函数零出现；片头 Store_Data()/Store_Clear() 是作者自定义封装，不是标准库函数。
  2. 四个地址别写串：主存 0x08000000 ｜ 系统存储器 0x1FFFF000（2K） ｜ 选项字节 0x1FFFF800（16 字节） ｜ 接口寄存器 0x40022000（属外设，不是闪存本体）。
  3. 容量口径：中容量 128 页×1K＝128K，C8T6 只有页 0～63＝64K；小容量 32 页×1K；大容量 256 页×2K；「芯片 64K/128K」只指主存储器。
  4. 三个键值：KEY1=0x45670123、KEY2=0xCDEF89AB（写 FLASH_KEYR，先 KEY1 后 KEY2，顺序错会锁死到复位）；RDPRT=0x000000A5（解除读保护）。
  5. 两把锁：大锁 FLASH_KEYR 管 FPEC/FLASH_CR；小锁 FLASH_OPTKEYR 管选项字节，且要先置 OPTWRE。
  6. 触发方式差异：全擦除/页擦除＝置位后还要置 STRT；编程＝写半字本身就是触发，不需要 STRT。
  7. 三条写限制：先擦后写、只能半字写、只能 1 写 0；写 8 位极麻烦（整页读 SRAM→改→整页擦→整页写回）；写全 0 可绕过擦除检查。
  8. 术语对照：字 Word=32 位、半字=16 位、字节=8 位；程序存储器=主存储器、启动程序代码=系统存储器、用户选择字节=选项字节。
  9. 选项字节反码+反逻辑：16 字节成对（带 n 的是反码、硬件自动算）；写保护 0=保护、1=不保护（默认）。
  10. 读不解锁、写必解锁；闪存在程序运行时只读；SRAM 可直接写。
  11. volatile：防止空循环延时被优化掉、防止变量被缓存到寄存器——读写硬件相关存储器必须加。
  12. 任何读写闪存都会让 CPU 暂停（对时间敏感的频繁中断会卡顿/闪烁）→ 慎用内部闪存存用户数据。
  13. 闪存由保护→未保护会自动整片擦除。
  14. 写/擦除需开 HSI 时钟（SystemInit 已配好，别动）。
  15. 器件电子签名：F_SIZE@0x1FFFF7E0（16 位）、UID@0x1FFFF7E8（96 位，每片唯一，可加密）。
