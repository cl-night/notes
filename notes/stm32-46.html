[14-1] WDG看门狗 — 学习笔记

一句话结论

看门狗本质是定时器：规定时间内没喂狗，硬件就自动复位。IWDG 独立看门狗用 LSI 40kHz、精度要求低、停机待机仍工作；WWDG 窗口看门狗用 PCLK1 36MHz，要求喂狗落在精确时间窗口内。

0. 本集定位

  • 混合课：00:00–04:15 只演示两个已写好的工程（14-1 独立看门狗、14-2 窗口看门狗，含代码展示），没有从零写码过程。
  • 04:15–40:07 全是 PPT 理论 + 手册精读：WDG 简介 → 与定时器对比 → IWDG 框图/键寄存器/超时公式 → WWDG 框图/工作特性/超时公式 → 对比表。
  • 结尾 40:04「本小节课到这里就结束了」，无下集预告。

1. 片头两个成品工程

1.1 程序①：14-1 独立看门狗

int main(void)
{
    OLED_Init();
    OLED_ShowString(1, 1, "IWDG TEST");

    /* 判断复位来源 */
    if (RCC_GetFlagStatus(RCC_FLAG_IWDGRST) == SET)
    {
        OLED_ShowString(2, 1, "IWDG RST");
        Delay_ms(500);
        OLED_ShowString(2, 1, "        ");
        Delay_ms(100);
        RCC_ClearFlag();          /* 清除复位标志 */
    }
    else
    {
        OLED_ShowString(3, 1, "RST");
        Delay_ms(500);
        OLED_ShowString(3, 1, "   ");
        Delay_ms(100);
    }

    /* 独立看门狗初始化 */
    IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);   /* 解除 PR/RLR 写保护 */
    IWDG_SetPrescaler(IWDG_Prescaler_16);           /* 16 分频 */
    IWDG_SetReload(2500);                           /* 1000ms */
    IWDG_ReloadCounter();                           /* 重装计数器 */
    IWDG_Enable();                                  /* 启用 IWDG */

    while (1)
    {
        Key_GetNum();

        IWDG_ReloadCounter();                       /* 喂狗 */
        OLED_ShowString(4, 1, "FEED");
        Delay_ms(200);
        OLED_ShowString(4, 1, "    ");
        Delay_ms(600);
    }
}
  • 初始化调用顺序：IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable) → IWDG_SetPrescaler(IWDG_Prescaler_16) → IWDG_SetReload(2500) //1000ms → IWDG_ReloadCounter() → IWDG_Enable()。
  • 写进 main.c 后带分号，同样是五行：IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);、IWDG_SetPrescaler(IWDG_Prescaler_16);、IWDG_SetReload(2500); //1000ms、IWDG_ReloadCounter();、IWDG_Enable();。
  • 喂狗间隔＝200 + 600 ＝ 800ms < 1000ms：IWDG_SetReload(2500) + 16 分频 → 1000ms，赶在超时前喂狗所以不会复位。
  • 复位来源判断：RCC_GetFlagStatus(RCC_FLAG_IWDGRST) 为 SET 说明是看门狗复位，显示 IWDG RST；否则正常复位显示 RST。
  • 现象：首行 IWDG TEST，主循环里 FEED 闪烁——Delay_ms(200) 亮、Delay_ms(600) 灭，Key_GetNum 是阻塞式按键读取。
  • 主循环原文：Key_GetNum(); IWDG_ReloadCounter(); OLED_ShowString(4,1,"FEED"); Delay_ms(200); … Delay_ms(600);。

1.2 程序②：14-2 窗口看门狗

int main(void)
{
    OLED_Init();
    OLED_ShowString(1, 1, "WWDG TEST");

    if (RCC_GetFlagStatus(RCC_FLAG_WWDGRST) == SET)
    {
        OLED_ShowString(2, 1, "WWDG RST");
        Delay_ms(500);
        OLED_ShowString(2, 1, "        ");
        Delay_ms(100);
        RCC_ClearFlag();
    }
    else
    {
        OLED_ShowString(3, 1, "RST");
        Delay_ms(500);
        OLED_ShowString(3, 1, "   ");
        Delay_ms(100);
    }

    RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);   /* WWDG 挂在 APB1 */
    WWDG_SetPrescaler(WWDG_Prescaler_8);                   /* 8 分频 */
    WWDG_SetWindowValue(0x40 + 21);                        /* 30ms 窗口 */
    WWDG_Enable(0x40 + 21);                                /* 使能并给初值 */
    ...
    while (1)
    {
        ...
        Delay_ms(20);
        WWDG_SetCounter(0x40 + 21);                        /* 喂狗 */
        Delay_ms(20);
    }
}
  • 复位来源换成 RCC_FLAG_WWDGRST：if (RCC_GetFlagStatus(RCC_FLAG_WWDGRST) == SET) { OLED_ShowString(2,1,"WWDG RST"); … RCC_ClearFlag(); } else { OLED_ShowString(3,1,"RST"); … }。
  • 复位后必须调 RCC_ClearFlag() 清标志，否则下次复位仍会被误判成看门狗复位。
  • 配置三句：RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);、WWDG_SetPrescaler(WWDG_Prescaler_8);、WWDG_SetWindowValue(0x40 + 21); //30ms。
  • 三句去掉分号的原型写法：RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE)、WWDG_SetPrescaler(WWDG_Prescaler_8)、WWDG_SetWindowValue(0x40 + 21) //30ms。
  • 首行 OLED_ShowString(1, 1, "WWDG TEST");，现象显示 WWDG TEST 与第 4 行 FEED。
  • WWDG_SetWindowValue(0x40 + 21)：0x40 是 T6 位为 1 的基准（0x40＝64），+21 得 0x55；配合 8 分频形成 30ms 窗口、超时约 50ms。
  • 主循环 Delay 20+20＝40ms 后喂狗，落在 30～50ms 窗口内；喂太早（窗口外）复位，喂太晚（低于 0x40）也复位。
  • 用按键阻塞式 Key_GetNum() 模拟程序卡死：按住按键时主循环不喂狗 → 超时复位，OLED 显示 WWDG RST。

1.3 WDG 是什么、为什么要用

  • 看门狗监控程序运行状态：程序因设计漏洞、硬件故障、电磁干扰出现卡死或跑飞时及时复位，避免长时间「罢工」。
  • 本质是定时器：指定时间范围内程序没执行喂狗（重置计数器），看门狗硬件电路自动产生复位信号。
  • STM32 内置两个：IWDG 独立看门狗（独立工作、对时间精度要求较低）、WWDG 窗口看门狗（要求看门狗在精确计时窗口起作用）。
  • 为什么需要：复杂项目的状态与可能性极多，bug 无法避免；常用手段是「已知 bug 写处理逻辑」+「看门狗兜底」。
  • 看门狗不能解决 bug 本身，但能让偶发卡死的程序回到正轨。
  • 局限：硬件关键器件损坏时复位也没用，而且不能因为有看门狗就写大量死循环或不规范程序。

2. 与普通定时器的对比

  • 普通定时器时基单元（图57）：PSC 预分频器 + CNT 计数器 + ARR 自动重装器；输入时钟经预分频驱动计数器自增/自减，减到 0 产生更新事件和中断，并由硬件自动重装。
  • 看门狗的三点不同：
    1. 必须自减（不能自增）。
    2. 减到 0 直接产生复位（不是中断）。
    3. 没有自动重装器——必须在减到 0 之前由程序手动重装，这就是「喂狗」。
  • 类比：定时器是闹钟（响了没事），看门狗是定时炸弹（到点就复位）。

图 6：PPT「定时中断基本结构」图57——时基单元由 PSC 预分频器 + CNT 计数器 + ARR 自动重装器组成

3. IWDG 独立看门狗

3.1 框图（图157）

  • LSI 40kHz（内部低速时钟）→ 8 位预分频器（由 IWDG_PR 的 PR[2:0] 控制）→ 驱动 12 位递减计数器，减到 0 产生 IWDG 复位。
  • IWDG_RLR（重装寄存器，RL[11:0]）的值经「12 位重装载数值」送进计数器——喂狗就是把它重新装进计数器。
  • IWDG_SR（状态寄存器）只有 RVU（重装值更新）与 PVU（预分频值更新）两个同步位，基本不用看。
  • IWDG_KR（键寄存器）控制启停与喂狗（见 3.2）。
  • 12 位计数器最大值＝2^12−1＝4095。
  • ⚠ IWDG 位于 VDD 供电区（不是 1.8V 区域），所以在停机和待机模式下仍能正常工作——这也是「独立」的含义之一。

3.2 键寄存器 IWDG_KR（核心）

  • 本质是控制寄存器，但为避免干扰，用「整个键寄存器写入特定值」代替「给控制寄存器某一位写值」——16 位全比对，抗干扰强，键值都是 1/0 交替的「刁钻组合」。
写入 IWDG_KR 的值 作用
0xCCCC 启用独立看门狗
0xAAAA 把 IWDG_RLR 的值重新加载到计数器（喂狗）
0x5555 解除 IWDG_PR 和 IWDG_RLR 的写保护
0x5555 之外的其他值 启用 IWDG_PR 和 IWDG_RLR 的写保护
  • 写 PR/RLR 之前必须先写 0x5555，写完再写任意值恢复写保护；库函数里就是 IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable/Disable)。

3.3 超时时间公式与表83

  • T_IWDG = T_LSI × PR 预分频系数 × (RL + 1)，其中 T_LSI = 1/F_LSI = 1/40kHz = 0.025ms。
  • 等价说法：超时频率＝LSI 频率 / 预分频 / 重装值。
  • 表83（40kHz 输入时钟 LSI）：
预分频系数 PR[2:0] 位 最短时间（ms，RL=0x000） 最长时间（ms，RL=0xFFF）
/4 0 0.1 409.6
/8 1 0.2 819.2
/16 2 0.4 1638.4
/32 3 0.8 3276.8
/64 4 1.6 6553.6
/128 5 3.2 13107.2
/256 6 或 7 6.4 26214.4
  • 规律：分频系数每翻一倍，超时时间也翻一倍；/4 档最短 0.1ms、最长 409.6ms。
  • 验算（对应程序①）：IWDG_SetReload(2500)、16 分频 → T = 0.025ms × 16 × (2500+1) ≈ 1000.4ms，这就是注释里「//1000ms」的来历。

4. WWDG 窗口看门狗

4.1 框图（图158）

  • PCLK1（36MHz，来自 RCC 时钟控制器）→ 看门狗预分频器 WDGTB（1/2/4/8）→ 6 位递减计数器。
  • 公式里还要乘一个框图中未画出的固定 4096 分频：36MHz 太快，先固定 /4096 再送 WDGTB。
  • 计数器值在 WWDG_CR：WDGA（激活位）+ T6～T0；其中 T6～T0 是 7 位，实际有效计数是低 6 位 T[5:0]，T6 单独作溢出标志位。
  • 窗口值 W[6:0] 在 WWDG_CFR（另有 EWI 中断使能与 WDGTB[1:0]）。
  • 比较器：「当 T[6:0] > W[6:0]，比较结果＝1」，即当前计数值还在窗口之上 → 此刻喂狗属于「太早」。
  • 两路复位经或门、再经 WDGA 与门输出复位：① T6 溢出标志位（T6 变成 0）；② 窗口比较结果（窗口外重装）。
  • 只有在 WDGA＝1（看门狗已激活）时，复位信号才能输出。

4.2 工作特性（4 条）与图159 时序图

  1. 递减计数器 T[6:0] 的值小于 0x40 时，WWDG 产生复位（喂狗太晚——已经掉到 0x3F 以下）。
  2. T[6:0] 在窗口 W[6:0] 之外被重新装载时，WWDG 产生复位（喂狗太早）。
  3. T[6:0] 等于 0x40 时可产生早期唤醒中断（EWI），用于重装载计数器以避免复位——俗称「死前中断」，可在其中保存重要数据、关闭危险设备，或直接喂狗。
  4. 定期写入 WWDG_CR 寄存器（喂狗）以避免 WWDG 复位。
  • 图159 时序图：纵轴 T[6:0]，画出 W[6:0] 与 3Fh 两条水平线；横轴分段为「不允许刷新」（高于 W）与「刷新窗口」（W 与 0x40 之间）；T6 位在计数器从 3Fh 掉到 0 时翻转，同时产生复位。

4.3 超时时间与窗口时间公式

  • 超时时间：T_WWDG = T_PCLK1 × 4096 × WDGTB 预分频系数 × (T[5:0] + 1)。
  • 窗口时间：T_WIN = T_PCLK1 × 4096 × WDGTB 预分频系数 × (T[5:0] − W[5:0])。
  • 其中 T_PCLK1 = 1/F_PCLK1（36MHz 时＝1/36µs）。
  • WDGTB 的分频系数＝2^WDGTB：WDGTB＝0→1 分频、1→2、2→4、3→8。
  • 4096 是框图中没画出的固定分频，务必别漏乘。
  • 手册表（PCLK1＝36MHz，最小/最大超时时间）：
WDGTB 最小超时时间 最大超时时间
0 113µs 7.28ms
1 227µs 14.56ms
2 455µs 29.12ms
3 910µs 58.25ms
  • 窗口时间手册不给表，需要自己套公式：先按需求定超时时间，再算窗口时间。
  • 量级参考：WDGTB＝0 最小 113us、最大 7.28ms；WDGTB＝3 最小 910µs、最大 58.25ms。

  • LSI 实际频率在 30K～60K 之间变化、并不精确，所以 IWDG 超时时间只能按 40kHz 估算——这也正是「对时间精度要求较低」的原因。
  • 键值表里只有「启动看门狗」指令，没有「关闭」指令——看门狗一旦开启就无法关闭（防止误操作关掉）。
  • IWDG 的 CNT 计数器不开放读写，运行中看不到当前计数值，对调试不友好。
  • 表84 寄存器映像：IWDG_KR@000h（KEY[15:0]，复位值全 0）、IWDG_PR@004h（PR[2:0]）、IWDG_RLR@008h（RL[11:0]，复位值 0xFFF）、IWDG_SR@00Ch（RVU/PVU）。
  • 注：若使用多个重装值或预分频值，必须在 RVU 位被清除后才能改重装值、PVU 位清除后才能改预分频值；但更新后不必等 RVU/PVU 复位就可继续执行，低功耗模式下写操作仍会完成。

6.2 第 18 章 WWDG

  • 结构：18.1 简介/主要特性、18.3 功能描述、18.4 如何编写看门狗超时程序、18.6 寄存器描述、18.6.4 寄存器映像（表85）。
  • 系统复位后必须始终置 T6 位为 1，以避免立即产生复位——因为 T6 一为 0 就判溢出。
  • WDGA 位置 1 之后不能再关闭，只有复位能关掉；递减计数器处于自由运行状态，即使看门狗被禁止，计数器仍继续递减。
  • 上电开启时一定要先给一个重装值，否则立即复位。
  • 表85 寄存器映像：WWDG_CR@000h（WDGA + T[6:0]，复位值 0 与 1111111）、WWDG_CFR@004h（EWI + WDGTB[1:0] + W[6:0]）、WWDG_SR@008h（EWIF 早期唤醒中断标志）。

坑与易错点

  1. 本集不是从零写码课：片头只演示两个成品工程（含代码展示），其余全是 PPT + 手册。
  2. 看门狗必须自减、减到 0 直接复位、没有自动重装——手动重装就是「喂狗」。
  3. IWDG 减到 0 复位；WWDG 是 T[6:0] 减到小于 0x40（即到 0x3F）复位——不是减到 0。
  4. T[6:0] 与 T[5:0] 别混：T6 只是溢出标志，有效计数是低 6 位，公式里用 (T[5:0]+1)。
  5. WWDG 公式必须乘 4096（框图中未画出的固定分频），WDGTB 分频系数＝2^WDGTB。
  6. IWDG 键值：0xCCCC 启用、0xAAAA 喂狗、0x5555 解除写保护、其他值启用写保护；写 PR/RLR 前必须先写 0x5555。
  7. IWDG 位于 VDD 供电区，停机/待机下仍工作；IWDG_CNT 不开放读写。
  8. LSI 实际 30K～60K 不精确：超时只能按 40kHz 估算。
  9. IWDG_SetReload(2500)×16×0.025ms≈1000.4ms——可用来自验公式（预分频是 IWDG_Prescaler_16）。
  10. 看门狗一旦开启就无法关闭（键值表无关闭指令；WWDG 的 WDGA 也只能靠复位清）。
  11. WWDG 复位后必须始终把 T6 置 1，否则立即复位；上电首次必须给重装值。
  12. 对比表里 IWDG 预分频疑似漏 16（列 4、8、32、64、128、256）——以表83/手册七档为准。
  13. WWDG_SetWindowValue(0x40 + 21)：0x40 是 T6 为 1 的基准，+21＝0x55；喂狗要落在「窗口内、0x40 之上」的区间。
  14. 喂狗频率：IWDG 演示 800ms < 1000ms；WWDG 演示 40ms 落在 30～50ms 窗口——别喂太早也别喂太晚。
  15. 硬件器件损坏时看门狗也救不了；不能因为有看门狗就写死循环。
