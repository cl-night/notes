1. 接线与工程准备

1.1 接线：A→PA6、B→PA7

  • 接线和「外部中断那一节」（P12 旋转编码器计次）类似：把旋转编码器插在面包板左边；
  • VCC 和 GND 接上电源正负极；
  • 下面的 A 相输出接到 PA6、B 相输出接到 PA7。
  • PA6 和 PA7 两个引脚可以交换：A 接 PA6、B 接 PA7，或者 A 接 PA7、B 接 PA6——都是可以的，只是正转和反转的极性不一样（方向反过来）。
  • 但是 PA6 和 PA7 这两个引脚不能随便更换：查引脚定义表，PA6 和 PA7 分别就是 TIM3 的通道 1 和通道 2；本程序计划用 TIM3 接编码器，所以必须接在 PA6/PA7。其他定时器同理，都要按这张表接在对应 TIM 的 CH1 和 CH2 引脚位置。
  • 面包板操作：编码器插好 → 跳线接 VCC（电源正）、GND（电源负）→ 两根飞线，A 相接 PA6、B 相接 PA7。

2. 写代码前先理清六步

先看 PPT 的「编码器接口基本结构」图（理论见 P19），把流程理一遍：

步 做什么 本集要点
① RCC 开启时钟（GPIO + 定时器） TIM3 在 APB1、GPIOA 在 APB2
② 配置 GPIO 为输入模式 PA6/PA7 上拉输入
③ 配置时基单元 预分频一般选不分频；ARR 给最大 65535——只需要 CNT 执行计数就行了
④ 配置输入捕获单元 只有「滤波器」和「极性」这两个参数有用，后面的参数（分频器、数据选择器）与编码器无关
⑤ 配置编码器接口模式 直接调一个库函数
⑥ TIM_Cmd 启动定时器 电路初始化完成

  • 测位置：直接读出 CNT 的值就行；
  • 测速度和方向：每隔一段固定的闸门时间取出一次 CNT、再把 CNT 清零——这就是测频法测量速度（P17 的思路，加了方向）。

图 4：PPT「编码器接口基本结构」——红圈圈出「时基单元」里的 PSC 预分频器与 CNT 计数器、以及两路 GPIO；字幕「第三步，配置时基单元，这里预分频器我们一般选择不分频」

  • 本小节需要新学的库函数只有一个：TIM_EncoderInterfaceConfig（定时器编码器接口配置）——它的参数依次是：定时器、编码器模式、通道 1 极性、通道 2 极性。「其他函数我们就不需要再了解了」。

3. Encoder_Init 完整代码

#include "stm32f10x.h"

void Encoder_Init(void)
{
    /* ① 时钟：TIM3 在 APB1、GPIOA 在 APB2 */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    /* ② GPIO：PA6、PA7 上拉输入 */
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6 | GPIO_Pin_7;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    /* ③ 时基单元：ARR 满量程、PSC 不分频 */
    TIM_TimeBaseInitTypeDef TIM_TimeBaseInitStructure;
    TIM_TimeBaseInitStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseInitStructure.TIM_CounterMode = TIM_CounterMode_Up;   // 编码器模式下无作用
    TIM_TimeBaseInitStructure.TIM_Period = 65536 - 1;                 // ARR
    TIM_TimeBaseInitStructure.TIM_Prescaler = 1 - 1;                  // PSC
    TIM_TimeBaseInitStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM3, &TIM_TimeBaseInitStructure);

    /* ④ 输入捕获单元：两个通道只配滤波器（极性删掉，由编码器接口函数统一配） */
    TIM_ICInitTypeDef TIM_ICInitStructure;
    TIM_ICStructInit(&TIM_ICInitStructure);

    TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
    TIM_ICInitStructure.TIM_ICFilter = 0xF;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    TIM_ICInitStructure.TIM_Channel = TIM_Channel_2;
    TIM_ICInitStructure.TIM_ICFilter = 0xF;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    /* ⑤ 编码器接口模式：TI1、TI2 都计数，两个通道都不反相 */
    TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12, TIM_ICPolarity_Rising, TIM_ICPolarity_Rising);

    /* ⑥ 启动定时器 */
    TIM_Cmd(TIM3, ENABLE);
}

3.1 时钟与 GPIO：上拉输入的选择原则

  • 开时钟：第一步开时钟，TIM3、GPIOA 没问题（TIM3 是 APB1 外设，所以用 RCC_APB1PeriphClockCmd）。
  • GPIO：用的是 PA6 和 PA7，所以 GPIO_Pin = GPIO_Pin_6 | GPIO_Pin_7，初始化 GPIOA，模式选 GPIO_Mode_IPU（上拉输入）。
  • 三种输入模式（上拉/下拉/浮空）怎么选：
    • 看接在这个引脚的外部模块输出的默认电平：外部模块空闲默认输出高电平 → 选上拉输入（默认输入高电平）；默认输出低电平 → 选下拉输入（默认输入低电平）——和外部模块保持默认状态一致，防止默认电平「打架」；
    • 一般来说默认高电平是一个习惯的状态，所以上拉输入用得比较多；
    • 如果不确定外部模块输出的默认状态，或者外部信号输出功率非常小，这时就尽量选择浮空输入——浮空输入没有上拉电阻和下拉电阻去影响外部信号（不过外部输入信号弱时，输入可能会受噪声干扰、来回不断地跳变）。

3.2 时基单元：ARR 满量程、PSC 不分频

  • TIM_InternalClockConfig 没用了（最终代码里已删掉）：编码器接口会托管时钟——编码器接口就是一个带方向控制的外部时钟，所以这个内部时钟就没有用了（留着也不起作用）。
  • TIM_CounterMode 这个参数目前也是没有作用的：因为计数方向也是被编码器接口托管的。
  • ARR 给 65536 - 1（满量程）：这样计数的范围是最大的，而且方便换算为负数（见 4.3/4.4 的补码）。
  • PSC 改成 1 - 1（预分频给 0，就是不分频）：这样编码器的时钟直接驱动计数器（再来一个边沿就计一个数）。

3.3 输入捕获单元：只留滤波器

  • 看 PPT：输入捕获单元并没有全部使用到——编码器接口只使用了通道 1 和通道 2 的「滤波器」和「极性选择」，所以只需要配置这两部分的参数；
  • 结构体里后面的参数（分频器、数据选择器）与编码器无关，「留着也行，只是它们目前没有作用」；
  • 参数删掉后结构体配置是不完整的，为了防止结构体里出现不确定值造成问题，先用 TIM_ICStructInit 给结构体赋一个初值（「加个 StructInit 也是提醒一下我们」）；
  • 然后配通道 1：TIM_Channel_1 + TIM_ICFilter = 0xF + TIM_ICInit；再把通道号改成 TIM_Channel_2、同样再 TIM_ICInit 一次——TIM_ICInit 之后结构体已经写入寄存器了，所以同一个结构体改个值可以继续用，不用重新定义。
  • 关于极性参数：上一小节说过，这里的「上升沿」并不代表上升沿有效（编码器接口始终是上升沿、下降沿都有效），「上升沿」参数代表的是高低电平极性不反转——对应 PPT 里 TI1/TI2 是否反相：给上升沿就是不反相、给下降沿就是反相。
  • 但这个极性参数等会儿配置编码器接口时也有（属于重复配置），所以最终代码里把 TIM_ICInit 的极性行删掉了，只留下滤波器和通道号。

图 5：Encoder.c 时基与输入捕获部分——TIM_Period = 65536 - 1; //ARR、TIM_Prescaler = 1 - 1; //PSC；两个通道 TIM_Channel_1 / TIM_Channel_2 都只配 TIM_ICFilter = 0xF（这一行高亮），TIM_ICPolarity 行此时还在、后面会被删掉；字幕「把下面这些参数写入到通道2」

3.4 编码器接口模式：TIM_EncoderInterfaceConfig

TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12, TIM_ICPolarity_Rising, TIM_ICPolarity_Rising);

四个参数（图 6 完整可见）：

参数 取值 含义
第 1 个：定时器 TIM3 用哪个定时器的编码器接口
第 2 个：编码器模式 TIM_EncoderMode_TI1 / TIM_EncoderMode_TI2 / TIM_EncoderMode_TI12 仅在 TI1 计数 / 仅在 TI2 计数 / TI1、TI2 都计数（对应 P19 表77 的三种模式）；一般用 TI12（两个边沿都计数，精度最高）
第 3 个：通道 1 极性 TIM_ICPolarity_Rising / TIM_ICPolarity_Falling Rising = 不反相；Falling = 反相
第 4 个：通道 2 极性 同上 同上，可按实际情况配置
  • 「这里的这个极性，等会儿我们配置编码器接口的时候也有，属于重复配置了」——所以要用后面这个函数来统一配极性。

3.5 坑：极性重复配置与函数顺序

  • TIM_ICInit 里的极性、和 TIM_EncoderInterfaceConfig 的后两个参数，配置的其实是同一个寄存器——属于重复配置，后配置的参数会覆盖前面的参数。
  • 所以：把前面 TIM_ICInit 里的极性参数删掉，只使用 TIM_EncoderInterfaceConfig 来配置极性；
  • 但一定要注意顺序：TIM_EncoderInterfaceConfig 必须位于 TIM_ICInit 的下面，否则就是 TIM_ICInit 覆盖 Encoder 函数的配置（方向配置就白配了）。
  • 改完之后，TIM_ICInit 的参数就只剩一个滤波器还有用了。

图 6：编码器接口配置——TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12, TIM_ICPolarity_Rising, TIM_ICPolarity_Rising); 四参数完整可见（高亮），上方是 TIM_ICInit 两通道；字幕「这两个地方的参数，其实都配置的是同一个寄存器」

3.6 启动定时器

  • 最后 TIM_Cmd(TIM3, ENABLE);——这样初始化配置就结束了；调用一下 Encoder_Init()，编码器旋转就能控制 CNT 自增自减了。

4.2 现象：向右转一格 CNT 变 4

  • 下载后显示 CNT 是 0；向右转一下编码器，可以看到值变成 4。
  • 原因：这个编码器是有「段落感」的（机械触点式），每转一格它输出的波形是：A 相产生一个低电平脉冲、B 相产生一个相位差 90° 的脉冲（提前还是滞后取决于正转还是反转；连续转动就和 PPT 的波形一样）。
  • 所以转动一格，A、B 相各出现了一个下降沿和上升沿，计次总共加了 4 次。
  • 注意：如果你用的是电机的编码器（霍尔/光栅），就不会有这个段落感了，计数取决于实际脉冲。
  • 继续往右转，CNT 继续自增；往左转，CNT 自减。

图 8：初版现象——OLED 显示 CNT:00004（向右转一格、计次加了 4 次），右侧红笔画的是 A/B 两相的波形（各一个上升沿+下降沿）；字幕「所以计次总共加了4次」

图 9：初版 Encoder_Get——uint16_t Encoder_Get(void) { return TIM_GetCounter(TIM3); }（高亮），上方是 TIM_EncoderInterfaceConfig(TIM3, TIM_EncoderMode_TI12, ...) 与 TIM_Cmd(TIM3, ENABLE)；字幕「这样来测试一下」

4.3 现象：向左转到 0 再减，会溢出到 65535

  • 实验：向左转到 0 之后再向左转，0 再自减，计数器就反向溢出、回到自动重装值 65535，然后继续往下减：65535、65534……
  • 原因：Encoder_Get 返回的是 uint16_t（16 位无符号数），所以 0 减 1 就变成了 65535。

图 10：反向溢出——OLED 显示 CNT:65520（左转到 0 后再减，回到 65535 附近继续往下减）；字幕「回到自动重装值，65535，然后继续往下减」

4.4 转有符号：把 uint16_t 转成 int16_t

  • 如果想要 0 之后变成 -1，直接把 uint16_t 类型强制转换成 int16_t 就行了；
  • 两种做法（视频都说了）：可以直接把 OLED_ShowNum 改成 OLED_ShowSignedNum（这个函数内部也做了类型强转）；还是在 Encoder_Get 里转换——函数的返回值直接换成 int16_t，函数声明也别忘了改，主循环里改成 ShowSignedNum，这样就能显示负数了。
  • 最终写法（Encoder_Get 的返回类型改掉）：
int16_t Encoder_Get(void)
{
    return TIM_GetCounter(TIM3);
}
  • 现象：向右转数值自增、向左转数值自减，变成负数后继续自减（实测画面 CNT:-0013）。
  • 原理：这就是借用补码的特性、快速完成负数转换的小技巧——65535 当成有符号数看就是 -1、65534 是 -2……（P19 讲过）。

图 11：转有符号后的现象——OLED 显示 CNT:-0013（0 以下正常显示负数）；此时字幕「目前向右转是增，向左转是减」

4.5 方向反了怎么办

  • 目前是向右转是增、向左转是减；如果这个方向和想要的不一致，可以改极性：
    • 硬件层面：把 A、B 相两根线换一下，增减方向就可以反过来；
    • 软件层面：修改两个输入通道的极性——把任意一个极性反转一下，方向就会反过来；如果两个极性都反转，那极性还是保持不变。
  • 演示：把第一个 TIM_ICPolarity_Rising 改成 TIM_ICPolarity_Falling，下载后发现向右是增、向左是减（极性又反转过来了）。
  • 到这一步，这个代码其实是**「编码器测量位置」**——需要测位置就直接 TIM_GetCounter 读出来。

5. 测速：闸门时间 + 读后清零

5.1 测速版 Encoder_Get

  • 想用编码器测速，就要在固定的闸门时间读一次 CNT、然后把 CNT 清零（P19 的测频法思路）。
  • 要求读完后清零 CNT，所以要先定义一个临时变量缓存：
int16_t Encoder_Get(void)
{
    int16_t Temp;
    Temp = TIM_GetCounter(TIM3);   // 先读
    TIM_SetCounter(TIM3, 0);       // 后清零
    return Temp;
}
  • 因为要先读取后清零，所以需要用 Temp 缓存一下——这是这段代码的逻辑要点。

5.2 闸门 1s：先用的 Delay_ms(1000)

  • 在主循环里每隔一段时间 Get 一次，所以下面给一个 Delay_ms(1000)；
  • 因为人手转比较慢，所以闸门时间就给 1s；如果是电机飞速旋转的话，闸门时间就可以给短点。
  • 此时 CNT 的值就代表速度，单位是「脉冲个数 / s」。
  • 现象：向右慢速转，速度是正数、比较小；快速转，正数比较大；向左转，速度是负数、比较小；快速转，负数比较大。
  • 注意：本集没有换算 RPM、也没有讲「编码器每圈多少个脉冲」——单位就是脉冲个数/s；如果接的是编码电机，可以实际接电机的编码器试试（现象一样，但要把闸门时间弄短点）。

5.3 改进：改用现成的 1s 定时中断（最终版）

  • 缺点：目前是直接通过 Delay 实现闸门时间——如果主程序没有其他东西还行，但如果有其他东西，最好就不要在主循环加入过长的 Delay，这样会阻塞主循环的执行。
  • 比较好的方法：用 main.c 里留了这么久的定时中断（6-1 定时器定时中断 工程带过来的）：
    1. 上面 Timer_Init() 解除注释；「这里定时中断目前是每隔 1s 执行一次，你可以修改定时中断的时间来调整闸门时间」；
    2. 在前面定义一个全局变量 int16_t Speed;；
    3. 在定时中断 TIM2_IRQHandler 里执行 Speed = Encoder_Get();——每隔 1s 读取一下速度、存到 Speed 变量里；
    4. 主循环就可以快速刷新显示 Speed 了，Delay 可以删掉，这样就不会阻塞主循环运行；
    5. 前面的字符串也改成 "Speed:"，下面显示数字的位置往后挪两格、改到第 7 列。
int16_t Speed;

int main(void)
{

    Timer_Init();
    Encoder_Init();

    OLED_ShowString(1, 1, "Speed:");

    while (1)
    {
        OLED_ShowSignedNum(1, 7, Speed, 5);

void TIM2_IRQHandler(void)
{
    if (TIM_GetITStatus(TIM2, TIM_IT_Update) == SET)
    {
        Speed = Encoder_Get();
        TIM_ClearITPendingBit(TIM2, TIM_IT_Update);
    }
}

坑与易错点

  1. 引脚只能用所选定时器的 CH1/CH2：本程序用 TIM3，所以 PA6（TIM3_CH1）/ PA7（TIM3_CH2）；换定时器要按引脚定义表接对应 TIM 的 CH1/CH2，PA6/PA7 本身不能随便换。
  2. A/B 两根线可以交换（A→PA7、B→PA6 也行），只改变正反转极性；VCC/GND 不能接反。
  3. TIM_InternalClockConfig 在编码器模式下没用（编码器接口托管时钟），最终代码里已经删掉；TIM_CounterMode 也没有作用（方向被托管）——留着不报错，但别以为它管用。
  4. ARR 给 65536-1（满量程）：一是计数范围最大，二是方便把 16 位无符号数当有符号数、直接得到负数。
  5. PSC 给 1-1（不分频）：编码器的时钟直接驱动计数器，来一个边沿计一次；分频会降低分辨率。
  6. TIM_ICInit 里只保留 TIM_Channel 和 TIM_ICFilter：编码器接口只用通道 1/2 的滤波器和极性，其余参数（分频器、数据选择器）与编码器无关。
  7. 极性重复配置大坑：TIM_ICInit 的极性与 TIM_EncoderInterfaceConfig 后两个参数是同一个寄存器，后配置覆盖前配置——所以要删掉 TIM_ICInit 的极性行，并保证 TIM_EncoderInterfaceConfig 写在 TIM_ICInit 之后（否则方向配置被覆盖）。
  8. TIM_EncoderInterfaceConfig 的模式参数一般用 TIM_EncoderMode_TI12（TI1、TI2 都计数，两个边沿都计入，精度最高）；TI1/TI2 是只在一个通道的边沿计数。
  9. 编码器模式下 Rising/Falling 不是「上升沿/下降沿有效」：而是**「不反相 / 反相」（高低电平极性）**——P19 讲过、本集代码也用来调方向。
  10. 改方向的三种办法：①A/B 两根线对调；②把任一通道极性从 Rising 改成 Falling；③换引脚——注意两个极性都反则方向不变。
  11. Encoder_Get 初版返回 uint16_t：左转到 0 再减会溢出到 65535；要显示负数就改成 int16_t（配合 OLED_ShowSignedNum），这是借补码强转的技巧。
  12. 测速必须先读后清零：Temp = TIM_GetCounter(TIM3); TIM_SetCounter(TIM3, 0); return Temp;——顺序反了（先清零再读）就永远是 0；因为要先读后清零，所以需要 Temp 缓存。
  13. 闸门时间决定速度单位：Delay_ms(1000) 时速度单位是脉冲个数/s；本集没有 RPM/每圈脉冲数换算——想要 RPM 得自己乘系数（本集未讲）。
  14. 不要在主循环放长 Delay：会阻塞主循环；最终版改用 1s 定时中断在 TIM2_IRQHandler 里读速度、主循环只刷新显示。
  15. 中断里必须清标志位：TIM_ClearITPendingBit(TIM2, TIM_IT_Update)，否则会反复进中断（P14 讲过）。
  16. 「一格=4 次计数」只对机械触点式编码器成立（它有段落感）；电机用的霍尔/光栅编码器没有段落感，计数取决于实际脉冲数，别拿「一格 4 次」套所有编码器。
  17. 本集无示波器：所有现象都是 OLED 数值 + 口述。
  18. Timer_Init() 的 1s 配置本集没展示：直接沿用 6-1 定时器定时中断 模板，写笔记/写代码时别自己编它的 PSC/ARR。

存疑

  • 本集文本来自画面硬字幕的 OCR（PP-OCRv4，source=subtitle-ocr，370 段），不是 ASR。Keil 输出污染严重：Build Time Elapsed: 00:00:18、Load "C:\...\Project.axf"、Flash Load finished at ...、Programming Done. 等行反复出现，不是口述内容；另有行首噪声（如 1*、门 等）。典型 OCR 错字（本集实际出现）：编码器接口 → 「编码器接回」、TIM_EncoderInterfaceConfig → 「TlMEncoderlnterfaceConfig/TlmEncoderlnterfaceConfig」、TIM_ICStructInit → 「TIMICStructlnit/Structlnit」、引脚 → 「引I脚」、比较 → 「此较」、uint16_t/int16_t → 「uint16t/int16t」、Encoder_Init → 「Encoder lnit」等，已按画面和上下文校正。
  • TIM_EncoderInterfaceConfig 的第三/第四参数：f_00142（11:45）只显示到第三个参数，f_00145（12:00）才完整显示四个（…, TIM_EncoderMode_TI12, TIM_ICPolarity_Rising, TIM_ICPolarity_Rising）——本笔记以 f_00145 为准。
  • 定时中断的「1s」配置本集没有展示：Timer_Init() 沿用 6-1 定时器定时中断 模板，口述只说「定时中断目前是每隔 1s 执行一次」，没有出现 Timer.c 的 PSC/ARR 画面；本笔记只写「沿用模板的 1s 更新中断」，没有编 PSC/ARR（具体见 P14 笔记）。
  • 速度没有换算成 RPM/圈速：本集速度单位是**「脉冲个数 / 秒」**，没有讲编码器每圈脉冲数、也没有乘系数；想要 RPM 要自己换算，本集未展开。
  • 最终代码里 TIM_ICInit 的极性行确实删掉了：f_00217（18:00）画面里 ICInit 只剩 TIM_Channel 和 TIM_ICFilter；但视频里是「先配极性→讲坑→再删」的过程，本笔记给的是最终代码，过程见 3.5。
  • 「一格 = 4 次计数」只对机械触点式编码器成立（有段落感）；电机霍尔/光栅编码器没有段落感，计数取决于实际脉冲（视频里也提到了）。
  • 本集没有示波器画面：所有现象都是 OLED 数值（CNT:00004、CNT:65520、CNT:-0013、Speed:+00000）+ 口述，没有波形实测。
  • 片尾没有预告（模块 6 最后一集）：20:56「代码就写完了」直接结束，下一集是模块 7 的内容。
  • TIM_InternalClockConfig 的去留：口述说它「没有用了」，最终代码里确实没出现这一行（f_00155 画面从 GPIO 直接到时基结构体）；本笔记按最终代码写「已删掉」，并说明「留着也不起作用」。
