[10-4] I2C通信外设 — 学习笔记

一句话结论

I2C 是同步时序，用 GPIO 模拟很常见；STM32 内置硬件 I2C，自动生成时钟与起始终止条件，只需写 CR/DR、读 SR。F103C8T6 的硬件 I2C 只有 I2C1、I2C2 两路。

本集定位

  • 模块 10 的理论课：讲 STM32 内部 I2C 硬件外设，并精读《STM32F10xxx 参考手册》第 24 章。
  • 本集没有写一行代码，也几乎不出现库函数名（只在口述里提了 I2C_Cmd）；I2C_Init、I2C_SendData、I2C_GetFlagStatus 的写法留到 10-5。
  • 重点是主机发送/主机接收两个流程图与事件编号，以及 CR/DR/SR 的角色。
  • 从机模式、PEC、SMBus、双地址寄存器、10 位地址只要求「了解」。
  • 片头说明「程序现象和上一集一样，这里就不演示了」；片尾 44:55 说本节结束，代码在 10-5。

1. 软件 I2C 与硬件 I2C

  • 软件 I2C＝用 GPIO 手动拉低/释放时钟线凑时序；I2C 是同步时序，每位持续时间要求不严格（长点短点、中途暂停都无妨），所以模拟很常见。
  • 对比串口：异步时序对时间要求严格，软件模拟很困难，所以基本都倒向硬件外设。
  • 硬件 I2C 的好处：执行效率高、节省软件资源、时序波形规整、通信速率快。
  • 选择建议：简单应用用灵活的软件 I2C，性能要求高用硬件 I2C。

2. I2C 外设简介

  • STM32 内部集成硬件 I2C 收发电路，由硬件自动执行时钟生成、起始/终止条件生成、应答位收发、数据收发。
  • 我们只写控制寄存器 CR 和数据寄存器 DR、读状态寄存器 SR；比喻：写 CR 像踩油门/刹车/方向盘，读 SR 像看仪表盘。
  • 意义：减轻 CPU 负担、节省软件资源，硬件生成时序的效率更高。

标准 / 快速速度 标准速度高达 100kHz、快速高达 400kHz（协议规定的上限）

3. 多主机模型与地址模式

3.1 多主机模型

  • 固定多主机：总线上有两个或更多固定主机，其余固定为从机；两个主机同时说话＝总线冲突→总线仲裁，失败方让出控制权。
  • 可变多主机：没有固定主机，谁要发数据谁就「跳出来」当主机，通信完退回从机位置。
  • STM32 按可变多主机设计；实际没人跟它抢，但程序仍按「谁要做主机谁跳出来」的思路写。

3.2 7 位与 10 位地址模式

  • 7 位地址：起始条件后第一字节＝7 位地址 + 读写位，共 128 种；挂 128 个以上设备就不够用（还有厂商地址冲突，可改低位地址或开多条总线）。
  • 10 位地址共 1024 种：起始后两个字节都作寻址，第一字节前 5 位固定 11110 当标志位，剩下 2 位 + 第二字节 8 位 = 10 位。
  • 11110 开头的组合在 7 位模式下不会出现，所以不会混淆；本课程只要求掌握 7 位地址，10 位了解即可。

4. I2C 框图（图242）

  • 左侧引脚 SDA、SCL，另有 SMBALERT（SMBus 的中断信号线，I2C 用不到）。
  • 数据通路：SDA ↔ 数据控制 ↔ 数据移位寄存器 ↔ DATA REGISTER（数据寄存器 DR）。
  • 从机相关（了解）：比较器 + 自身地址寄存器/双地址寄存器，STM32 可同时响应两个从机地址。
  • PEC：错帧校验计算 + PEC 寄存器，硬件 CRC 校验（本课程不用）。
  • 时钟：SCL ↔ 时钟控制 ↔ 时钟控制寄存器 CCR，决定 SCL 频率与占空比。
  • 寄存器与控制：CR1&CR2、SR1&SR2 → 控制逻辑电路 → 中断、DMA 请求与响应。
  • 主机收发时真正要关注的：DR + 数据移位寄存器这一段，以及 CR 与 SR。

4.1 数据收发：DR + 移位寄存器两级

  • 发送：字节写到 DR，移位寄存器空时 DR 值转入其中逐位输出；移位中可写下一字节无缝衔接——DR 转移位寄存器时置 TxE（发送寄存器空）。
  • 接收：从 SDA 逐位移入移位寄存器，收满一个字节整体转到 DR——置 RxNE（接收寄存器非空）。
  • 与串口的结构类似（串口也是 DR + 移位寄存器两级）。

4.2 简化基本结构

去掉比较器/自身地址/双地址/PEC/SMBALERT 后：

  • 时钟控制器 → GPIO → SCL（一主多从只画输出方向）。
  • 数据控制器 + DR ↔ 移位寄存器 → GPIO（双向）→ SDA。
  • 右下「开关控制」＝I2C_Cmd 使能外设。
  • 移位寄存器向左移：I2C 是高位先行，最高位移出、一个 SCL 移一位。
  • GPIO 必须配复用开漏输出：图 17 里输出驱动器的 P-MOS 上管不存在（只剩 N-MOS），输出低＝拉低、输出高＝释放浮空；输入仍经 TTL 肖特基触发器读回。

6. 主机发送流程（手册图245）

前提：初始化后总线空闲、STM32 默认处于从模式。

  1. 写 CR1 的 START = 1：硬件自动产生起始条件，并从从模式切换到主模式。
  2. 等 EV5：SB = 1（起始已发送），读 SR1 后把从机地址写入 DR 即可清除。
  3. 硬件自动把「地址 + 写」发到总线上，从机应答；没有应答则置应答失败标志。
  4. 等 EV6：ADDR = 1（主模式下地址发送结束），读 SR1 再读 SR2 清除。
  5. EV8_1：TxE = 1 且移位寄存器空、DR 空，表示可以写数据。
  6. 写第一个数据到 DR → 转移位寄存器发送 → EV8（TxE = 1、移位寄存器非空、DR 空，写入 DR 清除）。
  7. 逐字节重复：写 DR → EV8 消失 → 移位完成 → 又产生 EV8。
  8. 最后字节移位完成 → EV8_2：TxE = 1 且 BTF = 1 → 写 CR1 的 STOP = 1 产生停止条件。

EV 事件的本质是若干标志位的组合；按正常流程读写寄存器会自动清标志，不需要手动清。

图 9：手册图245「主发送器传送序列图」——7 位主发送：S→地址 A→数据1 A→…→数据N A→P，下方 EV5、EV6、EV8_1、EV8、EV8、EV8_2；10 位主发送：S→帧头 A→地址 A→数据→…→P，经 EV9；注：S=Start、Sr=重复起始、P=Stop、A=响应、NA=非响应、EVx=事件；EV8 的软件序列必须在本字节传输结束前完成

图 10：同一页上的红笔——写「DR → <<」并画箭头：把要发送的字节写入 DR，硬件再送到移位寄存器、逐位发到 I2C 总线；字幕「再把这一个字节发送到I2C总线上」

7. 主机接收流程（手册图246）

  1. 写 CR1 的 START = 1 → 等 EV5（SB = 1）。
  2. 写「地址 + 读」到 DR → 硬件发地址 → 等 EV6（ADDR = 1，读 SR1 再读 SR2 清除）。
  3. 清 ADDR 后自动进入接收：每收到一字节产生 EV7（RxNE = 1，读 DR 清除）。
  4. 读 DR 拿走数据 → EV7 消失 → 下一字节移入移位寄存器 → 再产生 EV7。
  5. 不想再接收时提前把 CR1 的 ACK 置 0（非应答），并设置 STOP 请求。
  6. 最后一字节收完 → EV7_1（RxNE = 1 且 ACK = 0）→ 硬件产生停止条件。
  7. 只收 1 个字节用 EV6_1：它没有对应事件标志，只适合收 1 字节，要在清 ADDR 后清响应和停止产生位。
  • 另：10 位地址的从机模式对应 EV9（ADDR10=1）；10 位主接收在 EV6 之后应设 CR2 的 START=1（本课程不深入）。

图246 的「7 位主接收」是当前地址读；要指定地址读，需把「指定地址写（不发数据）」和「读」组合（重复起始），具体在 10-5 的代码里。

图 11：手册图246「主接收器传送序列图」——7 位主接收：S→地址 A→数据1 A→…→数据N NA→P，下方 EV5、EV6、EV6_1、EV7、EV7、EV7_1、EV7；10 位主接收：S→帧头 A→地址 A→Sr→帧头 A→数据1 A→…；字幕「因为发送读的指令之后，必须要立刻转入读的时序」

图 12：同一页上的红笔——写「DR」并用箭头指向「数据1」处（对应 EV7），红圈标出 EV6_1/数据1 区域；字幕「下面解释是，RxNE=1，数据寄存器非空」

8. 软件 / 硬件波形对比

  • 上面软件 I2C、下面硬件 I2C（都是指定地址读），两种方式传的数据完全一样。
  • 硬件波形更规整：SDA 变化紧贴 SCL 下降沿（可理解为「SCL 下降沿写、上升沿读」）；应答结束也是从机释放 SDA 的同时主机立刻拉低。
  • 软件模拟因 Delay 不准，SCL 周期不均、SDA 变化也不一定紧贴下降沿。
  • 但完全不影响通信：I2C 是同步时序，只要 SCL 高电平期间数据稳定就能被正确读取。

图 13：PPT「软件/硬件波形对比」——上半软件 I2C、下半硬件 I2C（都是指定地址读时序），两侧都标注 Send Byte 0xD0、Send Byte 0x19、Send Byte 0xD1、RA 0、Receive Byte、P 等段落

9. 参考手册第 24 章要点

9.1 功能描述与 4 种模式

  • 24.3 功能描述：I2C 模块收发数据、串行/并行互相转换；通过 SDA + SCL 接总线；允许接标准（高达 100kHz）或快速（高达 400kHz）总线；支持中断/DMA。
  • 24.3.1 模式选择共 4 种：从发送器、从接收器、主发送器、主接收器。
  • 默认从模式；产生起始条件后自动切到主模式；仲裁丢失或产生停止信号后切回从模式。

9.2 主模式操作顺序与起始条件

  • 操作顺序：CR2 中设输入时钟 FREQ → 配时钟控制寄存器 → 配上升时间寄存器 → 编程 CR1 启动外设 → 置 CR1 的 START = 1。
  • 输入时钟要求：标准模式 ≥ 2MHz、快速模式 ≥ 4MHz，低于这个值不能保证时序正确。
  • 起始条件：BUSY = 0 时置 START = 1，接口产生开始条件并切主模式（M/SL 置位），SR1 的 SB 位被置位；随后读 SR1、紧接着把地址写入 DR（即 EV5）。
  • 主模式下再次置 START 位，会在当前字节传输完成后由硬件产生重开始条件（Sr）。

图 14：参考手册 24.3 功能描述与 24.3.1 模式选择——「接口可以 4 种模式中的一种运行：从发送器、从接收器、主发送器、主接收器」「默认工作于从模式，生成起始条件后自动切到主模式；仲裁丢失或产生停止信号时切回从模式」；上方特点尾部（25ms 超时、带 ACK 控制的硬件 PEC、ARP、兼容 SMBus）

图 15：参考手册 24.3.3 I²C主模式——操作顺序：CR2 设输入时钟 → 配时钟控制寄存器 → 配上升时间寄存器 → 编程 CR1 启动 → 置 START 位产生起始；输入时钟必须至少：标准模式 2MHz、快速模式 4MHz；BUSY=0 时设 START=1，SB 置位后读 SR1 再把地址写入 DR

9.3 寄存器一览

  • 有库函数时这些公式不用自己算（I2C_Init 里给个时钟频率就行），只需了解寄存器结构和作用。
  • 写代码（10-5）按「配 CR2 时钟 → 配 CCR → CR1 使能 → START → 等 EV 事件 → 读写 DR」走。

坑与易错点

  1. 硬件 I2C 引脚固定：I2C1 = PB6/PB7（可重映射 PB8/PB9）、I2C2 = PB10/PB11，不能任意指定。
  2. GPIO 要配「复用开漏输出」：不是普通推挽，开漏下 P-MOS 不存在，输出高电平＝释放。
  3. STM32 默认从模式：写 START=1 才切到主模式，写完 STOP 又回到从模式。
  4. 主机发送必须按事件顺序：START → EV5 → 地址 → EV6 → EV8_1 → 写 DR → EV8 → EV8_2 → STOP，跳步会卡死。
  5. EV5/EV6 清除方式不同：EV5 读 SR1 后写 DR 清除；EV6 要读 SR1 再读 SR2；EV8 写入 DR 清除。
  6. EV8 的软件序列必须在本字节传输结束前完成；EV5/EV6/EV9/EV8_1/EV8_2 会拉长 SCL 低电平。
  7. 接收最后一字节前要「提前」设 ACK=0 + STOP 请求，收到后是 EV7_1；顺序反了会多收字节或停不下来。
  8. 只收 1 个字节用 EV6_1（没有事件标志位）；收多字节用 EV7 循环。
  9. 输入时钟要求：标准模式 ≥2MHz、快速模式 ≥4MHz，时钟太低时序不准。
  10. CCR/TRISE 公式不用背：有库函数；本集只举例 CCR=0x28 → 100kHz（FREQR=08）。
  11. 100kHz/400kHz 是上限：设备声称快速 I2C 就是最大 400kHz。
  12. SMBALERT、PEC、双地址寄存器、10 位地址都属「了解即可」，真正要掌握的是 7 位地址 + 主发送/主接收。
  13. 上集软件 I2C 用 PB10/PB11，正好是 I2C2 的引脚——换硬件 I2C2 接线不用改；用 I2C1 则要改到 PB6/PB7。
