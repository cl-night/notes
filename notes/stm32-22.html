[7-2] AD单通道与AD多通道 — 学习笔记

一句话结论

把 [7-1] 的 ADC 理论落成两个工程：AD_Init 六步 + AD_GetValue 三步；多通道不用扫描模式，改为在 AD_GetValue 里先改序列 1 的通道再转换。

本集定位

  • 模块 7（ADC）的代码课：理论（原理/框图/4 种转换模式/表64/对齐/TCONV）全在 P21 [7-1]，本集只用结论，推导见 notes/stm32-21-ADC模数转换器.md。
  • 两个程序一集写完：① 7-1 AD单通道（0:00–39:20）② 7-2 AD多通道（39:20–49:00）。
  • 本集不涉及 DMA、中断（ADC_ITConfig 只读不配）、模拟看门狗、扫描模式；片尾 48:50「扫描模式和更多高级玩法下节继续」。
  • 编号对照：视频标题 [7-2]，两个工程目录叫 7-1/7-2，两套编号不是一回事。

1. 程序一：7-1 AD单通道

1.1 接线：电位器 → PA0

  • 接线图 7-1 AD单通道.jpg：蓝色小电位器有 3 个引脚，左右两端是电阻固定端、中间是滑动抽头，十字槽往左拧抽头左移、往右拧右移。
  • 左端接 GND、右端接 3.3V，中间抽头输出 0～3.3V 可调电压 → PA0。
  • 查引脚表：PA0～PB1 这 10 个引脚才是 ADC 通道，可任选其一；其他引脚不能接模拟电压。
  • 面包板：3 个引脚一侧朝上插好，最左侧引到负极、最右侧引到正极，中间用飞线接 PA0。

1.3 六步流程：AD_Init 完整代码

先对着「ADC 基本结构」图把结构图打通，配置步骤自然就有数：

步 做什么 本集要点
① 开启 RCC 时钟（ADC + GPIO），并配置 ADCCLK 分频 ADC、GPIOA 都在 APB2
② 配置 GPIO 为模拟输入 GPIO_Mode_AIN
③ 配置多路开关：把通道接入规则组列表 ADC_RegularChannelConfig（点菜）
④ 配置 ADC 转换器 ADC_Init 结构体（模式/对齐/触发/连续/扫描/通道数）
⑤ 开关控制：给 ADC 上电 ADC_Cmd
⑥ 校准 四个校准函数
  • 模拟看门狗和中断本节暂不用，需要时再加 ADC_ITConfig + NVIC。
  • 软件触发、读结果也各有一个函数。

完整代码（六成员顺序与最终代码一致）：

#include "stm32f10x.h"

void AD_Init(void)
{
    /* ① 时钟：ADC1 与 GPIOA 都在 APB2；ADCCLK = 72MHz / 6 = 12MHz */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_ADC1, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    RCC_ADCCLKConfig(RCC_PCLK2_Div6);

    /* ② GPIO：模拟输入 */
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AIN;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    /* ③ 规则组序列 1 填通道 0，采样时间 55.5 个 ADCCLK 周期 */
    ADC_RegularChannelConfig(ADC1, ADC_Channel_0, 1, ADC_SampleTime_55Cycles5);

    /* ④ ADC 转换器参数 */
    ADC_InitTypeDef ADC_InitStructure;
    ADC_InitStructure.ADC_Mode = ADC_Mode_Independent;
    ADC_InitStructure.ADC_DataAlign = ADC_DataAlign_Right;
    ADC_InitStructure.ADC_ExternalTrigConv = ADC_ExternalTrigConv_None;
    ADC_InitStructure.ADC_ContinuousConvMode = DISABLE;
    ADC_InitStructure.ADC_ScanConvMode = DISABLE;
    ADC_InitStructure.ADC_NbrOfChannel = 1;
    ADC_Init(ADC1, &ADC_InitStructure);

    /* ⑤ 给 ADC 上电 */
    ADC_Cmd(ADC1, ENABLE);

    /* ⑥ 校准四步 */
    ADC_ResetCalibration(ADC1);
    while (ADC_GetResetCalibrationStatus(ADC1) == SET);
    ADC_StartCalibration(ADC1);
    while (ADC_GetCalibrationStatus(ADC1) == SET);
}

① 时钟与 ADCCLK：ADC1 与 GPIOA 都在 APB2，用 RCC_APB2PeriphClockCmd；ADCCLK 用 RCC_ADCCLKConfig（stm32f10x_rcc.h 第 680 行，原型 void RCC_ADCCLKConfig(uint32_t RCC_PCLK2)），对 APB2 的 72M 选 2、4、6、8 分频——本代码写 RCC_ADCCLKConfig(RCC_PCLK2_Div6)，即 72M/6 = 12MHz（最大 14MHz，2 分频 36M、4 分频 18M 都超限）。

图 4：stm32f10x_rcc.h 第 680 行高亮 void RCC_ADCCLKConfig(uint32_t RCC_PCLK2);（配置 ADCCLK 分频器）

② GPIO 模拟输入：复制 LED.c 的初始化，模式改 GPIO_Mode_AIN、Pin 改 GPIO_Pin_0——AIN 模式下 GPIO 断开、不干扰模拟电压，是 ADC 专属模式。

③ 填规则组菜单：ADC_RegularChannelConfig(ADC1, ADC_Channel_0, 1, ADC_SampleTime_55Cycles5)——参数依次是 ADCx、ADC_Channel（0～17）、Rank（序列位置）、ADC_SampleTime。本程序只有一个通道且非扫描，所以通道 0 放序列 1，采样时间无要求就给 55.5 个 ADCCLK 周期（要快要小参数、要稳稳要大参数），要填序列 2 就复制一行改序号与通道。

图 5：RCC_APB2PeriphClockCmd(RCC_APB2Periph_ADC1/GPIOA, ENABLE)、RCC_ADCCLKConfig(RCC_PCLK2_Div6);、GPIO_Mode_AIN、GPIO_Pin_0、GPIO_Speed_50MHz 与 ADC_RegularChannelConfig(ADC1, ADC_Channel_0, 1, ADC_SampleTime_55Cycles5);

④ ADC_Init 六成员：

成员 本代码取值 含义
ADC_Mode ADC_Mode_Independent 独立模式（ADC1、ADC2 各转各的）；其余 ADC_Mode_* 都是双 ADC 模式，本课不用
ADC_DataAlign ADC_DataAlign_Right 右对齐（直接读即结果；左对齐用于取高 8 位等场合）
ADC_ExternalTrigConv ADC_ExternalTrigConv_None 不使用外部触发 → 即内部软件触发
ADC_ContinuousConvMode DISABLE 单次转换（ENABLE 为连续）
ADC_ScanConvMode DISABLE 非扫描（ENABLE 为扫描，多通道用）
ADC_NbrOfChannel 1 只在扫描模式下才表示「扫描几个通道」；非扫描时这个参数没有用（无论写多少，只有序列 1 有效）

图 6：stm32f10x_adc.h 导出列表——ADC_DeInit、ADC_Init、ADC_StructInit、ADC_Cmd、ADC_DMACmd、ADC_ITConfig、校准四函数、ADC_SoftwareStartConvCmd、ADC_DiscModeChannelCountConfig、ADC_DiscModeCmd 等

⑤ 上电：ADC_Cmd(ADC1, ENABLE)，对应 PPT 的开关控制。

⑥ 校准四步：

ADC_ResetCalibration(ADC1);                              /* 第一步：复位校准 */
while (ADC_GetResetCalibrationStatus(ADC1) == SET);      /* 第二步：等待复位校准完成 */
ADC_StartCalibration(ADC1);                              /* 第三步：开始校准 */
while (ADC_GetCalibrationStatus(ADC1) == SET);           /* 第四步：等待校准完成 */
  • 四个函数：ADC_ResetCalibration（复位校准）、ADC_GetResetCalibrationStatus（取复位校准状态）、ADC_StartCalibration（开始校准）、ADC_GetCalibrationStatus（取开始校准状态）；初始化后依次调用，内部电路自动完成。
  • 对照手册 ADC_CR2：RSTCAL 位「由软件设置、由硬件清除」，所以 ADC_GetResetCalibrationStatus == SET 就是「读到 1 就死等，硬件清 0 才跳出」，ADC_GetCalibrationStatus == SET 同理；== SET 可省（SET 本身非 0）。

图 7：内部判断 (ADCx->CR2 & CR2_RSTCAL_Set) != RESET，置位返回 SET，否则 RESET

图 8：位 11 ALIGN（0 右对齐/1 左对齐）、位 8 DMA、位 3 RSTCAL（软件设置/硬件清除）、位 2 CAL、位 1 CONT（连续转换）

图 9：P21 那页结构图——GPIO(16)/温度/VREFINT → 多路开关 → AD 转换器（规则组/注入组）→ 数据寄存器（规则组×1、注入组×4）；触发控制、RCC 时钟、看门狗、EOC、开关控制

1.4 读值函数 AD_GetValue

调完 AD_Init() 后 ADC 即就绪，「启动 → 等待 → 读取」一气呵成：

uint16_t AD_GetValue(void)
{
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);                  /* 软件触发转换 */
    while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET);  /* 等待转换完成（EOC 置 1） */
    return ADC_GetConversionValue(ADC1);                     /* 读数据寄存器 */
}
  • 软件触发：ADC_SoftwareStartConvCmd(ADC1, ENABLE)。
  • 等待完成：ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) 套 while 空循环（while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET);）；可选标志有 AWD、EOC、JEOC、JSTRT、STRT，规则组用 EOC——RESET 时死等，硬件置 1 后跳出。
  • ADC_GetSoftwareStartConvStatus 是坑：它只读 CR2 的 SWSTART 位，而该位「转换一开始就被硬件清除」，与「转完没转完」无关，别被名字骗。
  • EOC 的口径：手册写「规则或注入通道组转换结束时设置」——不只是规则组（视频口述有误，以手册为准）；且读 DR 会自动清除 EOC，不用手动清。
  • 等多久：采样 55.5 + 转换 12.5 = 68 个 ADCCLK 周期，12MHz 下 1/12M × 68 ≈ 5.6us。
  • 读结果：ADC_GetConversionValue 内部就是直接读 DR，拿到值直接 return。

1.5 主函数与现象

#include "Delay.h"
#include "OLED.h"
#include "AD.h"

uint16_t ADValue;

int main(void)
{
    OLED_Init();
    AD_Init();

    OLED_ShowString(1, 1, "ADValue:");

    while (1)
    {
        ADValue = AD_GetValue();
        OLED_ShowNum(1, 9, ADValue, 4);
    }
}
  • 两个函数在头文件里声明，main 里 include AD.h，先调 OLED_Init(); AD_Init();；变量用 uint16_t ADValue 声明，第 1 行第 1 列显示 ADValue:、第 1 行第 9 列显示 4 位数字，循环里 ADValue = AD_GetValue();。
  • 现象：ADValue:xxxx 随电位器变化，左拧减小、右拧增大，范围 0～4095（画面 ADValue:1986）。

1.6 AD 值抖动与三种对策

  • 末位抖动是正常波动；若用 AD 值做判断（光线低于某值开灯、高于某值关灯），阈值附近来回跳会让输出跟着抖，三种对策：
    1. 迟滞比较：设两个阈值，低于下阈值才开、高于上阈值才关，中间留不动作区间（同 GPIO 那节的施密特触发器）；
    2. 均值滤波：读 10 个或 20 个取平均；
    3. 裁剪分辨率：去掉数据尾数。

1.7 换算并显示实际电压

  • 线性变换把 0～4095 映射到 0～3.3V：Voltage = (float)ADValue / 4095 * 3.3，落到代码就是 Voltage = (float)ADValue / 4095 * 3.3;。
  • 必须先强转 float：ADValue 是整数，写成 Voltage = ADValue / 4095 * 3.3 会因整数除法丢掉小数，结果直接错。
  • 4095 与 4096：严格说 AD 值到 4096 才对应 3.3V，所以 4095 对应的电压略小于 3.3V；两种近似都行，差别看不出来。
  • OLED 驱动没有显示浮点数的函数，用整数显示拼出来：
float Voltage;
OLED_ShowString(2, 1, "Voltage:0.00V");
Voltage = (float)ADValue / 4095 * 3.3;

OLED_ShowNum(2, 9, Voltage, 1);                                /* 整数部分（小数被舍弃） */
OLED_ShowNum(2, 11, (uint16_t)(Voltage * 100) % 100, 2);       /* 两位小数 */
Delay_ms(100);                                                 /* 刷新慢一些 */
  • 小数原理：Voltage * 100（1.23 → 123）再对 100 取余（123 % 100 = 23）；浮点不能直接取余，要先强转 uint16_t 再取余，即 (uint16_t)(Voltage*100)%100，显示长度 2。
  • 拧电位器时 AD 值与电压一起变；只做判断或记录时可以不换算，直接用原始数据。

1.8 顺带演示：连续转换、非扫描模式

  • 本代码是第一种（单次 + 非扫描），还可以用第二种（连续 + 非扫描）：不必反复触发、也不必等转换完成。
  • 改法：ADC_InitStructure.ADC_ContinuousConvMode = ENABLE;；把软件触发挪到初始化末尾触发一次；AD_GetValue 去掉触发和 EOC 等待，只留 return ADC_GetConversionValue(ADC1);。
  • 单次版对应的三个成员是 ADC_ContinuousConvMode = DISABLE、ADC_ScanConvMode = DISABLE、ADC_NbrOfChannel = 1，连续模式只改第一个。
  • 现象与单次版一样，演示完改回单次。

图 12：ADC_ContinuousConvMode = ENABLE，ADC_Cmd + 校准四步后接 ADC_SoftwareStartConvCmd(ADC1, ENABLE);，读值函数只剩 uint16_t AD_GetValue(void) { while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET); return ADC_GetConversionValue(ADC1); }

2. 程序二：7-2 AD多通道

2.1 接线：4 路模拟量 → PA0～PA3

  • 接线图 7-2 AD多通道.jpg：电位器仍接 PA0，另加光敏、热敏、反射式红外三个模块，VCC/GND 接正负极。
  • 三个模块的 AO（模拟输出）分别接 PA1、PA2、PA3——要用 AO，不能接 DO（DO 是数字输出）。
  • 加 PA0 共 4 个通道，仍从 PA0～PB1 里任选。

图 13：三个传感器模块（反射式红外、光敏、热敏）的 VCC/GND 接电源，AO 接 PA1/PA2/PA3，电位器滑动端接 PA0

2.2 为什么不用扫描模式

  • 扫描模式（4 个通道都填序列、触发一次转完）本身不错，但数据覆盖难解决，手动转运不推荐，理由两条：
    1. 扫描模式下单通道转换完成没有任何标志位、也不触发中断，整个序列转完才产生一次 EOC——等你能判断时，前面的数据早被覆盖；
    2. 转换极快（一个通道只要几 us），来不及转运就丢数据。
  • 间断模式可以每转完一个通道暂停等转运，但单通道完成无标志位，只能用 Delay 猜时间，既不省心也不提效，不建议用。
  • 本节办法：单次 + 非扫描，每次触发前改序列 1 的通道——写通道 0 → 触发、等待、读值，再改通道 1……依次实现多通道。扫描 + DMA 的正规做法留到下一节。

2.3 改代码：把填通道搬进 AD_GetValue 并加参数

把 AD_Init 里填通道那一行剪到触发之前，再把通道号提成形参：

uint16_t AD_GetValue(uint8_t ADC_Channel)
{
    ADC_RegularChannelConfig(ADC1, ADC_Channel, 1, ADC_SampleTime_55Cycles5);  /* 转换前指定通道 */
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);
    while (ADC_GetFlagStatus(ADC1, ADC_FLAG_EOC) == RESET);
    return ADC_GetConversionValue(ADC1);
}
  • 参数 uint8_t 就是 ADC_Channel_x 宏的类型（ADC_RegularChannelConfig 第二个参数），原样往下传。
  • 调用时指定通道，返回值就是该通道的结果，如 AD_GetValue(ADC_Channel_0)、(ADC_Channel_3)。
  • GPIO 也要改：GPIO_Pin 改成 GPIO_Pin_0 | GPIO_Pin_1 | GPIO_Pin_2 | GPIO_Pin_3。
  • 头文件声明同步加参数。

图 14：uint16_t AD_GetValue(uint8_t ADC_Channel) 内依次 ADC_RegularChannelConfig(ADC1, ADC_Channel, 1, ADC_SampleTime_55Cycles5);、触发、等 EOC、return ADC_GetConversionValue(ADC1);

2.4 多通道主函数与现象

#include "Delay.h"
#include "OLED.h"
#include "AD.h"

uint16_t AD0, AD1, AD2, AD3;

int main(void)
{
    OLED_Init();
    AD_Init();

    OLED_ShowString(1, 1, "AD0:");
    OLED_ShowString(2, 1, "AD1:");
    OLED_ShowString(3, 1, "AD2:");
    OLED_ShowString(4, 1, "AD3:");

    while (1)
    {
        AD0 = AD_GetValue(ADC_Channel_0);
        AD1 = AD_GetValue(ADC_Channel_1);
        AD2 = AD_GetValue(ADC_Channel_2);
        AD3 = AD_GetValue(ADC_Channel_3);

        OLED_ShowNum(1, 5, AD0, 4);
        OLED_ShowNum(2, 5, AD1, 4);
        OLED_ShowNum(3, 5, AD2, 4);
        OLED_ShowNum(4, 5, AD3, 4);

        Delay_ms(100);
    }
}
  • 四行 OLED_ShowString(1..4, 1, "AD0:"～"AD3:")，循环里 4 次 AD_GetValue(ADC_Channel_0～3) + 4 次 OLED_ShowNum + Delay_ms(100);。
  • 现象：AD0～AD3 四行分别随电位器、遮挡光敏、加热热敏、靠近红外变化，互不影响（画面 AD0:1668 / AD1:1984 / AD2:2809 / AD3:2094）。
  • 这就是用「单次非扫描」做 AD 多通道，简单直观；扫描模式的正规做法等 DMA 之后。

坑与易错点

  1. 只有 PA0～PB1 这 10 个引脚是 ADC 通道：其他引脚接模拟电压读不出正确值，还可能损伤引脚。
  2. GPIO 必须配 GPIO_Mode_AIN：AIN 会断开数字部分防干扰；上拉/下拉/浮空都不对。
  3. ADCCLK 不能超 14MHz：RCC_ADCCLKConfig 只有 2/4/6/8 分频，72MHz 下只能用 6 分频 12MHz 或 8 分频 9MHz。
  4. ADC_NbrOfChannel 在非扫描模式无效：非扫描只有序列 1 有效，写多少都一样；扫描模式下它才表示扫几个通道。
  5. ADC_ExternalTrigConv_None = 软件触发：不是「没有触发」，而是不用外部触发，由 ADC_SoftwareStartConvCmd 手动启动。
  6. ADC_GetSoftwareStartConvStatus 不能判断结束：它只读 SWSTART，而 SWSTART 在转换一开始就被硬件清零；判断结束要用 ADC_FLAG_EOC。
  7. EOC 不只是规则组：规则组或注入组转换结束都会置 1；读 DR 会自动清除，不用手动清。
  8. 校准不要漏：ADC_Cmd 上电后按手册走校准四步，减小内部电容误差。
  9. while (status == SET) 的语义：标志位为 1 表示「校准进行中」，硬件完成自动清 0，所以条件写 == SET（省略也等价）。
  10. 单次转换必须每次触发：AD_GetValue 里要有 ADC_SoftwareStartConvCmd；连续模式才把触发挪到初始化末尾。
  11. 电压换算要先强转 float：(float)ADValue / 4095 * 3.3，否则整数除法丢小数；4095 与 4096 对应 3.3V 都可接受。
  12. 显示小数要拆开：OLED 没有浮点显示函数，用「ShowNum(整数位) + ShowNum((uint16_t)(V*100)%100, 2)」拼。
  13. AD 值抖动正常：判断阈值用迟滞比较（双阈值），或均值滤波（10/20 次平均）、裁剪分辨率。
  14. 扫描模式不能靠手动转运：单通道完成没有标志位、没有中断，只有整序列完成才有 EOC，转换只要几 us——必须配 DMA（下节）。
  15. 多通道用「每次改序列 1」实现：ADC_RegularChannelConfig 要放进 AD_GetValue、在触发之前调用，参数用形参传，别写死通道 0。
  16. 改多通道别忘了 GPIO：GPIO_Pin 要 | Pin_1 | Pin_2 | Pin_3，否则 PA1～PA3 不是模拟输入，读数无效。
  17. 传感器模块接 AO 不是 DO：DO 只有高低电平，ADC 读模拟量必须接 AO。
  18. 本集没有 DMA / 中断 / 扫描代码：ADC_DMACmd、ADC_ITConfig、看门狗函数只是读了一遍库函数列表，没有配置。
