[8-1] DMA直接存储器存取 — 学习笔记

一句话结论

DMA 是不经过 CPU 的数据转运助手：外设与存储器之间都能搬。结构是总线矩阵 + 仲裁器 + AHB 从设备 + 请求；两站点各 3 个参数 + 方向 + 传输计数器 + 自动重装 + M2M + 开关，三个条件同时满足才转运。C8T6 只有 DMA1 的 7 通道。代码在 P24。

本集定位

  • 模块 8（DMA）的理论课：00:20–04:12 只演示两个成品工程，04:18 起全是 PPT + 参考手册翻页，到 49:38 没有现场写码；片尾 49:38「我们下一小节来开始写代码」——代码在 P24 [8-2]。
  • 片头两工程：① 8-1 DMA数据转运（DataA → DataB）② 8-2 DMA+AD多通道（ADC 扫描 4 路，DMA 搬结果）。
  • 本集没有任何 DMA_Init 之类结构体、没有库函数列表，只在基本结构里顺口提一句「开关控制就是库函数里的 DMA 使能」；寄存器留到手册导读翻页。
  • 理论衔接：ADC 原理、扫描模式、转换时间在 P21、P22，本集只套结论。

1. 片头两个成品工程

1.1 8-1 DMA数据转运

  • 任务：存储器到存储器的转运——把一个数组复制到另一个数组。
  • 代码里 uint8_t DataA[] = {0x01, 0x02, 0x03, 0x04}; 是源，uint8_t DataB[] = {0, 0, 0, 0}; 是目的；另有模块 MyDMA（MyDMA.c/MyDMA.h），调用 MyDMA_Init((uint32_t)DataA, (uint32_t)DataB, 4) 传入源地址、目的地址、转运长度 4。

2. DMA 是什么

2.1 定义：直接存储器存取

  • DMA（Direct Memory Access），直译「直接存储器存取」，也叫「直接存储器访问」。
  • 顾名思义，DMA 能直接访问 STM32 内部存储器——SRAM、Flash、寄存器都行，所以才能搬数据。
  • 「DMA 可以提供外设和存储器、或者存储器和存储器之间的高速数据传输，无须 CPU 干预，节省了 CPU 的资源。」
    • 外设指外设寄存器，一般是数据寄存器 DR，比如 ADC 的 DR、串口的 DR；
    • 存储器指运行内存 SRAM 和程序存储器 Flash，即存变量、数组、程序代码的地方。
  • 搬运不必 CPU 参与，省下的时间可以干更专业的事，「搬数据这种杂活交给 DMA 就行」。

2.2 通道与触发方式

  • 12 个独立可配置通道：DMA1 有 7 个、DMA2 有 5 个；通道就是转运路径，一次转运占一个通道，多通道各转各的互不干扰。
  • 每个通道都支持软件触发和特定的硬件触发：
    • 软件触发：用于存储器到存储器——触发后 DMA 一股脑把整批数据尽快搬完；
    • 硬件触发：外设到存储器不能一股脑搬，因为外设数据有时机——比如 ADC 要在每个通道转换完成后触发一次，触发一次转运一次；
    • 「特定」：每个通道的硬件触发源不同，用哪个外设的触发源就得用哪个通道，不能任选。
  • 本芯片资源：STM32F103C8T6 只有 DMA1（7 个通道），没有 DMA2。

图 4：DMA 定义、12 个独立可配置通道（DMA1 7 个、DMA2 5 个）、每通道支持软件触发与特定硬件触发；C8T6 资源 DMA1（7 个通道）

3. 存储器映像：DMA 搬的到底是什么

3.1 计算机组成与存储器的两个知识点

  • 计算机五大组成：运算器、控制器、存储器、输入设备、输出设备；运算器与控制器合称 CPU，所以核心就是 CPU 与存储器。
  • 存储器两个知识点：存储器的内容与存储器的地址；STM32 也有这样一张表，列出所有存储器及分配的地址。

3.3 手册的存储器映像图

  • 所有存储器都被安排在 0x0000 0000 到 0xFFFF FFFF 这 4GB 地址范围内——CPU 是 32 位，寻址就是 32 位；而 STM32 存储器只有 KB 级，大量地址是空的，使用率不到 1%。
  • 图里灰色填充是 Reserved（保留）区域。
  • 0x0000 0000 处实际没有存储器：程序从 0 地址开始运行，所以要把待执行程序映射到 0 地址——映射到 Flash 就从 Flash 执行、映射到系统存储器就跑 BootLoader、映射到 SRAM 就从 SRAM 启动，由 BOOT0 与 BOOT1 引脚决定，这就是 0 地址的「别名区」。
  • 其余：0800 是 Flash 区、1FFF 是系统存储器与选项字节、2000 是 SRAM 区、4000 是外设寄存器区、E000 是内核外设寄存器；每个外设还有自己的起始地址（如 TIM2 0x40000000、TIM3 0x40000400）。

4. DMA 控制器框图（图21）

4.1 总览：CPU + 存储器 + 总线矩阵

  • 左上角是 Cortex-M3 内核（含 CPU 与内核外设）；除了 CPU，其余都可看成存储器（Flash、SRAM、各外设寄存器），所以系统就是「CPU + 存储器」。
  • 寄存器是特殊的存储器：CPU 能像读写内存一样读写它；而寄存器每一位背后连着导线，可控制外设电路（置引脚电平、通断开关、切换数据选择器）——寄存器是软件与硬件的桥梁。
  • 总线矩阵：
    • 左端主动单元（有访问权）：内核有 DCode 总线（专访问 Flash）与系统总线（访问其他）；DMA1、DMA2 的总线，以及以太网私有的 DMA 总线（不用管）。
    • 右端被动单元：Flash、SRAM、AHB 桥上挂的 APB1/APB2 外设（ADC、GPIO、定时器、串口等），只能被主动单元读写。

图 7：左上红圈「Cortex-M3 内核」（ICode/DCode/系统三条总线），总线矩阵右侧被动单元（Flash 接口控制器、SRAM、RCC、桥1/桥2 → APB1/APB2 外设），左侧 DMA1（通道 1～7 + 仲裁器 + AHB 从设备）与 DMA2（通道 1～5 + 仲裁器 + AHB 从设备）、DMA 请求线

4.2 仲裁器、AHB 从设备与 DMA 请求

  • 内部通道：DMA1 有 7 个、DMA2 有 5 个，可以各自独立工作。
  • 仲裁器（通道级）：DMA 总线只有一条，所有通道分时复用；冲突时按通道优先级决定先后。
  • 仲裁器（总线矩阵级）：DMA 与 CPU 抢同一目标时，DMA 暂停 CPU 的访问，但保证 CPU 仍有一半总线带宽。
  • AHB 从设备：就是 DMA 自己的配置寄存器，挂在右侧 AHB 总线上——所以 DMA 既是主动单元（读写存储器），也是被动单元（被 CPU 配置）。
  • DMA 请求：请求即触发——各外设通过这条线把硬件触发信号送进来，如 ADC 转换完成、串口收到数据。
  • 一句话：DMA 总线访问存储器、多通道独立转运、仲裁器防冲突、AHB 从设备供配置、DMA 请求供硬件触发。

4.3 额外提醒：Flash 是只读的

  • Flash 属 ROM，通过总线直接访问时无论 CPU 还是 DMA 都只读，不能写。
  • 所以 DMA 目的地址填 Flash 区会出错。
  • Flash 并非绝对不能写，配 Flash 接口控制器可写，但那是另一课题；总之直接访问只能读。
  • SRAM 可任意读写；外设寄存器要看手册（有的只读、有的只写），常用的数据寄存器都能正常读写。

5. DMA 基本结构图（写代码必看）

上面的框图只是笼统结构，这张「DMA 基本结构图」才是写代码控制 DMA 的必备依据。

5.1 两个站点的三个参数

  • 左边「外设寄存器」站点、右边「存储器」站点（Flash 与 SRAM），这就是转运的两大站点。
  • 手册用词：说「存储器」一般特指 Flash 与 SRAM，不含外设寄存器；外设寄存器直接叫「外设」——所以说法是「外设到存储器、存储器到存储器」。
  • 方向参数：外设→存储器、存储器→外设，还有存储器→存储器（Flash→SRAM、SRAM→SRAM）；Flash 只读，所以不能 SRAM→Flash、Flash→Flash。
  • 两站点各 3 个参数：
    1. 起始地址：数据从哪来、到哪去；
    2. 数据宽度：一次搬多宽——字节 Byte = 8 位（一个 uint8_t）、半字 HalfWord = 16 位（一个 uint16_t）、字 Word = 32 位（一个 uint32_t）；ADC 结果是 uint16_t，所以选半字；
    3. 地址是否自增：一次转运后地址是否移到下一个，相当于 p++；ADC 扫描用 DMA 时，外设地址（ADC_DR）不自增、存储器地址要自增，否则后一个数据会覆盖前一个。
  • 存储器到存储器怎么配：把其中一个存储器的地址填到「外设」站点即可——站点名字只是个称呼，写 Flash 地址就去 Flash 找、写 SRAM 地址就去 SRAM 找；把方向反过来也行，叫站点 A、站点 B 也可以。

5.2 传输计数器、自动重装与触发控制

  • 传输计数器：指定总共转运几次，它是自减计数器；写 5 就只转 5 次，每次减 1，减到 0 停止并把自增过的地址复原。
  • 自动重装器：决定减到 0 后是否恢复初值——不重装是单次模式（转一轮就结束），重装是循环模式（如 ADC 扫描 + 连续转换要配循环）。
  • 触发控制：决定何时转运，选硬件还是软件由 M2M 决定（M2M = Memory to Memory，「2」与 two 同音）：
    • M2M = 1 → 软件触发：以最快速度连续触发，尽早把计数器清零，可理解为「连续触发」，一般用于存储器到存储器；
    • M2M = 0 → 硬件触发：触发源可选 ADC、串口、定时器，用于需要时机的外设转运；
    • ⚠️ 软件触发不能配循环模式：软件触发想清零、循环模式清零后重装，两个一起用 DMA 就停不下来。
  • 开关控制：DMA 的使能位（库函数里的 DMA 使能函数，写法在 P24）。
  • 转运三条件：① 开关使能 ② 传输计数器 > 0 ③ 有触发信号——触发一次、转运一次、计数器减一次；计数器到 0 且不重装时，怎么触发都不再转，此时要关闭 DMA → 写入大于 0 的数 → 再使能。
  • 注意：写传输计数器前必须先关闭 DMA，开启状态下写是手册不允许的。

  • 同通道多个触发源时（通道 1 的 ADC1/TIM2_CH3/TIM4_CH1）：选哪个取决于你在外设里开启了哪路 DMA 输出（库函数，P24 讲）；三个都开则理论上都能触发（图里是或门），一般只开一个。
  • 优先级：7 路请求进仲裁器产生内部 DMA1 请求，默认通道号越小优先级越高，也可在程序里配置，影响不大。
  • DMA2 有自己的一套请求映像（图23），内容相同；本芯片没有 DMA2，一句带过。

图 10：左侧外设请求信号列（ADC1/TIM2_CH3/TIM4_CH1 → 通道1；USART3_TX/TIM1_CH1/TIM2_UP/TIM3_CH3/SPI1_RX → 通道2……），每通道有「软件触发（MEM2MEM位）」与「通道x的EN位」，右侧固定硬件优先级 → 内部DMA1请求

7. 数据宽度与对齐（表57）

  • 两站点都有数据宽度：一样就正常逐个搬，不一样按**表57「可编程的数据传输宽度和大小端操作」**处理（第一列源宽度、第二列目标宽度、第三列传输数目）。
  • 8 位 → 8 位：0 位置读 B0 写 B0，再 B1、B2、B3。
  • 源窄目标宽（8 → 16）：目标前补 0——读 B0 写 00B0；8 → 32 同理。
  • 源宽目标窄（16 → 8）：读 B1B0 只写 B0，高位舍弃。
  • 总结：小转大高位补 0，大转小高位舍弃，等宽直接搬。
  • 表名提到大小端，但只讲了宽度补 0/截断，未展开大小端。

图 11：表57「可编程的数据传输宽度和大小端操作（当PINC = MINC = 1）」9 行组合（8→8/8→16/8→32/16→8/16→16/16→32/32→8/32→16/32→32），如 8→16 时「在 0x0 读 B0 的低 8 位，在 0x0 写 00B0」

8. 两个典型例子

8.1 例 1：数据转运 + DMA（存储器 → 存储器）

  • 任务：把 SRAM 里的 DataA 转运到 DataB（对应程序①），按基本结构图逐项配（配置思路，不是代码）：
    • 外设站点地址给 DataA 首地址，存储器站点地址给 DataB 首地址；两数组都是 uint8_t，按 8 位字节传输；
    • 想 DataA[0]→DataB[0]、DataA[1]→DataB[1] 一一对应，所以两边地址都自增；
    • 错误组合：左边不自增、右边自增 → DataB 全等于 DataA[0]；左边自增、右边不自增 → 只有 DataB[0] 等于 DataA 最后一个数；两边都不自增 → 一直只搬 DataA[0]；
    • 方向：外设站点 → 存储器站点；传输计数器填 7，不重装；软件触发（存储器到存储器不等时机）；
    • 使能后转运 7 次，计数器到 0 自动停止，相当于把 DataA 复制到 DataB。

8.2 例 2：ADC 扫描模式 + DMA（外设 → 存储器）

  • 任务：ADC 扫描依次转换 7 个通道，结果都进 ADC_DR，要在每个通道转换完成后各转运一次，且目的地址自增，数据才不会互相覆盖（对应程序②）。
  • 配置：外设地址写 ADC_DR；存储器地址用 SRAM 里的 uint16_t ADValue[7]；两者都是 uint16_t，16 位半字传输；外设不自增、存储器自增；方向外设 → 存储器；计数器填 7。
  • 重装看 ADC 配置：ADC 单次扫描 → DMA 不重装；ADC 连续扫描 → DMA 用自动重装，两者同步。
  • 触发：选 ADC 的硬件触发——ADC_DR 的值只有单通道转换完成后才有效，转运时机必须与它同步。

图 12：规则组序列 1～7 填通道 2/5/4/1/0/3/6，结果都进 ADC_DR（DMA 外设地址）；ADC 硬件触发 → DMA；右侧把各通道结果依次放进 SRAM 数组 uint16_t ADValue[7]

9. ADC 与 DMA 为什么是「天生一对」

  • P22 讲过：ADC 扫描模式下，单个通道转换完成没有任何标志位、也不触发中断，程序很难判断时机。
  • 实测结论（非手册原文）：单通道转换完成虽然无标志位/中断，但确实会产生 DMA 请求去触发转运——手册没细写，只能靠实验验证。
  • 所以 DMA 最常见的用途就是配合 ADC 扫描：扫描模式有数据覆盖的固有缺陷，这个缺陷让两者成为最常见的伙伴，ADC 对 DMA 的需求非常强烈。
  • 其他外设用 DMA 是锦上添花；ADC 扫描不用 DMA，功能会受很大限制。

坑与易错点

  1. DMA 的「外设/存储器」只是名字：外设站点照样能放 SRAM/Flash 地址，存储器到存储器就是靠它。
  2. Flash 只能读不能写：DMA 目的地址填 Flash 区会出错，SRAM 才能随便读写。
  3. 软件触发与循环模式不能同时用：软件触发一直想清零、循环模式清零后重装，同时用 DMA 停不下来。
  4. 写传输计数器前必须先关闭 DMA：手册规定，开启状态下写不允许。
  5. 计数器减到 0 且不重装后不会自动复活：要关闭 → 重写计数器 → 再使能。
  6. DMA 工作三条件缺一不可：开关使能 + 计数器 > 0 + 有触发信号。
  7. 硬件触发源绑定固定通道：ADC1 只能用通道 1，用错通道不会触发；软件触发则任意通道。
  8. 同通道多触发源时，看开启了哪个外设的 DMA 输出：不开对应外设的 DMA 输出，这路硬件触发无效。
  9. 默认通道号越小优先级越高（可配置）：多通道同时请求由仲裁器排队。
  10. DMA 与 CPU 抢总线时 CPU 可能被暂停：但仲裁器保证 CPU 至少一半总线带宽。
  11. 数据宽度要按数据类型选：ADC 结果 uint16_t → 半字 16 位，uint8_t → 字节，uint32_t → 字；选错会漏数据或错位。
  12. 地址自增要按场景配：ADC_DR 这类寄存器不自增（永远读同一格），目标数组必须自增，否则数据都写到同一格互相覆盖。
  13. 小转大高位补 0、大转小舍弃高位：8 → 16 位是 00B0，16 → 8 位只留低 8 位。
  14. 循环模式要跟外设模式配套：ADC 单次扫描 → DMA 不重装；ADC 连续扫描 → DMA 循环模式，否则数据对不上。
  15. 本集没有代码：初始化结构体、通道选择、使能、中断全在 P24，本集只给原理与参数含义。
  16. ADC 单通道 DMA 请求属实测结论：手册没写「单通道转换完成会产生 DMA 请求」，只能靠实验验证。
