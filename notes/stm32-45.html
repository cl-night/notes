① 修改主频：入口在 system_stm32f10x.c 文件头注释——它提供 SystemInit()（配置系统时钟源、PLL 倍频因子、AHB/APBx 预分频、Flash 设置；在 startup 文件里复位后被调用、进入 main 之前）、SystemCoreClock 变量（存 HCLK，可用来配 SysTick）、SystemCoreClockUpdate()（运行时改了主频必须调用它更新变量）。真正改主频的地方在第 106～116 行的预编译宏区：#if defined(STM32F10X_LD_VL)… 一组、#else 一组；F103C8T6 是 MD 中容量，看 #else 这一组，里面有 SYSCLK_FREQ_HSE / SYSCLK_FREQ_24MHz / SYSCLK_FREQ_36MHz / SYSCLK_FREQ_48MHz / SYSCLK_FREQ_56MHz / SYSCLK_FREQ_72MHz 六档宏（默认只放开 72MHz）——用法就是把当前宏注释掉、把目标频率的宏解除注释。⚠ 该文件默认是只读的（工程树里文件图标带锁），要右键文件（或整个文件夹）→ 属性 → 取消「只读」才能编辑。SetSysClockToXX 里的实际算式：72M ＝ HSE×9、56M ＝ HSE×7、48M ＝ HSE×6、36M ＝ HSE/2×9、24M ＝ HSE/2×6、HSE 档＝不分频直通；AHB /1、APB2 /1、APB1 /2（所以 72M 时 HCLK＝PCLK2＝72M、PCLK1＝36M）。若 HSE 起振失败会走 else 分支（注释提示「the application will have wrong clock configuration，可自行加错误处理」），此时系统仍用最初启动的 HSI 8MHz——所以「发现主频变成 8M」就说明 HSE 真有问题。连锁影响（必写）：Delay_us 里按 72M 写死了常量，改主频后所有计时都不准，通用做法是按 SystemCoreClock 动态计算；作者的结论是「牵一发动全身，不推荐随便修改主频」。现象：72M 时 OLED 显示 SYSCLK:72000000、Running 1s 周期；改成 36M 后显示 SYSCLK:36000000、Running 周期变 2s。② 睡眠模式：主循环末尾加 __WFI(); 即可（也可用 __WFE()，区别只是唤醒方式；本工程只演示 WFI，推荐 WFI 的中断唤醒）；SLEEPDEEP=0 是默认值，进的就是睡眠模式，不必配寄存器；若要配 SLEEPDEEP/SLEEPONEXIT/SEVONPEND 得直接操作内核的 SCB->SCR（见 Cortex-M3 编程手册 4.4 系统控制块；属内核、不是 PWR 库）。适用性分析：串口「随时待命收数据」用睡眠 ✓（USART 硬件仍能收数据、收到后产生中断唤醒 CPU）；停止 ✗（1.8V 时钟全关，USART 中断不能唤醒停止模式）；待机 ✗。③ 停止模式：必须先开 PWR 时钟 RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE)——不开则写寄存器无效、读回来全是 0；然后调 PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFI)（参数一：PWR_Regulator_ON 调节器开／PWR_Regulator_LowPower 低功耗；参数二：PWR_STOPEntry_WFI／_WFE）。函数内部：读 PWR->CR → tmpreg &= CR_DS_MASK（清 PDDS 和 LPDS，清 PDDS＝选择停止模式）→ 按参数 设 LPDS（ON 时 LPDS=0）→ 写回 PWR->CR → SCB->SCR |= SCB_SCR_SLEEPDEEP → 按参数执行 __WFI() 或 __WFE()。坑：唤醒后主频变 8M——PPT 停止模式条目写「当一个中断或唤醒事件导致退出停止模式时，HSI 被选为系统时钟」；首次复位时 SystemInit 配的是 HSE×9＝72M，但退出停止模式后 PLL/HSE 未恢复、默认用 HSI 8MHz（现象：Running 明显变慢）。解决：唤醒后立刻再调一次 SystemInit()，主频恢复 72M。④ 待机模式：先把显示改成 CNT:/ALR:/ALRF:（去掉年月日时分秒和 DIV），用 RTC 闹钟唤醒：uint32_t Alarm = RTC_GetCounter() + 10; RTC_SetAlarm(Alarm);（约 10s 后唤醒）。坑：RTC_ALR 寄存器是「只写」的（手册位说明里标 W、没有 R）→ 读不回来，所以必须用变量 Alarm 保存闹钟值再显示；主循环末尾调 PWR_EnterSTANDBYMode()：内部先清 WUF 唤醒标志 → 再 PDDS=1 选择待机 → 设 SLEEPDEEP → 执行 __WFI()；待机不区分 WFI/WFE（唤醒源固定为那 4 个信号）。进待机前先 OLED_Clear()（模拟关闭外部模块）并显示 STANDBY 便于观察；唤醒后程序从头开始执行（CNT/ALR 重新刷新、Running 再闪，说明没在暂停点继续）。PWR_WakeUpPinCmd(ENABLE) 使能位于 PA0 的 WKUP 引脚——该脚默认下拉、接高电平即唤醒、不需要做 GPIO 初始化。进待机前必须关掉外部模块（作者用 OLED_Clear 模拟，真实产品要切断外挂模块电源，否则「外挂模块耗电远超 STM32 本身，捡了芝麻丢了西瓜」）。实测电流：直接测 1mA 多（电源指示灯）→ 去掉指示灯 几百 µA → 继续排查后 降到 3µA，与手册「待机约 3µA」吻合；正常工作 20 多 mA。

2. 程序①：修改主频（13-1 修改主频）

2.1 system_stm32f10x.c 文件头注释

  • 这个文件就是用来配置系统时钟的（注释要认真读，「读懂这些注释就差不多能理解这个文件了」）；
  • 文件头写明：本文件提供 2 个函数和 1 个全局变量：
    1. SystemInit()：设置系统时钟（系统时钟源、PLL 倍频因子、AHB/APBx 预分频、Flash 设置）——在 startup 文件里、复位之后、跳转到 main 之前被调用；
    2. SystemCoreClock：全局变量，保存核心时钟（HCLK），可用于配置 SysTick 定时器或其他参数；
    3. SystemCoreClockUpdate()：更新 SystemCoreClock 变量——只要在程序运行中改变了核心时钟，就必须调用它；
  • 文件版本 V3.5.0、日期 11-March-2011（CMSIS Cortex-M3 Device Peripheral Access Layer System Source File）。

2.2 RCC 时钟树（图8）

  • HSE 8MHz（外部晶振）→ PLLXTPRE（可 /2）→ PLLSRC 选源 → PLLMUL（×4～×16） → PLLCLK → SW 选择 → SYSCLK 72MHz；
  • AHB 预分频 → HCLK 72MHz；APB2 预分频 /1 → PCLK2 72MHz；APB1 预分频 /2 → PCLK1 36MHz；
  • 另有 LSE 32.768kHz → RTCCLK、LSI 40kHz → IWDGCLK、MCO 时钟输出、USB 预分频等；
  • 此前课程一直保持默认配置（晶振 8M、AHB/APB2＝72M、APB1＝36M），但这些都不是绝对的，可以按需改——随意改可能出问题。

2.3 改主频的宏（第 106～116 行）

  • 文件里用预编译指令分成两组：#if defined(STM32F10X_LD_VL) || (defined STM32F10X_MD_VL) || (defined STM32F10X_HD_VL)（VL 型）与 #else（其他型号）；
  • F103C8T6 是 MD 中容量，看 #else 这组；组内 6 个宏（默认只放开 72MHz）：
宏 值 说明
SYSCLK_FREQ_HSE HSE_VALUE 不倍频，直接用 HSE（8MHz）
SYSCLK_FREQ_24MHz 24000000 HSE/2×6
SYSCLK_FREQ_36MHz 36000000 HSE/2×9（本集演示用它）
SYSCLK_FREQ_48MHz 48000000 HSE×6
SYSCLK_FREQ_56MHz 56000000 HSE×7
SYSCLK_FREQ_72MHz 72000000 HSE×9（默认）
  • 用法：把当前频率的宏注释掉、把目标频率的宏解除注释（比如想改 36M，就注掉 72M 宏、放开 36M 宏）。

3. 程序②：睡眠模式（13-2 睡眠模式+串口发送+接收）

3.1 为什么用睡眠、能不能用其它模式

  • 复制 9-2 串口收发工程；功能是收到一个字节 → 中断置标志 → 主循环查到后读数据并回发；
  • 问题：如果一直没收到数据，主循环不断查询标志位——这是无意义的耗电操作；
  • 思路：空闲时让 CPU 睡，中断来了再醒来干活；
  • 三种模式对「串口随时待命」的适用性：
    • 睡眠 ✓：程序不执行，但 USART 硬件电路仍能接收数据，收到后产生中断唤醒 CPU；
    • 停止 ✗：1.8V 区域时钟全关，CPU 和外设都不能运行，USART 中断也不能唤醒停止模式（只有 EXTI 能）；
    • 待机 ✗：唤醒源固定 4 个，也不适合。

    {
        RxData = Serial_GetRxData();
        Serial_SendByte(RxData);
        OLED_ShowHexNum(1, 8, RxData, 2);
    }

    OLED_ShowString(2, 1, "Running");
    Delay_ms(100);
    OLED_ShowString(2, 1, "        ");
    Delay_ms(100);

    __WFI();      /* 主循环最后：进入睡眠，等中断唤醒 */
}
  • 只需在主循环最后加 __WFI();（也可以 __WFE()，区别只是唤醒方式；推荐 WFI 的中断唤醒，本工程只演示 WFI）；
  • __WFI 是 CPU 的内核汇编指令（转到定义就到头了，看不到实现）——记得住格式即可；
  • SLEEPDEEP=0 是默认值 → 直接就是睡眠模式，不必配寄存器；
  • 若要配 SLEEPDEEP/SLEEPONEXIT/SEVONPEND，必须直接操作内核的 SCB->SCR（Cortex-M3 编程手册 4.4 系统控制块 SCB → SCR）：
    • Bit 4 SEVONPEND：0＝只有使能的中断或事件能唤醒；1＝**使能的事件和所有中断（含被禁止的中断）**都能唤醒；
    • Bit 2 SLEEPDEEP：0＝Sleep（睡眠）；1＝Deep sleep（深度睡眠）；
    • Bit 1 SLEEPONEXIT：0＝中断返回时不睡；1＝中断返回时进入 sleep；
    • 例如在 WFI 上面写 SCB->SCR |= SCB_SCR_SLEEPDEEP;——本工程保持默认 0 即可。

4. 程序③：停止模式（13-3 停止模式+对射式红外传感器计次）

4.1 为什么用停止模式

  • 复制 5-1 工程；原代码 CounterSensor_Get() 不断轮询，没有中断信号时就是无意义的耗电操作；
  • 本代码可以用外部中断唤醒，所以适合用更省电的停止模式——停止模式下 1.8V 区域时钟全关，但外部中断的工作不需要时钟（EXTI 是硬件触发），所以仍然能唤醒；
  • 表8（红圈）：停机的唤醒列是「任一外部中断」、对 1.8V 区域时钟的影响是「关闭所有 1.8V 区域的时钟」。

4.2 代码：开 PWR 时钟 + PWR_EnterSTOPMode

/* 停止模式和待机模式都需要 PWR 外设 → 必须先开 PWR 时钟 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

...

while (1)
{
    /* 显示与计次 */
    OLED_ShowString(2, 1, "Running");
    Delay_ms(100);
    OLED_ShowString(2, 1, "        ");
    Delay_ms(100);

    PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFI);   /* 进入停止模式 */

    /* 唤醒后必须重配时钟，否则主频是 HSI 的 8MHz */
    SystemInit();
}
  • ① 先开 PWR 时钟：RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE)——千万不要忘，不开则写寄存器无效、读取寄存器全是 0（可以自己试）；
  • ② 调用 PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFI)：
    • 参数一：PWR_Regulator_ON（电压调节器开启）/ PWR_Regulator_LowPower（调节器低功耗，更省电、唤醒多一段延时）；
    • 参数二：PWR_STOPEntry_WFI / PWR_STOPEntry_WFE；
  • 函数内部（stm32f10x_pwr.c）：
    1. tmpreg = PWR->CR;
    2. tmpreg &= CR_DS_MASK;——清除 PDDS 和 LPDS 位（清 PDDS 就是选择停止模式，对应流程图 PDDS=0 分支）；
    3. tmpreg |= PWR_Regulator;——按参数设置 LPDS（调节器开时 LPDS=0）；
    4. PWR->CR = tmpreg;
    5. SCB->SCR |= SCB_SCR_SLEEPDEEP;——置内核 SLEEPDEEP 位（对应流程图「深度睡眠」分支）；
    6. 根据参数执行 __WFI() 或 __WFE()。
  • 下载方式：低功耗模式下按住复位键 → 点下载 → 松手。

4.3 坑：唤醒后主频变 8M

  • 现象：遮挡计次正常，但唤醒后 Running 明显变慢；
  • 原因：PPT 停止模式条目写得很清楚——「当一个中断或唤醒事件导致退出停止模式时，HSI 被选为系统时钟」；首次复位时 SystemInit 配的是 HSE×9＝72M，但退出停止模式后 PLL/HSE 没有自动恢复，默认用 HSI 8MHz；
  • 解决：在 PWR_EnterSTOPMode() 后面立刻再调一次 SystemInit()，主频恢复到 72M（现象恢复正常）。

5. 程序④：待机模式（13-4 待机模式+实时时钟）

5.1 用 RTC 闹钟唤醒

  • 复制 12-2 实时时钟 工程；先把显示改成 CNT: / ALR: / ALRF:，去掉年月日时分秒和 DIV 的显示；
  • 设定闹钟（约 10s 后唤醒）：
uint32_t Alarm = RTC_GetCounter() + 10;   /* 当前秒数 + 10s */
RTC_SetAlarm(Alarm);
OLED_ShowNum(2, 6, Alarm, 10);            /* 显示闹钟值：必须用变量，不能读寄存器 */
  • 坑：RTC_ALR 寄存器是只写的！查手册 RTC 寄存器描述可以发现 RTC_ALR 各位的读写特征里只有 W（写）、没有 R（读）——读不回来；
  • 所以必须用变量 Alarm 保存闹钟值再显示（手册里还有读写缩写对照表可以查：W＝只写、R＝只读、rw＝读写等）；
  • 现象验证：主循环显示 CNT 不断自增、ALR 是复位后 10s；等 CNT 增长到与 ALR 相等，在 CNT = ALR 的最后时刻 ALRF 置 1——闹钟功能正常。

5.2 进入待机

/* PWR 时钟：本工程前面已有，但为了独立可用，这里再开一次也无妨 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

while (1)
{
    OLED_ShowNum(1, 6, RTC_GetCounter(), 10);
    OLED_ShowNum(3, 6, RTC_GetFlagStatus(RTC_FLAG_ALR), 1);

    OLED_ShowString(4, 1, "Running");
    Delay_ms(100);
    OLED_ShowString(4, 1, "        ");
    Delay_ms(100);

    OLED_ShowString(4, 9, "STANDBY");
    Delay_ms(1000);              /* 测电流时改 10000 */
    OLED_ShowString(4, 9, "        ");
    Delay_ms(100);

    OLED_Clear();                /* 模拟关闭外部模块 */
    PWR_EnterSTANDBYMode();      /* 进入待机模式 */
}
  • 说明：虽然 12-2 工程里已经开过 PWR 时钟，但本程序独立使用待机模式，所以再开一次 PWR 时钟（重复开启不会有问题）——这样能降低对 RTC 代码的依赖；
  • PWR_EnterSTANDBYMode() 内部：
    1. 清除 WakeUp 标志（PWR_CSR 的 WUF）；
    2. 选择 STANDBY 模式——实际上就是 PDDS=1；
    3. 设置内核 SLEEPDEEP 位；
    4. 执行 __WFI()；
  • 待机不区分 WFI/WFE：它的唤醒条件是固定的那 4 个信号（WKUP 上升沿 / RTC 闹钟 / NRST / IWDG），没有区分中断唤醒和事件唤醒，所以函数里固定用 WFI；
  • 现象：复位后 Running 闪烁、随后 CNT 不再刷新（已进入待机）→ RTC 闹钟触发唤醒 → CNT 与 ALR 重新刷新、Running 再闪——说明唤醒后程序是从头开始执行的（如果从中断暂停点继续执行，闹钟值就不会更新）；
  • 因为待机退出＝程序从头跑，所以 PWR_EnterSTANDBYMode() 之后的代码永远执行不到（while (1) 其实也可以去掉）。

5.3 WKUP 引脚唤醒与「必须关外部模块」

PWR_WakeUpPinCmd(ENABLE);    /* 使能 WKUP 引脚（PA0），放在 main 靠前位置 */
  • PWR_WakeUpPinCmd(ENABLE) 使能位于 PA0 的 WKUP 引脚；
  • 这个引脚默认是下拉的，接高电平即可唤醒，不需要做 GPIO 初始化（手册：使能 WKUP 引脚后由 PWR 直接控制）——所以这句放在 main 里靠前位置即可；
  • 现象：给 WKUP 接高电平（或接其他传感器信号）就能唤醒 STM32；
  • 进待机前必须关掉外部模块：作者用 OLED_Clear() 模拟——真实产品里要切断外挂模块的电源，因为外挂模块的耗电远超 STM32 本身（「捡了芝麻丢了西瓜」）；这需要精心设计硬件电路。

坑与易错点

  1. 4 个程序的复制来源别混：13-1←OLED、13-2←9-2 串口、13-3←5-1、13-4←12-2 实时时钟。
  2. SYSCLK_FREQ_* 宏在第 106～116 行的 #else 组（F103C8T6 是 MD），共 6 档；改法＝注掉当前、放开目标。
  3. system_stm32f10x.c 默认只读：要先在文件夹里取消只读属性才能改。
  4. PLL 倍频关系：72M＝HSE×9、56M＝HSE×7、48M＝HSE×6、36M＝HSE/2×9、24M＝HSE/2×6；AHB /1、APB2 /1、APB1 /2。
  5. HSE 起振失败走 else：主频仍是 HSI 8M——「发现主频 8M」就是 HSE 有问题。
  6. 改主频连带所有计时：Delay_us 写死 72M，改主频后不准；改完要调 SystemCoreClockUpdate()；作者不推荐随便改主频。
  7. 睡眠只需 __WFI()：SLEEPDEEP=0 默认就是睡眠；配置 SCB->SCR 属内核，不是 PWR 库。
  8. __WFI/__WFE 是 CMSIS 内核指令，不是库函数；推荐用 WFI 的中断唤醒。
  9. 停止模式两坑：① PWR 时钟必须开（否则写寄存器无效、读回全 0）；② 唤醒后 HSI 8M 成系统时钟 → 必须立刻 SystemInit()。
  10. PWR_EnterSTOPMode 参数：PWR_Regulator_ON/_LowPower（LPDS=0/1）与 PWR_STOPEntry_WFI/_WFE。
  11. RTC_ALR 只写：读不回来，必须用变量保存闹钟值再显示。
  12. 待机不区分 WFI/WFE：唤醒源固定 4 个（WKUP(PA0)/RTC 闹钟/NRST/IWDG）。
  13. 待机唤醒后程序从头跑：PWR_EnterSTANDBYMode() 之后的代码永远执行不到。
  14. PWR_WakeUpPinCmd(ENABLE) 不用 GPIO 初始化：WKUP(PA0) 默认下拉、接高唤醒。
  15. 进待机前必须关外部模块：外挂模块耗电远超 STM32 本身（示例只 OLED_Clear 模拟）。
  16. 实测待机 3µA 与手册吻合；正常 20 多 mA——测之前先把电源指示灯等耗电件处理掉。
  17. 低功耗模式下下载：按住复位 → 点下载 → 松手。

  • 本集文本来自画面硬字幕的 OCR（PP-OCRv4，source=subtitle-ocr，699 段），不是 ASR。错字主要是 停止 → 「停北」（7 处）、运行 → 「云行」（3 处）、模式 → 「模贰」（3 处）、编译 → 「扁译」（2 处）、数据 → 「数居」（2 处）、晶振 → 「显振」；并混入网页/PDF 文字与工具栏文字——已按画面/上下文校正。
  • 4 个程序的复制来源请不要写混：13-1←OLED 显示屏、13-2←9-2 串口收发、13-3←5-1、13-4←12-2 实时时钟。
  • SYSCLK_FREQ_* 在第 106～116 行（#else 分支，F103C8T6 属 MD）：HSE / 24M / 36M / 48M / 56M / 72M 共 6 档；文件默认只读，须先取消只读属性（作者是在文件夹里改属性）。
  • PLL 倍频算式按 SetSysClockToXX 源码写：72M＝HSE×9、56M＝HSE×7、48M＝HSE×6、36M＝HSE/2×9、24M＝HSE/2×6、HSE 档直通；AHB /1、APB2 /1、APB1 /2。
  • 改主频的连锁影响：Delay_us 按 72M 写死常量，改主频后计时不准，通用做法按 SystemCoreClock 动态计算；改完要调 SystemCoreClockUpdate()；作者结论「不推荐随便修改主频」。
  • 睡眠模式只需 __WFI()，SLEEPDEEP=0（默认）即睡眠；配置 SLEEPDEEP/SLEEPONEXIT/SEVONPEND 需直接操作 SCB->SCR（内核，非 PWR 库；见 Cortex-M3 手册 4.4）。
  • 停止模式两坑：① PWR 时钟必须开（否则写寄存器无效、读回全 0）；② 唤醒后 HSI(8MHz) 成为系统时钟 → 必须立刻 SystemInit()（现象是 Running 变慢）。
  • PWR_EnterSTOPMode 两参数：PWR_Regulator_ON/_LowPower（LPDS=0/1）、PWR_STOPEntry_WFI/_WFE；内部流程为「读 CR → 清 CR_DS_MASK(PDDS/LPDS) → 按参数设 LPDS → 写回 → 置 SCB_SCR_SLEEPDEEP → WFI/WFE」。
  • RTC_ALR 是只写寄存器：手册位说明里只标 W，读不回来，必须用变量 Alarm 保存再显示。
  • 待机模式：不区分 WFI/WFE（唤醒源固定 4 个）、唤醒后程序从头跑、PWR_WakeUpPinCmd(ENABLE) 无需 GPIO 初始化、进待机前必须关外部模块。
  • 实测电流：未处理 1mA 多（电源指示灯）→ 去掉后 几百 µA → 最终 3µA（与手册一致）；正常工作 20 多 mA。为测电流把 STANDBY 显示延长到 10s、闹钟改 100s。
  • 无下集预告：结尾是待机电流实测收束。
  • 待机电流「约 3µA」的口径：作者原话是「手册说大概 3µA」，但 P42 讲过的表16 典型值是 1.7～2µA 级（不同温度/电压下最大 4～5µA）——3µA 是四舍五入的说法，实测 3µA 落在典型值与最大值之间，跨集阅读别当成矛盾。
