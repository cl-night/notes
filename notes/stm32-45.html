2. 程序①：修改主频（13-1 修改主频）

2.1 system_stm32f10x.c 文件头注释

  • 文件头写明：本文件提供 2 个函数 + 1 个全局变量。
    1. SystemInit()：设置系统时钟源、PLL 倍频因子、AHB/APBx 预分频、Flash 设置；在 startup 文件里、复位之后、跳转到 main 之前被调用。
    2. SystemCoreClock：全局变量，保存核心时钟 HCLK，可用于配置 SysTick 定时器或其他参数。
    3. SystemCoreClockUpdate()：更新 SystemCoreClock 变量；程序运行中改变了核心时钟就必须调用。
  • 文件版本 V3.5.0、日期 11-March-2011（CMSIS Cortex-M3 Device Peripheral Access Layer System Source File）。

图 3：system_stm32f10x.c 文件头注释——@file / @author MCD Application Team / @version V3.5.0 / @date 11-March-2011；正文 1. 列出 2 函数 + 1 变量

2.2 RCC 时钟树（图8）

  • HSE 8MHz（外部晶振）→ PLLXTPRE（可 /2）→ PLLSRC 选源 → PLLMUL（×4～×16）→ PLLCLK → SW 选择 → SYSCLK 72MHz。
  • AHB 预分频 → HCLK 72MHz；APB2 预分频 /1 → PCLK2 72MHz；APB1 预分频 /2 → PCLK1 36MHz。
  • 另有 LSE 32.768kHz → RTCCLK、LSI 40kHz → IWDGCLK、MCO 时钟输出、USB 预分频。
  • 此前课程一直保持默认配置（晶振 8M、AHB/APB2＝72M、APB1＝36M），但这些都不是绝对的，随意改可能出问题。

2.3 改主频的宏（第 106～116 行）

  • 文件用预编译指令分两组：#if defined(STM32F10X_LD_VL)…（VL 型）与 #else（其他型号）。
  • VL 型的完整条件：#if defined(STM32F10X_LD_VL) || (defined STM32F10X_MD_VL) || (defined STM32F10X_HD_VL)。
  • F103C8T6 是 MD 中容量，看 #else 这一组；组内 6 个宏（默认只放开 72MHz）：
宏 值 说明
SYSCLK_FREQ_HSE HSE_VALUE 不倍频，直接用 HSE（8MHz）
SYSCLK_FREQ_24MHz 24000000 HSE/2×6
SYSCLK_FREQ_36MHz 36000000 HSE/2×9（本集演示用它）
SYSCLK_FREQ_48MHz 48000000 HSE×6
SYSCLK_FREQ_56MHz 56000000 HSE×7
SYSCLK_FREQ_72MHz 72000000 HSE×9（默认）
  • 宏区原文六行全部被注释：/* #define SYSCLK_FREQ_HSE HSE_VALUE */、/* #define SYSCLK_FREQ_24MHz 24000000 */、/* #define SYSCLK_FREQ_36MHz 36000000 */、/* #define SYSCLK_FREQ_48MHz 48000000 */、/* #define SYSCLK_FREQ_56MHz 56000000 */、/* #define SYSCLK_FREQ_72MHz 72000000 */。
  • 用法：把当前频率的宏注释掉、把目标频率的宏解除注释（想改 36M 就注掉 72M 宏、放开 36M 宏）。

  • 预分频与切换：/* PCLK2 = HCLK */ …PPRE2_DIV1;、/* PCLK1 = HCLK */ …PPRE1_DIV1; 之后，/* Select HSE as system clock source */ … RCC_CFGR_SW_HSE;，并 while ((RCC->CFGR & RCC_CFGR_SWS) != 0x04) { } 等切换完成。
  • 72M 档的完整流程：RCC_CR_PLLON 使能 PLL → while(!(RCC->CR & RCC_CR_PLLRDY)); 等就绪 → RCC_CFGR_SW 切到 PLL → while((RCC->CFGR & RCC_CFGR_SWS) != 0x08); 等切换完成（对应注释 /* PLL configuration: PLLCLK = HSE * 9 = 72 MHz */）。
  • PLL 配置段：先按位取反 RCC_CFGR_PLLSRC | RCC_CFGR_PLLXTPRE | RCC_CFGR_PLLMULL 再与运算清位，然后 RCC->CFGR |= (uint32_t)(RCC_CFGR_PLLSRC_HSE | RCC_CFGR_PLLMULL7); 选 HSE×7（/* PLL configuration: PLLCLK = HSE * 7 = 56 MHz */）。
  • 使能与等待：/* Enable PLL */ RCC->CR |= RCC_CR_PLLON; 之后 /* Wait till PLL is ready */ while((RCC->CR & RCC_CR_PLLRDY) == 0) { }。
  • 72M 档对应 SetSysClockTo72，else 分支注释为 else { /* If HSE fails to start-up, the application will have wrong clock configuration. User can add here some code to deal with this error */ }，其后接 #elif defined SYSCLK_FREQ_24MHz。
  • 各档算式：SetSysClockTo56 → HSE×7＝56M；SetSysClockTo48 → HSE×6＝48M；SetSysClockTo36 → HSE/2×9＝36M；SetSysClockTo24 → HSE/2×6＝24M；SetSysClockToHSE → 不分频直通。

3. 程序②：睡眠模式（13-2 睡眠模式+串口发送+接收）

3.1 为什么用睡眠、能不能用其它模式

  • 复制 9-2 串口收发工程：收到一个字节 → 中断置标志 → 主循环查到后读数据并回发。
  • 一直没收到数据时主循环不断查询标志位，是无意义的耗电操作；思路是空闲时让 CPU 睡，中断来了再醒来干活。
  • 三种模式对「串口随时待命」的适用性：
    • 睡眠 ✓：程序不执行，但 USART 硬件电路仍能接收数据，收到后产生中断唤醒 CPU。
    • 停止 ✗：1.8V 区域时钟全关，USART 中断不能唤醒停止模式（只有 EXTI 能）。
    • 待机 ✗：唤醒源固定 4 个，也不适合。

3.2 代码：一句 __WFI()

while (1)
{
    if (Serial_GetRxFlag() == 1)
    {
        RxData = Serial_GetRxData();
        Serial_SendByte(RxData);
        OLED_ShowHexNum(1, 8, RxData, 2);
    }

    OLED_ShowString(2, 1, "Running");
    Delay_ms(100);
    OLED_ShowString(2, 1, "        ");
    Delay_ms(100);

    __WFI();      /* 主循环最后：进入睡眠，等中断唤醒 */
}
  • 只需在主循环最后加 __WFI();；也可用 __WFE()，区别只是唤醒方式，推荐 WFI 的中断唤醒（本工程只演示 WFI）。
  • __WFI 是 CPU 的内核汇编指令（转到定义就到头了，看不到实现），记住格式即可。
  • SLEEPDEEP=0 是默认值 → 直接就是睡眠模式，不必配寄存器。
  • 要配 SLEEPDEEP/SLEEPONEXIT/SEVONPEND，必须直接操作内核的 SCB->SCR（Cortex-M3 编程手册 4.4 系统控制块 SCB，属内核、不是 PWR 库）：
    • Bit 4 SEVONPEND：0＝只有使能的中断或事件能唤醒；1＝使能的事件和所有中断（含被禁止的中断）都能唤醒。
    • Bit 2 SLEEPDEEP：0＝Sleep（睡眠）；1＝Deep sleep（深度睡眠）。
    • Bit 1 SLEEPONEXIT：0＝中断返回时不睡；1＝中断返回时进入 sleep。
    • 在 WFI 上面写 SCB->SCR |= SCB_SCR_SLEEPDEEP; 可置深度睡眠，本工程保持默认 0 即可。

3.3 现象

  • 串口助手（COM10、9600 8N1）发一个字节，STM32 回传并显示 RxData:66。
  • 只有收发那一刻 Running 才闪一次——空闲时 CPU 一直在睡眠，不影响功能又省电。
  • 初版 main.c 的关键行：#include "Serial.h"、uint8_t RxData;、OLED_Init();、OLED_ShowString(1, 1, "RxData:");、Serial_Init();，循环体为 while (1) { if (Serial_GetRxFlag() == 1) { RxData = Serial_GetRxData(); Serial_SendByte(RxData); OLED_ShowHexNum(1, 8, RxData, 2); } }。

4. 程序③：停止模式（13-3 停止模式+对射式红外传感器计次）

4.1 为什么用停止模式

  • 复制 5-1 工程：原代码 CounterSensor_Get() 不断轮询，没有中断信号时就是无意义的耗电操作。
  • 本代码可以用外部中断唤醒，所以适合用更省电的停止模式：停止模式下 1.8V 区域时钟全关，但外部中断的工作不需要时钟（EXTI 硬件触发）。
  • 表8（红圈）：停机唤醒列＝「任一外部中断」，对 1.8V 区域时钟的影响＝「关闭所有 1.8V 区域的时钟」。

4.2 代码：开 PWR 时钟 + PWR_EnterSTOPMode

/* 停止模式和待机模式都需要 PWR 外设 → 必须先开 PWR 时钟 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

...

while (1)
{
    /* 显示与计次 */
    OLED_ShowString(2, 1, "Running");
    Delay_ms(100);
    OLED_ShowString(2, 1, "        ");
    Delay_ms(100);

    PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFI);   /* 进入停止模式 */

    /* 唤醒后必须重配时钟，否则主频是 HSI 的 8MHz */
    SystemInit();
}
  • ① 先开 PWR 时钟：RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);——不开则写寄存器无效、读回来全是 0。
  • ② 调用 PWR_EnterSTOPMode(PWR_Regulator_ON, PWR_STOPEntry_WFI)：参数一 PWR_Regulator_ON（调节器开启）/ PWR_Regulator_LowPower（低功耗，更省电、唤醒多一段延时）；参数二 PWR_STOPEntry_WFI / PWR_STOPEntry_WFE。
  • 函数内部（stm32f10x_pwr.c）：uint32_t tmpreg = 0;、assert_param(IS_PWR_REGULATOR(PWR_Regulator));、assert_param(IS_PWR_STOP_ENTRY(PWR_STOPEntry)); 之后读寄存器 PWR->CR 到 tmpreg（tmpreg = PWR->CR;）。
  • 清 PDDS 与 LPDS：tmpreg &= CR_DS_MASK（源码注释 /* Clear PDDS and LPDS bits */ tmpreg &= CR_DS_MASK;，单独写就是 tmpreg &= CR_DS_MASK;），清 PDDS＝PDDS=0 选停止模式。
  • 设 LPDS 并写回：tmpreg |= PWR_Regulator;（源码 /* Set LPDS bit according to PWR_Regulator value */ tmpreg |= PWR_Regulator;），调节器开启时 LPDS=0；再 PWR->CR = tmpreg;（源码 /* Store the new value */ PWR->CR = tmpreg;）。
  • 置位进停止：SCB->SCR |= SCB_SCR_SLEEPDEEP（源码 /* Set SLEEPDEEP bit of Cortex System Control Register */ SCB->SCR |= SCB_SCR_SLEEPDEEP;），然后 /* Select STOP mode entry */ if (PWR_STOPEntry == PWR_STOPEntry_WFI) { __WFI(); }，否则执行 __WFE()。

4.3 坑：唤醒后主频变 8M

  • 现象：遮挡计次正常，但唤醒后 Running 明显变慢。
  • 原因：PPT 停止模式条目写明「当一个中断或唤醒事件导致退出停止模式时，HSI 被选为系统时钟」。
  • 首次复位时 SystemInit 配的是 HSE×9＝72M，退出停止模式后 PLL/HSE 没有自动恢复，默认用 HSI 8MHz。
  • 解决：在 PWR_EnterSTOPMode() 后面立刻再调一次 SystemInit()，主频恢复 72M。

5. 程序④：待机模式（13-4 待机模式+实时时钟）

5.1 用 RTC 闹钟唤醒

  • 复制 12-2 实时时钟 工程；显示改成 CNT: / ALR: / ALRF:，去掉年月日时分秒和 DIV 的显示。
  • 坑：RTC_ALR 寄存器是只写的（手册寄存器描述里只有 W、没有 R），读不回来；读写缩写对照：W＝只写、R＝只读、rw＝读写。
  • 所以必须用变量 Alarm 保存闹钟值再显示。
  • 显示与闹钟的关键行：OLED_ShowString(1, 1, "CNT :")/(2, 1, "ALR :")/(3, 1, "ALRF:");、uint32_t Alarm = RTC_GetCounter() + 10;、RTC_SetAlarm(Alarm);、OLED_ShowNum(2, 6, Alarm, 10);。
  • 主循环读值：while (1) { OLED_ShowNum(1, 6, RTC_GetCounter(), 10); OLED_ShowNum(3, 6, RTC_GetCounter(), 10); }。
uint32_t Alarm = RTC_GetCounter() + 10;   /* 当前秒数 + 10s */
RTC_SetAlarm(Alarm);
OLED_ShowNum(2, 6, Alarm, 10);            /* 显示闹钟值：必须用变量，不能读寄存器 */
  • 一句话：uint32_t Alarm = RTC_GetCounter() + 10; RTC_SetAlarm(Alarm); 即约 10s 后唤醒。
  • 现象：CNT 不断自增、ALR 是复位后 10s；CNT 增长到与 ALR 相等（CNT = ALR）的最后时刻 ALRF 置 1。

5.2 进入待机

/* PWR 时钟：本工程前面已有，但为了独立可用，这里再开一次也无妨 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE);

while (1)
{
    OLED_ShowNum(1, 6, RTC_GetCounter(), 10);
    OLED_ShowNum(3, 6, RTC_GetFlagStatus(RTC_FLAG_ALR), 1);

    OLED_ShowString(4, 1, "Running");
    Delay_ms(100);
    OLED_ShowString(4, 1, "        ");
    Delay_ms(100);

    OLED_ShowString(4, 9, "STANDBY");
    Delay_ms(1000);              /* 测电流时改 10000 */
    OLED_ShowString(4, 9, "        ");
    Delay_ms(100);

    OLED_Clear();                /* 模拟关闭外部模块 */
    PWR_EnterSTANDBYMode();      /* 进入待机模式 */
}
  • 虽然 12-2 工程里已开过 PWR 时钟，本程序再写一次 RCC_APB1PeriphClockCmd(RCC_APB1Periph_PWR, ENABLE)（重复开启没问题），可降低对 RTC 代码的依赖。
  • 标志读取：RTC_GetFlagStatus(RTC_FLAG_ALR) 判断闹钟标志，进待机前再 PWR_EnterSTANDBYMode();。
  • 进待机的完整动作：OLED_ShowString(4, 9, "STANDBY"); Delay_ms(1000); OLED_ShowString(4, 9, " "); Delay_ms(100); OLED_Clear(); PWR_EnterSTANDBYMode();（图 17），简写为 OLED_ShowString(4, 9, "STANDBY"); Delay_ms(1000); … OLED_Clear(); PWR_EnterSTANDBYMode();。
  • PWR_EnterSTANDBYMode() 内部：清 PWR_CSR 的 WUF 唤醒标志 → PDDS=1 选待机模式 → 设内核 SLEEPDEEP 位 → 执行 __WFI()。
  • 待机不区分 WFI/WFE：唤醒条件固定为那 4 个信号（WKUP 上升沿 / RTC 闹钟 / NRST / IWDG），函数里固定用 WFI。
  • 现象：复位后 Running 闪烁、随后 CNT 不再刷新（已进待机）→ RTC 闹钟唤醒 → CNT 与 ALR 重新刷新、Running 再闪，说明唤醒后程序是从头开始执行的。
  • 因为待机退出＝程序从头跑，PWR_EnterSTANDBYMode(); 之后的代码永远执行不到，while (1) 其实可以去掉。

5.3 WKUP 引脚唤醒与「必须关外部模块」

PWR_WakeUpPinCmd(ENABLE);    /* 使能 WKUP 引脚（PA0），放在 main 靠前位置 */
  • PWR_WakeUpPinCmd(ENABLE) 使能位于 PA0 的 WKUP 引脚；这个引脚默认下拉，接高电平即可唤醒，不需要做 GPIO 初始化，所以放在 main 靠前位置即可。
  • 进待机前必须关掉外部模块：示例用 OLED_Clear() 模拟，真实产品里要切断外挂模块的电源。
  • 外挂模块的耗电远超 STM32 本身，这需要精心设计硬件电路。

5.4 实测电流

  • 手册说待机电流约 3µA，实测：直接测 1mA 多（电源指示灯耗电）→ 去掉指示灯仍有几百 µA → 继续排查后降到 3µA，与手册数据基本一致。
  • 正常工作电流 20 多 mA。
  • 为便于测量，把 STANDBY 显示延长到 10s（OLED_ShowString(4, 9, "STANDBY"); Delay_ms(10000);）、待机闹钟改成 100s（uint32_t Alarm = RTC_GetCounter() + 100;）。

坑与易错点

  1. 4 个程序的复制来源别混：13-1←OLED、13-2←9-2 串口、13-3←5-1、13-4←12-2 实时时钟。
  2. SYSCLK_FREQ_* 宏在第 106～116 行的 #else 组（F103C8T6 是 MD），共 6 档；改法＝注掉当前、放开目标。
  3. system_stm32f10x.c 默认只读：先取消只读属性才能改。
  4. PLL 倍频关系：72M＝HSE×9、56M＝HSE×7、48M＝HSE×6、36M＝HSE/2×9、24M＝HSE/2×6；AHB /1、APB2 /1、APB1 /2。
  5. HSE 起振失败走 else：主频仍是 HSI 8M——「发现主频 8M」就是 HSE 有问题。
  6. 改主频连带所有计时：Delay_us 写死 72M，改完要调 SystemCoreClockUpdate()；不推荐随便改主频。
  7. 睡眠只需 __WFI()：SLEEPDEEP=0 默认就是睡眠；配置 SCB->SCR 属内核，不是 PWR 库。
  8. __WFI/__WFE 是 CMSIS 内核指令，不是库函数；推荐用 WFI 的中断唤醒。
  9. 停止模式两坑：PWR 时钟必须开（否则写寄存器无效、读回全 0）；唤醒后 HSI 8M 成系统时钟，必须立刻 SystemInit()。
  10. PWR_EnterSTOPMode 参数：PWR_Regulator_ON/_LowPower（LPDS=0/1）与 PWR_STOPEntry_WFI/_WFE。
  11. RTC_ALR 只写：读不回来，必须用变量保存闹钟值再显示。
  12. 待机不区分 WFI/WFE：唤醒源固定 4 个（WKUP(PA0)/RTC 闹钟/NRST/IWDG）。
  13. 待机唤醒后程序从头跑：PWR_EnterSTANDBYMode() 之后的代码永远执行不到。
  14. PWR_WakeUpPinCmd(ENABLE) 不用 GPIO 初始化：WKUP(PA0) 默认下拉、接高唤醒。
  15. 进待机前必须关外部模块：外挂模块耗电远超 STM32 本身（示例只 OLED_Clear 模拟）。
  16. 实测待机 3µA 与手册吻合；正常 20 多 mA——测之前先处理电源指示灯等耗电件。
  17. 低功耗模式下下载：按住复位 → 点下载 → 松手。
