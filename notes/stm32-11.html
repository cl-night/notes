[5-1] EXTI外部中断 — 学习笔记

一句话结论

中断是触发条件出现后 CPU 暂停主程序、执行中断程序再返回，靠优先级决定先后、靠抢占优先级决定能否嵌套。STM32 的 68 个可屏蔽中断通道全由 NVIC 统一管理，EXTI 有 20 条中断线：所有 GPIO 都能用，但相同 Pin 编号不能同时触发。

本集定位

  • 中断部分的纯理论课：全片没有新建工程、没有写代码、没有烧录。
  • 对应 PPT 的 05-EXTI外部中断 部分（画面里幻灯片编号从第 41 张开始），讲到旋转编码器硬件电路后切到参考手册。
  • 片头只演示两个现成程序的现象（工程名 5-1 对射式红外传感器计次、5-2 旋转编码器计次），它们正是 [5-2] 要写的程序。
  • 内容路线：中断概念 → STM32 中断资源 → NVIC → EXTI → AFIO → 旋转编码器 → 参考手册导读。
  • EXTI 初始化、库函数用法、中断服务函数都不在本集，那些在 [5-2]。

1. 片头现象：两个现成的外部中断程序

程序 1：对射式红外传感器计次

  • 面包板上接一个红外对管传感器，OLED 显示一个数字，初始 Count: 00000。
  • 用挡光片挡在红外对管中间：模块的输出指示灯灭，代表输出高电平。
  • 拿开挡光片：指示灯亮，代表输出低电平。「灭到亮」之间产生一个下降沿，触发单片机引脚的外部中断，中断程序执行「数字加 1」，屏幕变成 Count: 00001。
  • 再挡光几次，屏幕上的数字就统计了挡光次数。

程序 2：旋转编码器计次

  • 面包板上接一个旋转编码器，OLED 显示一个数字（画面中是 Num:+00006）。
  • 向右转就加，向左转就减。

2. 中断的概念

2.1 中断的定义与中断源

  • 中断：主程序运行过程中出现特定的中断触发条件（中断源），CPU 暂停当前程序，转去处理中断程序，处理完返回被暂停的位置继续运行。
  • 中断源举例：外部中断可以是引脚电平跳变；定时器可以是定时时间到了；串口通信可以是接收到了数据。
  • 这些事件往往比较紧急：外部中断不处理，下一个跳变信号马上就来；串口数据不读取，下一个数据会把原来的覆盖掉。
  • 所以希望条件满足时 CPU 立即停下当前程序去处理（外部中断就计次、变量 ++；串口中断就把数据转存起来），处理完再回来。
  • 中断能极大地提高程序效率：没有中断，为防止漏掉事件或覆盖数据，主程序只能不断查询；没有定时器中断，只能靠 Delay 函数定时。
  • 有了中断，主程序可以放心做别的事。视频的比方：定好闹钟就能安心睡觉，没闹钟就得不断看时间。

2.2 中断优先级

  • 多个中断源同时申请时，CPU 按轻重缓急裁决，优先响应更紧急的。
  • 中断优先级就是中断的紧急程度，由我们按程序需求自己设置：紧急的设高、不紧急的设低。
  • 这样可以防止紧急事件被别的中断耽误；STM32 的优先级还有多种分类（见 NVIC 部分）。

2.3 中断嵌套

  • 中断嵌套：一个中断程序正在运行时，又有更高优先级的中断源申请中断，CPU 再次暂停当前中断程序去处理新的，处理完依次返回。
  • 嵌套也是为了照顾非常紧急的中断：它可以把当前中断程序二次中断、立即执行。
  • 能否嵌套由中断优先级决定（见抢占优先级）。

图 4：中断系统 PPT——中断的定义（中断源/暂停主程序/处理完返回）、中断优先级、中断嵌套三条概念

3. 中断的执行流程

  • 中断条件满足时，无论主程序在干什么（加减乘除没算完、OLED 显示才一半、Delay 还在等），主程序都立即暂停，程序由硬件电路自动跳转到中断程序；执行完再返回被暂停的地方继续。
  • 被暂停的地方叫断点。中断执行前对现场保护，执行后还原现场，保证主程序回来后能继续运行。
  • 用 C 语言编程不需要我们做现场保护，编译器自动完成。
  • 中断嵌套流程：普通中断执行时，更高优先级中断到来会再次打断它；新中断结束继续原中断，原中断结束继续主程序。
  • C 语言程序结构：main 里的 while (1) 死循环是主程序；中断程序写在一个子函数里，不需要我们调用——中断来临时由硬件自动调用。

PPT 右侧的结构示意（本集不写实现，具体代码在 [5-2]）：

int main(void)
{
	while (1)
	{
		// 主程序
		// ...
		// 主程序
	}
}

// 中断程序：不需要我们调用，中断来临时由硬件自动调用
void EXTI0_IRQHandler(void)
{
	// 中断程序
	// ...
	// 中断程序
}

4. STM32 的中断系统

  • 68 个可屏蔽中断通道（通道就是中断源的意思），这是 F1 系列最多的数量；具体型号可能没这么多，以对应型号的数据手册为准。
  • 包含 EXTI 外部中断、TIM 定时器、ADC、USART 串口、SPI、I2C、RTC 实时时钟等多个外设——几乎所有模块都能申请中断。
  • NVIC 统一管理中断：每个通道有 16 个可编程的优先等级，还可对优先级分组，进一步设置抢占优先级和响应优先级。
  • 右侧中断资源表：灰色部分是内核的中断（复位、NMI、HardFault、MemManage 等），比较「高深」、一般用不到；其余是 STM32 外设的中断——窗口看门狗（程序卡死没及时喂狗就申请中断，可在中断里做错误检查）、PVD 电源电压监测（供电电压不足时申请中断）等。本节要学的外部中断对应表里的 EXTI0～EXTI4、EXTI9_5、EXTI15_10。
  • 表里还有一列中断地址：硬件跳转受限制，中断后只能跳到固定地址；为了跳到不固定的中断函数，需要在内存里定义一个地址列表——列表地址固定，先跳到这个固定位置，再由编译器在这个位置加一条跳转到中断函数的指令。这个列表叫中断向量表，相当于中断跳转的「跳板」。
  • 用 C 语言编程不需要管中断向量表，编译器都帮我们做好了。

5. NVIC 的基本结构

  • NVIC = 嵌套向量中断控制器（Nested Vectored Interrupt Controller），用来统一分配中断优先级和管理中断。
  • 它是内核外设，相当于 CPU 的「小助手」。
  • 为什么需要：中断非常多，全接到 CPU 上要引出很多线、设计麻烦；多个中断同时申请或产生拥堵时 CPU 也难处理，毕竟 CPU 主要用来运算。
  • 结构图：左边是各外设（EXTI、TIM、ADC、USART……），各自有中断线接到 NVIC；线上的斜杠加 n 表示一个外设可能同时占用多个中断通道。NVIC 只有一个输出口，按优先级分配先后顺序，再通过这个口告诉 CPU「你该处理哪个中断」。
  • 分配先后顺序的任务，CPU 不需要知道。
  • 医院叫号的类比：CPU 好比医生，病人多时医生自己安排先后很繁琐、影响效率；医院就安排叫号系统——统一取号、按病人等级分配优先级，优先叫紧急病人，医生专心看病。这个叫号系统在 STM32 里就是 NVIC。

图 8：NVIC 基本结构——多路外设中断（EXTI/TIM/ADC/USART…）接入，NVIC 分配优先级 0～15 后单路输出给 CPU

6. NVIC 的优先级分组

6.1 抢占优先级与响应优先级

NVIC 可以对优先级分组，分为抢占优先级和响应优先级。用叫号的例子区分：

  • 响应优先级 = 「插队」的优先级：上一个病人看完后，紧急的病人即使是后来的，也会最先进去看病。
  • 抢占优先级 = 「能否中断嵌套」的优先级：病人更紧急时可以不等上一个看完，直接冲进医生屋里先看，等他看完上一个病人再继续。

6.2 优先级规则

  • 优先级由优先级寄存器的 4 位决定：4 位二进制可表示 0～15，对应 16 个优先级；数值越小，优先级越高（0 是最高）。
  • 这 4 位可以切分：高 n 位的抢占优先级 + 低 4-n 位的响应优先级。
  • 三条排队规则：抢占优先级高的可以中断嵌套；响应优先级高的可以优先排队；两者都相同的按中断号排队——中断号就是中断资源表里的数字，数值小的优先响应。
  • 所以 STM32 的中断不存在先来后到，任何时候都是优先级高的先响应。

6.3 优先级分组表（0～4 共 5 种分组）

分组方式 抢占优先级 响应优先级
分组 0 0 位，取值为 0 4 位，取值为 0～15
分组 1 1 位，取值为 0～1 3 位，取值为 0～7
分组 2 2 位，取值为 0～3 2 位，取值为 0～3
分组 3 3 位，取值为 0～7 1 位，取值为 0～1
分组 4 4 位，取值为 0～15 0 位，取值为 0
  • 分组方式在程序中由我们自己选择；选好后配置优先级时要注意抢占、响应的取值范围，不要超出表里规定。

7. EXTI 简介

  • EXTI = Extern Interrupt，外部中断。
  • 它监测指定 GPIO 口的电平信号：电平变化时立即向 NVIC 发出中断申请，经 NVIC 裁决后中断 CPU 主程序，执行 EXTI 对应的中断程序。简单说：引脚电平变化，申请中断。
  • 支持的触发方式（4 种）：
触发方式 含义
上升沿 电平从低电平变到高电平的瞬间触发中断
下降沿 电平从高电平变到低电平的瞬间触发中断
双边沿 上升沿和下降沿都可以触发中断
软件触发 引脚啥事没有，程序里执行一句代码就能触发中断
  • 支持的 GPIO：所有 GPIO 口都能当外部中断引脚，但相同的 Pin 不能同时触发中断——PA0 和 PB0 不能同时用；PA1、PB1、PC1 这种 Pin 编号一样的端口只能选 1 个。要多路就选不同 Pin 编号：PA6 和 PA7、PA9 和 PB15、PB0 和 PB1 都可以。
  • 通道数：20 个中断线路 = 16 个 GPIO_Pin（GPIO_Pin_0 ～ GPIO_Pin_15）+ PVD 输出、RTC 闹钟、USB 唤醒、以太网唤醒 4 个。
  • 这 4 个外设是来「蹭网」的：外部中断有从低功耗停止模式唤醒 STM32 的功能——PVD 电压过低恢复、RTC 闹钟唤醒、USB 与以太网唤醒都要借助它。主要学引脚中断，这 4 个知道即可。
  • 触发响应方式有两种：
    • 中断响应：申请中断，让 CPU 执行中断函数（正常流程）。
    • 事件响应：外部中断的信号不通向 CPU，而是通向其它外设，用来触发其它外设的操作（ADC 转换、DMA 等），属于外设之间的联合工作；事件响应不会触发中断。

图 10：EXTI 简介 PPT——外部中断的功能、上升沿/下降沿/双边沿/软件触发、所有 GPIO 可用但相同 Pin 不能同时触发、20 条中断线、中断/事件响应

8. EXTI 的基本结构

  • 最左边是 GPIO 外设（GPIOA、GPIOB、GPIOC……），每个有 16 个引脚，所以进来 16 根线。
  • EXTI 只有 16 个 GPIO 通道，而每个 GPIO 外设都有 16 个引脚，一个引脚占一个通道显然不够用；所以中间有 AFIO「中断引脚选择」模块——一个数据选择器，从每个 GPIO 的 16 个引脚里选一个接到 EXTI 的通道。
  • 这就是「所有 GPIO 都能触发中断，但相同的 Pin 不能同时触发」的原因：PA0、PB0、PC0 经 AFIO 选择后只有一个能接到通道 0；PA1、PB1、PC1 也只能有一个接到通道 1。
  • AFIO 选出的 16 个通道接到 EXTI 边沿检测及控制电路；下面 4 个「蹭网」外设（PVD、RTC、USB、ETH）也并列接进来——合起来就是 EXTI 的 20 个输入信号。
  • 经过 EXTI 电路后分成两种输出：
    • 上一路接到 NVIC，触发中断。本来 20 路输入应有 20 路中断输出，但 ST 觉得 20 个太多、占用 NVIC 通道资源，就把外部中断的 5～9 分到一个通道、10～15 分到一个通道——即 5～9 触发同一个中断函数，10～15 也触发同一个中断函数；编程时要在这两个函数里再根据标志位区分是哪个中断进来的。
    • 下面 20 条输出线路到其它外设，触发其它外设操作，就是刚才说的事件响应。

图 11：EXTI 基本结构——16 路 GPIO 经 AFIO（红圈：中断引脚选择）进入 EXTI 边沿检测及控制电路，中断输出到 NVIC、事件输出到其它外设

9. AFIO 复用 IO 口与中断引脚选择

  • AFIO 主要用于引脚复用功能的选择和重定义，也就是数据选择器的作用。主要完成两个任务：
    1. 复用功能引脚重映射：把某些功能重映射到别的引脚（「引脚定义表」里的复用功能重映射）；
    2. 中断引脚选择：把 PA0…PG0 里的一个选出来接到 EXTI0 上。
  • 结构图（「图 20 外部中断通用 I/O 映像」）是一系列数据选择器：第一组输入是 PA0、PB0、PC0……PG0（尾号都是 0），最终选一个连接到 EXTI0；图上标注了通过配置 AFIO_EXTICR 寄存器的相应位来决定选哪一路。EXTI1……EXTI15 同样都是数据选择器，道理一样。

图 12：AFIO 复用 IO 口——AFIO 的两个任务，以及 EXTI0/EXTI1/EXTI15 的中断引脚选择（AFIO_EXTICR 数据选择器）

10. EXTI 的内部框图

  • 右边是 20 根输入线，先进入边沿检测电路；上升沿触发选择寄存器和下降沿触发选择寄存器决定是上升沿、下降沿还是两个都触发。
  • 触发信号进入或门：硬件触发和软件中断事件寄存器的值都接到或门输入端，任意一个为 1 就输出 1——所以支持上升沿、下降沿、双边沿和软件触发。
  • 逻辑符号科普（STM32 框图里非常常见）：
    • 或门（弯弯的符号）：多输入单输出，输入端只要有一个高电平 1 输出就是 1，全部为 0 才输出 0。
    • 与门（带点直边的符号）：多输入单输出，输入端只要有一个低电平 0 输出就是 0，全部为 1 才输出 1。
    • 非门（三角号加个圈）：一个输入一个输出，输入 1 输出 0，输入 0 输出 1。
    • 数据选择器（梯形）：多输入一个输出，侧面有选择控制端，根据控制端的数据选一路输出。
  • 触发信号通过或门之后兵分两路：
    • 上一路：触发中断。先置挂起寄存器，它相当于一个中断标志位，读取它就能判断是哪个通道触发的中断。
    • 挂起寄存器和中断屏蔽寄存器共同进入一个与门，再到 NVIC。这个与门就是开关：屏蔽寄存器给 1 就允许中断，给 0 就屏蔽。
    • 下一路：触发事件。先经事件屏蔽寄存器做开关控制，最后通过脉冲发生器到其它外设——脉冲发生器就是给一个电平脉冲，用来触发其它外设的动作。
  • 框图其余部分：一条斜线写着 20，表示 20 根线、20 个通道；上面是外设接口和 APB 总线，可以通过总线访问这些寄存器。

11. 外部中断的适用场景

适合用外部中断去获取的是外部驱动的、很快的、突发的信号：

  • 外部驱动：信号由外部设备驱动，STM32 只能被动读取；
  • 突发：STM32 不知道它什么时候会来；
  • 非常快：稍微晚一点读取就会错过很多波形。

例子：

  • 旋转编码器的输出信号：可能很久都不拧，一拧就有很多脉冲——突发、外部驱动、非常快。适合用外部中断：有脉冲立即进中断处理，没脉冲时专心做其它事。
  • 红外遥控接收头的输出：收到遥控数据后输出一段波形，转瞬即逝、不会等你，需要外部中断来读取。
  • 按键：动作也是外部驱动的突发事件，但不推荐用外部中断读取按键——不好处理按键抖动和松手检测，输出波形也不是转瞬即逝的。要求不高可以在主程序循环读取；不想用主循环，可以考虑定时器中断读取，既不阻塞主程序，也能处理抖动和松手检测。

12. 旋转编码器

本节程序还用到了对射式红外传感器（之前讲过、用法简单，本集不再讲），重点介绍旋转编码器。

12.1 定义与类型

  • 旋转编码器用来测量位置、速度或旋转方向；旋转轴旋转时输出与旋转速度和方向对应的方波信号，读取方波的频率和相位信息即可得知速度和方向。
  • 类型：机械触点式、霍尔传感器式、光栅式等。

12.2 单相输出：只能测位置和速度

  • 最简单的样式用对射式红外传感器测速，配合一个光栅编码盘：编码盘转动时红外光遮挡、透过交替，模块输出高低电平交替的方波。
  • 方波的个数表示转过的角度，方波的频率表示转速；可以用外部中断捕获方波的边沿，判断位置和速度。
  • 但只有一路输出，正转、反转的波形没法区分——这种测速方法只能测位置和速度，不能测旋转方向。

12.3 两相正交输出：正反转可区分

  • 套件里的编码器是机械触点式：内部用金属触点通断，左右两部分开关触点；内侧两根细触点都与中间引脚连接，外侧触点左、右各接一个引脚；中间圆形金属片是一个按键——轴可以按下去，按下时上面两根线短路、松手断开，就是普通按键。
  • 编码盘是一系列金属触点，旋转时依次接通、断开两侧触点。关键是金属盘的位置经过设计，让两侧触点的通断产生一个 90° 的相位差。
  • 配合外部电路，两个输出会输出这样的波形：正转时左边引脚（A 相）输出方波，右侧引脚（B 相）输出相位相差 90° 的波形，B 相滞后 90°；反向旋转时 A 相还是方波，但 B 相提前 90°。这样正转和反转就能区分。
  • 相位相差 90° 的波形叫正交波形；带正交波形输出的编码器可以测方向——这就是单相输出和两相正交输出的区别。
  • 也有编码器不输出正交波形，而是一路输出方波代表转速、另一路输出高低电平代表方向，也能测方向，了解一下即可。
  • 其它形式：霍尔传感器式（附在电机后面，圆形磁铁 + 边上两个位置错开的霍尔传感器，磁铁旋转时输出正交方波）、独立编码器元件（输入轴转动时输出波形，用法看手册）。
  • 适用场合：机械触点式一般用来调节（如音响调音量），触点接触不适合电机这种高速旋转的地方；另外几种是非接触形式，可用于电机测速。本小节先用外部中断学读取编码器计次，以后学了定时器再讲编码器测速。

14. 参考手册导读

  • NVIC 是内核外设，所以要在 Cortex-M3 编程手册（STM32F10xxx/20xxx/21xxx/L1xxxx Cortex-M3 programming manual，资料里的 PM0056）里找，目录里找「内核外设—NVIC」一节。（没找到中文版。）
  • NVIC 的寄存器包括：中断使能、中断清除使能、中断设置挂起、中断清除挂起、中断活动位、中断优先级。中断优先级寄存器就是设置每个中断优先级的；直接配寄存器比较复杂，用库函数给结构体赋值就行——但要知道库函数最终落实到这些寄存器上。
  • 这些寄存器里还少了中断分组的配置：它在 SCB 里，SCB->AIRCR 的这三位就是用来配置中断分组的。
  • 再打开 STM32F10xx 参考手册（中文版），目录里找「中断和事件」一节：
    • 9.1 嵌套向量中断控制器（NVIC）：特性（68 个可屏蔽中断通道、16 个可编程优先等级、低延迟的异常和中断处理、电源管理控制、系统控制寄存器实现等）、9.1.1 系统嘀嗒（SysTick）校准值寄存器、9.1.2 中断和异常向量（中断向量表）；
    • 9.2 外部中断/事件控制器（EXTI）：框图（和 PPT 里一样）、外部中断唤醒事件的说明、功能说明，以及中断的线路映像（中断引脚选择）——这一部分实际在 AFIO 里；
    • 9.3 EXTI 寄存器描述：中断屏蔽寄存器、事件屏蔽寄存器、上升沿触发选择寄存器、下降沿触发选择寄存器、软件中断事件寄存器等，这些在中断框图里都有体现；
    • 最后是 AFIO 外设：手册对 AFIO 的描述只有一句话（复用功能引脚重映射），下面全部都是重映射的表；最后几个寄存器就是用来选择外部中断引脚的（图 20 里的 AFIO_EXTICR）。用库函数更简单——调一个函数、填两个参数。

15. 坑与易错点

  1. 相同 Pin 编号不能同时触发中断：PA0 和 PB0 不能同时用；PA1/PB1/PC1 只能选一个；多引脚就选不同编号（如 PA6+PA7、PA9+PB15、PB0+PB1）。
  2. 20 条中断线 = 16 个 GPIO_Pin + 4 个「蹭网」外设（PVD/RTC/USB/ETH），别以为 20 条都是 GPIO。
  3. EXTI5～9 共用一个中断函数、EXTI10～15 共用一个中断函数，编程时要再按标志位区分是哪个通道。
  4. 抢占优先级与响应优先级别记反：抢占高的能中断嵌套，响应高的能优先排队，两者都相同才按中断号排队。
  5. 优先级数值越小越高：0 是最高优先级。
  6. 分组后取值范围别超：如分组 1 时抢占只能 0～1、响应只能 0～7，超出就是错的。
  7. STM32 中断不是「先来后到」：任何时候都是优先级高的先响应。
  8. 事件响应不触发中断：事件只触发别的外设（ADC、DMA 等），不会让 CPU 执行中断函数。
  9. 不推荐用外部中断读按键：抖动和松手检测不好处理，主循环轮询或定时器中断更合适。
  10. 单相编码器测不了方向：只有一路输出只能测位置和速度，要测方向必须用两相正交（AB 相）。
  11. AB 相正反转的记忆：以 A 相为参考，正转 B 相滞后 90°，反转 B 相超前 90°。
  12. 现场保护不用手写：保护/还原现场由编译器自动完成；中断函数由硬件自动调用，不要在主程序里调用它。
  13. 本集没有代码：不要在本集找 EXTI 初始化、中断服务函数、清中断标志的写法，那些在 [5-2]。
