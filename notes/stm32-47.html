一句话结论

程序① 14-1 独立看门狗（复制 OLED 工程）：先写复位源判断——OLED_ShowString(1, 1, "IWDG TEST")，然后 if (RCC_GetFlagStatus(RCC_FLAG_IWDGRST) == SET)：是看门狗复位就在第 2 行闪 IWDG RST 并必须调用 RCC_ClearFlag() 清除标志；否则在第 3 行闪 RST。这是作者反复强调的坑：实测即使按下复位键，这个标志位也不会自动清 0，不清的话下次复位还会被误判成看门狗复位，现象就错了。IWDG 初始化（四步）：① IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable)（内部向键寄存器写 0x5555，解除 PR/RLR 写保护）→ ② IWDG_SetPrescaler(IWDG_Prescaler_16)（写 PR，16 分频）→ ③ IWDG_SetReload(2499) //1000ms（写 RLR）→ ④ IWDG_ReloadCounter()（向 KR 写 0xAAAA，启动前先喂一次）→ ⑤ IWDG_Enable()（向 KR 写 0xCCCC，启动看门狗）——之后主循环里不断 IWDG_ReloadCounter() 喂狗。最反直觉的一点：IWDG 不需要手动开 LSI 时钟——手册 6.2.9 看门狗时钟明确写「如果独立看门狗已经由硬件选项或软件启动，LSI 振荡器将被强制打开」，所以配置流程里「开 LSI」这一步一行代码都不用写（对照 PPT 框图从左到右：开 LSI→解保护→写 PR/RLR→启动→喂狗）。IWDG_SetReload(2499) 的完整来历：目标超时 1000ms，公式 T = 0.025ms × PR系数 × (RL+1)；表83 前两档不够——/4 最长 409.6ms、/8 最长 819.2ms，都不到 1000ms 必须剔除（PPT 上被打了红叉）；/16 及以后都可选，优先选小的预分频系数——因为可以更充分地利用 12 位计数值、减小 RL 取整带来的误差；选 16 分频 → RL = 1000 / 0.025 / 16 − 1 = 2500 − 1 = 2499（正好整除，无取整误差）→ 代码 IWDG_SetPrescaler(IWDG_Prescaler_16); IWDG_SetReload(2499); //1000ms。现象与临界实测：编译下载后只有第一次上电那一下是正常复位，之后不再复位（喂狗满足要求）；把喂狗间隔改大后就会不断显示 IWDG 复位；实测临界时间≈1000ms——间隔 1000ms 不复位、1010ms 就复位（LSI 本身有误差、代码执行也耗时），所以实际使用要留出时间余量，不要卡得这么死。完善程序：引入 Key.h / Key_Init()，主循环加 Key_GetNum()（阻塞式，按住按键不放程序就卡在这里）模拟程序卡死，再加 FEED 闪烁 + Delay_ms(200) + Delay_ms(600) → 主循环约 800 多 ms，余量约 200ms；现象：正常时不断闪 FEED，按住 PB1 不放 → 看门狗复位。程序② 14-2 窗口看门狗（复制 14-1 工程）：代码结构与 14-1 差不多，直接改——复位标志换成 RCC_FLAG_WWDGRST、显示字符串换掉。stm32f10x_wwdg.h 共 8 个函数：WWDG_DeInit、WWDG_SetPrescaler、WWDG_SetWindowValue、WWDG_EnableIT（无参数）、WWDG_SetCounter(uint8_t Counter)（喂狗）、WWDG_Enable(uint8_t Counter)（带参数）、WWDG_GetFlagStatus、WWDG_ClearFlag。WWDG_Enable 为什么必须带参数：手册 18.3 说递减计数器是自由运行的——使能瞬间计数值可能是任意值，很可能使能瞬间就产生复位，所以这个函数必须同时把计数器值写进去（＝使能 + 首次喂狗）；而 IWDG_Enable() 是无参的。配置流程（对照 WWDG 框图）：① 开启 PCLK1 时钟 —— RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE)（不像 IWDG 会自动开，WWDG 必须手动开）→ ② 配预分频与窗口值 WWDG_SetPrescaler(WWDG_Prescaler_8)、WWDG_SetWindowValue(0x40 | 21)（WWDG 没有写保护，可以直接写）→ ③ 写 CR 使能并首喂 WWDG_Enable(0x40 | 54)（使能位 + T6 + 计数器值一起写）→ ④ 主循环直接写计数器喂狗 WWDG_SetCounter(0x40 | 54)。参数完整推导（超时 50ms + 窗口 30ms）：①只能选 WDGTB＝3（8 分频）——手册表里前三档最大只有 29.12ms（0:7.28ms、1:14.56ms、2:29.12ms），WWDG 上限是 58.25ms（除非改 PCLK1，不推荐）；②50ms ÷ (1/36MHz) ÷ 4096 ÷ 8 = 54.9 → 取整 55 → T[5:0] + 1 = 55 → T[5:0] = 54；③30ms ÷ (1/36MHz) ÷ 4096 ÷ 8 = 32.9 → 取整 33 → T[5:0] − W[5:0] = 33 → W[5:0] = 54 − 33 = 21；④T6 必须置 1：用 0x40 | 54、0x40 | 21（54 未触及次高位，| 与 + 等效）→ 代码 WWDG_SetWindowValue(0x40 | 21); //30ms、WWDG_Enable(0x40 | 54); //50ms。库内部对 CR 的操作：WWDG_Enable 里是 CR |= CR_WDGA_Set（0x80，最高位置 1），WWDG_SetCounter 里是 CR = Counter & BIT_Mask（0x7F，最高位清 0）。疑问解答：喂狗时把使能位（WDGA）写 0 会不会顺手关掉看门狗？不会——看门狗开启后无法关闭，写 0 无效，所以 WWDG_SetCounter 不需要「读-改-写」。「读-改-写」三步法顺带讲到：①读寄存器到临时变量 ②用 |= / &= 只改指定位 ③写回；好处是只改某几位不影响其他位、连续改多次效率高、最终一起生效（WWDG_SetPrescaler 就是这样写的）。两个大坑：①使能后立刻又喂第二次 → 死循环复位——因为 WWDG_Enable 时已经喂过一次，若主循环第一句紧接着又喂，两次间隔 < 30ms（窗口下界）→ 立即复位；修改：先延时 40ms 再喂（Delay 各 20ms），或加「首次/非首次」标志位判断。②喂狗太快、太慢都会复位——这正是窗口看门狗与独立看门狗的核心区别。实测验证：Delay 改 30ms → 不停复位；改 31ms → 不复位（窗口下界≈30ms ✓）；超时改 49ms → 不复位（上界≈50ms ✓）。

2. 程序①：14-1 独立看门狗

2.1 配置流程（对照 PPT 框图）

从左到右：① 开启 LSI 时钟（这一步不用写代码）→ ② 解除写保护（键寄存器写 0x5555）→ ③ 写入预分频和重装值 → ④ 启动独立看门狗 → ⑤ 主循环不断喂狗。

  • 为什么开 LSI 不用写代码：手册 6.2.9 看门狗时钟（在 6.3 章里，位置比较深）明确写「如果独立看门狗已经由硬件选项或软件启动，LSI 振荡器将被强制打开」——启动 IWDG 时 LSI 会被硬件自动强制打开；
  • 对照 PPT 的 IWDG 键寄存器表：0xCCCC 启用独立看门狗、0xAAAA 喂狗（把 RLR 重新加载到计数器）、0x5555 解除 IWDG_PR/IWDG_RLR 写保护、其他值启用写保护。

2.2 库函数与宏

stm32f10x_iwdg.h 共 6 个函数：

函数 作用

复位源判断用到 rcc.h 的 RCC_GetFlagStatus，它的参数分两类：

类别 参数
时钟 Ready 类（判断时钟好了没） RCC_FLAG_HSIRDY / HSERDY / PLLRDY / LSERDY / LSIRDY（RTC 那节用过）
Reset 类（判断复位来源） RCC_FLAG_PINRST（引脚复位）/ PORRST（POR/PDR 复位）/ SFTRST（软件复位）/ IWDGRST（独立看门狗复位） / WWDGRST（窗口看门狗复位） / LPWRRST（低功耗复位）
  • 配套 RCC_ClearFlag()（无参数）清除标志。

2.3 复位源判断（含必写的坑）

OLED_Init();
OLED_ShowString(1, 1, "IWDG TEST");

if (RCC_GetFlagStatus(RCC_FLAG_IWDGRST) == SET)   /* 是看门狗复位？ */
{
    OLED_ShowString(2, 1, "IWDGRST");
    Delay_ms(500);
    OLED_ShowString(2, 1, "       ");
    Delay_ms(100);

    RCC_ClearFlag();          /* 必须清！否则下次复位仍误判 */
}
else
{
    OLED_ShowString(3, 1, "RST");
    Delay_ms(500);
    OLED_ShowString(3, 1, "   ");
    Delay_ms(100);
}
  • 坑（必须写）：RCC_ClearFlag() 一定要调用——实测即使按下复位键，这个标志位也不会自动清 0；不清的话，下一次复位仍会被判成「看门狗复位」，实验现象就错了。

2.4 初始化四步与参数推导

IWDG_WriteAccessCmd(IWDG_WriteAccess_Enable);   /* ① 解除 PR/RLR 写保护（KR=0x5555） */
IWDG_SetPrescaler(IWDG_Prescaler_16);           /* ② 16 分频 */
IWDG_SetReload(2499);                           /* ③ 重装值 → 1000ms */
IWDG_ReloadCounter();                           /* ④ 启动前先喂一次（KR=0xAAAA） */
IWDG_Enable();                                  /* ⑤ 启动（KR=0xCCCC） */
  • 写完 PR/RLR 不需要手动恢复写保护：后续写 KR 的其他值（如 0xAAAA/0xCCCC）会自动重新启用保护；
  • 参数推导（目标 1000ms）：公式 T = 0.025ms × PR系数 × (RL + 1)；
    • 表83 前两档不够 1000ms：/4 最长 409.6ms、/8 最长 819.2ms → 必须剔除（PPT 上打了红叉）；
    • /16 及以后都够，优先选小的预分频系数——能更充分利用 12 位计数值、减小 RL 取整误差；
    • 选 16 分频 → RL = 1000 / 0.025 / 16 − 1 = 2500 − 1 = 2499（正好整除，无取整误差）；
  • 最终：IWDG_SetPrescaler(IWDG_Prescaler_16); IWDG_SetReload(2499); //1000ms。

2.5 主循环喂狗、现象与临界实测

while (1)
{
    Key_GetNum();              /* 阻塞式：按住 PA1/PB1 按键不放，程序就卡在这里 */
    IWDG_ReloadCounter();      /* 喂狗 */

    OLED_ShowString(4, 1, "FEED");
    Delay_ms(200);
    OLED_ShowString(4, 1, "    ");
    Delay_ms(600);
}
  • 现象：编译下载后只有第一次上电是正常复位，之后不再复位（喂狗满足要求）；把喂狗间隔改大后 → 不断显示 IWDG 复位；
  • 临界实测：喂狗间隔 1000ms 不复位、1010ms 就复位 → 临界≈1000ms（LSI 本身有误差、代码执行也占时间）——所以实际项目要留时间余量，别卡这么死；
  • 完善版：主循环加 Key_GetNum()（阻塞式，按住按键不放就卡死）模拟程序卡死；FEED 闪烁 + 200ms + 600ms → 主循环约 800ms 多，余量约 200ms；
  • 演示效果：正常情况下 FEED 不断闪烁；按住 PB1 不放 → 程序卡在按键函数 → 不再喂狗 → 看门狗复位。

WWDG_SetWindowValue(uint8_t WindowValue) 写窗口值（W[6:0]，参数必须 < 0x80）
WWDG_EnableIT(void) 无参数，使能早期唤醒中断（EWI）
WWDG_SetCounter(uint8_t Counter) 喂狗：直接写计数器
WWDG_Enable(uint8_t Counter) 带参数：使能 + 首次喂狗
WWDG_GetFlagStatus / WWDG_ClearFlag 标志位
  • 为什么 WWDG_Enable 要带参数：手册 18.3 说递减计数器是自由运行的——使能时计数值可能是任意值，若刚使能时计数值已经低于 0x40（或高于窗口），使能瞬间就会产生复位，所以这个函数必须同时把计数器值写进去；
  • 对照手册 18.3 原文：「如果看门狗被启动（WWDG_CR 寄存器中的 WDGA 位被置 1），并且当 7 位（T[6:0]）递减计数器从 0x40 翻转到 0x3F（T6 位清零）时，则产生一个复位；如果软件在计数器值大于窗口寄存器中的数值时重新装载计数器，将产生一个复位」。

3.3 配置流程与参数推导

/* ① 必须手动开启 WWDG 的 APB1（PCLK1）时钟 */
RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE);

/* ② 配预分频与窗口值（WWDG 没有写保护，可直接写） */
WWDG_SetPrescaler(WWDG_Prescaler_8);      /* WDGTB = 3 → 8 分频 */
WWDG_SetWindowValue(0x40 | 21);           /* //30ms  窗口值 W[5:0] = 21 */

/* ③ 使能 + 首次喂狗（T6 必须置 1） */
WWDG_Enable(0x40 | 54);                   /* //50ms  T[5:0] = 54 */
  • ① 开时钟：WWDG 挂在 APB1（PCLK1）上、不像 IWDG 那样会被硬件自动开，所以必须手动 RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE)；
  • 参数推导（目标：超时 50ms、窗口 30ms）：
    1. 超时 50ms → 只能选 WDGTB＝3（8 分频）：手册表前三档最大只有 7.28 / 14.56 / 29.12ms，都不够 50ms；WDGTB＝3 最大 58.25ms——WWDG 的超时上限就是 58.25ms（除非改 PCLK1，不推荐）；
    2. 超时：50ms ÷ (1/36MHz) ÷ 4096 ÷ 8 = 54.9 → 取整 55 → 因为公式用 (T[5:0]+1)，所以 T[5:0] = 55 − 1 = 54；
    3. 窗口：30ms ÷ (1/36MHz) ÷ 4096 ÷ 8 = 32.9 → 取整 33 → T[5:0] − W[5:0] = 33 → W[5:0] = 54 − 33 = 21；
    4. T6 必须置 1：所以最终写 0x40 | 54 与 0x40 | 21（54 与 21 都没触及次高位，| 与 + 等效）。

3.4 库内部对 CR 的操作与「读-改-写」

  • WWDG_Enable：CR |= CR_WDGA_Set（0x80，最高位置 1）；
  • WWDG_SetCounter：CR = Counter & BIT_Mask（0x7F，最高位清 0）；
  • 疑问：喂狗会把使能位（WDGA）写 0，会不会顺手把看门狗关掉？不会——看门狗开启后无法关闭，写 0 无效；所以 WWDG_SetCounter 不需要「读-改-写」；
  • 「读-改-写」三步法（以 WWDG_SetPrescaler 为例）：①tmpreg = WWDG->CFR & CFR_WDGTB_Mask;（读出并清掉 WDGTB[1:0]）②tmpreg |= WWDG_Prescaler;（只改这两位）③WWDG->CFR = tmpreg;（写回）；
    • 好处：只改指定几位、不影响其他位；连续改多次效率高；最终改动同时生效。

3.5 两个大坑与实测验证

坑①：使能后立刻再喂第二次 → 死循环复位

/* ✗ 踩坑版：喂狗在循环开头，紧贴 WWDG_Enable 之后 */
WWDG_Enable(0x40 | 54);
while (1)
{
    Key_GetNum();
    WWDG_SetCounter(0x40 | 54);     /* ← 距上次「使能时喂狗」不到 30ms → 复位 */
    OLED_ShowString(4, 1, "FEED");
    Delay_ms(20);
    OLED_ShowString(4, 1, "    ");
    Delay_ms(20);
}
  • 原因：WWDG_Enable 已经喂过一次，主循环第一句紧接着又喂，两次间隔 < 窗口下界 30ms → 判为「喂太早」→ 复位，于是反复复位（看起来像死循环）；
  • 修法 A：调整顺序，先延时 40ms 再喂（把喂狗移到两次 Delay_ms(20) 之后）：
/* ✓ 修复版：喂狗在延时之后 */
while (1)
{
    Key_GetNum();

    OLED_ShowString(4, 1, "FEED");
    Delay_ms(20);
    OLED_ShowString(4, 1, "    ");
    Delay_ms(20);                    /* 累计 40ms 左右，进入允许窗口 */

    WWDG_SetCounter(0x40 | 54);      /* 现在喂狗才合法 */
}
  • 修法 B：加「首次/非首次」标志位判断，首次不喂、后续正常喂。

坑②：喂狗太快、太慢都会复位——这正是窗口看门狗与独立看门狗的核心区别（IWDG 只要不超时就行；WWDG 还要不能太早）。

坑与易错点

  1. 两个工程复制来源不同：14-1←OLED 显示屏工程；14-2←复制 14-1（不是 OLED）。
  2. IWDG 不必手动开 LSI（手册 6.2.9：启动 IWDG 后 LSI 被强制打开）；WWDG 必须手动 RCC_APB1PeriphClockCmd(RCC_APB1Periph_WWDG, ENABLE)。
  3. RCC_ClearFlag() 必须调用：按复位键标志位也不会自动清 0，不清会一直误判成看门狗复位。
  4. IWDG 参数推导：表83 前两档（409.6/819.2ms）不够 1000ms 必须剔除；优先小预分频减小 RL 取整误差；选 /16 → RL = 1000/0.025/16 − 1 = 2499（整除无误差）。
  5. 实测 IWDG 临界≈1000ms（1000ms 不复位、1010ms 复位）——项目里要留余量。
  6. WWDG_Enable 带参数＝使能 + 首次喂狗：计数器自由运行，使能瞬间值任意，不喂就立即复位；IWDG_Enable() 无参。
  7. WWDG 参数推导写全：超时 50ms → 只能 WDGTB=3（8 分频）（前 3 档最大 29.12ms）→ 50/(1/36M)/4096/8 = 54.9 → 55 → T[5:0]=54；窗口 30ms → 30/… = 32.9 → 33 → W = 54−33 = 21。
  8. T6 必须置 1：0x40 | 54、0x40 | 21（| 与 + 在本例等效，但用 | 更稳）。
  9. 坑① 使能后立刻再喂 → 死循环复位（间隔 < 30ms 下界）；先延时 40ms 再喂或加首次标志位。
  10. 坑② 喂狗太快、太慢都复位——WWDG 与 IWDG 的核心区别。
  11. WWDG_SetCounter 把 CR 最高位写 0，但关不掉看门狗 → 不需要「读-改-写」；WWDG_Enable 用 CR |= 0x80，SetCounter 用 CR = v & 0x7F。
  12. 中间态帧别当最终代码：f_00130（字符串仍是 IWDG TEST）、f_00060（if/else 空壳）、f_00180（参数未填、编译报错）都是过程帧。
  13. 复位源判断的两个参数：RCC_FLAG_IWDGRST（IWDG）/ RCC_FLAG_WWDGRST（WWDG），别写混。
  14. WWDG_SetWindowValue 参数必须 < 0x80（库注释明确）。
