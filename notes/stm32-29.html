[9-5] 串口收发HEX数据包与文本数据包 — 学习笔记

一句话结论

HEX 包在中断里用 3 状态机收：0xFF 包头 → 4 字节载荷 → 0xFE 包尾。文本包把缓存换成 char Serial_RxPacket[100]，用 @ 包头、\r\n 包尾，靠 strcmp 判指令。状态变量必须 static，分支必须 else if。

本集定位

  • 模块 9 的代码课（数据包实战）：程序一 9-3 串口收发HEX数据包（复制 P27 的 9-2 改）、程序二 9-4 串口收发文本数据包（复制 9-3 改）。
  • 流程：00:00 看接线图 → 写 Serial_SendPacket + 中断状态机 → 看现象 → 17:30 复制改文本包 → strcmp + LED → 最后讲两个坑。
  • 本集不涉及校验和/CRC、长度字段、DMA 串口收发；片尾 26:20「本小节内容到这里就结束了」，没有下集预告。
  • 协议格式沿用 P28，理论见 notes/stm32-28-USART串口数据包.md。

1. 接线与工程准备

  • 串口模块接线同前：跳线帽 VCC-3V3、RXD→PA9、TXD→PA10、GND 共地。
  • 程序①在 PB1 接按键控制发送；程序②在 PA1 接 LED 指示（长脚接正极、短脚接 PA1）。
  • 复制 9-2 工程，改名 9-3 串口收发HEX数据包；先编译一下（后面写代码时提示框更好用）。

图 1：接线图 9-4 串口收发文本数据包——串口模块接 PA9/PA10、STM32 最小系统板、OLED，以及接在 PA1 的红色 LED

2. 程序一：HEX 数据包收发

2.1 定义缓存数组、清理旧代码

#include "stm32f10x.h"
#include <stdio.h>
#include <stdarg.h>

uint8_t Serial_TxPacket[4];   /* 发送缓存：4 字节载荷 */
uint8_t Serial_RxPacket[4];   /* 接收缓存：4 字节载荷 */
uint8_t Serial_RxFlag;        /* 收到一包的标志（沿用 9-2） */
  • 两个缓存 uint8_t Serial_TxPacket[4];、uint8_t Serial_RxPacket[4];，个数都是 4（对应 P28 的固定 4 字节载荷）。
  • Serial_RxFlag 沿用：收到一个数据包就置位。初始化代码不用改，P27 的 Serial_Init 直接可用。
  • 删掉 Serial_GetRxData（数据不再是一个字节，改由数组承载），中断函数里的旧内容也删掉，重写成状态机。

图 2：Serial.c 开头——#include "stm32f10x.h"、<stdio.h>、<stdarg.h>，正在输入 uint8_t Serial_TxPack（4 个元素），下方已有 uint8_t Serial_RxFlag;

2.2 Serial_SendPacket：拼包头包尾

void Serial_SendPacket(void)
{
    Serial_SendByte(0xFF);                 /* 包头 */
    Serial_SendArray(Serial_TxPacket, 4);  /* 4 字节载荷 */
    Serial_SendByte(0xFE);                 /* 包尾 */
}
  • void Serial_SendPacket(void) 就三行：Serial_SendByte(0xFF); 发包头 → Serial_SendArray(Serial_TxPacket, 4); 发 4 字节载荷 → Serial_SendByte(0xFE); 发包尾。
  • 速记：Serial_SendPacket() = Serial_SendByte(0xFF) + Serial_SendArray(Serial_TxPacket, 4) + Serial_SendByte(0xFE)。
  • 头文件里把 Serial_TxPacket[4]/Serial_RxPacket[4] 直接 extern 声明（模块里有数组要外部调用就这么写；也可用 Set/Get 函数封装，但要传指针，比较麻烦），同时声明 Serial_SendPacket、Serial_GetRxFlag，删掉 Serial_GetRxData。

图 3：Serial.c 里的 void Serial_SendPacket(void)——三行发送（Serial_SendByte(0xFE); 高亮），下方是 uint8_t Serial_GetRxFlag(void) 的开头

2.3 中断里的接收状态机

void USART1_IRQHandler(void)
{
    static uint8_t RxState = 0;    /* 状态变量：0 等包头、1 收数据、2 等包尾 */
    static uint8_t pRxPacket = 0;  /* 表示当前收到第几个数据，最初为 0 */

    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)
    {
        uint8_t RxData = USART_ReceiveData(USART1);

        if (RxState == 0)                       /* 状态 0：等待包头 */
        {
            if (RxData == 0xFF)
            {
                RxState = 1;
            }
        }
        else if (RxState == 1)                  /* 状态 1：接收数据 */
        {
            Serial_RxPacket[pRxPacket] = RxData;
            pRxPacket ++;
            if (pRxPacket >= 4)
            {
                RxState = 2;
            }
        }
        else if (RxState == 2)                  /* 状态 2：等待包尾 */
        {
            if (RxData == 0xFE)
            {
                RxState = 0;
                pRxPacket = 0;                  /* 清零，为下次接收做准备 */
                Serial_RxFlag = 1;
            }
        }

        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}
  • 中断函数是 USART1_IRQHandler，三分支写成 if (RxState == 0) … else if (RxState == 1) … else if (RxState == 2)。
  • 状态变量必须 static：static uint8_t RxState = 0; 只初始化一次、函数退出后仍有效、作用域仅本函数，相当于全局变量，用来当 P28 图里的 S。
  • 同时 static uint8_t pRxPacket = 0; 记收到第几个，每收一个 ++。
  • 各状态的动作：S=0 判 RxData == 0xFF；S=1 执行 Serial_RxPacket[pRxPacket] = RxData; pRxPacket ++;，满 4 个置 RxState = 2；S=2 判 RxData == 0xFE，是就 RxState = 0; pRxPacket = 0; Serial_RxFlag = 1;。
  • 分支必须用 else if（或 switch-case）：写成并列 if 会在状态转移后立刻命中下一个条件，一次中断连跑两个状态。S=1 分支就用 if (RxState == 1) 判。
  • 进入中断先 uint8_t RxData = USART_ReceiveData(USART1);，末尾 USART_ClearITPendingBit(USART1, USART_IT_RXNE) 清挂起位。
  • S=2 收到不是 0xFE 就不动、继续等包尾——这样即使载荷里有 FF/FE 也不会错位。

图 4：Serial_GetRxFlag 尾部与中断骨架——void USART1_IRQHandler(void) 开头写了 static uint8_t RxState = 0;（高亮），if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET) 里暂时只有 USART_ClearITPendingBit(...)

图 5：中断里 S=0 与 S=1 开头——static uint8_t pRxPacket = 0;（高亮）、uint8_t RxData = USART_ReceiveData(USART1);，而后 if (RxState == 0) { if (RxData == 0xFF) { RxState = 1; } } else if (RxState == 1) {

图 6：S=1 与 S=2 完整代码——pRxPacket ++; 与 if (pRxPacket >= 4) { RxState = 2; }；S=2 里判断 0xFE 则 RxState 归 0、Serial_RxFlag 置 1（高亮）

2.4 先测发送，再测接收

  • 发送：初始化后把 Serial_TxPacket 填 0x01 0x02 0x03 0x04、调 Serial_SendPacket()，HEX 模式收到 FF 01 02 03 04 FE——就是 SendArray 加了包头包尾。
  • 接收：串口助手发 FF 11 22 33 44 FE → OLED 显示 11 22 33 44；发 FF 66 88 AB CD FE → 显示 66 88 AB CD。
  • 特殊：发 FE FF 88 FE（载荷里有 FF/FE）也不受影响，因为收载荷时不做包头包尾判断。

2.5 主函数：PB1 按键触发发送

#include "stm32f10x.h"
#include "Delay.h"
#include "OLED.h"
#include "Serial.h"
#include "Key.h"

uint8_t KeyNum;

int main(void)
{
    OLED_Init();
    Key_Init();
    Serial_Init();

    OLED_ShowString(1, 1, "TxPacket");
    OLED_ShowString(3, 1, "RxPacket");

    Serial_TxPacket[0] = 0x01;
    Serial_TxPacket[1] = 0x02;
    Serial_TxPacket[2] = 0x03;
    Serial_TxPacket[3] = 0x04;

    while (1)
    {
        KeyNum = Key_GetNum();
        if (KeyNum == 1)
        {
            Serial_TxPacket[0] ++;
            Serial_TxPacket[1] ++;
            Serial_TxPacket[2] ++;
            Serial_TxPacket[3] ++;
            Serial_SendPacket();
        }

        if (Serial_GetRxFlag() == 1)
        {
            OLED_ShowHexNum(2, 1, Serial_RxPacket[0], 2);
            OLED_ShowHexNum(2, 4, Serial_RxPacket[1], 2);
            OLED_ShowHexNum(2, 7, Serial_RxPacket[2], 2);
            OLED_ShowHexNum(2, 10, Serial_RxPacket[3], 2);
        }
    }
}
  • main 里 OLED_Init(); Key_Init(); Serial_Init();，标题 OLED_ShowString(1, 1, "TxPacket") 与 OLED_ShowString(3, 1, "RxPacket");。
  • 发送：按 PB1（Key_GetNum() == 1）先把四个字节各加一、再调 Serial_SendPacket()，所以每包数据都在变。
  • 接收：if (Serial_GetRxFlag() == 1) 后把 4 个字节显示在第 2 行；标题第一行 TxPacket、第三行 RxPacket。
  • 现象：每次按键收到 FF 02 03 04 05 FE 这类递增包（形如 FF xx xx xx xx FE）；发 FF 05 06 07 08 FE → OLED 显示 05 06 07 08。
  • main 里用 Serial_GetRxFlag() 判断有没有收到包。

图 7：main 中间态——OLED_Init(); Key_Init(); Serial_Init();、正在输入 OLED_ShowString(1, …) 与 OLED_ShowString(1, 1, "TxPacket")、发送缓存赋 0x01～0x04、调用 Serial_SendPacket()

图 8：main 最终版——OLED_ShowString(3, 1, "RxPacket"); 即 (3, 1, "RxPacket")、发送缓存初值 0x01～0x04，while 里按 Key_GetNum 判键 1 后发送，再用 Serial_GetRxFlag 判断收包

图 9：程序一现象——串口助手收到多包 FF 02 03 04 05 FE、FF 05 06 07 08 FE…，发送区手写 FF 05 06 07 08 FE；OLED 显示 TxPacket/RxPacket，面包板是 PB1 蓝色按键

2.6 坑①：接收缓存的读写冲突（只讲未改代码）

  • 坑①：Serial_RxPacket 在中断里写、主循环里读：主循环读得慢，中断已把它写成下一包的前半部分，于是显示「一半上一包、一半下一包」。
  • 解决思路：处理完一包再收下一包（加标志位做闸门，或先把数据转存到另一个缓冲区）。
  • 数据本身连续不断发（陀螺仪 XYZ、温湿度）时错位也无所谓，按实际需求决定。
  • 本集对坑①只讲思路、没有落地代码。

3. 程序二：文本数据包收发

3.1 复制工程、改接收缓存

  • 复制 9-3 工程，改名 9-4 串口收发文本数据包；删掉按键相关和发送部分（文本包发送主函数里 Serial_SendString/printf 就行）。
  • 接收缓存改成 char Serial_RxPacket[100];——字符数组，长度 100 防溢出（单条指令不超过 100 字符，也可用宏定义）。
  • 格式同 P28：@ 包头 + 指令字符串 + \r\n 包尾。

图 10：程序二 Serial.c 开头——uint8_t Serial_TxPacket（4）;、uint8_t Serial_RxPacket（4）;、uint8_t Serial_RxFlag;，第 6 行改成 char Serial_RxPacket（100）;，下方 Serial_Init 不动

3.2 文本包状态机

void USART1_IRQHandler(void)
{
    static uint8_t RxState = 0;
    static uint8_t pRxPacket = 0;

    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)
    {
        uint8_t RxData = USART_ReceiveData(USART1);

        if (RxState == 0)                       /* S=0：等待包头 '@' */
        {
            if (RxData == '@')
            {
                RxState = 1;
                pRxPacket = 0;
            }
        }
        else if (RxState == 1)                  /* S=1：接收数据，兼等包尾 '\r' */
        {
            if (RxData == '\r')
            {
                RxState = 2;
            }
            else
            {
                Serial_RxPacket[pRxPacket] = RxData;
                pRxPacket ++;
            }
        }
        else if (RxState == 2)                  /* S=2：等待包尾 '\n' */
        {
            if (RxData == '\n')
            {
                RxState = 0;
                Serial_RxPacket[pRxPacket] = '\0';   /* 补字符串结束符 */
                Serial_RxFlag = 1;
            }
        }

        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}
  • S=0：判断是不是 '@'，是就执行 if (RxData == '@') { RxState = 1; pRxPacket = 0; }，即 RxState = 1; pRxPacket = 0;。
  • S=1：可变包长，收数据的同时要监视包尾——先判 '\r'，是就不存进载荷、直接跳 S=2；不是就存进 Serial_RxPacket[pRxPacket] 并 pRxPacket ++。
  • 整段判断：if (RxData == '\r') { RxState = 2; } else { Serial_RxPacket[pRxPacket] = RxData; pRxPacket ++; }。
  • S=2：判 '\n'，是就 RxState = 0、Serial_RxFlag = 1，并补 '\0'。这两步代码里连写成 RxState = 0; Serial_RxFlag = 1;。
  • 补 '\0' 是因为后面要用 strcmp 等字符串函数，必须以 \0 结束。
  • 这里 S=1 不能再留 if (pRxPacket >= 4) { RxState = 2; }——那是 HEX 版残留，文本包可变长、靠包尾结束，要用 else 存数据。
  • 中断末尾同样要 USART_ClearITPendingBit(USART1, USART_IT_RXNE); 清挂起位。

图 11：文本状态机中间态——S=0 判断 @ 后 RxState = 1、pRxPacket = 0；S=1 仍留着 HEX 版残留（else if (RxState == 1) 高亮）

图 12：S=1 改成判断回车符 \r：是则转 S=2、不存载荷；否则 else 里存数据并自增；S=2 判断 \n，是则归 0、Serial_RxFlag 置 1（高亮）

3.3 main：擦除显示 + strcmp 判指令

#include "stm32f10x.h"
#include "Delay.h"
#include "OLED.h"
#include "Serial.h"
#include "LED.h"
#include <string.h>

int main(void)
{
    OLED_Init();
    LED_Init();
    Serial_Init();

    OLED_ShowString(1, 1, "TxPacket");
    OLED_ShowString(3, 1, "RxPacket");

    while (1)
    {
        if (Serial_GetRxFlag() == 1)
        {
            /* 先用 16 个空格擦干净第 4 行，再显示新内容 */
            OLED_ShowString(4, 1, "                ");
            OLED_ShowString(4, 1, Serial_RxPacket);

            if (strcmp(Serial_RxPacket, "LED_ON") == 0)
            {
                LED1_ON();
                Serial_SendString("LED_ON_OK\r\n");
            }
            else if (strcmp(Serial_RxPacket, "LED_OFF") == 0)
            {
                LED1_OFF();
                Serial_SendString("LED_OFF_OK\r\n");
            }
            else
            {
                Serial_SendString("ERROR_COMMAND\r\n");
            }
        }
    }
}
  • main 里 OLED_Init(); LED_Init(); Serial_Init();，两行标题照旧。
  • 先擦除：上一包可能比新包长，直接用 OLED_ShowString(4, 1, ...) 重写会残留旧字符，所以先用 16 个空格 " " 填满第 4 行，再 OLED_ShowString(4, 1, Serial_RxPacket);。
  • strcmp：要 #include <string.h>，strcmp(a, b) == 0 表示两个字符串完全相等（相等返回 0），所以写 strcmp(Serial_RxPacket, "LED_ON") == 0。
  • LED_ON → LED1_ON() + 回传 LED_ON_OK\r\n；LED_OFF → LED1_OFF() + LED_OFF_OK\r\n；其它 → ERROR_COMMAND\r\n。
  • 回传带 \r\n 是为了在串口助手一行一行显示。

图 13：文本版 main——OLED_Init(); LED_Init(); Serial_Init();、两行标题、判断收包标志后用 16 个空格擦行，收尾 OLED_ShowString(4, 1, Serial_RxPacket); } }

图 14：正在输入 strcmp(Serial_RxPacket, "LED_ON")（第 24 行高亮），上方是擦除行与显示行；相等时返回 0

3.4 现象与坑②

  • 现象：文本模式发 @LED_ON → LED 亮、收到 LED_ON_OK；发 @LED_OFF → 灯灭、收到 LED_OFF_OK；发 @adfasda → 回传 ERROR_COMMAND。
  • OLED 显示为 TxPacket ERROR_COMMAND 与 RxPacket adfasda。
  • 坑②：连续发包时 Serial_RxFlag 还没被主循环读走，中断又开始收下一包，把 Serial_RxPacket 覆盖了。
  • 落地修改三步：① S=0 的包头判断加闸门 if (RxData == '@' && Serial_RxFlag == 0)（'@' 就是 0x40）；② Serial_GetRxFlag 取消「读后自动清零」，改成只判断；③ 主循环写 if (Serial_GetRxFlag() == 1) { Serial_RxFlag = 0; …处理…}。
  • 这样写数据（中断）与读数据（主循环）严格分开、不会同时进行，避免错位。
  • 代价：发包频率不能太快，否则会丢包；进一步方案是再定义一个指令缓存区，把收到的字符串放进去排队。

图 15：程序二现象——串口助手接收区依次 LED_ON_OK、LED_OFF_OK、ERROR_COMMAND，发送区 @adfasda；OLED 显示 TxPacket ERROR_COMMAND 与 RxPacket adfasda

图 16：坑②的落地修改——中断里 static uint8_t RxState = 0; static uint8_t pRxPacket = 0;，S=0 判断变成 if (RxData == '@' && Serial_RxFlag == 0)（高亮）

4. 两个程序差异对照

项 程序一 9-3 串口收发HEX数据包 程序二 9-4 串口收发文本数据包
工程来源 复制 9-2（P27） 复制 9-3
额外硬件 PB1 按键 PA1 LED
接收缓存 uint8_t Serial_RxPacket[4]; char Serial_RxPacket[100];
发送 Serial_SendPacket()（0xFF + SendArray 4 + 0xFE） 主函数用 Serial_SendString/printf（回传 xxx_OK\r\n）
包格式 0xFF + 固定 4 字节 + 0xFE @ + 可变长字符串 + \r\n

结束条件 pRxPacket >= 4 再等 0xFE 靠 \r\n 包尾（无长度计数）

坑与易错点

  1. 状态机必须用 else if 或 switch-case：并列 if 会在状态转移后立刻命中下一个条件。
  2. 状态变量必须 static：否则每次进中断都重新初始化为 0，永远停在 S=0。
  3. pRxPacket 要在收新包前清零：HEX 版在 S=2 收尾清，文本版在 S=0 收到 @ 时清。
  4. HEX 收数据要先存数组再计数：收够 4 个才转 S=2，判断用 >= 4 更稳妥。
  5. 收载荷时不要判包头包尾：只在收包头/包尾时判，才能容忍载荷含 FF/FE。
  6. 文本包 S=1 不能残留 if (pRxPacket >= 4)：那是 HEX 版逻辑，文本包靠 \r/\n 结束。
  7. \r 不能存进载荷：它是包尾的一部分，收到就转状态、不写入数组。
  8. 字符串必须以 '\0' 结尾：文本包收完要手动补，否则 strcmp 会越界读。
  9. strcmp 相等返回 0：要写 == 0，别写成 == 1。
  10. 回传要带 \r\n：否则串口助手不换行，多包会粘在一行。
  11. OLED 重写前要擦行：上一包更长会残留旧字符，先写 16 个空格。
  12. 坑①与坑②不是一回事：坑①只讲思路（处理完再收）；坑②给了代码（闸门 + 手动清标志）。
  13. 坑②取消自动清零后：主循环必须手动清 Serial_RxFlag，否则闸门永远为 1。
  14. 本集协议没有校验和/CRC/长度字段：靠包头包尾 + 固定长度界定，别自行加。
  15. 发送太快会丢包：坑②方案的代价，需要时用指令队列排队。
