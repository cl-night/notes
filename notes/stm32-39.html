[11-4] SPI通信外设 — 学习笔记

一句话结论

软件 SPI 手动翻转电平，方便灵活；硬件 SPI 用 STM32 内部外设自动生成时钟并收发数据，性能高。SPI1 挂 APB2（72M）、SPI2 挂 APB1（36M），SCK ＝ fPCLK/分频，分频只能取 2/4/8/16/32/64/128/256。

本集定位

  • 模块 11 的理论课（下）：PPT 讲外设简介、框图、两种传输流程、软硬件波形对比，再做示波器实测，最后精读手册第 23 章。
  • 全程无代码：Keil 工程没打开，也没有 SPI_InitTypeDef 成员表，只口述了 SPI_Cmd 和「初始化结构体主要就是用来填充这些位」。
  • 结尾 45:17「那到这里，本小节课程，也就结束了」，无下节预告；库函数写法在 [11-5]/[11-6]。
  • 硬件 SPI 知识点多，是因为硬件电路一旦设计出来功能就基本定死，只能把各种场景都做进去；学习抓主线即可：主机、全双工、8 位数据帧、高位先行。

1. SPI 外设简介

1.1 功能列表

  • STM32 内部集成硬件 SPI 收发电路，由硬件自动执行时钟生成、数据收发，减轻 CPU 负担。
  • 可配置 8 位/16 位数据帧、高位先行/低位先行。
  • 时钟频率＝fPCLK/(2, 4, 8, 16, 32, 64, 128, 256)。
  • 支持多主机模型、主或从操作；可精简为半双工/单工；支持 DMA；兼容 I2S。
  • STM32F103C8T6 的硬件 SPI 资源只有 SPI1、SPI2。
  • 功能这么多，是因为硬件电路不像软件那么灵活，设计时要覆盖最全的应用场景，结果很多功能实际很少用到。

1.2 数据帧与位序

  • 最常用 8 位数据帧：一般以字节为单位，一个字节就是 8 位；16 位数据帧用得很少。
  • SPI 与 I2C 都是高位先行，串口才是低位先行。
  • 发 0x34（0011 0100）：波形上数据由高位到低位依次出现。
  • 串口的 0x55＝0101 0101，波形从前到后是 10101010，看数据要从右往左才是 0101 0101。
  • 图213/图218 的示例波形画的都是低位先行（b0 在前），而实际 SPI 高位先行用得更多，理解时序时注意区分。

1.3 时钟频率与总线

  • SCK 频率 ＝ fPCLK/分频系数，一个 SCK 时钟交换一位，所以 SCK 频率体现传输速度。
  • 分频系数只能是 2/4/8/16/32/64/128/256，频率数值不能任意指定。
  • PCLK 是外设时钟：SPI1 挂 APB2，PCLK＝72MHz；SPI2 等挂 APB1，PCLK＝36MHz。
  • 所以 SPI1 的最高 SCK 频率比 SPI2 大，开时钟与算 SCK 频率时都要注意。
  • 最低频率是 PCLK 的 256 分频；I2C 最大只有 400kHz，SPI 的速度上限高得多。

1.4 其他功能（了解即可）

  • 多主机模型：SPI 支持，但实现复杂、用得少，本课程只学 SPI 做主机。
  • 半双工：两根数据线合成一根分时收发，节省一根通信线；单工：只保留发送线或只保留接收线。
  • DMA：让 DMA 自动搬运数据，比手动操作高效，少量数据可以不用。
  • I2S：数字音频传输专用协议（音乐数据按约定格式送 DAC 再输出到扬声器），和 I2C 区别很大、别搞混；SPI 与 I2S 电路可以共用，所以手册一半内容在讲 I2S，本课程用不到。

2. SPI 框图（图209）

2.1 整体分两块

  • 左上：数据寄存器 + 移位寄存器的配合，和串口、I2C 的设计思路一样，目的是实现连续的数据流。
  • 右下：波特率发生器、通信电路、主控制电路与 CR1/CR2/SR，具体查手册的寄存器描述。

2.2 数据通路：DR / TDR / RDR / 移位寄存器

  • 数据寄存器 DR 就是 SPI_DR：下面的发送缓冲区是发送数据寄存器 TDR，上面的接收缓冲区是接收数据寄存器 RDR，两者占用同一个地址。
  • 写入 DR 时数据写入 TDR；读取 DR 时数据从 RDR 读出。
  • 移位寄存器受 LSBFIRST 控制位控制：图上画的是低位先行（右移，从右边移入、左边移出）；LSBFIRST 给 0 就改为左移、高位先出。
  • 发送流程：写 DR → 数据进 TDR → 移位寄存器空时 TDR 的数据自动转入并开始发送，同时置 TXE=1；检测到 TXE=1 就立刻写下一个字节，数据不间断跟进。
  • 接收流程：移入的数据整体转入 RDR，同时置 RXNE=1；必须尽快读出，否则下一个数据会把它覆盖。
  • BSY 在有数据传输时由硬件置 1，传输结束由硬件清除。
  • 三种通信的收发缓冲设计对比：SPI 全双工 → 收发分离（TDR/RDR 各一个）；I2C 收发不会同时进行 → 数据寄存器可以共用；串口收发分离 → 也是两套缓冲。设计理念相同、细节不同。

2.3 MOSI/MISO 交叉电路

  • 作用：主从模式的引脚变换。
  • 做主机时 MOSI 是主机输出、MISO 是主机输入，不走交叉。
  • 做从机时 MOSI 变 SI（从机输入）、MISO 变 SO（从机输出），都要走交叉支路；本课程只用主模式。

2.4 波特率发生器与寄存器

  • 波特率发生器输入 PCLK（72M 或 36M），由 CR1 的 BR[2:0]（BR0、BR1、BR2）选分频后输出到 SCK 引脚，三位可做 2～256 的分频。
  • CR1 关键位：BR（波特率）、MSTR（主/从）、CPOL/CPHA（4 种模式）、LSBFIRST、SPE（使能，SPI_Cmd 配的就是这一位）。
  • CR1 另有 BIDIMODE/BIDIOE/CRCEN/CRCNext/RXONLY/SSM/SSI 等（半双工/单工、CRC、NSS 相关，用不到）。
  • SR：TXE（发送寄存器空）、RXNE（接收寄存器非空）最常关注，另有 BSY/OVR/MODF/CRCERR。
  • CR2：中断使能（TXEIE/RXNEIE/ERRIE）、SSOE、DMA 使能等。

2.5 NSS 引脚与多主机仲裁

  • 硬件 NSS 模式（SSM=0）：SSOE=1 时 NSS 作输出，主机结束把 SSOE 清 0、NSS 变回输入；外部输入低电平说明总线上已有别的主机，本机进不了主模式。
  • 软件 NSS 模式（SSM=1）：内部 NSS 的电平由 SSI 位决定。
  • 多主机仲裁的「揪小辫子」比喻：3 个 STM32 的 NSS 连在一起，谁先跳出来做主机就把公共 NSS 拉低，别人想当主机会发现小辫子被揪住，只能等它结束；主机结束后松开，下一个才能当主机。
  • 局限：只能保证同一时刻只有一个主机，要指定某个从机通信还得再加寻址机制，实现比较复杂。
  • 本课程结论：不用硬件 NSS，SS 用普通 GPIO 模拟，因为硬件 NSS 完成不了多从机选择。

4. 两种传输流程

  • 视频顺序是先图213（连续，25:43–32:25）、再图218（非连续，33:47 起），图218 的图在 25:29 先露了一下；本节为便于理解把非连续放前面讲。

4.1 图218：非连续传输

  • 标题：非连续传输发送（BIDIMODE=0 且 RXONLY=0）时 TXE/BSY 变化示意图；例子为 CPOL=1、CPHA=1（模式 3）、低位先行。
  • 四步流程（可封装成「交换一个字节」函数）：① 软件等待 TXE=1；② 软件写入发送数据至 TDR；③ 软件等待 RXNE=1；④ 软件读取 RDR 的接收数据。
  • 封装好之后与软件 SPI 的流程基本一样，可以直接把软件 SPI 改成硬件 SPI（交换第二个字节同理）。
  • 缺点：数据写入 TDR 后，字节时序结束时下一个字节还没送过来，字节之间产生间隙，拖慢整体速度。
  • 间隙的影响：SCK 频率低时影响不大；SCK 非常高时间隙占比很大（见示波器实测）。
  • 优点：容易封装、好理解、好用。

4.2 图213：主模式全双工连续传输

  • 标题：主模式、全双工（BIDIMODE=0 且 RXONLY=0）连续传输时的 TXE/RXNE/BSY 变化，同样 CPOL=1、CPHA=1（模式 3）。
  • 流程：写入 0xF1 → TDR → 移位寄存器发送；TXE=1 时立刻写下一个数据 0xF2，不等波形发完，时钟可以连续不间断产生。
  • 接收侧 RXNE=1 时要及时读 RDR（接收数据是 0xA1/A2/A3）。
  • 注意：收发操作顺序是交叉的——不是「发数据1、收数据1、发数据2、收数据2」，而是「发数据1、发数据2…之后接收数据1」，对程序设计不太友好。
  • 适用：对传输效率有非常高要求时用；否则用非连续传输。

5. 示波器实测：不同分频下非连续传输的间隙

  • 测试条件：SPI 模式 0、非连续传输、连续交换 5 个字节；CH1 是 SCK，CH2 是 SS（低电平表示选中从机）。
  • 256 分频：SCK ≈ 72M/256 ≈ 281kHz（整帧重复率 F=569.557Hz），几乎看不出字节之间的间隙。
  • 128 分频：能明显看出字节之间不严丝合缝，但比例上仍然很小，可忽略不计。
  • 64 分频：SCK 频率大概 1M 多点，频率增大、时间尺度缩小，间隙更明显。
  • 2 分频：SCK ＝ 72M/2 ＝ 36MHz，已经超过示波器采样率，每个字节的时钟看不完整，但传输与间隙仍能区分，间隙时间已是数据传输的好几倍。
  • 结论：忽略间隙算出的速率应是 256 分频的 128 倍，实测肯定达不到；2 分频「干活效率高」，但每干 1 个时间单位就要休息好几个时间单位。追求极限性能必须用连续传输或 DMA，日常用非连续传输即可。

6. 软硬件波形对比

  • 上面软件 SPI 波形、下面硬件 SPI 波形，数据变换趋势完全一致，采样得到的数据也一致。
  • 区别：硬件波形的数据线变化紧贴 SCK 边沿，软件波形有延迟（与上一集 I2C 的对比一样）。
  • I2C 是「SCL 下降沿数据移出」，SPI 是「下降沿移出、上升沿移入」，最终表现都是数据变化尽量紧贴边沿，这样数据才稳定、不容易出错。

7. 参考手册第 23 章

7.1 23.1 SPI 简介

  • SPI 接口默认工作在 SPI 方式，可以通过软件把功能从 SPI 模式切换到 I2S 模式。
  • 大容量产品和互联型产品可配置为 SPI 或 I2S；小容量和中容量产品不支持 I2S（F103C8T6 属中容量，没有 I2S）。
  • 警告：SPI3/I2S3 的部分引脚与 JTAG 共用——SPI3_NSS/I2S3_WS 与 JTDI、SPI3_SCK/I2S3_CK 与 JTDO；这些引脚不受 IO 控制器控制，复位后默认保留为 JTAG 用途，要当 SPI3 用得先关闭 JTAG 改用 SWD（详见 8.3.5 节）。

7.2 23.3 功能描述要点

  • NSS 硬件模式（SSM=0）：SSOE=1 时 NSS 作输出；外部输入低电平时不能进主模式。
  • 4 种模式（CPOL/CPHA）的图就是前面讲的那张。
  • 主模式配置步骤（手册用寄存器方式描述）：设置 CPOL、CPHA、LSBFirst、BR、SSM、SSI、MSTR 等位 → 使能 SPI（SPE）；用库函数更容易理解。
  • 裁剪为半双工/单工：全双工变成「1 条时钟 + 1 条双向数据线」（半双工）或「1 条时钟 + 1 条单向数据线」（单工），本课程只看主模式全双工。
  • 其余：连续传输发送流程、CRC 计算（数据流后跟校验码，判断传输是否出错，本课程不用）、利用 DMA 的 SPI 通信、错误标志与中断（MODF 主模式失效错误等，需要时再看）。

7.3 23.5 寄存器

  • SPI_CR1：BIDIMODE/BIDIOE/CRCEN/CRCNext/RXONLY/SSM/SSI/LSBFIRST/SPE/BR[2:0]/MSTR/CPOL/CPHA，初始化结构体主要就是用来填充这些位。
  • SPI_CR2：TXEIE/RXNEIE/ERRIE/SSOE/TXDMAEN/RXDMAEN 等中断/DMA 使能。
  • SPI_SR：标志位多，重点是 TXE 与 RXNE（另有 BSY/OVR/MODF/CRCERR）。
  • SPI_DR：写操作写到发送缓冲区 TDR，读操作返回接收缓冲区 RDR 的数据。
  • SPI_CRCPR（CRC 多项式）、SPI_RXCRCR、SPI_TXCRCR：CRC 相关，本课程不用。
  • 23.5.10 寄存器地址映象（表171）：SPI_CR1@000h、SPI_CR2@004h、SPI_SR@008h、SPI_DR@00Ch、SPI_CRCPR@010h、SPI_RXCRCR@014h、SPI_TXCRCR@018h。

坑与易错点

  1. SCK 频率不能任意指定：只能是 fPCLK/(2,4,8,16,32,64,128,256)，最低 256 分频。
  2. 总线挂载别搞混：SPI1→APB2（72M）、SPI2→APB1（36M），开时钟和算 SCK 频率都要对应。
  3. SPI 与 I2C 高位先行、串口低位先行：看低位先行的波形要从右往左还原数据。
  4. 示例波形是低位先行、模式 3（图213/图218），实际最常用高位先行、模式 0，别当成通用配置。
  5. TDR/RDR 共用 SPI_DR 地址：写 DR 是发、读 DR 是收，别以为有两个地址。
  6. TXE=1 表示发送寄存器空可以写下一个；RXNE=1 表示收到数据要及时读，读晚会被覆盖。
  7. BSY 由硬件置位/清除：关闭 SPI 前要等最后一个 RXNE=1，不能只看 TXE。
  8. 图213 是连续传输、图218 是非连续传输：视频口述顺序先 218 再 213，别写反。
  9. 连续传输的收发顺序交叉：不是「发1收1发2收2」，而是「发1发2…收1」。
  10. 非连续传输有字节间隙：SCK 越高占比越大，极限性能要用连续传输或 DMA。
  11. 硬件 NSS 做不了多从机选择：本课程用 GPIO 模拟 SS，NSS 硬件模式只用于多主机仲裁。
  12. 「揪小辫子」只是理解思路：真要指定从机通信还得加寻址机制。
  13. 简化结构图标题栏是错的（写着「I2C基本结构」），实际是 SPI 结构图。
  14. SPI3/I2S3 引脚与 JTAG 共用：要用 SPI3 得先关闭 JTAG 改用 SWD。
  15. fPCLK 与分频算出的频率只是上限：实际能跑多快还要看从机器件与接线。
