[10-5] 硬件I2C读写MPU6050 — 学习笔记

一句话结论

把 10-1 工程的 MyI2C 底层换成 STM32 内部 I2C2，只改 MPU6050_Init、WriteReg、ReadReg 三处，main 与芯片配置不动，接线仍是 PB10/PB11。

本集定位

  • 模块 10 的代码课（下）：不写新程序，只换通信底层。
  • 复制 10-1 软件I2C读写MPU6050 → 改名 10-2 硬件I2C读写MPU6050，删掉 MyI2C 模块。
  • 只改 MPU6050.c 里三处：MyI2C_Init → 硬件 I2C2 初始化；WriteReg → 指定地址写；ReadReg → 指定地址读。
  • 不改 main.c、MPU6050 的寄存器配置（6 条 WriteReg）与 MPU6050_GetData 取数——协议和时序一样，只是底层实现不同。
  • 片尾 49:37 硬件 I2C 代码部分结束，无下集预告（模块 10 结束）。

1. 接线与引脚规划

  • VCC/GND 供电，SCL→PB10、SDA→PB11，与上一集软件 I2C 的接线一模一样。
  • 软件 I2C 引脚可任意指定，所以上集特意把引脚选在 PB10/PB11。
  • 硬件 I2C 引脚固定，查引脚定义表的复用功能：I2C1 是 PB6=SCL、PB7=SDA（可重映射 PB8/PB9）；I2C2 是 PB10=SCL、PB11=SDA。
  • 本板 PB6～PB9 在右下角被 OLED 占用，不方便接线；I2C2 重映射栏里没有它，所以只能用 PB10/PB11。
  • 且 SCL 必须接 PB10、SDA 必须接 PB11，两者不能互换——私自改到别的引脚，I2C2 无法操作。
  • 画板建议：不确定用硬件还是软件 I2C 时，直接接在硬件 I2C 的引脚上，给后面留余地。

2. 复制工程、删除 MyI2C 模块

  • 复制 10-1 软件I2C读写MPU6050 → 改名 10-2 硬件I2C读写MPU6050（画面里是「- 副本」），打开工程先编译。
  • 区别只在通信底层：MyI2C.c 是用程序手动翻转引脚，有了硬件外设，MyI2C 模块整个不再需要。
  • 删模块三步（保证工程树与工程目录一致）：文件选项卡里 Close → 工程树里 Remove → 工程目录 Hardware 里删掉 MyI2C.c/.h。
  • MPU6050.c 里原来调用 MyI2C 的代码（#include "MyI2C.h"、MyI2C_Init、读写函数）先注释掉便于对照；基于通信层的配置与取数不动。

3. 硬件 I2C 初始化

四步与之前外设的套路一样：

  1. 开时钟：I2C1/I2C2 都是 APB1 外设 → RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C2, ENABLE)；GPIO 是 APB2 → RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE)。
  2. GPIO 初始化：GPIO_Mode_AF_OD（复用开漏）、GPIO_Pin_10 | GPIO_Pin_11、GPIO_Speed_50MHz、GPIO_Init(GPIOB, &GPIO_InitStructure)。
  3. 结构体配置 I2C2：I2C_InitTypeDef I2C_InitStructure; 引出六个成员，再 I2C_Init(I2C2, &I2C_InitStructure);。
  4. 使能外设：I2C_Cmd(I2C2, ENABLE)，即代码里的 I2C_Cmd(I2C2, ENABLE);。
  • 为什么是「复用开漏」：开漏是 I2C 协议的要求；复用是把 GPIO 控制权交给硬件外设（软件 I2C 用通用开漏 Out_OD，硬件 I2C 用 AF_OD）。
void MPU6050_Init(void)
{
    /* 硬件 I2C2 初始化（替换原 MyI2C_Init） */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C2, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_OD;      /* 复用开漏 */
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    I2C_InitTypeDef I2C_InitStructure;
    I2C_InitStructure.I2C_Mode = I2C_Mode_I2C;
    I2C_InitStructure.I2C_ClockSpeed = 50000;
    I2C_InitStructure.I2C_DutyCycle = I2C_DutyCycle_2;
    I2C_InitStructure.I2C_Ack = I2C_Ack_Enable;
    I2C_InitStructure.I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit;
    I2C_InitStructure.I2C_OwnAddress1 = 0x00;
    I2C_Init(I2C2, &I2C_InitStructure);

    I2C_Cmd(I2C2, ENABLE);
    ...
}

说明：I2C_ClockSpeed 与 I2C_DutyCycle 两行在画面里被代码提示框挡住，按口述 19:00–22:30 与示波器实验整理为 ClockSpeed = 50000、DutyCycle = 2:1。

3.1 I2C_Mode 与 I2C_ClockSpeed

  • I2C_Mode 三个可选值：I2C_Mode_I2C、I2C_Mode_SMBusDevice、I2C_Mode_SMBusHost，本课程用 I2C，代码写 I2C_InitStructure.I2C_Mode = I2C_Mode_I2C;。
  • I2C_ClockSpeed 配 SCL 时钟频率，越大传得越快：0～100kHz 是标准速度，100k～400kHz 是快速，最大只能 400kHz。
  • 本集给 50000（50kHz），MPU6050 支持到 400kHz，还可以加大。
  • I2C_DutyCycle 只对 >100kHz 的快速模式生效（标准速度固定 1:1），可选 I2C_DutyCycle_16_9（低:高＝16:9）与 I2C_DutyCycle_2（2:1），本集选 2:1。
  • 六成员一次列全：I2C_Mode = I2C_Mode_I2C、I2C_ClockSpeed、I2C_DutyCycle、I2C_Ack = ENABLE、I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit、I2C_OwnAddress1 = 0x00。

3.2 为什么快速模式要改占空比（示波器实验）

  • 50kHz：标准速度，占空比 1:1 的 50% 方波，波形完美；数据位在 SCL 高电平期间被读，能读出 11010000。
  • 100kHz：仍是标准速度、仍 1:1，但下降沿非常快、上升沿缓慢——开漏输出低是强下拉，输出高只是释放，靠上拉电阻把线拉回。
  • 101kHz：刚进快速模式，占空比自动变成约 2:1（低电平变宽）；因为低电平写数据、高电平读数据，低电平要多留时间等上升沿完成翻转。
  • 200kHz：时间轴更窄，上升沿的「弯弯」更明显；400kHz（快速上限）：SCL 没完全回弹到高就被拉低，波形变成三角形，这个「弯弯」限制了总线最大速率。
  • 结论：标准速度接近 1:1、快速接近 2:1；本程序是标准速度，占空比参数其实用不上。

4. 库函数与状态监控

打开 stm32f10x_i2c.h，本集用到的函数：

函数 作用
I2C_DeInit / I2C_Init / I2C_StructInit / I2C_Cmd 老套路：复位/初始化/结构体默认值/使能
I2C_GenerateSTART 置 CR1 的 START 位，产生起始条件
I2C_GenerateSTOP 置 CR1 的 STOP 位，产生终止条件
I2C_AcknowledgeConfig 配置 CR1 的 ACK 位：1 应答、0 非应答
I2C_SendData 写 DR（发送数据）
I2C_ReceiveData 读 DR（接收数据）
I2C_Send7bitAddress 发送 7 位地址，内部自动按方向设置最低位读写位
I2C_CheckEvent 基本状态监控：把 SR1/SR2 与给定事件比较（本集用这个，需掌握）
I2C_GetLastEvent 高级状态监控：把 SR1+SR2 拼成 16 位返回（了解即可）
I2C_GetFlagStatus 基于标志位的状态监控（老朋友，了解）
  • 应答位不用手动处理：发数据时函数内部自带接收应答，收数据时也自带发送应答；应答错误时硬件用标志位/中断提示。
  • I2C_Send7bitAddress 的函数头是 void I2C_Send7bitAddress(I2C_TypeDef* I2Cx, uint8_t Address, uint8_t I2C_Direction)，内部逻辑：方向为发送就把地址最低位清 0，为接收就置 1（源码见图 4），即 if (I2C_Direction != I2C_Direction_Transmitter) { /* Set the address bit0 for read */ Address |= OAR1_ADD0_Set; } else { /* Reset the address bit0 for write */ Address &= OAR1_ADD0_Reset; }。
  • 嫌它多此一举，也可以用 I2C_SendData 直接发地址。
  • 三种状态监控选 I2C_CheckEvent，正好对应上集 PPT 的 EV 事件流程图；返回 SUCCESS 表示事件已发生、ERROR 表示未发生。

5. 写寄存器（硬件版 MPU6050_WriteReg）

void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
    I2C_GenerateSTART(I2C2, ENABLE);                                    /* 起始条件 */

    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT) != SUCCESS);      /* 等 EV5 */

    I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter);      /* 地址 + 写 */
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED) != SUCCESS); /* 等 EV6 */

    I2C_SendData(I2C2, RegAddress);                                     /* 寄存器地址 */
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTING) != SUCCESS);  /* 等 EV8 */

    I2C_SendData(I2C2, Data);                                           /* 数据 */
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTED) != SUCCESS);   /* 等 EV8_2 */

    I2C_GenerateSTOP(I2C2, ENABLE);                                     /* 终止条件 */
}
  • 为什么每一步都要 while 等待：硬件库函数是非阻塞的，I2C_GenerateSTART 只给 CR1 的 START 位置 1 就返回，波形发没发出去它不管。
  • 软件 I2C 里函数自带 Delay，是阻塞式的，所以不用等。
  • 事件对应：I2C_EVENT_MASTER_MODE_SELECT 是 EV5（起始已发出，STM32 默认从机、发完起始变主机）。
  • I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED 是 EV6（地址+读写位已发出且收到应答）；MASTER_BYTE_TRANSMITTING（全名 I2C_EVENT_MASTER_BYTE_TRANSMITTING）是 EV8（字节正在发送）；MASTER_BYTE_TRANSMITTED 是 EV8_2（BTF=1、两级缓存都空了）。
  • EV8_1 不用等：库函数里没有对应的事件参数，EV6 之后直接写 DR 即可。
  • MPU6050_WriteReg(…) 的调用骨架分三段：起始用 I2C_GenerateSTART(I2C2, ENABLE) 并等 MASTER_MODE_SELECT，再 I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter)。
  • 中段发 I2C_SendData(I2C2, RegAddress) 与 I2C_SendData(I2C2, Data)，每步等 while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTING) != SUCCESS); 这类判断。
  • 收尾等 I2C_EVENT_MASTER_BYTE_TRANSMITTED，最后 I2C_GenerateSTOP(I2C2, ENABLE)。
  • 每个等待都是 while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED) != SUCCESS); 这种形态，只换 EV 参数。
  • 末尾为什么等 EV8_2 而不是 EV8：EV8 只表示该字节正在发送、DR 已空；只有 EV8_2 表示 BTF=1、移位寄存器也空了，两级全空才能安全产生停止条件。

6. 读寄存器（硬件版 MPU6050_ReadReg）

uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
    uint8_t Data;

    /* 前半段：只指定地址（和 WriteReg 前半一样） */
    I2C_GenerateSTART(I2C2, ENABLE);
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT) != SUCCESS);
    I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Transmitter);
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED) != SUCCESS);
    I2C_SendData(I2C2, RegAddress);
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_BYTE_TRANSMITTED) != SUCCESS);

    /* 重复起始 + 地址+读 */
    I2C_GenerateSTART(I2C2, ENABLE);
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT) != SUCCESS);
    I2C_Send7bitAddress(I2C2, MPU6050_ADDRESS, I2C_Direction_Receiver);
    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED) != SUCCESS);

    /* 只读 1 字节：提前设 ACK=0 与 STOP=1 */
    I2C_AcknowledgeConfig(I2C2, DISABLE);
    I2C_GenerateSTOP(I2C2, ENABLE);

    while (I2C_CheckEvent(I2C2, I2C_EVENT_MASTER_BYTE_RECEIVED) != SUCCESS);   /* 等 EV7 */
    Data = I2C_ReceiveData(I2C2);

    I2C_AcknowledgeConfig(I2C2, ENABLE);   /* 恢复默认应答，便于以后扩展多字节 */
    return Data;
}

说明：完整函数体在画面里是分段拼出来的（前半段、重复起始、收尾各一帧），这里按帧 + 口述整理；ACK=0 与 STOP 的先后以口述「先置 ACK=0、再设 STOP 请求」为准。

  • 和写寄存器的区别：前半段一样，但地址发完要转读，必须再来一次起始条件（重复起始 Sr），用 I2C_Send7bitAddress(..., I2C_Direction_Receiver) 重新寻址并把读写位改成读。
  • EV6 要换成接收模式的参数 I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED，与发送用的 MASTER_TRANSMITTER_MODE_SELECTED 名字很像，别混用。
  • 最绕的是提前设 ACK=0 与 STOP=1：进入接收模式之后、数据还没收到时，就要把 ACK 置 0、STOP 位置 1。
  • 原因：应答位在字节收到之前就发出去了，等收到数据再设非应答就晚了。
  • 停止条件也不会截断当前字节，会等它接收完成后再产生停止波形，所以提前设置是安全的。
  • 只读 1 字节的流程：EV6 之后立刻 I2C_AcknowledgeConfig(I2C2, DISABLE) + STOP，再等 EV7（I2C_EVENT_MASTER_BYTE_RECEIVED），数据已在 DR，Data = I2C_ReceiveData(I2C2) 即可。
  • 最后 I2C_AcknowledgeConfig(I2C2, ENABLE) 恢复应答：本程序只读 1 字节、全程没给过应答，但为了以后扩展多字节还是要写。

7. EV8 与 EV8_2 的选择、现象验证

  • 实测结论：写 RegAddress 之后，等 TRANSMITTING（EV8）还是 TRANSMITTED（EV8_2）都能用——调用起始条件时若有字节正在移位，起始条件会延迟到当前字节发完才产生，不会截断数据。
  • 两种写法区别只是「等在哪」：用 TRANSMITTING，等待发生在重复起始之后；用 TRANSMITTED，先等波形全部发完、再产生重复起始。
  • 保险起见：数据流的最后用 TRANSMITTED（本集 ReadReg 前半段与 WriteReg 末尾都用它）。
  • 编译下载后的现象与软件 I2C 完全一致：OLED 显示 ID = 0x68，下面是 6 个加速度/角速度数据，转动模块数据变化正常。

图 15：WriteReg 完整版（无超时）——起始、EV5、地址+写、EV6、寄存器地址、EV8、数据、EV8_2 依次走完，最后 I2C_GenerateSTOP(I2C2, ENABLE);；字幕「我们就用一个简单的计数等待就行了」

8. 超时退出与 MPU6050_WaitEvent

  • 问题：程序里有大量 while (I2C_CheckEvent(...)) 死循环等待，一旦某个事件永远不产生（从机没接、总线被拉死），整个程序就卡死。
  • 简单超时（计次计时）：uint32_t Timeout = 10000;，循环里 Timeout --，减到 0 就 break。
  • break 只跳出本层循环，return 才能结束整个函数；循环 10000 次到底多久不确定（和主频/优化有关），实际取值要手动调。
  • 一行写法：uint32_t Timeout = 10000; while (…) { Timeout --; if (Timeout == 0) { break; } }。
uint32_t Timeout = 10000;
while (I2C_CheckEvent(I2C2, I2C_EVENT) != SUCCESS)
{
    Timeout --;
    if (Timeout == 0)
    {
        break;      /* 超时，跳出循环（break 只跳出本层循环） */
    }
}
  • 进一步封装成 MPU6050_WaitEvent(I2C_TypeDef* I2Cx, uint32_t I2C_EVENT)：Timeout = 10000; 与 while (I2C_CheckEvent(I2Cx, I2C_EVENT) != SUCCESS) { Timeout --; if (Timeout == 0) { break; } } 搬进函数里。
  • 原来每个 while (I2C_CheckEvent(...)) 都换成 MPU6050_WaitEvent(I2C2, 事件)，代码更整洁。
  • 缺点：函数内部用 break 只能结束这个子函数，外层函数无法直接 return。
  • 实际项目建议：超时退出处不能只 break，要做错误处理——打日志、系统复位、或紧急停机（涉及危险机械结构时）。
void MPU6050_WaitEvent(I2C_TypeDef* I2Cx, uint32_t I2C_EVENT)
{
    uint32_t Timeout = 10000;
    while (I2C_CheckEvent(I2Cx, I2C_EVENT) != SUCCESS)
    {
        Timeout --;
        if (Timeout == 0)
        {
            break;      /* 这里无法让外层函数 return */
        }
    }
}

图 16：MPU6050_WaitEvent 封装——函数体内 Timeout = 10000;、超时 break；下方 MPU6050_WriteReg 已全面改用 MPU6050_WaitEvent(I2C2, I2C_EVENT_MASTER_MODE_SELECT);；字幕「好，我们我再试一下」

9. 软件 I2C vs 硬件 I2C（本集改造对照）

项 软件 I2C（10-1） 硬件 I2C（10-2）
通信底层 MyI2C.c：GPIO 手动翻转 + Delay（阻塞） I2C2 外设：库函数 + 等事件（非阻塞）
引脚 任意 GPIO（PB10/PB11） 固定：I2C2 只能 PB10/PB11（不可互换）
GPIO 模式 通用开漏 Out_OD 复用开漏 AF_OD
起始/终止 MyI2C_Start/Stop I2C_GenerateSTART/STOP
发字节/收字节 SendByte/ReceiveByte（含延时） I2C_SendData/ReceiveData + 等 EV 事件
应答 SendAck/ReceiveAck 库函数内部自动处理（I2C_AcknowledgeConfig 单独改）
时钟 程序延时决定 I2C_ClockSpeed 配置（本集 50kHz，可到 400kHz）
应用层 main 不变 main 完全不变
现象 ID=0x68 + 6 轴数据 完全相同

坑与易错点

  1. 必须用 I2C2 而不是 I2C1：本板 PB6～PB9 被 OLED 占用；I2C2 无重映射、只能 PB10/PB11。
  2. SCL=PB10、SDA=PB11 不能互换：改到其他引脚 I2C2 就无法工作。
  3. GPIO 必须配 GPIO_Mode_AF_OD（复用开漏）：Out_OD 是软件 I2C 用的通用开漏，硬件 I2C 要复用。
  4. I2C 是 APB1 外设：RCC_APB1Periph_I2C2；GPIO 是 APB2，两个时钟别写混。
  5. 硬件库函数是非阻塞的：每个操作后必须 while 等对应事件，否则时序全乱。
  6. EV6 分发送/接收两个参数：MASTER_TRANSMITTER_MODE_SELECTED 与 MASTER_RECEIVER_MODE_SELECTED 别混用。
  7. 读的最后一个字节要提前置 ACK=0 + STOP=1：收到数据再设就晚了；STOP 会等当前字节收完才生效。
  8. 末尾等 EV8_2（BTF=1）再 STOP：两级缓存都空了才能安全停止。
  9. EV8 与 EV8_2 实测都能用：起始条件会延迟到当前字节发完；但数据流末尾建议用 TRANSMITTED。
  10. I2C_OwnAddress1 = 0x00 是随便给的（本程序不做从机），不能当通用推荐值。
  11. I2C_DutyCycle 只在 >100kHz 生效：标准速度固定 1:1，配了也没用。
  12. I2C_ClockSpeed 不能超过 400kHz；50kHz 属标准速度。
  13. 大量 while 死循环可能卡死程序：加超时退出；break 只能跳出本层循环，return 才能结束整个函数。
  14. MPU6050_WaitEvent 用 break 是作者自认的小缺点（无法结束外层函数）；实际项目超时要打日志/复位/紧急停机。
  15. 删模块要三处都删：文件选项卡 Close、工程树 Remove、工程目录删文件，否则工程树与目录不一致。
