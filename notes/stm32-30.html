[9-6] FlyMcu串口下载与STLINK Utility — 学习笔记

一句话结论

FlyMcu 用串口下载 hex，只认 USART1：BOOT0=1 加复位进 BootLoader，下载完换回再复位。STLINK Utility 走 SWD，两种文件都支持，还能单独改选项字节，可解写保护死循环。

本集定位

  • 工具实操课：只借 3-1 LED闪烁 示例工程生成 hex，全程没写新代码。
  • 主体是两个上位机软件的操作演示，中间插 PPT（存储器映像、表6 启动配置）与 CH340G 原理图（一键下载电路）。
  • 不讲 Keil 内置下载（在软件安装集），也不讲 DAP-Link 等其它下载器。
  • 片尾 21:50 收尾，无下集预告，模块 9（USART）结束。

1. 两个软件是什么

资料「工具软件」文件夹里有 FlyMcu 程序烧录软件、STLINK Utility、UltraCodingSwitch、USB 转串口 CH340 驱动、串口助手，本集讲前两个。

软件 下载通道 特点
FlyMcu 串口（USART1） 绿色免安装，打开即用；没有 ST-Link 时的方案，作用类似 51 的 STC-ISP
STLINK Utility ST-Link（SWD） 需要安装（含 ST-Link 驱动）；功能更全，可单独配选项字节、升级固件
  • 两者都能下载程序，区别只是下载通道。
  • 串口下载的硬件要求：电路要能保证 USART1 与电脑通信（模块 RXD→PA9、TXD→PA10、GND 共地），接 USART2/3 不行。

2. FlyMcu 串口 ISP 下载流程

2.1 生成 HEX 文件（Keil 侧唯一改动）

  • 打开示例工程，Keil 里 工程选项 → Output → 勾 Create HEX File，再重新编译。
  • Build Output 里会多出一条 FromELF: creating hex file...。
  • 工程目录 Objects 文件夹里出现 Project.hex（示例 5 KB），这就是串口下载要的程序文件。

图 2：Keil 打开示例工程 3-1 LED闪烁（main.c 里 GPIOA Pin_0 推挽输出、GPIO_ResetBits / Delay_ms(500) / GPIO_SetBits 循环），Build Output 出现 FromELF: creating hex file... 与 0 Error(s), 0 Warning(s)

图 3：工程目录 Objects 文件夹里的 Project.hex（HEX 文件，5 KB，修改时间 2022/8/18 15:05，高亮）

2.2 FlyMcu 界面设置

打开 FlyMcu V0.188，按顺序设置：

  1. 点 「搜索串口」；
  2. Port 选 COM 号（这里 COM12）；
  3. bps 保持默认 115200；
  4. 点 「…」 选 Objects 里的 hex 文件；
  5. 其余配置保持默认。
  • 界面上还有「编程前重装文件」（勾选后每次下载都重新加载 hex）、「校验」「编程后执行」「使用 RamIsp」「连续烧录模式」、读器件信息(R)/清除芯片(Z)/读FLASH、选项字节区，以及底部下拉框（配 DTR/RTS 电平，配合一键下载电路用）。

图 4：FlyMcu V0.188 主界面——菜单栏 搜索串口(V) / Port:COM12 / bps:115200 / www.mcuisp.com，「联机下载时的程序文件」栏与「编程前重装文件」勾选；左侧「开始编程(P)」与校验/编程后执行/使用RamIsp/连续烧录模式；选项字节区「编程到FLASH时写选项字节」「设定选项字节等」；底部下拉框 DTR的高电平复位,RTS高电平进BootLoader

2.3 进 BootLoader：拔跳线帽 + 按复位

  • 不配 BOOT 引脚直接点「开始编程」会一直卡住：芯片还在跑主程序，没人接收串口数据。
  • BOOT0 跳线帽拔下来，插到右边两个针脚 = BOOT0 = 1。
  • 再按一下复位：STM32 只在刚复位时读 BOOT 引脚，运行中切换无效。
  • 进 BootLoader 后，它不断接收 USART1 数据、刷新到主闪存。

图 5：面包板实拍——手上正把 BOOT0 跳线帽从原位置拔下，准备插到右边针脚（BOOT0=1）；右侧是 FlyMcu 窗口

2.4 下载与现象

  • 点「开始编程」后日志：DTR/RTS 电平操作 → 开始连接 → 收到 1F 1F → COM12 连接成功 115200bps → BootLoader 版本 3.0 → 芯片 PID 0x00000414（STM32F10xxx High-density）→ 读出选项字节 A5 5A FF 00 … → 96 位唯一序列号 → FLASH 容量 256KB → 全片擦除成功 → 写入 1KB 进度 100% → 成功写入选项字节 → 命令执行完毕，一切正常。
  • 此时 LED 还不亮，芯片还在跑 BootLoader。
  • BOOT0 换回左边 + 按复位 → LED 闪烁，程序正常运行。

图 6：FlyMcu 日志窗口——DTR/RTS 时序、开始连接、收到 1F 1F、串口 COM12 连接成功 115200bps、芯片内 BootLoader 版本 3.0、PID 0x00000414、读出选项字节 A5 5A FF 00 …、96 位唯一序列号、FLASH 容量 256KB、全片擦除成功、写入 1KB 进度 100%、成功写入选项字节

3. 原理：BootLoader 与启动配置

3.1 BootLoader 是「给自己换电池的小机器人」

  • ROM 区 0x08000000 位置存的就是编译后的程序代码，写什么就执行什么。
  • 串口下载是把数据通过串口发给 STM32，由它接收并刷新到 0x0800 这一块位置。
  • 但「接收并转存」这个动作本身也是程序——机器人给自己换电池：旧电池一拆就断电，所以必须额外做一个小机器人。
  • 小机器人就是 BootLoader：ST 写好的一段程序，存放在 ROM 区最后 0x1FFFF000 的「系统存储器」里（也叫自举程序），用途就是程序自我更新。
  • 更新时它接收 USART1 数据、刷新到程序存储器，期间主程序瘫痪；更新完再启动主程序执行新程序。
  • 类比：手机的刷机模式、电脑的 PE 系统。

3.2 启动配置表6：BOOT1/BOOT0 决定启动哪个程序

BOOT1 BOOT0 启动模式 说明
X 0 主闪存存储器 从 0x08000000 启动，跑你的程序
0 1 系统存储器 从 0x1FFFF000 启动，跑 BootLoader
1 1 内置 SRAM 从 0x20000000 启动，比较高级，暂时不用
  • 串口下载把 BOOT0 置 1（BOOT1=0）→ 从系统存储器启动 → 跑 BootLoader，才能接收串口数据写 Flash。
  • 下载完把 BOOT0 换回 0 → 复位后从主闪存启动。
  • 复位后 SYSCLK 的第 4 个上升沿锁存 BOOT 引脚值，所以每次改跳线帽都要按复位。

图 7：PPT「启动配置」——BOOT1=X/BOOT0=0 → 主闪存；BOOT1=0/BOOT0=1 → 系统存储器；BOOT1=1/BOOT0=1 → 内置SRAM；下方说明「在系统复位后，SYSCLK 的第4个上升沿，BOOT引脚的值将被锁存」

4. 一键下载电路（原理，本套板没有）

  • 痛点：每下载一次就要拔插两遍跳线帽 + 按两次复位。
  • 思路：程序自我更新必须让 BOOT0 和 RST 引脚产生高低电平变化，那就引出两根线，让电脑在点下载时自动给出这两个电平。
  • 用什么线：CH340G 除 TXD/RXD 外还有 RTS、CTS、DTR、DSR 流控脚，其中 RTS 和 DTR 是输出脚，可用来控制 BOOT0 和 RST。
  • 外围电路：一般用两个三极管开关，细节可搜「STM32 一键下载电路」。
  • 有电路后，点下载自动完成进 BootLoader → 下载 → 回主程序；FlyMcu 底部下拉框就是配 DTR/RTS 电平的，要按电路选。
  • 本套板没有一键下载电路，仍要手动切跳线帽，下拉框选哪个都无所谓（软件会置电平，但对本板无物理作用）。

4.1 缓招：勾「编程后执行」+ 去掉「写选项字节」

  • 勾上「编程后执行」，同时去掉「编程到FLASH时写选项字节」，否则下载后会提示执行失败。
  • 这样软件会人工加一条跳转指令，让芯片直接从 0x0800 开始跑主程序；跳线帽还在 BootLoader 状态，LED 也会立刻闪。
  • 但这是一次性的：按一下复位，又回到 BootLoader（LED 不亮）。
  • 用法：调试阶段停在 BootLoader 反复下载，全部调完再切回主程序，只在最开始和最后各切一次。

图 8：FlyMcu 勾选「编程后执行」、「编程到FLASH时写选项字节」未勾选，底部下拉框 DTR的低电平复位,RTS高电平进BootLoader；右侧日志显示 BootLoader 3.0、FLASH 256KB、全片擦除成功

图 9：CH340G 模块原理图——U1 的 14 脚 RTS#、13 脚 DTR# 可用来控制 BOOT0 与 RST；右侧排针 5V/VCC/3V3/TXD/RXD/GND

5. FlyMcu 的其它功能

5.1 读 Flash → .bin

  • 点「读FLASH」→ 选保存位置（桌面）、起名 led → 保存 → 桌面出现程序文件。
  • 用途：别人做了产品，你抄了 PCB 板再把芯片里的程序读出来，就能大批量山寨，所以自己做产品要开读保护。
  • .bin 是没有地址信息的原始数据文件（记录从 0x0800 开始的数据），.hex 带地址信息。
  • FlyMcu 下载只能选 .hex、读出来只能存 .bin，读出的 bin 不能再下回去；STLINK Utility 两种都支持。

图 10：读完 Flash 后，桌面出现 led.bin（高亮）

5.2 清除芯片与读器件信息

  • 「清除芯片」：把主程序区全部擦除，擦除后所有数据都是 FF。
  • 「读器件信息」：读出序列号等信息，以及 Flash 容量。
  • 实测：这片 C8T6 读出 256KB，而 C8T6 标称 64KB（中容量产品）。
  • 多片试过：有 64K、128K、256K；网上说法是生产时一个模子做出来、C8T6 只保证前 64K 没问题——属实测 + 传闻，不是官方结论。
  • Ramlsp、连续烧录模式用得不多，可自行研究。

图 11：FlyMcu 日志里红框标出「芯片FLASH容量为256KB」，而字幕说 C8T6 标称 64K

6. 选项字节（Option Bytes）

选项字节是 ROM 区最后的一小块存储单元，存一些独立于程序代码的配置参数。点「设定选项字节等」→ 选 STM32F1 → 打开配置窗口，共四大块。

6.1 读保护

  • A5 允许读出，FF 阻止读出（RDP 等于 0xA5 允许读 Flash，其它值阻止读出并阻止对前 4KB 读写）。
  • 不开读保护，别人很容易把程序偷走。
  • 阻止读出之后回 Keil 下载会失败，要回这里改回 A5。
  • 取消读保护时会同时清空芯片里的程序。

6.2 硬件选项字节

  • 包括软件看门狗（WWDG）硬件/软件启动、进 STOP 模式不产生复位、进 Standby 模式不产生复位，以及 B3～B7「大概也许可以使用」；了解即可。

6.3 用户数据字节

  • Data0（地址 0x1FFFF804）、Data1（地址 0x1FFFF806），这两个字节用户可自由使用。

6.4 写保护

  • WRP0～WRP3 可对 Flash 的页单独写保护（0-3、4-7、8-11 … 分组勾选，每 2KB 一页）。
  • 用途：主程序最后几页写自定义数据、不想下载时被擦掉，就设成写保护锁起来。
  • 设了写保护就不能再写，要写必须先解除。

6.5 选项字节的好处

  1. 不随程序更新变化，可存不随程序变化的参数。
  2. 可用上位机（FlyMcu / STLINK Utility）方便修改，做成产品中供用户配置的参数。

6.6 写保护的坑：FlyMcu 的死循环

  • 设了写保护之后再下载，写到保护区就出错（比如最前面几页设了写保护，下载一次之后再下载肯定出错）。
  • FlyMcu 不能单独写选项字节，只能下载 Flash 时顺便写。
  • 于是写保护了 → 下载不了 → 解不了写保护 → 死循环。
  • 解决：用 STLINK Utility 单独配置选项字节。
  • 配置完点「采用这个设置」，并把「编程到FLASH时写选项字节」勾上，再走正常下载流程。

图 12：FlyMcu「Option Bytes Setting」——读保护（A5 允许读出/FF 阻止读出）、硬件选项字节 B0～B7、用户数据字节 Data0(0x1FFFF804)/Data1(0x1FFFF806)、写保护 WRP0～WRP3

7. STLINK Utility（SWD 下载）

7.1 安装

  • 安装包：下一步 → Yes → 指定路径 → 下一步。
  • 最后勾上安装 ST-Link 驱动 → Finish，桌面出现软件图标。

7.2 下载流程

  1. 跳线帽恢复（两个都回最左边，BOOT0=0）+ 按复位；
  2. 点工具栏连接 → 右侧出现器件信息：Device（STM32F10xx High-density）、Device ID 0x414、Revision ID、Flash size 256KBytes；
  3. 下方大框显示 0x08000000 开始的程序数据，芯片刚被擦除过所以全是 FF；
  4. 保存：可把这数据存成 .hex 或 .bin；
  5. 断开连接、橡皮擦（擦除芯片）；
  6. 打开文件：支持 .hex 和 .bin，可打开 FlyMcu 读出的 bin；
  7. 点编程，再点 Start → 下载完成，LED 闪烁；
  8. 流程和 Keil 内置下载基本一样。

图 13：ST-LINK Utility 主界面——Device ID 0x414、Flash size 256KBytes；Address 0x08000000、Size 0x40000、Data Width 32 bits；日志 Memory programmed in 9s and 844ms.、Verification...OK、Checksum 0x03F846DD

7.3 选项字节：Target → Option Bytes（可单独修改）

  • 菜单 Target → Option Bytes 打开配置页，内容与 FlyMcu 里一样：
    • Read Out Protection（下拉可选 Disabled 等）、BOR Level；
    • User configuration option bytes（IWDT_STOP/IWDT_SW、WWDG_SW、nBOOT0、nBOOT1、nRST_STOP、nRST_STDBY、nRST_SHDW、VDDA_Monitor 等）；
    • Security option bytes（SEC_SIZE0/SEC_SIZE2、BOOT_LOCK）；
    • Boot address option bytes（BOOT_ADD0/BOOT_ADD1）；
    • User data storage option bytes（Data 0 / Data 1，默认 0xFF）；
    • Flash sectors protection（Page 0、1、2 … 每页 Start address / Size 2K / Protection：No Protection）；
  • 该型号没有的项显示成灰色（如 BOR Level 显示 Unavailable）。
  • 配好直接点 Apply 就能单独改选项字节，不像 FlyMcu 必须下载时顺便更新；所以芯片被读保护或写保护锁住时，可以到这里解除。

图 14：Option Bytes 窗口——Read Out Protection: Disabled、BOR Level（Unavailable 灰）、User configuration option bytes、Security option bytes、Flash sectors protection（Page 0～10，Size 2K）；下方 Apply / Cancel

7.4 固件升级：ST-LINK → Firmware update

  • 菜单 ST-LINK → Firmware update → 打开 ST-LinkUpgrade → 点 Device Connect（提示要重启，按提示拔掉重插）。
  • 显示当前固件 V2.J29.S7，最新可升到 V2.J37.S7（Type：STM32+STM8 Debugger）。
  • 要升级点 Yes >>>>；用着没问题不必经常更新。

图 15：ST-Link Upgrade——Current Firmware: Version: V2.J29.S7 / Type: STM32+STM8 Debugger；Upgrade to Firmware: STM32+STM8 Debugger V2.J37.S7；Yes >>>>；日志可见 Option bytes updated successfully.

8. 两者对比与适用场景

对比项 FlyMcu STLINK Utility
下载通道 串口 USART1（ISP） ST-Link SWD
是否需要额外硬件 只要 USB 转串口模块（有板载 CH340 即可） 必须有 ST-Link 调试器
安装 绿色免安装 需安装（含驱动）
下载文件 只能 .hex .hex 和 .bin 都支持
读取文件 只能存 .bin（不能再下回去） hex/bin 均可
进下载模式 手动切 BOOT0 + 复位 不需要（SWD 直接连）
选项字节 只能下载时顺带写（写保护后死循环） 可单独改（Apply），能解保护
速度/便利性 慢（115200 串口）、步骤多 快，和 Keil 内置下载一样简单
典型场景 没有 ST-Link 时救急、量产简单下载 日常开发下载/调试、救砖解保护
  • 一句话：日常开发用 ST-Link；手头没有 ST-Link 时，FlyMcu 用串口也能下载，前提是芯片没被写保护锁死。

坑与易错点

  1. 串口下载只认 USART1，接 USART2/3 不行。
  2. 必须先勾 Create HEX File 并重编，否则 Objects 里没有 Project.hex。
  3. 下载前必须 BOOT0=1 + 按复位；不按复位点「开始编程」会一直卡住。
  4. STM32 只在复位时读 BOOT 引脚（SYSCLK 第 4 个上升沿锁存），改了跳线帽不按复位等于没改。
  5. 下载完 LED 不亮是正常的，芯片还在跑 BootLoader；换回 + 复位才跑主程序。
  6. FlyMcu 只能下 .hex、只能读出 .bin，bin 不能再下回去；要下 bin 用 STLINK Utility。
  7. 读保护设成 FF 后 Keil 下载会失败，要改回 A5；取消读保护会同时清空程序。
  8. 写保护 + FlyMcu = 死循环，要用 STLINK Utility 的 Option Bytes 解除。
  9. 「编程后执行」是一次性的，去掉「写选项字节」勾能让下载后立刻运行，但按复位又回 BootLoader。
  10. 本套板没有一键下载电路，DTR/RTS 下拉框选了也没实际作用，仍要手动拔跳线帽。
  11. Flash 显示 256K ≠ 官方 64K：C8T6 标称 64K、读出值因片而异（64/128/256K），只保证前 64K，属实测 + 传闻。
  12. STLINK Utility 的选项字节改完必须点 Apply；没有的项显示灰色（Unavailable）属正常。
  13. ST-Link 固件升级前会提示重启，按提示拔插一次再连；用着没问题不必常更新。
  14. 擦除后数据全是 FF，这是正常空片状态（0x08000000 起全 FF 就是已擦除）。
