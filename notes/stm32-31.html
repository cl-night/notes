[10-1] I2C通信协议 — 学习笔记

一句话结论

I2C 是 Philips 的两线同步半双工总线：SCL 时钟 + SDA 数据，开漏配 4.7KΩ 上拉、支持线与。一主多从靠 7 位地址点名，每字节带应答，数据高位先行。

本集定位

  • 模块 10（I2C）的理论课（上），本集没写一行代码；软件 I2C 在 [10-2]、硬件 I2C 在 [10-3]。
  • 片头 3 分钟只演示两个成品工程（10-1 软件I2C读写MPU6050 与硬件 I2C 读写，现象相同），03:00 起 48 分钟全是 PPT。
  • 顺序：设计背景（四点要求）→ I2C 简介 → 硬件电路 → 6 个时序基本单元 → 3 种完整时序（含示波器实测波形）→ 多字节进阶。
  • 未讲时钟频率（100kHz/400kHz）与校验/CRC（I2C 靠 ACK 保证完整性），本笔记不补。
  • 片尾 50:54：「下一小节我们来了解 MPU6050 这个芯片」。

1. 设计背景：从串口到大公司的四点要求

1.1 回顾串口

  • 串口是 TX 发送、RX 接收两根线，异步、全双工、没有时钟线；数据以字节为单位，可组多字节数据包。

1.2 任务：用少量线读写外部模块的寄存器

  • 芯片内部众多设备都靠读写寄存器控制，寄存器被分配到一个线性存储空间。
  • 任务：在单片机和外部模块之间连少量几根线，实现读写寄存器——至少要有「指定位置写寄存器」和「指定位置读寄存器」。

1.3 第一版方案：串口 HEX 数据包

  • 定义 3 个字节：第 1 字节读写标志（0 写 / 1 读）、第 2 字节寄存器地址、第 3 字节写入的数据。
  • 例：发 0x00, 0x06, 0xAA = 在 0x06 地址写入 0xAA；发 0x01, 0x06, 0x00 = 读取 0x06 地址的数据（第 3 字节无效），模块收到后回一个字节。

1.4 大公司的四点要求

# 要求 动机
1 删掉一根通信线，同一根线上收和发（全双工 → 半双工） 对话式操作并不需要同时收发，全双工是资源浪费
2 增加应答机制：每发一个字节对方要应答，每收一个字节我也要应答 原协议无应答，单片机不知道对方收没收到
3 一根线上能接多个模块，主机可指定与任意一个通信，其余不能干扰 一根线只接一个模块不给力
4 异步时序改同步时序（加一根时钟线） 异步对速率要求严格、不能暂停、依赖硬件外设，难软件模拟
  • 同步的好处：多了时钟线后对时间要求不高，暂停传输时时钟线也暂停，双方定格，过一会继续也不影响——没有硬件外设的低端单片机也能软件模拟（51 就没有 I2C 硬件外设）。
  • 异步省一根时钟线但依赖硬件；同步对时间不严格、不依赖硬件，代价是多一根时钟线。

2. I2C 简介

  • I2C（Inter IC BUS）：Philips 公司开发的通用数据总线，应用非常广泛。
  • 两根通信线：SCL（Serial Clock，串行时钟）、SDA（Serial Data，串行数据），用 I2C 的器件都有这两个引脚。
  • 特性：同步（满足要求 4）、半双工（一根 SDA 兼收发，满足要求 1）、带数据应答（满足要求 2）、支持总线挂载多设备（满足要求 3）。
  • 常见器件：MPU6050（姿态，本课程用它学 I2C）、OLED 模块（显示）、AT24C02（存储器，51 教程用的就是它）、DS3231（实时时钟）。

2.1 一主多从模型（本课程使用）

  • 主机（单片机）：对 SCL 有完全控制权，空闲时主动发起对 SDA 的控制；只有从机发数据和从机应答时，才把 SDA 控制权交给从机。
  • 从机（被控 IC）：对 SCL 只能被动读取；不能主动发起 SDA，只有主机发读取命令或从机应答时才能短暂取得 SDA。
  • 比喻：老师（主机）主导课堂，学生（从机）只能被动听，被点名后才能说话。
  • 多主多从：任何模块都能跳出来当主机，同一时间只能一个说话（总线冲突）——I2C 会仲裁，胜者取得控制权、败者变回从机；多主机还要做时钟同步，本课程不作要求。

3. 硬件电路

3.1 接线与引脚模式

  • 接线：所有 I2C 设备的 SCL 连在一起、SDA 连在一起。
  • SCL 好办：一主多从下主机有绝对控制权——主机 SCL 配推挽输出，从机配浮空输入或上拉输入（数据流向：主机发、所有从机收）。
  • SDA 麻烦：半双工，主机和从机的 SDA 都要在输入/输出间切换；切换时机不协调就可能两个引脚同时输出、一个出高一个出低 → 电源短路。

3.2 规定：开漏输出 + 外置上拉电阻

  • 三条规定：① SCL 连一起、SDA 连一起 ② 设备的 SCL 和 SDA 均配开漏输出 ③ 各加上拉电阻，约 4.7KΩ。
  • 推挽是上管接正极、下管接负极：上管导通输出高（强上拉）、下管导通输出低（强下拉）；开漏就是去掉上面那个强上拉管。
  • 所以开漏只能输出低电平，高电平由外置上拉电阻提供（弱上拉）。
  • 弹簧与杆子模型：不许向上推杆，只能往下拉或放手，外面挂弹簧负责回弹——输出低就往下拽，输出高就放手。

3.3 开漏 + 弱上拉的三大好处

  1. 杜绝电源短路：所有人无论怎么拉或放手，杆子不会同时被强拉和强推。
  2. 避免引脚模式频繁切换：开漏兼具输入输出，想输入就放手观察杆子高低；输出高电平相当于断开引脚，输入前可直接输出高，不必切换模式。
  3. 线与：任一设备拉低则总线为低，全部放手才为高——多主机模式下正用它做时钟同步与仲裁，所以 SCL 虽可用推挽，实际仍用开漏 + 上拉。

4. 六个时序基本单元

I2C 在硬件（电路连接、引脚模式）和软件（时序定义、字节如何传输拼接）两方面都做了规定；先学 6 个基本单元，再拼成完整数据帧。

4.1 起始条件与终止条件

  • 起始条件：SCL 高电平期间，SDA 从高切换到低（下降沿）。
  • 总线空闲时 SCL 和 SDA 都是高电平；主机先打破宁静——SCL 保持高、把 SDA 拽下来，从机捕获到就自身复位等待召唤。
  • 之后主机再把 SCL 拽下来：一方面占用总线，另一方面便于拼接——除起始和终止，每个单元都是「SCL 低电平开始、低电平结束」。
  • 终止条件：SCL 高电平期间，SDA 从低切换到高（上升沿），之后回到全高空闲态。
  • 起始和终止只能由主机产生；从机在总线空闲时必须放开总线，不能主动碰（否则就是多主机模型）。

4.2 发送一个字节

  • SCL 低电平期间，主机把数据位依次放到 SDA（高位先行 B7→B0）；释放 SCL 后，从机在高电平期间读取。
  • 所以 SCL 高电平期间 SDA 不允许变化：低电平放数据、高电平读数据。
  • 循环 8 次即发送一个字节：想发 0 就拉低 SDA，想发 1 就放手。
  • 高位先行，与串口相反（串口低位先行）。
  • 同步的好处：主机发一半进中断也不会出错，时序在中断处拉长、电平暂停变化，回来继续即可。

4.3 接收一个字节

  • SCL 低电平期间，从机把数据位依次放到 SDA（高位先行）；释放 SCL 后主机在高电平读取；同样高电平期间 SDA 不许变化；循环 8 次。
  • 主机接收前必须先释放 SDA——相当于切换成输入，也可理解为所有设备始终是输入模式，要发时才主动拉低。
  • 为什么必须释放：总线是线与，任一设备拉低就是低；接收时还拽着 SDA，别人发什么都读不到。
  • 与发送的区别只有一句：发送是「低电平主机放、高电平从机读」，接收是「低电平从机放、高电平主机读」。
  • 图上实线是主机控制的电平、虚线是从机控制的电平；SCL 全程主机控制，所以从机换数据基本贴着 SCL 下降沿。

4.4 应答：发送应答与接收应答

  • 发送应答：主机接收完一个字节后，在下一个时钟发送一位——0 表示应答 ACK、1 表示非应答 NACK。
  • 接收应答：主机发送完一个字节后，在下一个时钟接收一位，判断从机是否应答；同样 0 应答、1 非应答，且接收前要释放 SDA。
  • 用法：每发完一个字节就紧跟「接收应答」——主机释放 SDA 后，从机若收到会立刻拉低；主机在高电平读到 0 就是有人应答，读到 1 说明没人应答（可直接发终止条件）。
  • 每接收一个字节后也要发应答位，告诉从机还要不要继续发；从机读到 1 就释放 SDA、交出控制权。
  • 应答结束的上升沿几乎与 SCL 下降沿同时发生（从机要尽快在低电平期间换数据）。

5. 从机地址（7 位）

  • 一主多从下主机要指定与谁通信，每个从设备要有唯一的设备地址；主机在起始条件后先发一个字节叫名字，所有从机都收到并与自己的比较，一样才响应后续读写。
  • 同一条总线上地址必须不同，否则叫一个地址多个设备响应就乱套。
  • 地址分 7 位和 10 位两种，本节只讲 7 位（简单、应用最广）。
  • 地址由厂商出厂分配（查手册）：不同型号一般不同，相同型号地址一样。
  • 同型号挂同一条总线：用地址里的可变部分，一般器件地址最后几位可在电路里改。
  • MPU6050：7 位地址 1101000，最后一位由 AD0 决定（AD0 接低 → 1101000）；AT24C02：最后三位由 A0/A1/A2 决定（接低=0、接高=1）。
  • 配合读写位：写 = 地址左移后最低位补 0 → 0xD0；读 = 最低位补 1 → 0xD1。

6. 三种完整时序

6.1 指定地址写

  • 任务：对指定设备（Slave Address），在指定地址（Reg Address）下写入指定数据（Data）。
  • 时序：S + 0xD0（从机地址+W） + RA(0) + 0x19（寄存器地址） + RA(0) + 0xAA（数据） + RA(0) + P。
  • 波形解读：上面线 SCL、下面线 SDA，空闲都是高；SCL 高电平期间拉低 SDA 产生起始 S。
  • 起始后紧跟「发送一个字节」，内容必须是「从机地址+读写位」（7 位地址 + 1 位读写位 = 8 位）：低电平换数据、高电平从机读；高 7 位 1101000 是地址，最低位 0 表示写，拼起来就是 0xD0。
  • 应答位 RA：主机释放 SDA（单看主机波形应回弹高），但从机在该位把 SDA 拉低，线与后保持低，主机读到 0 就知道寻址有人应答；读到 1 说明没人应答（可直接发停止条件）。
  • 第二个字节由从机定义用途（MPU6050 是寄存器地址，AD 转换器可能是指令控制字，存储器可能是存储器地址），波形 00011001 = 0x19；第三个字节是数据 0xAA，最后产生终止条件 P（先拉低 SDA 为上升沿做准备，再放 SCL、再放 SDA）。
  • 整帧含义：对地址 1101000 的设备，在内部 0x19 地址的寄存器写入 0xAA。

图 11：指定地址写的示波器实测波形——SCL 黄线、SDA 青线，绿色竖线为逐位采样标注，红色竖线分隔各段；标注 S、Send Byte: 0xD0 (Slave Address + R/W)、RA 0、Send Byte: 0x19 (Reg Address)；位值 1 1 0 1 0 0 0 对应 0xD0

图 12：同一波形的应答位细节——红笔竖直箭头指向「应答位结束」处的 SDA 上升沿（从机释放 SDA，与 SCL 下降沿几乎同时）

6.2 当前地址读（靠当前地址指针）

  • 任务：对指定设备，在当前地址指针指示的地址下读取数据。
  • 时序：S + 0xD1（地址+R） + RA(0) + 接收 1 字节（如 0x0F） + SA(1) NACK + P。
  • 为什么没有指定地址环节：一旦读写位给了 1，下一个字节必须立刻转为读，主机来不及指定读哪个寄存器。
  • 读哪个寄存器靠当前地址指针：从机内部一个指针变量，上电默认指向 0，每读写一个字节自动 +1。
  • 所以在 0x19 写了 0xAA（指针到 0x1A）后再调当前地址读，返回的就是 0x1A 的值，再调一次返回 0x1B。
  • 不能指定地址，所以这个时序用得不多。

图 13：当前地址读的示波器波形——标题「对于指定设备（Slave Address），在当前地址指针指示的地址下读取从机数据（Data）」；波形标注 S、Send Byte: 0xD1 (Slave Address + R/W)、RA 0、Receive Byte: 0x0F (Data)、SA 1、P

6.3 指定地址读（复合格式，含重复起始 Sr）

  • 任务：对指定设备，在指定地址下读取数据。
  • 怎么来的：把「指定地址写」最后的写数据部分去掉，再把「只指定地址、还没写数据」这段追加到当前地址读前面——地址已写进从机指针，再读就是指定地址读，这种拼接叫复合格式。
  • 时序：S → 0xD0 → RA 0 → 寄存器地址 0x19 → RA 0 → Sr（重复起始） → 0xD1 → RA 0 → 接收 1 字节（如 0xAA）→ SA 1（NACK）→ P。
  • 为什么必须重复起始：读写位只能紧跟起始条件，想切换读写方向只能再来一个 Sr 重新寻址。
  • 也可以分成两条时序（写地址 → P，再 起始 → 读当前位置 → P），因为地址存在指针里不会因停止而消失；但官方规定的复合格式是一整帧 S…Sr…P。
  • 用得最多的是「指定地址写」和「指定地址读」，后续代码就用这两个。

图 14：PPT「I2C时序」——指定地址读：对于指定设备（Slave Address），在指定地址（Reg Address）下读取从机数据（Data）；下方是整帧实测波形，红笔在中间画竖线分隔，前段只指定地址、后段读数据

图 15：指定地址读波形放大——标注 RA 0、Sr（红笔）、Send Byte: 0xD0 (Slave Address + R/W)、RA 0、Receive Byte: 0xAA (Data)、SA 1、P

7. 进阶：多字节读写与最后一字节 NACK

  • 多字节写：在「指定地址 + 写一个字节」之后不停止，把「发送一个字节 + 接收应答」重复多次；指针每写一个字节自动 +1，所以第 1 个数据写 0x19、第 2 个写 0x1A……
  • 多字节读：把「接收一个字节 + 发送应答」重复多次，指针自增，就能连续读出一片区域。
  • 关键：只想读一个字节就停止时，读完必须给从机发非应答（SA = 1）——非应答就是主机不把 SDA 拉低，从机读到 1 就释放总线、交出控制权。
  • 若主机读完还给应答，从机认为还要数据、继续发，主机想产生停止条件时 SDA 被拽住、无法正常回弹。
  • 所以读多字节时：之前所有字节给应答，最后一个字节给非应答。
  • 一句话：从机控制 SDA 发送数据的权利，开始于读写位为 1，结束于主机给的应答为 1（非应答）。

图 16：PPT「I2C时序」——同一页的小尺寸整帧波形，可见 Sr、Send Byte: 0xD0、RA 0、Receive Byte、SA 1、P 等分段

8. I2C 与 USART 对比

对比项 USART（串口） I2C
线数 TX、RX 两根通信线（+ GND） SCL、SDA 两根线
同步方式 异步（无时钟线） 同步（SCL 时钟线）
双工 全双工 半双工（一根 SDA 兼收发）
应答 无（靠协议/校验） 每字节带应答位
位数顺序 低位先行（LSB first） 高位先行（MSB first，B7→B0）
拓扑 点对点 一主多从 / 多主多从（需设备地址寻址）
电气 推挽输出为主 开漏 + 上拉电阻（4.7KΩ），线与
软件模拟 困难（异步对时间要求严） 容易（同步、可暂停）

坑与易错点

  1. I2C 是高位先行（B7→B0），串口低位先行，写代码/看波形别搞反。
  2. SCL 高电平期间 SDA 不许变化，数据只能在低电平期间改，否则会被当成起始/终止条件。
  3. 起始/终止只能在 SCL 高电平期间由 SDA 跳变产生：高时下降 = 起始，高时上升 = 终止。
  4. 每个基本单元「低进低出」：除起始/终止外，开始和结束时 SCL 都是低，才能无缝拼接。
  5. 主机接收（或接收应答）前必须释放 SDA，否则线与把总线拉死，从机发什么都读不到。
  6. 开漏只能输出低、不能输出高；别把 SCL/SDA 配成推挽输出（有电源短路风险）。
  7. 应答位 0 = ACK、1 = NACK（反直觉，0 才是应答）。
  8. 读多字节时最后一个字节必须 NACK，否则从机继续发、SDA 被拽住，停止条件无法产生。
  9. 读写位切换必须重新起始（Sr）：读写位只能紧跟起始条件，不能中途改。
  10. 「当前地址读」不能指定地址，读的是当前地址指针（上电默认 0、每字节 +1）指向的寄存器。
  11. 7 位地址 + 读写位 = 1 字节：MPU6050 = 1101000，写 0xD0 / 读 0xD1（最低位不是地址的一部分）。
  12. 同型号芯片要改地址低位：MPU6050 改 AD0、AT24C02 改 A0/A1/A2，否则同总线地址冲突。
  13. 应答位的上升沿和 SCL 下降沿几乎同时，这是从机尽快换数据造成的，不是异常。
  14. 同步总线可以「暂停」：中途进中断拉长时序不会出错，这是同步相对异步的关键优势。
