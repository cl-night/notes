[11-1] SPI通信协议 — 学习笔记

一句话结论

SPI 是 Motorola 开发的四线同步全双工总线（SCK/MOSI/MISO/SS），快但没有应答。它靠 SS 逐根选从机，收发以「字节交换」为单位：发一个字节必然同时收一个字节。本课程固定用模式 0。

本集定位

  • 模块 11 的理论课上集：全程 PPT，本集没有写一行代码；片头 00:00–02:50 只演示两个成品程序（11-1 软件SPI读写W25Q64 的软件/硬件 SPI 版，现象相同：OLED 显示 MID:EF DID:4017 / W:01 02 03 04 / R:01 02 03 04）。
  • 内容路线：I2C 对比 → SPI 简介 → 引脚 → 硬件电路 → 移位示意图 → 4 种模式 → W25Q64 指令时序实测波形。
  • 结尾 47:38 预告下一节讲 W25Q64 芯片——软件 SPI 代码在 [11-2]，硬件 SPI 在 [11-3]。
  • 本集不涉及：STM32 的 SPI 外设寄存器、W25Q64 完整指令集与地址映射、LSB/MSB 配置位（只提「一般高位先行」）。

图 1：PPT「SPI通信」——SPI（Serial Peripheral Interface）是由 Motorola 公司开发的一种通用数据总线；四根通信线：SCK（Serial Clock）、MOSI（Master Output Slave Input）、MISO（Master Input Slave Output）、SS（Slave Select）；同步、全双工；支持总线挂载多设备（一主多从）；下方四张器件图：W25Q64 模块、SPI OLED、NRF24L01 无线模块、MicroSD 卡；字幕「两个协议的设计目的都一样」

图 2：片头现象（工程 11-1 软件SPI读写W25Q64）——面包板上 W25Q64 模块与 STM32 由 4 根 SPI 线相连，OLED 显示 MID:EF DID:4017 / W:01 02 03 04 / R:01 02 03 04（写入与读回一致，说明读写正常）；字幕「这里的W25Q64，是一个Flash存储器芯片」

1. 与 I2C 对比：两种协议的设计取舍

  • I2C：开漏输出 + 4.7K 上拉，两根线兼顾收发、应答、寻址，硬件复杂但性价比高。
  • I2C 的速度上限来自开漏：高电平靠上拉电阻拉回、边沿缓慢，标准模式只有 100kHz、快速模式 400kHz，后来的高速模式 3.4MHz 普及度不高。
  • SPI：协议不严格规定最大传输速度（有的器件速率比 STM32F1 主频还高），功能比 I2C 少、设计简单粗暴，但快很多。
  • SPI 的代价：费线（一主多从要多根 SS）、没有应答、全双工下经常一根线闲着。
  • 一句话：两者设计目的一样（用少量线读写外部模块寄存器），只是取舍不同——I2C 省线但慢，SPI 费线但快。

图 3：PPT「硬件电路」（复习 I2C 的那页）+ 右上角红笔写的「100K」「400K」——讲 I2C 开漏 + 上拉的结构决定了速度上限；图中红圈圈出上拉电阻与开漏输出的开关管；字幕「虽然I2C协议之后又通过改进电路的方式」

2. SPI 简介与引脚含义

  • SPI（Serial Peripheral Interface，串行外设接口）：Motorola 开发的通用数据总线，同步、全双工、支持一主多从（不支持多主机）。
引脚 全称 含义
SCK Serial Clock 串行时钟线，由主机提供（对应 I2C 的 SCL），数据位在边沿收发
MOSI Master Output Slave Input 主机输出、从机输入（主机→从机的数据线）
MISO Master Input Slave Output 主机输入、从机输出（从机→主机的数据线）
SS Slave Select 从机选择，低电平有效（也叫 CS/NSS，不同芯片叫法不同）
  • SCK 的作用：主机提供时钟（对应 I2C 的 SCL），数据位在上升沿或下降沿收发，收发时刻明确确定——这就是同步时序的好处。
  • 全双工：MOSI、MISO 两根数据线同时收发，简单高效。
  • 一主多从靠 SS 线寻址（I2C 靠设备地址）：每多一个从机多一根 SS，要跟谁通信就拉低谁的 SS，指定从机「动动手指就能完成」，代价是费线。
  • SPI 没有应答机制：数据发出去就结束，不管对方在不在、收没收到（I2C 每个字节都有应答）。

3. 常见 SPI 器件

器件 说明
W25Q64 Flash 存储器芯片（本课程用它学 SPI），用于存大量数据；通过 4 根 SPI 线读写
SPI 版 OLED 引脚常写 DI/DO（而不是 MOSI/MISO）——DI 就是 MOSI、DO 就是 MISO，具体看模块手册
NRF24L01 2.4G 无线通信模块，使用 SPI 协议
MicroSD 卡 原生协议是 SDIO，但也支持 SPI 模式，可用 SPI 读写
  • 不同芯片/模块引脚命名不统一（MOSI 可能叫 DI、SDO、SDI，SS 可能叫 CS、NSS），接线前一定要看手册。

4. 硬件电路

4.1 三条规定

  1. 所有 SPI 设备的 SCK、MOSI、MISO 分别连在一起。
  2. 主机另外引出多条 SS 控制线，分别接到各从机的 SS 引脚。
  3. 输出引脚配置为推挽输出，输入引脚配置为浮空或上拉输入。
  • 为什么用推挽：推挽驱动能力强、边沿迅速（不像 I2C 开漏那样上升沿缓慢），所以 SPI 能跑高速。
  • 主机侧：SCK、MOSI、SS 是推挽输出，MISO 是浮空/上拉输入；从机侧反过来。
  • 典型接线：SCK + MOSI + MISO + 3 根 SS ＝ 6 根通信线（挂 3 个从机），另加 VCC/GND。

图 4：PPT「硬件电路」（SPI 版）——三条规定：所有 SPI 设备的 SCK、MOSI、MISO 分别连在一起；主机另外引出多条 SS 控制线，分别接到各从机的 SS 引脚（高亮）；输出引脚配置为推挽输出，输入引脚配置为浮空或上拉输入；下方示意图：SPI 主机（SS1/SS2/SS3、MISO、MOSI、SCK）分别接 3 个 SPI 从机，每台从机有 SCK/MOSI/MISO/SS；字幕「主机通过MISO输入」

图 5：同一页上的红笔——标注 SS1/SS2/SS3 三条选择线、MISO/MOSI/SCK 的方向箭头，并在三个从机的 SS 处画叉/圈：只有被拉低 SS 的从机才参与通信；字幕「这就是SPI实现选择从机的方式」

4.2 未选中从机的 MISO 必须高阻

  • 问题：MISO 是所有从机共用的线——未选中的从机（SS=高）若仍推挽输出，就会和正在发送的从机冲突短路。
  • 规定：从机未被选中时 MISO 必须切换为高阻态，只有被选中的从机才驱动 MISO。
  • 这是 SPI 对「可能冲突」做的规定，属从机端责任，主机程序不用管。
  • 主机 MISO 一般配上拉输入：浮空输入在未选中时电平不确定，上拉读到高电平。

5. 移位示意图与「字节交换」

  • 结构：主机和从机各有一个移位寄存器，主机另有波特率发生器产生 SCK。
  • 发送：数据高位先行（MSB first），主机逐位移到 MOSI、从机逐位移到 MISO。
  • 方向：主机 MOSI 的输出进入从机移位寄存器最低位，从机 MISO 的输出进入主机移位寄存器最低位——每个 SCK 两边各移出一位、各移入一位。
  • 8 个时钟后两边数据互换完成，这就是字节交换；它是 SPI 的基本单元：发一个字节必然同时收一个字节。
  • 只发送：忽略收到的字节；只接收：主机必须发占位字节 0x00 或 0xFF，用这 8 个时钟把从机数据「换」回来。
  • 只发/只收时必然有一根数据线闲着，这就是 SPI 的资源浪费，协议本身不管。

图 6：PPT「移位示意图」——左侧「SPI 主机」（含移位寄存器 01010101 与波特率发生器），右侧「SPI 从机」（含移位寄存器 10101010）；主机 MOSI → 从机 MOSI，从机 MISO → 主机 MISO，主机 SCK → 从机 SCK；字幕「分别放到MOSI和MISO的通信线上」

图 7：同一示意图上的红笔——在两个移位寄存器之间画交换箭头（主机数据跑到从机、从机数据跑到主机），并标出 SCK 由主机的波特率发生器驱动；字幕「这样，主机要发送的数据，跑到从机」

6. 起始与终止条件

  • 起始＝SS 由高电平切换到低电平（选中从机、通信开始）；终止＝SS 由低电平切换到高电平；SS 低电平期间就是通信期间。
  • 比 I2C 简单得多（I2C 要在 SCL 高电平期间做 SDA 跳变）。
  • 细节：SS 未选中时 SCK 处于默认电平（模式 0 空闲为低）；SS 上升沿结束后从机 MISO 置回高阻；MOSI 空闲电平未定义，可以不管。

7. 时序基本单元与 4 种模式

7.1 两个配置位：CPOL 与 CPHA

  • CPOL（Clock Polarity，时钟极性）：空闲状态时 SCK 的电平——0 低、1 高。
  • CPHA（Clock Phase，时钟相位）：在第 1 个还是第 2 个边沿采样（移入）——0 第一边沿、1 第二边沿。
  • 两者组合出模式 0～3，功能一样，只是采样时刻不同。

图 8：PPT「SPI时序基本单元」——「CPOL=0：空闲状态时，SCK为低电平」「CPHA=0：SCK第一个边沿移入数据，第二个边沿移出数据」（模式 0 的定义）；下方波形 SS/SCK/MOSI/MISO，标注 B7、B6 …… B0；字幕「分别叫作CPOL（Clock Polarity）时钟极性」

7.2 模式 0（最常用，本课程后续全部用它）

  • CPOL=0（空闲低）+ CPHA=0（第 1 个边沿移入、第 2 个边沿移出）：SCK 上升沿采样、下降沿准备下一位。
  • 多字节连续交换时注意拼接：一个字节的 B0 之后紧跟下一个字节的 B7。

图 9：模式 0 波形详解——「交换一个字节（模式0）」；CPOL=0（空闲低）、CPHA=0（第一个边沿移入、第二个边沿移出）；SS 拉低后 SCK 上升沿采样 B7、下降沿移出 B6……红笔标出 SS 下降沿与第一个 SCK 上升沿；字幕「之后，SCK下降沿，移出B6」

7.3 模式 1（对比）

  • CPOL=0、CPHA=1：第 1 个边沿移出、第 2 个边沿移入，所以采样边沿变成下降沿。

图 10：模式 1 波形——「交换一个字节（模式1）」；CPOL=0（空闲低）、CPHA=1：第一个边沿移出数据、第二个边沿移入数据；波形上红笔圈出采样位置（在下降沿）；字幕「然后MISO，从机必须得置回高阻态」

7.4 模式 2 / 模式 3

  • 模式 2 ＝ 模式 0 的 CPOL 取反（空闲高），模式 3 ＝ 模式 1 的 CPOL 取反。
  • CPHA 不能单独决定上升/下降沿采样，必须配合 CPOL 看。

8. W25Q64 的指令时序（实测波形）

波形是软件 SPI 抓的：MOSI 的电平变化相对 SCK 有延迟（软件翻转引脚的速度限制），属正常现象，不是器件问题。

8.1 0x06：写使能（单字节指令）

  • 时序：SS 拉低 → SCK 打 8 个时钟 → MOSI 高位先行发 00000110（0x06）→ SS 拉高。
  • MISO 全程高电平（FF）——这条指令没有回传数据。
  • 从机收到后会控制内部硬件允许后续写入，所以写操作前必须先发写使能。

图 11：PPT「SPI时序」——发送指令：向 SS 指定的设备，发送指令（0x06）；下方是实测波形（SS、SCK、MOSI、MISO，绿色竖线为逐位、红竖线分隔各段）；字幕「首先是SPI发送指令」

图 12：0x06 波形放大——SS、SCK、MOSI（位值 0 0 0 0 0 1 1 0＝0x06，红笔圈出并标 0x06，分段标注 Send Byte: 0x06 (Write Enable)）、MISO（全程高）；字幕「那从机就会控制硬件，进行写使能」

8.2 0x02：页编程（指令 + 24 位地址 + 数据）

  • 时序：SS 拉低 → 0x02 → 24 位地址（3 字节，如 0x12 0x34 0x56）→ 要写入的数据字节。
  • 后续字节会自动依次写入后续存储空间（页内递增）。
  • 8MB 的 W25Q64 地址要 3 字节（24 位）；小容量芯片可能只要 1 字节，甚至把地址合进指令里。

图 13：0x02 页编程波形——分段标注 Send Byte: 0x02 (Write Command) 与 Send Byte: 0x12 0x34 0x56 (24bit Address)；红笔圈出其后连续输出的数据字节；字幕「继续发送的字节就会依次写入到后续的存储空间里」

8.3 0x03：读数据（指令 + 24 位地址 + 占位换数据）

  • 时序：SS 拉低 → 0x03 → 24 位地址 → 主机连续发 0x00 占位，同时从 MISO 读回数据。
  • 本质仍是字节交换：要收一个字节，就得发一个占位字节去「换」。
  • 指令与地址发完后从机就开始输出数据。

图 14：0x03 读数据波形——分段标注 Send Byte: 0x03 (Read Command)、Send Byte: 0x12 0x34 0x56 (24bit Address) 与 Receive Byte: … (Data)；MOSI 在地址后变成 0x00 占位、MISO 上出现数据；字幕「因为这是SPI模式0，所以数据变化都要提前半个周期」

图 15：PPT「SPI时序」——指定地址读：向 SS 指定的设备发送读指令（0x03），随后在指定地址（Address 的 23:0 位）下读取从机数据（Data）；下方是整帧实测波形的缩略视图；字幕「W25Q64这个芯片的知识点」

8.4 指令时序的共同格式

  • 所有指令同构：起始（SS 拉低）→ 交换指令码 → 交换若干字节（地址/数据）→ 终止（SS 拉高）。
  • 差别只在指令码和后续字节的定义（哪个是地址、哪个是数据、要不要回传），时序玩法完全一样。
  • 理解了字节交换，任何 SPI 器件都能控制。

坑与易错点

  1. SPI 没有应答：发出去就不管对方在不在，别指望它告诉你「对方没收到」。
  2. 一主多从靠 SS 线，不是靠地址：每从机一根 SS，拉低哪个就跟哪个通信，费线。
  3. SS 低电平有效：拉低才是选中，别接反。
  4. 未选中的从机 MISO 必须高阻：从机端责任；主机 MISO 建议配上拉输入。
  5. 推挽 vs 开漏：SPI 用推挽（边沿快、能跑高速），I2C 用开漏（防短路但慢）。
  6. 只接收时必须发占位字节：0x00 或 0xFF——字节交换，不发就收不到。
  7. 只发送时收到的数据无意义：忽略即可。
  8. 模式 0 最常用：CPOL=0 + CPHA=0，本课程后面全用模式 0。
  9. CPHA 不能单独看：它说的是第几个边沿，上升沿还是下降沿要结合 CPOL。
  10. 起始/终止只看 SS：高→低起始、低→高终止，SS 低电平期间就是通信期间。
  11. 高位先行（MSB first）：先发 B7；LSB/MSB 配置位在硬件外设部分才讲。
  12. W25Q64 写之前要先发 0x06 写使能：否则写入无效。
  13. W25Q64 地址是 24 位（3 字节）：高位字节在前，小容量芯片地址长度可能不同。
  14. 软件 SPI 抓的波形有延迟：MOSI 相对 SCK 滞后属正常，不代表器件问题。
