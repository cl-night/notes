[2-2] 新建工程 — 学习笔记

一句话结论

从零搭出标准库工程模板：建 Start / Library / User 三个文件夹复制固件库文件，Keil 建同名分组，配好 Include Paths、USE_STDPERIPH_DRIVER、ST-Link 与 Reset and Run，再用寄存器、库函数两种方式点灯验证。

本集定位

  • 开发环境模块第 2 集（[2-2]），本集是实操课：跟着视频从零搭出标准库工程模板。
  • 产出一个可复用的工程骨架：Start / Library / User 三个文件夹 + Keil 同名分组 + Include Paths / Define / ST-Link / Reset and Run 配置。
  • 用寄存器点灯与库函数点灯各验证一次，并补充启动文件选择与工程架构说明。

最终工程结构（本集完成时）

文件夹 放什么 来源
Start startup\arm 下全部 8 个 startup_stm32f10x_*.s（Keil 分组里只添加 md.s 一个）、core_cm3.c/h、stm32f10x.h、system_stm32f10x.c/h 固件库 CMSIS\CM3\...

1. 三种开发方式与固件库

方式 做法 特点 本课程
基于寄存器 程序直接配置寄存器 最底层、最直接、效率高；但 STM32 寄存器太多，不推荐 演示一下，不是重点
基于标准库（库函数） 调用 ST 封装好的函数，间接配置寄存器 ST 封装得好，既能配置寄存器，对开发者也友好 本课程使用
基于 HAL 库 图形化界面快速配置 适合快速上手，但隐藏底层逻辑，不熟悉 STM32 容易停在浅层 学完标准库后了解
  • 固件库 STM32F10x_StdPeriph_Lib_V3.5.0（标准外设库），资料页 https://jiangxiekeji.com/download.html，解压后：
    • .htmresc：两张图片资源，用不到；
    • Libraries：库函数文件（建工程用），含 CMSIS 和 STM32F10x_StdPeriph_Driver；
    • Project：官方工程示例和模板，以后用库函数时可参考；
    • Utilities：STM32 官方评估板（一块小电路板）的测评程序；
    • 另有库函数发布文档和使用手册。

2. 新建工程

  1. 先建存放所有工程的总文件夹（如 STM32Project，以后工程都放这里）。
  2. 打开 Keil5，Project → New uVision Project。
  3. 总文件夹里再建本次工程的文件夹（视频命名 2-1 STM32工程模板，用名字说明工程用途）。
  4. 工程文件起通用名字（如 project）：文件夹名好改，工程名不好改。
  5. 器件选 STM32F103C8（芯片是 STM32F103C8T6），点 OK。

图 1：Keil 新建工程，选择工程文件夹并命名

图 2：Select Device 里选择 STM32F103C8

  1. 弹出 Manage Run-Time Environment 直接关掉；此时工程还是空的，需要添加必要文件。

3. Start / User 必要文件与分组

文件 作用 固件库位置
startup_stm32f10x_*.s（8 个） 启动文件，程序从这里开始执行；本课 Keil 分组里只添加 md.s 这一个 Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x\startup\arm
stm32f10x.h STM32 外设寄存器描述文件（类似 51 的 reg52.h），描述有哪些寄存器及地址 ...\DeviceSupport\ST\STM32F10x\
system_stm32f10x.c/h 配置系统时钟，72MHz 主频就是这里配置的 同上
core_cm3.c/h Cortex-M3 内核的寄存器描述（还带内核配置函数） Libraries\CMSIS\CM3\CoreSupport
  • 工程文件夹下建 Start：先把 startup\arm 里全部 8 个启动文件复制进去，再复制 stm32f10x.h + system_stm32f10x.c/h + core_cm3.c/h；Keil 分组里只添加 md.s，其余 7 个留文件夹备用。
  • Keil 自动生成的 DebugConfig、Listings、Objects 是输出/调试目录，不用管。

图 3：工程文件夹里新建 Start/User 等文件夹来分类放置文件

  1. 把 Source Group 1 选中再单击一下，改名为 Start。
  2. 在 Start 上右键 → Add Existing Files to Group 'Start'，文件过滤器选 All files。
  3. 先加启动文件 startup_stm32f10x_md.s（前缀 md = Medium Density，中容量；8 个启动文件都有，工程里只能加一个）。
  4. 按住 Ctrl 多选其余 .c 和 .h 文件，点 Add → Close。
  5. 魔术棒 → C/C++ → Include Paths 新建一行，点 ... 把 ..\Start 加进来（..\User、..\Library 后面再补）。
  • 带小钥匙图标的是只读文件，STM32 最基本文件，不用修改。

图 4：Keil 工程里的 Start / Library / User 分组与文件（全部建完后的最终状态，画面已滚动到 User/Library；Library 分组后面才加入；带小钥匙的是只读文件）

User 与 main.c

  1. 工程文件夹下建 User，main 函数放这里。
  2. Keil 里 Target 右键 → Add Group，命名 User。
  3. 右键 → Add New Item to Group 'User' → C File，名字写 main；Location 默认是工程根目录，要手动选到 User 文件夹。
  4. main.c 写最小程序：
#include "stm32f10x.h"

int main(void)
{
	while (1)
	{
	}
}
  • main 是返回 int、参数 void；文件最后一行必须是空行，否则报警告。
  • 编译后 0 Errors, 0 Warnings 说明工程能编译——此时还是基于寄存器的工程。

4. 硬件接线与调试器

  1. 硬件：STM32 最小系统板 + ST-Link + 4 根母对母杜邦线；按引脚旁标识接 3.3V、SWDIO、SWCLK、GND，ST-Link 插电脑 USB。
  2. 上电现象：电源灯长亮，接在 PC13 的 LED 默认闪烁（芯片预装的测试程序）。

图 5：ST-Link 与最小系统板的 SWD 接线（3.3V / SWDIO / SWCLK / GND）

  1. 魔术棒 → Debug：默认调试器是 ULINK，用 ST-Link 就下拉选 ST-Link Debugger。
  2. 右侧 Settings → Flash Download 勾 Reset and Run：勾上后下载完立即复位并执行，否则每次要手按复位键。

图 6：Debug 选项卡选择 ST-Link Debugger

图 7：Flash Download 里勾选 Reset and Run

  1. 重新编译，点 Load 下载；下载成功后 PC13 的灯不再闪（当前程序是空的）。

5. 寄存器点灯（理解底层）

点灯只需配置 3 个寄存器：

寄存器 配置 值
RCC_APB2ENR GPIO 都是 APB2 外设；IOPCEN（bit4）写 1 使能 GPIOC 时钟 0x00000010
GPIOC_CRH PC13 的 CNF13 = 00（通用推挽输出）、MODE13 = 11（输出 50MHz） 0x00300000
GPIOC_ODR ODR13 写 1 = 高电平，写 0 = 低电平；本板 LED 低电平点亮 0x00002000（灭）/ 0x00000000（亮） 
#include "stm32f10x.h"

int main(void)
{
	RCC->APB2ENR = 0x00000010;   // 使能 GPIOC 时钟
	GPIOC->CRH = 0x00300000;     // PC13 通用推挽输出，50MHz
	GPIOC->ODR = 0x00002000;     // 高电平（灭）；改成 0x00000000 则亮
	while (1)
	{
	}
}

图 8：寄存器点灯代码（RCC_APB2ENR / GPIOC_CRH / GPIOC_ODR）

  • 现象：ODR = 0 时灯亮，ODR = 0x2000 时灯灭。
  • 弊端：直接给整个寄存器赋值，PC13 之外的位也变成 0，影响其他端口原有配置；只改 PC13 得用 &=、|=——这正是要库函数的原因。

6. 库函数工程与库函数点灯

  1. 工程文件夹下新建 Library。
  2. 固件库 Libraries\STM32F10x_StdPeriph_Driver\src 里 Ctrl+A 全选 .c 复制到 Library；...\inc 里 Ctrl+A 复制全部 .h。misc.c 是内核相关的库函数，其余是外设库函数。
  3. Keil 里 Target 右键 → Add Group 命名 Library；右键 → Add Existing Files，Ctrl+A 全选 → Add。
  4. 还需要 3 个库函数配置文件：固件库 Project\STM32F10x_StdPeriph_Template 里的 stm32f10x_conf.h、stm32f10x_it.c、stm32f10x_it.h 复制到 User，并在 User 分组添加。
    • stm32f10x_conf.h 配置库函数头文件包含关系，还有参数检查宏；stm32f10x_it.c/h 存放中断服务函数。
  5. stm32f10x.h 最后能看到条件编译：
#ifdef USE_STDPERIPH_DRIVER
	#include "stm32f10x_conf.h"
#endif

所以必须在魔术棒 → C/C++ → Define 填 USE_STDPERIPH_DRIVER。 6. 同时在 Include Paths 补上 ..\User 和 ..\Library（三个文件夹都声明）。

图 9：C/C++ Define 填 USE_STDPERIPH_DRIVER

图 10：Include Paths 声明 ..\Start、..\User、..\Library

  1. 重新编译：第一次慢（编译整个库），结果 0 Errors, 0 Warnings。
    • Library 里的文件都带小钥匙，不需要改；唯一要改的是 User 里的文件。
    • STM32F10X_MD 新建工程时已自动声明，不用额外加。

图 11：库函数工程编译成功：0 Error(s), 0 Warning(s)（此时 main.c 里还是寄存器代码，后面才换成库函数）

库函数点灯：

#include "stm32f10x.h"

int main(void)
{
	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);   // 使能 GPIOC 时钟
	GPIO_InitTypeDef GPIO_InitStructure;
	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;        // 通用推挽输出
	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_13;              // PC13
	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;       // 50MHz
	GPIO_Init(GPIOC, &GPIO_InitStructure);                   // 配置生效
	GPIO_SetBits(GPIOC, GPIO_Pin_13);                        // PC13 高电平（灭）
	// GPIO_ResetBits(GPIOC, GPIO_Pin_13);                   // PC13 低电平（亮）
	while (1)
	{
	}
}

图 12：库函数点灯代码（RCC_APB2PeriphClockCmd / GPIO_Init / GPIO_SetBits）

  • 库函数内部仍然是配置寄存器，但已用 |= 和 &=，不影响寄存器的其他位；代码更长但语义明确，也不用查手册算寄存器值。
  • 下载验证：注释掉高电平、放开低电平 → 灯亮；反过来 → 灯灭。

图 13：库函数程序下载成功（Build Output 显示 Programming / Verify OK、Application running）

7. 启动文件怎么选

启动文件按芯片容量分多种，选错会出问题：

缩写 释义 Flash 容量 型号
LD_VL 小容量产品超值系列 16–32K STM32F100
MD_VL 中容量产品超值系列 64–128K STM32F100
HD_VL 大容量产品超值系列 256–512K STM32F100
LD 小容量产品 16–32K STM32F101/102/103
MD 中容量产品 64–128K STM32F101/102/103
HD 大容量产品 256–512K STM32F101/102/103
XL 加大容量产品 大于 512K STM32F101/102/103
CL 互联型产品 — STM32F105/107
  • 规则：F100 → 选带 VL 的，再按 Flash 选 LD/MD/HD；F101/102/103 → 不带 VL，按 Flash 选 LD/MD/HD/XL；F105/107 → 直接选 CL。
  • startup\arm 里共 8 个：startup_stm32f10x_cl/hd/hd_vl/ld/ld_vl/md/md_vl/xl.s，后缀与上表缩写一一对应。
  • 本课芯片 STM32F103C8T6：Flash 64K，选 startup_stm32f10x_md.s（MD）。

图 14：型号分类与缩写，C8T6 的 Flash 是 64K，对应 MD 启动文件

8. 六步总结与工程架构

  1. 建工程文件夹，Keil 新建工程、选择型号。
  2. 建 Start、Library、User 等文件夹，复制固件库文件到工程文件夹（外部文件一挪位置工程就找不到）。
  3. 工程里建同名分组，把文件夹里的文件加进分组（Keil 不能直接添加文件夹）。
  4. Include Paths 声明所有包含头文件的文件夹（自己建的文件夹 Keil 并不知道）。
  5. Define 定义 USE_STDPERIPH_DRIVER（STM32F10X_MD 已自动声明）。
  6. Debug 下拉选调试器 → Settings → Flash Download 勾 Reset and Run。
  • 文件夹的名称和数量没有限制；把 .h 加进工程是 UP 主习惯（.h 不参与编译，很多工程不加）。

图 15：新建工程六步总结（PPT）

图 16：工程架构（左：启动文件；中：用户代码；右：STM32 资源——寄存器描述、库函数、库函数配置）

  • startup_xx.s：汇编编写，定义中断向量表和中断服务函数；复位中断是程序入口，复位后调 SystemInit 再调 main；main 最后一定是死循环。
  • system_stm32f10x.c/h：定义 SystemInit，配置系统时钟、Flash、PLL（72MHz 主频来自这里），不需要改。
  • main.c：用户主程序入口。
  • stm32f10x_it.c/h：放中断服务函数（启动文件里是弱符号，实际处理写这里）。
  • stm32f10x.h：外设寄存器描述（寄存器名、每一位名字、地址）。
  • core_cm3.c/h：Cortex-M3 内核寄存器描述。
  • misc.c/h + stm32f10x_xxx.c/h：ST 封装的库函数，把寄存器操作包装成函数。
  • stm32f10x_conf.h：配置库函数头文件包含关系，被 stm32f10x.h 在 USE_STDPERIPH_DRIVER 条件下包含，所以只需 #include "stm32f10x.h" 就能用所有库函数。

坑与易错点

  1. 工程名不好改、文件夹名好改：工程起通用名（如 project），用外层文件夹名区分实验。
  2. 文件一定要复制进工程文件夹：加工程外文件，外部路径一变动工程就找不到。
  3. 启动文件只能加一个，后缀要对：F103C8T6 用 startup_stm32f10x_md.s（MD）；选错容量后缀会出问题。
  4. Include Paths 必须声明自己建的每个文件夹：否则编译时报找不到头文件。
  5. Define 必须写 USE_STDPERIPH_DRIVER：不写 stm32f10x_conf.h 不会被包含，库函数头文件都找不到。
  6. main 是 int main(void)，文件最后一行要留空行，否则报警告。
  7. 编码设为 UTF-8：中文乱码时查 Edit → Configuration；顺手可把字号调 14、Tab 设 4。
  8. Debug 默认是 ULINK：用 ST-Link 必须改成 ST-Link Debugger；勾 Reset and Run，下载后自动复位运行。
  9. 寄存器直接赋值会影响其他位：只改某一位要用 &=、|=；库函数内部已处理好。
  10. 第一次编译慢是正常的：要编译整个标准外设库，之后改代码就快了。
