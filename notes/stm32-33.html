[10-3] 软件I2C读写MPU6050 — 学习笔记

一句话结论

复制 OLED 工程改名 10-1 软件I2C读写MPU6050，SCL→PB10、SDA→PB11，用 GPIO 开漏模拟时序；其上是 MyI2C → MPU6050 → main 三层。点名 0xD0 应答、0xA0 无应答。

本集定位

  • 模块 10 的代码课（超长实操）：两层模块从零手写。
  • 先写 MyI2C 协议层（GPIO 翻转模拟时序，不占硬件 I2C 外设），再写 MPU6050 驱动层，最后由 main 调用。
  • 1:02:45 总结分层架构，无下集预告。
  • 本集不涉及：硬件 I2C 外设（下一集）、DMP、姿态解算。
  • 理论见 notes/stm32-31-I2C通信协议.md 与 notes/stm32-32-MPU6050简介.md。
  • 下文 WriteReg、ReceiveAck、GetData 分别是 MPU6050_WriteReg、MyI2C_ReceiveAck、MPU6050_GetData 的简写。

1. 接线与工程建立

1.1 硬件接线

  • VCC/GND 供 3.3V（模块内有 LDO）；SCL→PB10、SDA→PB11，别与串口的 PA9/PA10 混淆。
  • 软件 I2C 不占内部外设，端口可任意指定（PA0、PA8 都行），这是它相对硬件 I2C 的优点。
  • 模块自带 4.7K 上拉，不需外接；STM32 是主机、MPU6050 是从机，只写主机端程序。
  • AD0 可改从机地址最低位（模块内置下拉，悬空即 0x68），后面做改名实验。
  • 面包板接好后模块电源指示灯亮即供电正常；不亮查供电或模块。

2. MyI2C 协议层（软件模拟 I2C）

2.1 MyI2C.c 的 MyI2C_Init：开漏输出 + 释放总线

void MyI2C_Init(void)
{
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;      /* 开漏输出 */
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);       /* 释放总线，置空闲高电平 */
}
  • 两个任务：SCL/SDA 初始化为开漏输出；再置高释放总线（空闲态）。
  • 开漏兼具输入输出，输出高电平＝释放引脚，正好符合 I2C 的线与 + 弱上拉。
  • 代码由 LED.c 的 GPIO 初始化改：端口 GPIOB、引脚 GPIO_Pin_10 | GPIO_Pin_11、模式 GPIO_Mode_Out_OD、速度 GPIO_Speed_50MHz，最后 GPIO_Init 与 GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11)。
  • GPIO_SetBits 这一行容易漏，不释放总线后续时序就从错误电平开始。

图 3：MyI2C_Init（GPIO_Mode_Out_OD、GPIO_Pin_10 | GPIO_Pin_11、GPIO_Speed_50MHz、GPIO_Init(GPIOB, …)、GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11)）；下方 MyI2C_Start 留着宏写法 GPIO_SetBits(SCL_PORT, SCL_PIN);

2.2 三个底层函数：W_SCL / W_SDA / R_SDA

void MyI2C_W_SCL(uint8_t BitValue)
{
    GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)BitValue);
    Delay_us(10);
}

/* W_SDA 同构：引脚换成 GPIO_Pin_11 */
void MyI2C_W_SDA(uint8_t BitValue)
{
    GPIO_WriteBit(GPIOB, GPIO_Pin_11, (BitAction)BitValue);
    Delay_us(10);
}

uint8_t MyI2C_R_SDA(void)
{
    uint8_t BitValue;
    BitValue = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11);
    Delay_us(10);
    return BitValue;
}
  • 签名：MyI2C_W_SCL(uint8_t BitValue)、MyI2C_W_SDA(uint8_t BitValue)、MyI2C_R_SDA()；内部就是 GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)BitValue) 与 GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11) 加 Delay_us(10)，即 GPIO_WriteBit 写、读回用 GPIO_ReadInputDataBit。
  • 不用宏（#define SCL_PORT GPIOB、#define SCL_PIN GPIO_Pin_10）的原因：SCL_PORT 这类写法语义不明、换引脚要改多处、主频高时不好加延时。
  • 函数封装好移植，只改这几个函数；Delay_us(10) 是经验值，F1 不加也能跑，换高主频芯片要按手册时序调。

图 4：MyI2C.c 顶部——#include "Delay.h"；void MyI2C_W_SCL(uint8_t BitValue) 里 GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)BitValue); + Delay_us(10);；下方 MyI2C_Init 末行 GPIO_SetBits

2.3 起始与终止

void MyI2C_Start(void)
{
    MyI2C_W_SDA(1);   /* 先释放 SDA，保证起始条件从高电平开始（保险） */
    MyI2C_W_SCL(1);
    MyI2C_W_SDA(0);   /* SCL 高电平期间 SDA 下降沿 = 起始条件 */
    MyI2C_W_SCL(0);   /* 随后拉低 SCL，占用总线，便于时序拼接 */
}

void MyI2C_Stop(void)
{
    MyI2C_W_SDA(0);   /* 先拉低 SDA，为上升沿做准备 */
    MyI2C_W_SCL(1);
    MyI2C_W_SDA(1);   /* SCL 高电平期间 SDA 上升沿 = 终止条件 */
}
  • 起始（MyI2C_Start()）SDA=1, SCL=1, SDA=0, SCL=0：先释放 SDA 是保险（否则没有下降沿），最后拉低 SCL 占用总线、让每个单元低电平开始、低电平结束。
  • 终止 SDA=0, SCL=1, SDA=1：SCL 高电平期间产生上升沿，结束后回到双高空闲态。

图 5：PPT「I2C时序」指定地址写页（上集内容，本集写代码时对照）——对于指定设备在指定地址下写入指定数据；下方是实测波形，标注 Send Byte: 0xD0 (Slave Address + R/W)、RA 0、Send Byte: 0x19 (Reg Address)、RA 0、Send Byte: 0xAA (Data)、RA 0、P；字幕「先看一下指定地址写」

图 6：MyI2C_Start（W_SDA(1); W_SCL(1); W_SDA(0); W_SCL(0);）与 MyI2C_Stop（W_SDA(0); W_SCL(1); W_SDA(1);）完整，下方 MyI2C_SendByte 首行 MyI2C_W_SDA(Byte & 0x80);（红笔标注）；字幕「0x80是1000 0000」

2.4 发送一个字节（高位先行）

void MyI2C_SendByte(uint8_t Byte)
{
    uint8_t i;
    for (i = 0; i < 8; i ++)
    {
        MyI2C_W_SDA(Byte & (0x80 >> i));   /* 取第 i 位（从最高位开始），非 0 即 1 */
        MyI2C_W_SCL(1);                    /* SCL 高电平：从机读取 */
        MyI2C_W_SCL(0);                    /* SCL 低电平：允许换下一位数据 */
    }
}
  • MyI2C_SendByte(uint8_t Byte) 的一行写法：for (i = 0; i < 8; i ++) { W_SDA(Byte & (0x80 >> i)); W_SCL(1); W_SCL(0); }。
  • Byte & 0x80：0x80 是 1000 0000，结果只取决于最高位，非 0 即 1，可直接传给 BitAction；不放心可写 if (Byte & 0x80) W_SDA(1); else W_SDA(0);。
  • 第 i 次用 0x80 >> i：i=0 取 B7、i=1 取 B6，高位先行；括号保证优先级。
  • SCL 低电平放数据、高电平从机读，所以只能在低电平期间改 W_SDA。

图 7：MyI2C_SendByte 首行高亮 MyI2C_W_SDA(Byte & 0x80);（准备改成 for 循环 + 0x80 >> i）；字幕「如果你不放心的话，也可以写」

2.5 接收一个字节

uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t Byte = 0x00;
    uint8_t i;
    MyI2C_W_SDA(1);                        /* 主机接收前必须释放 SDA */
    for (i = 0; i < 8; i ++)
    {
        MyI2C_W_SCL(1);                    /* SCL 高电平：主机读取 */
        if (MyI2C_R_SDA()) { Byte |= (0x80 >> i); }
        MyI2C_W_SCL(0);                    /* SCL 低电平：从机换下一位数据 */
    }
    return Byte;
}

来源：完整函数体未落在任何一帧画面里，按口述 21:30–24:30 与发送字节的对称结构整理。

  • MyI2C_ReceiveByte() 先 W_SDA(1) 释放 SDA，否则线与把总线拽低，从机发什么主机都读成 0。
  • SCL 低电平＝从机写数据、高电平＝主机读数据；数据位期间 SCL 高电平绝不许动 SDA，只有起始/终止才允许跳变。
  • 循环结构：W_SCL(1); if (R_SDA()) Byte |= (0x80 >> i); W_SCL(0);。
  • 答疑：主机没写过 SDA 却有变化，因为从机在低电平期间改 SDA。

2.6 发送应答 / 接收应答

void MyI2C_SendAck(uint8_t AckBit)
{
    MyI2C_W_SDA(AckBit);   /* 主机把应答位放到 SDA（0=应答、1=非应答） */
    MyI2C_W_SCL(1);
    MyI2C_W_SCL(0);
}

uint8_t MyI2C_ReceiveAck(void)
{
    uint8_t AckBit;
    MyI2C_W_SDA(1);        /* 主机先释放 SDA，交给从机应答 */
    MyI2C_W_SCL(1);
    AckBit = MyI2C_R_SDA(); /* 读应答位：0=从机应答、1=无应答 */
    MyI2C_W_SCL(0);
    return AckBit;
}

来源：这两个函数的完整函数体同样未逐行落帧，按口述 22:00–24:20 整理。

  • 发送应答 MyI2C_SendAck(uint8_t AckBit) 就三行 W_SDA(AckBit); W_SCL(1); W_SCL(0);；MyI2C_ReceiveAck() 则是先 W_SDA(1) 交还 SDA，再 W_SCL(1) 读、W_SCL(0) 收尾。
  • 主机置 1 后仍可能读到 0：引脚是开漏 + 弱上拉，从机可以把线拉低；0 = 应答、1 = 非应答。

3. 先验证时序：点名测试与 AD0 改名

3.1 「点名」时序

OLED_Init();
MyI2C_Init();

MyI2C_Start();
MyI2C_SendByte(0xD0);          // 1101 000 0：从机地址 + 写

  • 0xD0 = 1101 0000：高 7 位地址 1101000，最低位 0 表示写。
  • OLED 显示 0（MPU6050 给了应答），说明接线与时序都没问题。

图 8：main「点名」测试——OLED_Init(); MyI2C_Init();、MyI2C_Start();、MyI2C_SendByte(0xD0); // 1101 000 0、uint8_t Ack = MyI2C_ReceiveAck();、MyI2C_Stop();、OLED_ShowNum(1, 1, Ack, 3);；字幕「就是看看你这个人在不在」

3.2 寻址改错与 AD0 改名实验

  • 把寻址改成 0xA0（总线上没这个设备）→ 显示 1（无应答），符合预期；据此可做从机地址扫描。
  • AD0 飞线接高后，要用 1101001（0xD2 写 / 0xD3 读）才叫得应，改回 0xD0 又不理人。
  • 同一条总线挂多个同型号芯片时可靠 AD0 改地址避冲突；本芯片只有 AD0（2 个地址），有 AD0+AD1 则 4 个。

4.2 写寄存器 MPU6050_WriteReg

#include "MyI2C.h"

#define MPU6050_ADDRESS 0xD0

void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data)
{
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDRESS);   /* 从机地址 + 写 */
    MyI2C_ReceiveAck();
    MyI2C_SendByte(RegAddress);        /* 寄存器地址 */
    MyI2C_ReceiveAck();
    MyI2C_SendByte(Data);              /* 写入的数据 */
    MyI2C_ReceiveAck();
    MyI2C_Stop();
}
  • 完整对应 P31 的「指定地址写」：S → 地址+W → RA → 寄存器地址 → RA → 数据 → RA → P。
  • 每字节后都调 ReceiveAck() 收应答，但不判断返回值——展开写会增加很多代码，为保证时序结构清晰这里不判断。
  • 进阶（未实现）：写多字节就是把「发送一个字节 + 接收应答」用 for 重复、数组依次发出。

图 10：MPU6050.c 里 #include "MyI2C.h"、#define MPU6050_ADDRESS 0xD0，void MPU6050_WriteReg(uint8_t RegAddress, uint8_t Data) 完整九行；下方 MPU6050_Init 开头 MyI2C_Init();

4.3 读寄存器 MPU6050_ReadReg

uint8_t MPU6050_ReadReg(uint8_t RegAddress)
{
    uint8_t Data;

    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDRESS);   /* 先写：只指定寄存器地址 */
    MyI2C_ReceiveAck();
    MyI2C_SendByte(RegAddress);
    MyI2C_ReceiveAck();

    MyI2C_Start();                     /* 重复起始 Sr：切换读写方向 */
    MyI2C_SendByte(MPU6050_ADDRESS | 0x01);  /* 地址 + 读 = 0xD1 */
    MyI2C_ReceiveAck();
    Data = MyI2C_ReceiveByte();
    MyI2C_SendAck(1);                  /* 最后一个字节给非应答 */
    MyI2C_Stop();

    return Data;
}
  • 前半段和 MPU6050_WriteReg(RegAddress, Data) 一模一样（MyI2C_Start(); SendByte(MPU6050_ADDRESS); ReceiveAck(); SendByte(RegAddress); ReceiveAck();），MPU6050_ReadReg(RegAddress) 只是后面换成收数据；设完地址要转读，必须重新起始（Sr）、重新指定读写位。
  • MPU6050_ADDRESS | 0x01：0xD0 或上 1 变成 0xD1（读）。
  • Data = MyI2C_ReceiveByte() 后必须 MyI2C_SendAck(1) 非应答，否则从机继续占 SDA、Stop 可能产生不了；连读时前面应答、最后一个非应答。
  • 进阶（未实现）：从 0x3B 起连读 14 字节一次取完 6 轴。

图 11：MPU6050_ReadReg(uint8_t RegAddress) 完整，重复起始处高亮；SendByte(MPU6050_ADDRESS | 0x01); ReceiveAck(); MyI2C_ReceiveByte();

4.4 验证读写寄存器

OLED_Init();
MPU6050_Init();

MPU6050_WriteReg(0x6B, 0x00);        /* PWR_MGMT_1：解除睡眠 */

5. MPU6050_Init 与 MPU6050_GetData

5.1 初始化配置六条

void MPU6050_Init(void)
{
    MyI2C_Init();                                       /* 底层初始化 */
    MPU6050_WriteReg(MPU6050_PWR_MGMT_1, 0x01);         /* 解睡 + 时钟选陀螺 PLL */
    MPU6050_WriteReg(MPU6050_PWR_MGMT_2, 0x00);         /* 各轴不待机 */
    MPU6050_WriteReg(MPU6050_SMPLRT_DIV, 0x09);         /* 采样率分频 */
    MPU6050_WriteReg(MPU6050_CONFIG, 0x06);             /* 数字低通滤波 */
    MPU6050_WriteReg(MPU6050_GYRO_CONFIG, 0x18);        /* 陀螺 ±2000°/s */
    MPU6050_WriteReg(MPU6050_ACCEL_CONFIG, 0x18);       /* 加速度 ±16g */
}
  • 六条配置即 PWR_MGMT_1 = 0x01、PWR_MGMT_2 = 0x00、SMPLRT_DIV = 0x09、CONFIG = 0x06、GYRO_CONFIG = 0x18、ACCEL_CONFIG = 0x18。
寄存器 值 含义
PWR_MGMT_1 0x01 清 SLEEP（解除睡眠）+ CLKSEL = 1（选 X 轴陀螺 PLL 作时钟源）
PWR_MGMT_2 0x00 低 6 位全 0 → 六轴都不进入待机
SMPLRT_DIV 0x09 采样分频：值越小采样越快（按实际需求调）
CONFIG 0x06 EXT_SYNC 全 0 + DLPF_CFG = 6（开数字低通滤波，输出更平滑）
GYRO_CONFIG 0x18 自测位全 0 + FS_SEL = 3 → ±2000 °/s
ACCEL_CONFIG 0x18 自测位全 0 + AFS_SEL = 3 → ±16 g（高通滤波位为 0）
  • 寄存器宏名来自 MPU6050_Reg.h；按 P32 手册：0x18 = 0001 1000（自测位 0、满量程选择位 11），0x01 = 0000 0001（解睡 + 时钟源 1）。

5.2 MPU6050_GetData：指针返回 6 个值

void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ,
                     int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ)
{
    uint8_t DataH, DataL;

    DataH = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_H);
    DataL = MPU6050_ReadReg(MPU6050_ACCEL_XOUT_L);
    *AccX = (DataH << 8) | DataL;

    /* Y/Z 轴、以及 GYRO_X/Y/Z 同理：各自读 _H 与 _L，再 (DataH << 8) | DataL */
    ...
}
  • 原型 void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ, int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ)：6 个返回值用指针传地址（另两种办法用全局变量、结构体打包）；函数体里 uint8_t DataH, DataL; 先读两个字节。
  • 每个轴读高字节 _H、低字节 _L，再 (DataH << 8) | DataL 拼成 16 位，经指针写回主函数。
  • 即 DataH = ReadReg(ACCEL_XOUT_H); DataL = ReadReg(ACCEL_XOUT_L); *AccX = (DataH << 8) | DataL;。
  • DataH 是 uint8_t，左移 8 位不丢位：赋值目标是 int16_t（16 位补码）；不放心可把中间变量改成 16 位。

7. 分层架构总结

  • 最底层 I2C 协议层（MyI2C）：引脚是哪两个、什么配置、时序怎么写。
  • 中间层 MPU6050 驱动层：如何读写寄存器、怎么配置、怎么取数。
  • 应用层 main：只调 MPU6050_GetData 这样的函数。
  • 意义：每层只管自己的事，移植只改对应层，代码好管理、好复用。

坑与易错点

  1. SCL/SDA 是 PB10/PB11，别和串口 PA9/PA10 混；要与代码里的 GPIO_Pin_x 一致。
  2. GPIO 必须配开漏输出 GPIO_Mode_Out_OD：I2C 靠开漏 + 上拉做线与，推挽会出问题。
  3. 初始化最后要 GPIO_SetBits 释放总线（GPIO_SetBits(...)），否则起始电平不对。
  4. Delay_us(10) 是经验值：F1 不加也能跑，换高主频芯片按手册时序调。
  5. 起始条件前先 W_SDA(1)，否则 SDA 本来是低电平，产生不了下降沿。
  6. 高位先行：Byte & (0x80 >> i) 从 B7 到 B0，与串口低位先行相反。
  7. 读字节/读应答前先 W_SDA(1) 释放 SDA，否则线与把总线拽低、从机发不出来。
  8. 应答 0 = ACK、1 = NACK：主机置 1 后仍可能读到 0。
  9. 读寄存器要用重复起始：Start() → 地址|0x01，读写方向只能在起始后指定。
  10. 读最后 1 个字节必须给非应答 SendAck(1)，否则从机继续发、Stop 可能不生效。
  11. 写寄存器前先解除睡眠：WriteReg(PWR_MGMT_1, 0x00)（或 0x01），否则所有写无效。
  12. DataH << 8 | DataL 要拼成 int16 有符号值；uint8_t 移位后赋给 int16 不丢位。
  13. 现象不是精确 0/1g：AX≈+122 有零偏、AZ≈1944≈0.95g，传感器与安装误差属正常。
  14. 多字节读写本集没写代码：写多字节、读 0x3B 起 14 字节都只提了思路。
