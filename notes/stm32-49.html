一句话结论

三级分层架构（作者红笔三框）：最上层 应用层（只管把参数写进 Store 的数组、什么时候保存）→ 中间 Store 层（一个 uint16_t Store_Data[512] 数组 + Store_Init / Store_Save / Store_Clear，负责「存哪些、什么时候存、首次怎么初始化」）→ 最底层 MyFLASH 层（只做读 / 擦除 / 编程这些原始操作，把库函数再包一层）——目标是「应用层不关心存在哪、怎么擦、什么读写策略」。⚠ 作者原话：「这个思路是我自己想的，并不是固定的」——这是一种推荐做法，不是官方范式。MyFLASH 模块：没有 Init 函数（FLASH 不需要初始化）；三个读函数都是一句返回——MyFLASH_ReadWord：return *((__IO uint32_t *)(Address));、ReadHalfWord（uint16）、ReadByte（uint8）——地址直接用参数、不需要加任何偏移（不像外设寄存器要加偏移量）；擦除/编程四个函数全是同一套路三行：FLASH_Unlock(); → 调对应库函数 → FLASH_Lock();（作者点评「我们就是再包装一下，并没有太多操作」）。FLASH_Status 五个状态（stm32f10x_flash.h）：FLASH_BUSY = 1、FLASH_ERROR_PG、FLASH_ERROR_WRP、FLASH_COMPLETE、FLASH_TIMEOUT（等待超时）——擦除/编程函数都返回它；这些库函数内部已经包含「等待忙」（FLASH_WaitForLastOperation），但不含解锁/加锁，所以解锁加锁要自己调。Store 模块（关键设计）：uint16_t Store_Data[512];（类型与闪存半字统一）；第 0 个元素当标志位、千万不要当数据使用；标志值 0xA5A5（因为闪存擦除后默认全是 FF，据此判断是不是首次上电）；Store_Init() 做两件事——①首次运行：读第 0 个半字 ≠ 0xA5A5 就擦页 + 写标志 0xA5A5 + 其余 511 个半字全写 0；②每次上电：for 循环把整个闪存区数据转存到 SRAM 数组（Store_Data[i] = MyFLASH_ReadHalfWord(0x0800FC00 + i * 2);）；Store_Save()＝MyFLASH_ErasePage(0x0800FC00) + for 循环把整个数组写回闪存；Store_Clear() 清空；存储起始地址 0x0800FC00（C8T6 最后一页＝页 63）。读取自证实验（很值得保留）：从 0x08000010（程序自身起始）分别按 32 / 16 / 8 位读同一地址 → OLED 显示 08000569 / 0569 / 69——既验证「用程序读程序自己」，又演示了小端字节序（内存里是 69 05 00 08）。应用层 main：OLED_Init(); Key_Init(); Store_Init();；Key1 → Store_Data[1] ++; Store_Data[2] += 2; Store_Data[3] += 3; Store_Data[4] += 4; Store_Save();；Key2 → Store_Clear();；主循环显示 Store_Data[0]～Store_Data[4]。现象：断电/复位后数据保持；每次按键递增后 Save，再断电重启值仍在——与 P48 片头演示一致。地址规划（实战要点）：把「存储区起始地址」抽成宏（STORE_START_ADDRESS 之类）替换所有硬编码 0x0800FC00——大量出现的可配置参数一定要定义宏；用 Keil Target → Read/Only Memory Areas 看 IROM1 范围（0x8000000 / Size 0x10000 ＝ 默认全部 64K）、IRAM1（0x20000000/0x5000），再看编译输出 Program Size（本例 2664 字节 ≈ 2.6KB）——据此规划用户数据区，避开程序区。15-2 读取芯片ID：复制 15-1 改名；OLED_ShowString(1, 1, "F_SIZE:") + OLED_ShowHexNum(1, 8, *((__IO uint16_t *)(0x1FFFF7E0)), 4) → 显示 0040＝64K；OLED_ShowString(2, 1, "U_ID:") + 按 16 位分别读 0x1FFFF7E8、+0x02（再往下可 +0x04），再按 32 位读（偏移 0x08、显示长度 8）——地址偏移运算必须加括号（否则指针强制类型转换的优先级出错）。实测每片芯片数据都不一样。

0. 本集定位：代码课（分层封装 + 两个工程）

  • 15-1 读写内部FLASH：复制 OLED 显示屏工程 → 改名 → 分层规划 → 讲库函数 → 新建 MyFLASH.c/h、Store.c/h 两个模块逐段写码 → 下载验证；
  • 15-2 读取芯片ID：复制 15-1 改名 → 写读 F_SIZE / UID 的代码；

1. 分层架构规划

  • 作者在 main.c 上用红笔画出三个框：应用层 → Store → MyFLASH（箭头表示调用方向）；
  • 分工：
    • 应用层：只管「把要保存的参数写到 Store 层的数组里」、什么时候调用保存；
    • Store 层：维护数组 + 提供 Init / Save / Clear，决定「存哪些、怎么组织、首次怎么初始化」；
    • MyFLASH 层：只做读 / 擦除 / 编程的原始操作；
  • 好处：应用层完全不关心数据存在哪个地址、怎么擦、什么读写策略——这就是「分层封装」的意义；
  • ⚠ 作者原话：「这个思路是我自己想的，并不是固定的」——这是推荐做法，不是固定范式。

图 1：main.c + 红笔三框分层规划——左侧应用层（OLED_Init(); while(1){}）、中间 Store 层、右侧 MyFLASH 层，红箭头标出调用方向；字幕「想要保存参数，就写到 Store 层的数组」

2. 先回顾 Flash 读写流程与工具

  • PPT 回顾 P48 的流程图（读 / 页擦除 / 全擦除 / 编程 + 选项字节），强调「这些功能分别对应一个库函数」；
  • 选项字节本课不作要求：手工配置更简单——用 ST-LINK Utility 的 Target → Option Bytes 勾选后 Apply 即可；
  • ⚠ 芯片自锁风险（本集最有价值的坑）：用代码配置读写保护容易把芯片锁死——写了写保护但程序里没预留解除代码，芯片就无法再下载程序；此时只能靠 ST-LINK Utility 打开 Target → Option Bytes、去掉读写保护后 Apply 来救活。所以作者的结论是：选项字节本课不作要求，少量需求直接用这个软件配置更方便。

图 2：ST-LINK Utility 读闪存——Memory display：Address 0x08000000、Size 0x10000、Data Width 下拉可选 8 bits / 16 bits / 32 bits；右侧信息 Device STM32F10xx Medium-density、Device ID 0x410、Flash size 64KBytes；下方地址 0x08000000～0x08000070 的数据表与日志（Connected via SWD、SWD Frequency = 4.0 MHz）；字幕「还是以16位或8位的形式显示」

3. 库函数速览（stm32f10x_flash）

3.1 文件头说明

  • stm32f10x_flash.c 文件头：This driver provides functions to configure and program the Flash memory of all STM32F10x devices…；
  • XL 大容量是双 bank（bank1: fixed size of 512 Kbytes (256 pages of 2Kbytes each)、bank2: up to 512 Kbytes）支持 RWW（读写同时）；其他型号只有单 bank、最大 512K；
  • V3.3.0 起部分函数兼容所有型号、部分仅 XL 专用。

3.2 FLASH_Status 五值

typedef enum
{
  FLASH_BUSY = 1,      /* 忙 */
  FLASH_ERROR_PG,      /* 编程错误 */
  FLASH_ERROR_WRP,     /* 写保护错误 */
  FLASH_COMPLETE,      /* 完成 */
  FLASH_TIMEOUT        /* 等待超时 */
} FLASH_Status;
  • 擦除/编程函数都返回这个枚举告知操作状态（不想关心状态可以忽略）。

3.3 主要库函数

函数 用途
FLASH_SetLatency / FLASH_PrefetchBufferCmd / FLASH_HalfCycleAccessCmd 与内核执行代码有关，不用管
FLASH_Unlock() / FLASH_Lock() 解锁 / 加锁（键寄存器写 KEY1、KEY2 / 置 LOCK 位）
FLASH_ErasePage(Page_Address) 页擦除（需给页起始地址）
FLASH_EraseAllPages() 全擦除
FLASH_EraseOptionBytes() 擦除选项字节
FLASH_ProgramWord(Address, Data) 字编程（内部就是写两次半字）
FLASH_ProgramHalfWord(Address, Data) 半字编程
FLASH_ProgramOptionByteData + 选项字节 4 个写函数 + FLASH_GetReadOutProtectionStatus / GetWriteProtectionOptionByte 选项字节相关
FLASH_GetFlagStatus / FLASH_ClearFlag 标志位
  • 关键：这些函数内部已经包含「等待忙」：
    • FLASH_ErasePage 内部＝事前等待 → 置 PER → 写 FLASH_AR → 置 STRT → 事后等待 → 最后把 PER 清零；
    • FLASH_ProgramHalfWord 内部＝事前等待 → 置 PG → 地址强转指针再取内容赋值 → 事后等待；
  • 均不含解锁/加锁——要自己调 FLASH_Unlock() / FLASH_Lock()。

4. 写 MyFLASH 模块（底层原始操作）

4.1 建模块与「无 Init」

  • 在工程 System 组下新建 MyFLASH.c / MyFLASH.h；
  • MyFLASH 没有 Init 函数——FLASH 不需要初始化（原话「FLASH 不需要初始化」）。

4.2 三个读函数（一句返回，地址不加偏移）

uint32_t MyFLASH_ReadWord(uint32_t Address)
{
    return *((__IO uint32_t *)(Address));
}

uint16_t MyFLASH_ReadHalfWord(uint32_t Address)
{
    return *((__IO uint16_t *)(Address));
}

uint8_t MyFLASH_ReadByte(uint32_t Address)
{
    return *((__IO uint8_t *)(Address));
}
  • 地址直接用参数、不需要加偏移（与外设寄存器「基地址+偏移」的写法不同——这里就是绝对地址）；
  • main 里测试：从 0x08000000 分别用三种宽度读同一地址并显示。

4.3 擦除 / 编程（三行式封装）

void MyFLASH_EraseAllPages(void)
{
    FLASH_Unlock();
    FLASH_EraseAllPages();
    FLASH_Lock();
}

void MyFLASH_ErasePage(uint32_t PageAddress)
{
    FLASH_Unlock();
    FLASH_ErasePage(PageAddress);
    FLASH_Lock();
}

void MyFLASH_ProgramWord(uint32_t Address, uint32_t Data)
{
    FLASH_Unlock();
    FLASH_ProgramWord(Address, Data);
    FLASH_Lock();
}

void MyFLASH_ProgramHalfWord(uint32_t Address, uint16_t Data)
{
    FLASH_Unlock();
    FLASH_ProgramHalfWord(Address, Data);
    FLASH_Lock();
}
  • 四个函数全是同一套路：解锁 → 调库函数 → 加锁（作者点评「我们就是再包装一下，并没有太多操作」）；
  • ⚠ 提示：写字节很麻烦，最好用「缓冲区」方式实现——先在 SRAM 改好整块，再整页写回。

5. 写 Store 模块（中间层）

5.1 数组与首元素标志位

#include "stm32f10x.h"
#include "MyFLASH.h"

uint16_t Store_Data[512];     /* 类型与闪存半字统一 */
  • 数组元素类型用 uint16_t，因为闪存只能按半字写（统一后最方便）；
  • 数组第 0 个元素是「标志位」，千万不要当数据使用；
  • 标志值 0xA5A5——因为闪存擦除后默认全是 FF，用它判断「是否已经初始化过」。

5.2 Store_Init：首次初始化 + 每次上电转存

void Store_Init(void)
{
    /* ① 首次上电：闪存还没初始化（第 0 个半字不是 0xA5A5） */
    if (MyFLASH_ReadHalfWord(0x0800FC00) != 0xA5A5)
    {
        MyFLASH_ErasePage(0x0800FC00);                 /* 先擦整页 */
        MyFLASH_ProgramHalfWord(0x0800FC00, 0xA5A5);   /* 写标志位 */

        for (uint16_t i = 1; i < 512; i ++)            /* 其余 511 个半字清零 */
        {
            MyFLASH_ProgramHalfWord(0x0800FC00 + i * 2, 0x0000);
        }
    }

    /* ② 每次上电：把闪存里的数据整体转存到 SRAM 数组 */
    for (uint16_t i = 0; i < 512; i ++)
    {
        Store_Data[i] = MyFLASH_ReadHalfWord(0x0800FC00 + i * 2);
    }
}
  • 存储起始地址 0x0800FC00＝C8T6 的最后一页（页 63）；
  • 注意偏移是 + i * 2（半字＝2 字节）。

5.3 Store_Save 与 Store_Clear

void Store_Save(void)
{
    MyFLASH_ErasePage(0x0800FC00);                     /* 整页擦除 */

    for (uint16_t i = 0; i < 512; i ++)                /* 整块写回 */
    {
        MyFLASH_ProgramHalfWord(0x0800FC00 + i * 2, Store_Data[i]);
    }
}

void Store_Clear(void)
{
    for (uint16_t i = 1; i < 512; i ++) { Store_Data[i] = 0x0000; }   /* 保留第 0 个标志位 */
    Store_Save();
}
  • Store_Save = 擦页 + 整块写回——所以保存一次就要擦写整页，别高频调用（闪存寿命 + CPU 暂停）；
  • Store_Clear 不要清掉第 0 个标志位（否则下次初始化会重新擦写）。

坑与易错点

  1. 分层思路是作者自创的（原话「这个思路是我自己想的，并不是固定的」）——推荐做法，不是固定范式。
  2. MyFLASH 没有 Init 函数：FLASH 不需要初始化。
  3. 读函数的地址直接用参数、不加偏移（与外设寄存器写法不同）。
  4. FLASH_Status 五值写准：FLASH_BUSY = 1、ERROR_PG、ERROR_WRP、COMPLETE、TIMEOUT；擦除/编程函数内部已含等待忙，但不含解锁/加锁。
  5. 四个封装函数都是三行式：FLASH_Unlock() → 库函数 → FLASH_Lock()。
  6. Store_Data[512] 第 0 个元素是标志位，千万不要当数据用；标志 0xA5A5（擦除后全 FF 可判首次）。
  7. 存储地址 0x0800FC00＝C8T6 最后一页（页 63）；半字偏移是 i * 2。
  8. Store_Init 做两件事：首次擦页+写标志+清零；每次上电整体转存到 SRAM。
  9. Store_Save = 擦整页 + 整块写回——别高频调用（闪存寿命 + CPU 暂停）。
  10. Store_Clear 别清第 0 个标志位，否则下次上电会重走初始化。
  11. 全擦除会把程序自己擦掉（按 Key1 后按键全无反应）——既是现象也是风险。
  12. 代码配读写保护容易芯片自锁：只能靠 ST-LINK Utility → Target → Option Bytes → 去掉保护后 Apply 救活；故选项字节本课不作要求。
  13. 地址偏移必须加括号：(0x1FFFF7E8 + 0x02)，否则指针类型转换优先级出错。
  14. 存储区起始地址要抽成宏，并用 IROM1 0x8000000/0x10000 + Program Size（本例 2664B≈2.6KB） 规划，避免与程序区冲突。
  15. 8/16/32 位读同一地址得 69/0569/08000569——顺带验证小端字节序（内存 69 05 00 08）。
