一句话结论

本集把 P26 的 USART 外设理论落成两个工程。接线：USB 转串口模块的跳线帽插在 VCC-3V3（选 3.3V TTL 电平，STM32 是 3.3V 器件），模块 RXD → PA9（PA9 是 STM32 的 TX，发送接对方接收，要交叉）、模块 TXD → PA10（PA10 是 STM32 的 RX）、GND 共地（单端信号必须共地才能比较电平）；两边都有独立供电，电源正极不接，两个程序接线完全一样。程序一 9-1 串口发送 由 OLED 工程复制、新建 Serial.c/Serial.h。Serial_Init 四步：① RCC_APB2PeriphClockCmd 开 USART1 与 GPIOA 时钟（USART1 是 APB2 外设）② GPIO 配 PA9 为 GPIO_Mode_AF_PP 复用推挽输出（引脚定义表：USART1 TX=PA9、RX=PA10；若用 USART2/3 要查对应引脚）③ USART_Init 六成员：USART_BaudRate = 9600、USART_HardwareFlowControl = USART_HardwareFlowControl_None、USART_Mode = USART_Mode_Tx（接收时 Tx | Rx）、USART_Parity = USART_Parity_No、USART_StopBits = USART_StopBits_1、USART_WordLength = USART_WordLength_8b ④ USART_Cmd(USART1, ENABLE)（要接收就再加 USART_ITConfig + NVIC）。发送一个字节 Serial_SendByte：USART_SendData(USART1, Byte) 把数据写进 DR（库函数内部就是 USARTx->DR = (Data & 0x01FF)），然后必须等 USART_FLAG_TXE 置 1——while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);，因为数据从 TDR 转移到移位寄存器之前不能写下一个、否则会覆盖；而 TXE 在对 DR 的写操作时由硬件自动清零（手册 SR 位7），所以不用手动清标志位。在这个基础上封装：Serial_SendArray(uint8_t *Array, uint16_t Length)（for 循环逐个发）、Serial_SendString(char *String)（循环到 '\0'，字符串末尾编译器自动补结束标志、所以存储空间比字符数大 1）、Serial_SendNumber(uint32_t Number, uint8_t Length)（先自己写 Serial_Pow 次方函数，用 Number / Serial_Pow(10, Length - i - 1) % 10 + '0' 逐位取出并转成 ASCII 字符；Serial_Pow 不是库函数）。printf 三种移植方法（①最常用）：① 勾选 Keil 工程的「Use MicroLIB」，在 Serial.c 里 #include <stdio.h> 并重写 int fputc(int ch, FILE *f){ Serial_SendByte(ch); return ch; }——printf 底层就是往 fputc 输出字符，重定向后 printf 就打到串口了；② sprintf 格式化到字符串数组、再 Serial_SendString（不需要重定向）；③ 自己封装 Serial_Printf(char *format, ...)（va_list / va_start / vsprintf / va_end，要 #include <stdarg.h>）。中文乱码：要么 Keil 与串口助手都用 UTF8，并在 C/C++ 杂项里加 --no-multibyte-chars；要么两边都用 GB2312/GBK（不用加参数，兼容性更好）。程序二 9-2 串口发送+接收 由 9-1 复制、接线不变：GPIO 增加 PA10 配 GPIO_Mode_IPU 上拉输入（也可浮空，串口空闲是高电平所以不用下拉）、USART_Mode = USART_Mode_Tx | USART_Mode_Rx。接收有两种写法：查询法——主循环 if (USART_GetFlagStatus(USART1, USART_FLAG_RXNE) == SET) { RxData = USART_ReceiveData(USART1); ... }，读 DR 会自动清 RXNE；中断法——USART_ITConfig(USART1, USART_IT_RXNE, ENABLE) + NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2) + NVIC_Init（通道 USART1_IRQn、抢占 1、子优先级 1—先随便给），在 USART1_IRQHandler 里读 DR 存到全局变量、置接收标志、调 USART_ClearITPendingBit 清挂起位，再封装 Serial_GetRxFlag()（读到标志后自动清零）与 Serial_GetRxData()。现象：串口助手 HEX 模式发 41 → OLED 显示 41、同时把 41 回传电脑；发 42 同理。

1. 接线与工程准备

1.1 接线：模块 RXD→PA9、TXD→PA10、GND 共地

  • 跳线帽：USB 转串口模块上的跳线帽要插在 VCC 和 3V3 这两个脚上，选择通信的 TTL 电平为 3.3V（上一集 P26 讲过：跳线帽既选电平又给 CH340 供电）；如果不是就拔下来换到这个位置；
  • 通信引脚：模块的 TXD 和 RXD 要接到 STM32 的 PA9 和 PA10——为什么是这两个？查引脚定义表：USART1 的 TX 是 PA9、RX 是 PA10；我们计划用 USART1 通信，所以选这两个；如果要用 USART2/3，就要在表里找对应引脚；
  • TX 和 RX 要交叉连接（这一点一定要注意、别接错）：PA9 是 STM32 的 TX（发送），接的是串口模块的 RXD（接收）；模块的 TXD（发送）接 STM32 的 PA10（RX，接收）；
  • GND 共地：两个设备之间要把负极接在一起——单端信号是相对 GND 的电压，只有共地电平才有高低的参考（「就像两个人比身高，必须站在同一地平面上」）；一般多个系统互连都要共地；
  • 供电：串口模块和 ST-Link 都插在电脑上，两边都有独立供电，所以通信的电源正极不需要接，只接 3 根线；
  • 第一个程序只有 STM32 发送，所以理论上一根通信线就够；但第二个程序要接收，两根都要接——为了两个程序接线一致，干脆把两根都接上；
  • 面包板接线：串口模块用 3 根公对母杜邦线：棕色 = GND → 电源负极、红色 = RXD → PA9、橙色 = TXD → PA10；两个 USB 都插电脑（USB 口不够可用拓展坞）；
  • 驱动检查：此电脑 → 属性 → 设备管理器，端口目录下能看到 USB-SERIAL CH340（COM12）、有 COM 号且图标没有感叹号就说明驱动正常；否则要装驱动（第二节软件安装里讲过）。

图 1：接线图 9-1 串口发送——右下是 USB 转串口模块（5V/VCC/3V3/TXD/RXD/GND，红圈标出跳线帽插在 VCC-3V3 上），画面用蓝/黄/绿杜邦线（口述里说的棕/红/橙是另一种配色，见存疑），把 GND→电源负极、RXD→PA9、TXD→PA10 接起来；上方是 STM32 最小系统板与 OLED；字幕「要插在VCC和3V3这两个脚上，选择通信的TTL电平为3.3V」

1.2 工程准备

  • 复制 OLED 工程，改名 9-1 串口发送，删掉原来的代码、编译；
  • 老规矩给串口新建模块：Serial.c / Serial.h，在 Serial.c 里写 void Serial_Init(void)；
  • 初始化流程（照 P26 的 USART 基本结构图）：① 开 USART 和 GPIO 时钟 → ② 配 GPIO 引脚 → ③ 用 USART_Init 结构体配 USART 参数 → ④ USART_Cmd 开启；如果还需要接收，就在开启 USART 之前再加 USART_ITConfig 和 NVIC 的代码——「整个初始化流程非常中规中矩」；
  • 初始化完成后：发送数据调发送函数、接收数据调接收函数、获取发送/接收状态调获取标志位的函数——这就是 USART 外设的使用思路。

2. Serial_Init：程序一（只发送）

2.1 时钟与 GPIO

#include "stm32f10x.h"
#include <stdio.h>

void Serial_Init(void)
{
    /* ① 时钟：USART1 是 APB2 外设，GPIOA 也在 APB2 */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    /* ② GPIO：PA9（USART1_TX）复用推挽输出 */
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
    ...
  • USART1 挂在 APB2 上，所以开时钟用 RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE)；GPIOA 也在 APB2，一起开；
  • GPIO 引脚：从 LED.c 复制初始化代码，改成 GPIO_Mode_AF_PP（复用推挽）、GPIO_Pin_9、GPIO_Speed_50MHz；
  • 关于接收引脚 RX 的配置：普通输入模式和复用功能输入模式在库函数里是混在一起的，不用分——所以 RX 引脚就按普通输入配（浮空输入或上拉输入）：串口空闲状态是高电平，所以不能用下拉；具体用哪种可以看手册的「GPIO 配置推荐表」（一般：复用功能输出选复用推挽、输入选浮空或上拉均可）；
  • 本程序只需要发送（用不到 RX 引脚），所以只配 PA9。

图 2：Serial.c 开头——#include "stm32f10x.h"、void Serial_Init(void)、RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE); 与 RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);；左侧项目树 9-1 串口发送 的 Hardware 组下新增 Serial.c/Serial.h

2.2 USART_Init 六成员与 USART_Cmd

    USART_InitTypeDef USART_InitStructure;
    USART_InitStructure.USART_BaudRate = 9600;
    USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
    USART_InitStructure.USART_Mode = USART_Mode_Tx;
    USART_InitStructure.USART_Parity = USART_Parity_No;
    USART_InitStructure.USART_StopBits = USART_StopBits_1;
    USART_InitStructure.USART_WordLength = USART_WordLength_8b;
    USART_Init(USART1, &USART_InitStructure);

    USART_Cmd(USART1, ENABLE);
}
成员 程序一取值 说明
USART_BaudRate 9600 直接写波特率数值，USART_Init 内部会自动算好对应的分频系数（P26 的 BRR/DIV），不用自己算
USART_HardwareFlowControl USART_HardwareFlowControl_None 可选 None / CTS / RTS / CTS+RTS；我们不用流控，选 None
USART_Mode USART_Mode_Tx 可选 Tx / Rx；同时收发就 Tx | Rx；本程序只发送，选 Tx
USART_Parity USART_Parity_No 无校验 / 奇校验 / 偶校验；选无校验
USART_StopBits USART_StopBits_1 0.5 / 1 / 1.5 / 2 位；一般用 1 位
USART_WordLength USART_WordLength_8b 8 位 / 9 位（含校验位）；不需要校验就选 8 位
  • 组合起来就是最常用的参数：9600、8 位数据、1 位停止、无校验、无流控；
  • 最后 USART_Cmd(USART1, ENABLE); 开启 USART，初始化完成。

3. 发送一个字节：Serial_SendByte

void Serial_SendByte(uint8_t Byte)
{
    USART_SendData(USART1, Byte);
    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);
}
  • USART_SendData(USART1, Byte)：把数据写进 USART 的 DR 寄存器；看库函数源码，它内部就是 USARTx->DR = (Data & (uint16_t)0x01FF);（把高 7 位清零，只保留 9 位数据）；
  • 写完之后数据会通向 TDR → 再由硬件转移到发送移位寄存器 → 通过 TX 引脚发送出去——这一步单片机内部软硬件高度配合，我们不用管；
  • 为什么调用完还要 while 等待：数据从 TDR 转移到移位寄存器之前，不能再写下一个，否则会数据覆盖——所以写完 DR 要等 USART_FLAG_TXE（发送数据寄存器空）置 1 再返回；
  • USART_GetFlagStatus(USART1, USART_FLAG_TXE)：第一个参数选 USART，第二个参数选要检查的标志位——可选的有 CTS（CTS 改变）、LBD（LIN 断开检测）、TXE（发送数据寄存器空）、TC（发送完成）、RXNE（接收数据寄存器非空）、IDLE（空闲检测）、ORE（溢出错误）、NE（噪声错误）、FE（帧错误）、PE（校验错误）；
  • TXE 需要手动清零吗？不用：看手册 SR 位7 TXE——「当 TDR 寄存器中的数据被硬件转移到移位寄存器的时候，该位被硬件置位；如果 USART_CR1 中的 TXEIE 为 1 则产生中断；对 USART_DR 的写操作，将该位清零」——所以写 DR 时它自动清零，下次发送前会自动置位。

图 5：stm32f10x_usart.c 里 USART_SendData 的源码——void USART_SendData(USART_TypeDef* USARTx, uint16_t Data)，函数体 USARTx->DR = (Data & (uint16_t)0x01FF);（高亮）；字幕「要想学好单片机，程序思维和电路分析都是必不可少的」

图 6：USART_GetFlagStatus 的注释参数列表——@arg USART_FLAG_CTS、LBD、USART_FLAG_TXE（高亮）、TC、RXNE、IDLE、ORE、NE、FE、PE；字幕「复制，放到这里」

*图 7：参考手册 USART_SR 位说明——位7 TXE（发送数据寄存器空）：TDR 数据被硬件转移到移位寄存器时置位、TXEIE=1 产生中断、对 USART_DR 的写操作将该位清零、单缓冲器传输中使用；位6 TC（发送完成）；位5 RXNE（读数据寄存器非空）：RDR 数据转移到 USART_DR 时置位、读 DR 可清零*

3.1 现象：串口助手看发送

  • 把 Serial_Init、Serial_SendByte 放头文件声明、编译；main 里先 Serial_Init() 再 Serial_SendByte(0x41)——上电初始化后就会通过串口发一次 0x41，TX 引脚产生波形；
  • 打开串口助手：选 COM 号，其他参数要与程序一致——波特率 9600、数据位 8、停止位 1、校验位无；按 STM32 复位后收到 41；
  • 接收模式：HEX 模式显示的是原始数据 41；文本模式会按字符集解析，0x41 对应字符 A——这就是 P25 讲过的「HEX/文本」区别。

4. 数据模式与 ASCII 码表

  • HEX 模式 / 十六进制模式 / 二进制模式：以原始数据的形式显示——数据是什么就显示什么（只能显示 0～9、A～F 这些十六进制字符）；
  • 文本模式 / 字符模式：以原始数据编码后的形式显示——把每个字节按字符集编码查表、显示对应的字符；
  • ASCII 码表：0x41 = A、0x61 = a、0x30～0x39 = 0～9、各种标点符号，还有不可见字符（0x00 空字符、\r=0x0D、\n=0x0A、\t=0x09 等）；0x00 在字符串里是结束标志；
  • 汉字等多字节字符：ASCII 只有英文，中文要用 GB2312/GBK/GB18030 或 Unicode/UTF8 等字符集——「对应外国也有相应的字符集」；
  • 收发模型：发送方把 0x41 发到线上，接收方收到 0x41——如果显示文本，发送方要先「编码」（把 'A' 编成 0x41）、接收方再「译码」（把 0x41 解成 'A'）；
  • 所以程序里 Serial_SendByte(0x41) 与 Serial_SendByte('A') 发出去的是同一个数据。

图 8：PPT「数据模式」——HEX模式/十六进制模式/二进制模式：以原始数据的形式显示；文本模式/字符模式：以原始数据编码后的形式显示；左侧 ASCII 码表（DEC/HEX/字符/解释），右侧收发模型：发送方 0x41 → 线路 0x41 → 接收方 0x41，发送方下方「编码 ← 'A'」、接收方下方「译码 → 'A'」；字幕「这就是文本模式，或者叫做字符模式」

5. 封装常用发送函数

5.1 Serial_SendArray：发送数组

void Serial_SendArray(uint8_t *Array, uint16_t Length)
{
    uint16_t i;
    for (i = 0; i < Length; i ++)
    {
        Serial_SendByte(Array[i]);
    }
}
  • 参数：uint8_t *Array（数组首地址）+ uint16_t Length（长度）——数组本身没法判断什么时候结束，所以必须额外给长度；长度用 16 位够用（「发送个几 K 的数据都够」）；
  • 逻辑：for 循环执行 Length 次、每次调用 Serial_SendByte 发一个字节；
  • 测试：定义 uint8_t MyArray[] = {0x42, 0x43, 0x44, 0x45};，Serial_SendArray(MyArray, 4) → 串口助手收到 42 43 44 45。

5.2 Serial_SendString：发送字符串

void Serial_SendString(char *String)
{
    uint8_t i;
    for (i = 0; String[i] != '\0'; i ++)
    {
        Serial_SendByte(String[i]);
    }
}
  • 字符串有结束标志，所以不需要长度参数：for 循环的条件是 String[i] != '\0'（'\0' 就是 ASCII 的 0x00，空字符的转义字符表示形式）；
  • 写完字符串后编译器会自动补上结束标志位，所以字符串的存储空间比字符个数大 1；
  • 现象：文本模式下显示 HelloWorld!；要换行就用转义字符 \r\n——必须两个一起用（\r=0x0D 回车、\n=0x0A 换行，都是不可见的控制字符）。

5.3 Serial_SendNumber：发送数字（十进制拆位）

uint32_t Serial_Pow(uint32_t X, uint32_t Y)
{
    uint32_t Result = 1;
    while (Y --)
    {
        Result *= X;
    }
    return Result;
}

void Serial_SendNumber(uint32_t Number, uint8_t Length)
{
    uint8_t i;
    for (i = 0; i < Length; i ++)
    {
        Serial_SendByte(Number / Serial_Pow(10, Length - i - 1) % 10 + '0');
    }
}
  • 目标：把 Number 的个位、十位、百位……依次转成字符数字发出去，电脑上就看到「字符串形式的数字」；
  • 十进制拆位的原理：取某一位 = 数字 / 10^x % 10——/10^x 把这一位右边去掉，%10 把左边去掉；以 12345 为例：/10000%10 = 1（万位）、/1000%10 = 2（千位）、/100%10 = 3（百位）……
  • 先写一个次方函数 Serial_Pow（这是作者自己写的、不是标准库函数）：Result 初值 1，while (Y --) Result *= X; 循环乘 Y 次，返回 X^Y；
  • 循环变量要反过来：Length - i - 1——因为遍历是从 0 开始的，而 10^0 是个位，第一次循环要发最高位，所以指数是 Length-1；例如 Length = 2：第一次 2-0-1 = 1（发十位）、第二次 2-1-1 = 0（发个位）；
  • 最后要加 ASCII 偏移 + '0'：字符 '0' 对应 0x30，所以把数字 0～9 加上 0x30（或直接写 '0'）就变成字符 '0'～'9'；
  • 测试：Serial_SendNumber(12345, 5) → 文本模式显示 12345；SendNumber 默认是十进制、无符号显示；
  • 其实 SendString/SendNumber 和 OLED 的 ShowString/ShowNum 是一样的逻辑，可以对照看。

图 10：Serial.c 中 Serial_SendByte 的 while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);、Serial_SendArray（for (i = 0; i < Length; i ++) { Serial_SendByte(Array 的 i 号元素); }）与 Serial_SendString 的循环条件 for (i = 0; String 的 i 号元素 != '\0' 正在输入；字幕「这就是空字符的转义字符表示形式」

*图 11：Serial.c 中 Serial_Pow（uint32_t Result = 1; while (Y --) { Result *= X; } return Result;）、Serial_SendNumber（for (i = 0; i < Length; i ++) { Serial_SendByte(Number / Serial_Pow(10, Length - i - 1) % 10 + '0'); }），以及开始写 int fputc(int ch, FILE；字幕「int fputc(int ch, FILE f)」

6. printf 的三种移植方法

printf 是 C 语言里非常强大的格式化打印函数，默认输出到屏幕；单片机没有屏幕，所以要重定向到串口。

6.1 方法①：Use MicroLIB + 重写 fputc（最常用）

  1. 打开工程选项，勾上「Use MicroLIB」——MicroLIB 是 Keil 为嵌入式平台优化的精简库，printf 会用到它；
  2. 在 Serial.c 里 #include <stdio.h>；
  3. 重写 fputc：
int fputc(int ch, FILE *f)
{
    Serial_SendByte(ch);
    return ch;
}
  • 原理：printf 底层就是通过 fputc 一个字符一个字符地输出，所以把 fputc 重定向到串口发送，printf 就打到串口了；
  • 测试：printf("Num=%d\r\n", 666); 就能在串口助手看到 Num=666；
  • 踩坑：如果没 #include <stdio.h>，会报隐式声明警告（implicit declaration）——在头文件里补上即可。

6.2 方法②：sprintf + Serial_SendString

  • 用 sprintf 先把格式化内容写到一个字符串数组里，再 Serial_SendString 发出去；
  • 这种方法不涉及重定向、也不需要勾 MicroLIB，适合只想偶尔格式化一次的场合。

6.3 方法③：自己封装 Serial_Printf（可变参数）

void Serial_Printf(char *format, ...)
{
    char String[100];
    va_list arg;
    va_start(arg, format);
    vsprintf(String, format, arg);
    va_end(arg);
    Serial_SendString(String);
}
  • 用 va_list / va_start / vsprintf / va_end 处理可变参数（要 #include <stdarg.h>）；
  • 其实就是在 sprintf 外面再包一层，把格式化结果用 Serial_SendString 发出去——封装好后用起来和 printf 一样方便。

作者说：最常见的是第一种（MicroLIB + fputc）；②③ 属于扩展了解。另外 C 标准库里的 printf 只有一个，如果想同时保留屏幕输出和串口输出，就要用别的方式（本集笔记不展开）。

图 12：Serial.c 尾部——int fputc(int ch, FILE *f) { Serial_SendByte(ch); return ch; } 与 void Serial_Printf(char *format, ...) { char String 数组（100 字节）; va_list arg; va_start(arg, format); vsprintf(String, format, arg); va_end(arg); Serial_SendString(String); }；字幕「如果学过了，那其实是基本操作」

6.4 中文乱码怎么办

  • 乱码原因：Keil 保存源文件的编码和串口助手解析数据的编码不一致；
  • 方案 A（UTF8）：Keil 与串口助手都选 UTF8，并且在工程选项 C/C++ → Misc Controls 里加上 --no-multibyte-chars；这个方案有时兼容性不太好；
  • 方案 B（GB2312/GBK）：Keil 的 Encoding 选 GB2312，串口助手的编码选 GBK，不用加任何参数、兼容性更好——「推荐这种」；
  • 两种方案任选一种、两边保持一致即可；实在乱码也可以用转码软件确认。

6.5 程序一最终现象

  • 恢复演示版代码后下载，串口助手（HEX 模式）依次收到：41（SendByte）、42 43 44 45（SendArray，文本模式下显示 ABCDE）、Num1=111（SendString + SendNumber）、Num2=222（printf）、Num3=333（sprintf）、Num4=444（Serial_Printf）——和片头演示完全一样。

7. 程序二：9-2 串口发送+接收

7.1 初始化改动：加 PA10 与接收模式

  • 接线不变（两根通信线前面已经都接了），从 9-1 复制代码、改名 9-2 串口发送+接收；
  • GPIO 增加 PA10：
    /* 在 Serial_Init 的 GPIO 部分追加：PA10（USART1_RX）上拉输入 */
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
  • RX 引脚配上拉输入 GPIO_Mode_IPU（也可以浮空输入）——串口空闲是高电平，所以不用下拉；
  • USART_Mode 改成 USART_Mode_Tx | USART_Mode_Rx（同时收发；如果只收不发就去掉 Tx）；
  • 接收有两种方法：查询法（主循环不断查 RXNE）与中断法（RXNE 触发中断）。

7.2 查询法

uint8_t RxData;

int main(void)
{
    OLED_Init();
    Serial_Init();

    while (1)
    {
        if (USART_GetFlagStatus(USART1, USART_FLAG_RXNE) == SET)
        {
            RxData = USART_ReceiveData(USART1);
            OLED_ShowHexNum(1, 1, RxData, 2);
            Serial_SendByte(RxData);
        }
    }
}
  • 流程：先定义变量 uint8_t RxData 存数据 → 主循环判断 USART_FLAG_RXNE 是否置 1（收到数据）→ 用 USART_ReceiveData(USART1) 读 DR → 把数据显示在 OLED 上、并原样回传给电脑；
  • USART_ReceiveData 内部就是读 DR；读 DR 会自动清 RXNE，所以不需要手动清标志位（手册 SR 位5 也是这么写的）；
  • 现象：串口助手发送区写 41（HEX 模式，两个数一组）发送 → OLED 显示 41、同时接收区回传 41；改发 AF 也一样。

7.3 中断法

① 开启 RXNE 中断 + 配置 NVIC（放在 Serial_Init 里、USART_Cmd 之前）：

    USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

    NVIC_InitTypeDef NVIC_InitStructure;
    NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_Init(&NVIC_InitStructure);

    USART_Cmd(USART1, ENABLE);
  • USART_ITConfig(USART1, USART_IT_RXNE, ENABLE)：开启 RXNE 中断；
  • NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2)：优先级分组 2；然后 NVIC_Init：通道 USART1_IRQn、使能、抢占优先级 1、子优先级 1——这里是「先随便给」的，实际项目再按需求设计；
  • 中断函数名查启动文件：startup_stm32f10x_md.s 里写的是 USART1_IRQHandler，格式是「外设名 + _IRQHandler」；
  • RXNE 置 1 时就会申请中断，程序跳进中断函数。

② 中断函数与模块封装：

uint8_t Serial_RxData;
uint8_t Serial_RxFlag;

void USART1_IRQHandler(void)
{
    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)
    {
        Serial_RxData = USART_ReceiveData(USART1);
        Serial_RxFlag = 1;
        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}

uint8_t Serial_GetRxFlag(void)
{
    if (Serial_RxFlag == 1)
    {
        Serial_RxFlag = 0;
        return 1;
    }
    return 0;
}

uint8_t Serial_GetRxData(void)
{
    return Serial_RxData;
}
  • 在中断函数里接收数据：USART_GetITStatus(USART1, USART_IT_RXNE) == SET 判断是不是 RXNE 中断 → 读 DR 存到全局变量 Serial_RxData → 置标志 Serial_RxFlag = 1 → USART_ClearITPendingBit(USART1, USART_IT_RXNE) 清中断挂起位（注意：读了 DR 其实会自动清 RXNE，但中断挂起位还是要清，所以这句保留）；
  • 为什么要在中断里转存：中断函数里不适合写太多代码（OLED 显示等应在主循环做），所以中断里只做「读走数据、置标志」，主循环再去取；
  • Serial_GetRxFlag()：读标志后自动清零（防止重复处理同一个数据）——收到数据时返回 1、否则 0；
  • Serial_GetRxData()：返回收到的数据；
  • 把这两个函数放头文件声明，main 里改成：
        if (Serial_GetRxFlag() == 1)
        {
            RxData = Serial_GetRxData();
            OLED_ShowHexNum(1, 1, RxData, 2);
            Serial_SendByte(RxData);
        }
  • 现象：与查询法一致——HEX 模式发 41 → OLED 显示 41、回传 41；发 42 → 显示/回传 42。

坑与易错点

  1. TX/RX 必须交叉：模块 RXD 接 STM32 的 TX（PA9）、模块 TXD 接 STM32 的 RX（PA10）；接成 RXD-RXD 一定收不到。
  2. GND 必须共地：单端信号以 GND 为参考，不共地电平没有比较基准。
  3. 跳线帽插 VCC-3V3（3.3V TTL）：STM32 是 3.3V 器件；电平选错可能通信异常。
  4. USART1 的 TX/RX 固定是 PA9/PA10：用 USART2/3 要按引脚定义表换脚。
  5. USART_Init 里直接写波特率数值（9600），分频系数库函数自动算，不用手写 BRR。
  6. 只发送时 Mode = USART_Mode_Tx；要接收必须改成 Tx | Rx——忘了改就永远收不到。
  7. 发送一个字节后必须等 TXE：while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);，否则连续写 DR 会覆盖数据。
  8. TXE 不需要手动清：写 DR 时硬件自动清零——这也是为什么循环里判断的是 TXE 而不用清标志。
  9. RXNE 读 DR 自动清：查询法里读完 USART_ReceiveData 就不用再清 RXNE；但中断里要清中断挂起位 USART_ClearITPendingBit。
  10. RX 引脚配上拉输入或浮空：串口空闲是高电平，不能配下拉。
  11. 字符串必须 '\0' 结尾：Serial_SendString 靠 String[i] != '\0' 判断结束；字符串数组空间比字符数大 1。
  12. 换行用 \r\n 两个字符：只写 \n 在某些串口助手上不会回到行首。
  13. Serial_Pow 是作者自写函数，不是标准库；SendNumber 依赖它做十进制拆位，指数要用 Length-i-1 而不是 i。
  14. 不加 '0' 偏移就发不出字符：数字 0～9 必须加 0x30（或 '0'）才是字符 '0'～'9'。
  15. printf 方法①要勾 Use MicroLIB 且 #include <stdio.h>：否则报隐式声明、且可能没输出。
  16. 中文乱码：UTF8 方案要两边都 UTF8 且加 --no-multibyte-chars；更稳的是两边都用 GB2312/GBK。
  17. 中断函数名必须与启动文件一致：USART1_IRQHandler（不是自己随便起名），否则中断进不来。
  18. 中断里不要写太多代码：只读数据、置标志，显示/处理放主循环（这也是 GetRxFlag 的用途）。
  19. GetRxFlag 读后自动清零：主循环处理好一个数据再取下一个，避免同一数据被重复处理。
  20. 本集只支持单字节接收：多字节数据包（帧头/长度/校验）在 P28，本集不要提前用。

存疑

  • 本集文本来自画面硬字幕的 OCR（PP-OCRv4，source=subtitle-ocr，947 段），不是 ASR。本集是 60 分钟长片，Keil 编译输出污染极多（compiling ...、linking...、"..\Objects\Project.axf" - 0 Error(s), 0 Warning(s)、Flash Load finished at ...、Programming Done.、Application running ...），这些不是老师口述内容；另有行首噪声（门 等）。典型 OCR 错字（本集实际出现）：Serial_SendByte → 「SerialSendByte/Serial SendByte」、va_list arg → 「va_listarg」、函数名下划线漏识别（USART_SendData→「USARTSendData」等），已按画面校正。
  • 两个程序的代码差异必须区分：程序①只配 PA9（GPIO_Mode_AF_PP）、USART_Mode = USART_Mode_Tx；程序②再加 PA10（GPIO_Mode_IPU）、USART_Mode = USART_Mode_Tx | USART_Mode_Rx；本笔记第 8 章给了对照表，别把两个版本的 Serial_Init 混写。
  • PA10 的 GPIO 初始化行没有抓到完整帧（本集帧间隔 14 秒）：第 7.1 节的 GPIO_Mode_IPU / GPIO_Pin_10 代码块依据口述 48:35–48:47与程序①的 GPIO 结构类推，行序与写法以口述为准。
  • 个别代码行未被帧捕获：Serial_GetRxData 函数体一行、OLED_ShowString/ShowNum 的列号（第 7.3 节 main）以口述 + 相邻帧为准；Serial_Init 里 USART_Cmd 前的顺序（ITConfig → NVIC → Cmd）与 f_00233 一致。
  • 中断优先级数值：f_00233 画面显示 NVIC_IRQChannelPreemptionPriority = 1、NVIC_IRQChannelSubPriority = 1（collect_report 里写的是「子 0」，以画面为准）；老师也明确说优先级是「先随便给」的，不是精心设计。
  • Serial_Pow 是作者自写函数（uint32_t Serial_Pow(uint32_t X, uint32_t Y)），不是标准库函数，本笔记按自写标注。
  • printf 三种方法：①MicroLIB + fputc 最常用；②sprintf + SendString、③Serial_Printf 属扩展，作者说「最常见的是第一种」——本笔记没有把 ②③ 写成必须。
  • 本集未涉及：DMA 串口收发、多字节数据包（片尾 59:26 明确「下一小节讲数据包」→ P28）、USART_ITConfig 只配 RXNE；没有讲 USART_SendData 的等待 TC 写法（只用 TXE）。
