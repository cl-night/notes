[9-3] USART串口发送与接收 — 学习笔记

一句话结论

两个工程：9-1 串口发送（只发）与 9-2 串口发送+接收（查询法/中断法）。发送的骨架是「写 DR 后等 USART_FLAG_TXE」，接收的骨架是「等 USART_FLAG_RXNE 后读 DR」，读写 DR 都会自动清对应标志。

本集定位

  • 模块 9 的代码课，现场写两个程序：9-1 串口发送、9-2 串口发送+接收；新建 Serial.c/Serial.h 模块。
  • 理论（USART 框图、帧格式、波特率、采样）全在 P26 [9-2]，详见 notes/stm32-26-USART串口外设.md，本集只套用。
  • 流程：00:00 看接线图 → 新建 Serial 模块 → Keil 写码/编译/下载 → 串口助手看现象；47:50 起复制改出第二个工程。
  • 本集不涉及 DMA、多字节数据包；片尾 59:26「目前只支持 1 个字节的接收……下一小节讲数据包」，数据包在 P28。
  • USART_ITConfig 只配了 USART_IT_RXNE 一种中断。

1. 接线与工程准备

1.1 接线：RXD→PA9、TXD→PA10、GND 共地

  • 跳线帽插在 VCC 与 3V3 两脚，把 TTL 电平选成 3.3V（STM32 是 3.3V 器件，跳线帽同时给 CH340 供电）。
  • 通信引脚选 PA9/PA10：查引脚定义表，USART1 的 TX 是 PA9、RX 是 PA10；用 USART2/3 要另找引脚。
  • TX 与 RX 必须交叉：模块 RXD → PA9（STM32 的 TX），模块 TXD → PA10（STM32 的 RX）。
  • GND 共地：单端信号以 GND 为参考，不共地就没有电平基准；多系统互连一般都要共地。
  • 供电：串口模块与 ST-Link 都插电脑、各自独立供电，所以电源正极不接，只接 3 根线。
  • 程序一只有 STM32 发送，一根通信线就够；为与程序二一致，两根都接。
  • 面包板：3 根公对母杜邦线——棕色 GND → 电源负极、红色 RXD → PA9、橙色 TXD → PA10；USB 口不够用拓展坞。
  • 驱动：此电脑 → 属性 → 设备管理器，端口下出现 USB-SERIAL CH340 (COM12)、图标无感叹号即正常。

图 1：接线图 9-1 串口发送——右下是 USB 转串口模块（5V/VCC/3V3/TXD/RXD/GND，红圈标出跳线帽插在 VCC-3V3），把 GND→电源负极、RXD→PA9、TXD→PA10 接起来

1.2 工程准备

  • 复制 OLED 工程，改名 9-1 串口发送，删掉原代码并编译。
  • 新建模块 Serial.c / Serial.h，在 Serial.c 里写 void Serial_Init(void)。
  • 初始化四步：① 开 USART 与 GPIO 时钟 ② 配 GPIO ③ USART_Init 填参数 ④ USART_Cmd(USART1, ENABLE) 开启。
  • 若要接收，在 USART_Cmd 之前再加 USART_ITConfig 与 NVIC。
  • 之后就是调发送函数、接收函数、USART_GetFlagStatus 查状态。

2. Serial_Init：程序一（只发送）

2.1 时钟与 GPIO

#include "stm32f10x.h"
#include <stdio.h>

void Serial_Init(void)
{
    /* ① 时钟：USART1 是 APB2 外设，GPIOA 也在 APB2 */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    /* ② GPIO：PA9（USART1_TX）复用推挽输出 */
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
    ...
  • 开时钟都用 RCC_APB2PeriphClockCmd：USART1 挂在 APB2，写 RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE)；GPIOA 也在 APB2，一起开。
  • PA9 配 GPIO_Mode_AF_PP（复用推挽）、GPIO_Pin_9、GPIO_Speed_50MHz。
  • RX 引脚不必单独配复用：库函数里普通输入与复用功能输入混在一起，浮空或上拉都行。
  • 串口空闲是高电平，所以 RX 不能配下拉；程序一用不到 RX，只配 PA9。

2.2 USART_Init 六成员与 USART_Cmd

    USART_InitTypeDef USART_InitStructure;
    USART_InitStructure.USART_BaudRate = 9600;
    USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
    USART_InitStructure.USART_Mode = USART_Mode_Tx;
    USART_InitStructure.USART_Parity = USART_Parity_No;
    USART_InitStructure.USART_StopBits = USART_StopBits_1;
    USART_InitStructure.USART_WordLength = USART_WordLength_8b;
    USART_Init(USART1, &USART_InitStructure);

    USART_Cmd(USART1, ENABLE);
}
成员 程序一取值 说明
USART_BaudRate 9600 直接写波特率数值，USART_Init 内部自动算分频系数（P26 的 BRR/DIV）
USART_HardwareFlowControl USART_HardwareFlowControl_None 可选 None / CTS / RTS / CTS+RTS；不用流控选 None
USART_Mode USART_Mode_Tx 可选 Tx / Rx；同时收发写 Tx | Rx；本程序只发送
USART_Parity USART_Parity_No 无校验 / 奇 / 偶；选无校验
USART_StopBits USART_StopBits_1 0.5 / 1 / 1.5 / 2 位；一般用 1 位
USART_WordLength USART_WordLength_8b 8 位 / 9 位（含校验位）；不校验选 8 位
  • 六个成员依次填 USART_BaudRate = 9600、USART_HardwareFlowControl = USART_HardwareFlowControl_None、USART_Mode = USART_Mode_Tx、USART_Parity = USART_Parity_No、USART_StopBits = USART_StopBits_1、USART_WordLength = USART_WordLength_8b。
  • 六个成员传进 USART_Init(USART1, &USART_InitStructure);，组合成最常用参数：9600、8 位数据、1 位停止、无校验、无流控。
  • 最后 USART_Cmd(USART1, ENABLE); 开启 USART，初始化完成。

3. 发送一个字节：Serial_SendByte

void Serial_SendByte(uint8_t Byte)
{
    USART_SendData(USART1, Byte);
    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);
}
  • USART_SendData(USART1, Byte) 把数据写进 DR；库函数内部是 USARTx->DR = (Data & (uint16_t)0x01FF);，即 USARTx->DR = (Data & 0x01FF)，高 7 位清零、只留 9 位数据。
  • 数据再从 TDR 转到发送移位寄存器、由 TX 引脚发出，这一步软硬件配合、不用管。
  • 必须等 USART_FLAG_TXE 置 1：USART_GetFlagStatus(USART1, USART_FLAG_TXE) 返回非 RESET 才能写下一个。
  • 写法就是一个 while 空循环：while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET);，不等会覆盖。
  • USART_GetFlagStatus 第二个参数可选：USART_FLAG_CTS（CTS 改变）、LBD（LIN 断开检测）、TXE、TC、RXNE、IDLE、ORE、NE、FE、PE。
  • TXE 不用手动清：手册 SR 位7 写明「对 USART_DR 的写操作将该位清零」，写 DR 时硬件自动清。

图 5：stm32f10x_usart.c 里 USART_SendData 的源码——void USART_SendData(USART_TypeDef* USARTx, uint16_t Data)，函数体 USARTx->DR = (Data & (uint16_t)0x01FF);（高亮）

图 6：USART_GetFlagStatus 注释里的参数——@arg USART_FLAG_CTS、LBD、TXE、TC、RXNE、IDLE、ORE、NE、FE、PE（USART_FLAG_TXE 高亮）

图 7：参考手册 USART_SR——位7 TXE：TDR 数据转走时硬件置位、TXEIE=1 产生中断、写 USART_DR 清零；位6 TC；位5 RXNE：RDR 数据转到 DR 时置位、读 DR 清零

3.1 现象：串口助手看发送

  • main 里 Serial_Init() 之后调 Serial_SendByte(0x41)，上电就发一次，TX 引脚产生波形。
  • 串口助手选 COM 号，波特率 9600、数据位 8、停止位 1、校验位无。
  • 复位后收到 41：HEX 模式显示原始数据 41，文本模式按字符集解析成 A（就是 P25 讲过的 HEX/文本区别）。

4. 数据模式与 ASCII 码表

  • HEX 模式 / 十六进制模式 / 二进制模式：以原始数据形式显示，只能显示 0～9、A～F。
  • 文本模式 / 字符模式：把每个字节按字符集编码查表、显示对应字符。
  • ASCII：0x41 = A、0x61 = a、0x30～0x39 = 0～9，还有标点与不可见字符。
  • 不可见字符：0x00（空字符，字符串的结束标志）、\r=0x0D、\n=0x0A、\t=0x09。
  • 汉字等多字节字符要靠 GB2312/GBK/GB18030 或 Unicode/UTF8 等字符集。
  • 收发模型：发送方编码（'A' → 0x41）、接收方译码（0x41 → 'A'），线上始终是 0x41。
  • 所以 Serial_SendByte(0x41) 与 Serial_SendByte('A') 发的是同一个数据。

图 8：PPT「数据模式」——HEX模式/十六进制模式/二进制模式以原始数据显示；文本模式/字符模式以编码后的形式显示；右侧收发模型：发送方 0x41 → 线路 0x41 → 接收方，发送方「编码 ← 'A'」、接收方「译码 → 'A'」

图 9：ASCII 码表全页（0～127）——0x00 = (NUL) 空字符、0x41 = A 大写字母A、0x61 = a 小写字母a、0x30～0x39 = 字符 0～9

5. 封装常用发送函数

5.1 Serial_SendArray：发送数组

void Serial_SendArray(uint8_t *Array, uint16_t Length)
{
    uint16_t i;
    for (i = 0; i < Length; i ++)
    {
        Serial_SendByte(Array[i]);
    }
}
  • 原型 Serial_SendArray(uint8_t *Array, uint16_t Length)：uint8_t *Array 是首地址、uint16_t Length 是长度。
  • 数组自己不知道何时结束，所以必须额外给长度。
  • 长度用 16 位够用，几 K 的数据都能发；for 循环 Length 次、每次发一个字节。
  • 测试：uint8_t MyArray[] = {0x42, 0x43, 0x44, 0x45}; + Serial_SendArray(MyArray, 4) → 收到 42 43 44 45。

5.2 Serial_SendString：发送字符串

void Serial_SendString(char *String)
{
    uint8_t i;
    for (i = 0; String[i] != '\0'; i ++)
    {
        Serial_SendByte(String[i]);
    }
}
  • 原型 Serial_SendString(char *String)：有结束标志就不用长度，循环条件 String[i] != '\0'（'\0' 即 0x00 的转义写法）。
  • 编译器自动补结束标志，所以字符串的存储空间比字符个数大 1。
  • 文本模式显示 HelloWorld!；换行用 \r\n，必须两个一起（\r=0x0D 回车、\n=0x0A 换行）。

5.3 Serial_SendNumber：发送数字（十进制拆位）

uint32_t Serial_Pow(uint32_t X, uint32_t Y)
{
    uint32_t Result = 1;
    while (Y --)
    {
        Result *= X;
    }
    return Result;
}

void Serial_SendNumber(uint32_t Number, uint8_t Length)
{
    uint8_t i;
    for (i = 0; i < Length; i ++)
    {
        Serial_SendByte(Number / Serial_Pow(10, Length - i - 1) % 10 + '0');
    }
}
  • 原型 Serial_SendNumber(uint32_t Number, uint8_t Length)：把 Number 的个位、十位、百位……依次转成字符。
  • 拆位公式：Number / Serial_Pow(10, Length - i - 1) % 10 + '0'。
  • 取某一位 = 数字 / 10^x % 10：/10^x 去掉这一位右边，%10 去掉左边。
  • 例：12345 → /10000%10 = 1（万位）、/1000%10 = 2（千位）、/100%10 = 3（百位）。
  • Serial_Pow 是自写的次方函数（不是库函数）：Result 初值 1，while (Y --) Result *= X; 循环 Y 次，返回 X^Y。
  • 指数要写 Length - i - 1（第一次是 Length-1）：从 0 开始遍历，而 10^0 是个位，第一次发最高位。
  • 例 Length = 2：第一次 2-0-1 = 1 发十位、第二次 2-1-1 = 0 发个位。
  • 最后加 + '0'（0x30）把 0～9 变成字符 '0'～'9'；默认十进制无符号显示。
  • 测试 Serial_SendNumber(12345, 5) → 显示 12345。
  • SendString/SendNumber 与 OLED 的 ShowString/ShowNum 是同一套逻辑。

图 10：Serial_SendArray（for (i = 0; i < Length; i ++) { Serial_SendByte(Array 的 i 号元素); }）与 Serial_SendString 的循环条件 for (i = 0; String 的 i 号元素 != '\0' 正在输入

图 11：Serial_Pow（uint32_t Result = 1; while (Y --) { Result *= X; } return Result;）与 Serial_SendNumber（for (i = 0; i < Length; i ++) { Serial_SendByte(Number / Serial_Pow(10, Length - i - 1) % 10 + '0'); }）

6. printf 的三种移植方法

printf 默认输出到屏幕，单片机没有屏幕，所以要重定向到串口。

6.1 方法①：Use MicroLIB + 重写 fputc（最常用）

  1. 工程选项里勾上「Use MicroLIB」——Keil 为嵌入式精简过的库，printf 会用到它。
  2. Serial.c 里 #include <stdio.h>。
  3. 重写 fputc：
int fputc(int ch, FILE *f)
{
    Serial_SendByte(ch);
    return ch;
}
  • 原理：printf 底层就是一个字符一个字符地调 fputc，重定向它 printf 就打到串口。
  • 测试 printf("Num=%d\r\n", 666); → 串口助手看到 Num=666。
  • 坑：漏 #include <stdio.h> 会报隐式声明警告（implicit declaration）。

6.2 方法②：sprintf + Serial_SendString

  • 先用 sprintf 把格式化内容写到字符串数组，再 Serial_SendString 发出去。
  • 不涉及重定向、不用勾 MicroLIB，适合偶尔格式化一次的场合。

6.3 方法③：自己封装 Serial_Printf（可变参数）

void Serial_Printf(char *format, ...)
{
    char String[100];
    va_list arg;
    va_start(arg, format);
    vsprintf(String, format, arg);
    va_end(arg);
    Serial_SendString(String);
}
  • 用 Serial_Printf(char *format, ...) 加 va_list / va_start / vsprintf / va_end 处理可变参数，要 #include <stdarg.h>。
  • 就是在 sprintf 外面再包一层，用起来和 printf 一样。

最常用的是方法①；②③ 属于扩展。C 标准库的 printf 只有一个，要同时保留屏幕输出与串口输出得另想办法。

图 12：Serial.c 尾部——int fputc(int ch, FILE *f) { Serial_SendByte(ch); return ch; } 与 Serial_Printf 的可变参数实现

6.4 中文乱码怎么办

  • 原因：Keil 保存源文件的编码与串口助手解析数据的编码不一致。
  • 方案 A（UTF8）：Keil 与串口助手都选 UTF8，并在 C/C++ → Misc Controls 加 --no-multibyte-chars；兼容性有时不好。
  • 方案 B（GB2312/GBK）：Keil 的 Encoding 选 GB2312、串口助手编码选 GBK，不加任何参数，兼容性更好，推荐。
  • 两边保持一致即可；实在乱码可用转码软件确认。

6.5 程序一最终现象

  • 恢复演示代码后，HEX 模式依次收到 41（SendByte）、42 43 44 45（SendArray，文本模式显示 ABCDE）。
  • 接着 Num1=111（SendString + SendNumber）、Num2=222（printf）、Num3=333（sprintf）、Num4=444（Serial_Printf）。

7. 程序二：9-2 串口发送+接收

7.1 初始化改动：加 PA10 与接收模式

  • 接线不变（两根通信线前面都接了），从 9-1 复制代码、改名 9-2 串口发送+接收。
  • GPIO 追加 PA10：
    /* 在 Serial_Init 的 GPIO 部分追加：PA10（USART1_RX）上拉输入 */
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);
  • RX 配 GPIO_Mode_IPU 上拉输入（也可浮空）：串口空闲是高电平，不用下拉。
  • USART_Mode 改成 USART_Mode = USART_Mode_Tx | USART_Mode_Rx；只收不发就去掉 Tx。
  • 接收两种方法：查询法（主循环不断查 RXNE）、中断法（RXNE 触发中断）。

7.2 查询法

uint8_t RxData;

int main(void)
{
    OLED_Init();
    Serial_Init();

    while (1)
    {
        if (USART_GetFlagStatus(USART1, USART_FLAG_RXNE) == SET)
        {
            RxData = USART_ReceiveData(USART1);
            OLED_ShowHexNum(1, 1, RxData, 2);
            Serial_SendByte(RxData);
        }
    }
}
  • 流程：uint8_t RxData 存数据 → 主循环判 USART_FLAG_RXNE 是否置 1 → USART_ReceiveData(USART1) 读 DR → OLED 显示并原样回传电脑。
  • USART_ReceiveData 内部就是读 DR；读 DR 自动清 RXNE，不用手动清（手册 SR 位5）。
  • 现象：HEX 模式发 41 → OLED 显示 41、回传 41；发 AF 也一样。

7.3 中断法

① 开启 RXNE 中断 + 配置 NVIC（放在 Serial_Init 里、USART_Cmd 之前）：

    USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);

    NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

    NVIC_InitTypeDef NVIC_InitStructure;
    NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;
    NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
    NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;
    NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;
    NVIC_Init(&NVIC_InitStructure);

    USART_Cmd(USART1, ENABLE);
  • USART_ITConfig(USART1, USART_IT_RXNE, ENABLE) 开启 RXNE 中断。
  • NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2) 优先级分组 2；NVIC_InitTypeDef NVIC_InitStructure; 里填 NVIC_IRQChannel = USART1_IRQn、IRQChannelCmd = ENABLE、IRQChannelPreemptionPriority = 1、IRQChannelSubPriority = 1。
  • 中断通道就是 USART1_IRQn，最后把结构体交给 NVIC_Init：NVIC_Init(&NVIC_InitStructure);。
  • 优先级先随便给，实际项目再按需求设计。
  • 中断函数名查启动文件 startup_stm32f10x_md.s：USART1_IRQHandler，格式是「外设名 + _IRQHandler」。
  • RXNE 置 1 时就会申请中断，程序跳进中断函数。

② 中断函数与模块封装：

uint8_t Serial_RxData;
uint8_t Serial_RxFlag;

void USART1_IRQHandler(void)
{
    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)
    {
        Serial_RxData = USART_ReceiveData(USART1);
        Serial_RxFlag = 1;
        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}

uint8_t Serial_GetRxFlag(void)
{
    if (Serial_RxFlag == 1)
    {
        Serial_RxFlag = 0;
        return 1;
    }
    return 0;
}

uint8_t Serial_GetRxData(void)
{
    return Serial_RxData;
}
  • 中断里判 USART_GetITStatus(USART1, USART_IT_RXNE) == SET → 读 DR 存到 Serial_RxData → 置 Serial_RxFlag = 1。
  • 最后仍要 USART_ClearITPendingBit(USART1, USART_IT_RXNE) 清挂起位：读 DR 自动清的是 RXNE，挂起位不自动清。
  • 中断里只做「读走数据、置标志」，OLED 显示等处理放主循环。
  • Serial_GetRxFlag() 读到标志后自动清零，防止同一数据被重复处理；收到返回 1、否则 0。
  • Serial_GetRxData() 返回收到的数据。
  • 两个函数在头文件声明后，main 里改成：
        if (Serial_GetRxFlag() == 1)
        {
            RxData = Serial_GetRxData();
            OLED_ShowHexNum(1, 1, RxData, 2);
            Serial_SendByte(RxData);
        }
  • 现象与查询法一致：HEX 模式发 41 → OLED 显示 41、回传 41；发 42 → 显示/回传 42。

项 程序一 9-1 串口发送 程序二 9-2 串口发送+接收
工程来源 复制 OLED 工程 复制程序一
GPIO 只配 PA9（GPIO_Mode_AF_PP） PA9（AF_PP）+ PA10（GPIO_Mode_IPU）
USART_Mode USART_Mode_Tx USART_Mode_Tx | USART_Mode_Rx

坑与易错点

  1. TX/RX 必须交叉：模块 RXD 接 PA9、TXD 接 PA10，接成 RXD-RXD 必收不到。
  2. GND 必须共地：单端信号以 GND 为参考，不共地没有电平基准。
  3. 跳线帽插 VCC-3V3：选 3.3V TTL，STM32 是 3.3V 器件，选错通信异常。
  4. USART1 的 TX/RX 固定 PA9/PA10：换 USART2/3 要查引脚定义表。
  5. USART_Init 直接写 9600：分频系数库函数自动算，不用手写 BRR。
  6. 要接收必须改 Tx | Rx：只写 USART_Mode_Tx 永远收不到。
  7. 发完字节必须等 TXE：不等就写下一个 DR，数据会被覆盖。
  8. TXE 不用手动清：写 DR 时硬件自动清零。
  9. RXNE 读 DR 自动清：但中断挂起位仍要 USART_ClearITPendingBit。
  10. RX 引脚不能配下拉：串口空闲是高电平，用上拉或浮空。
  11. 字符串必须 '\0' 结尾：空间比字符数大 1，靠它判结束。
  12. 换行用 \r\n 两个字符：只写 \n 有的助手不回行首。
  13. Serial_Pow 是自写函数：指数写 Length-i-1，不是 i。
  14. 不加 '0' 偏移发不出字符：0～9 要加 0x30 才是 '0'～'9'。
  15. printf 方法①要勾 Use MicroLIB：并 #include <stdio.h>，否则报隐式声明。
  16. 中文乱码：两边编码要一致；UTF8 方案还要加 --no-multibyte-chars。
  17. 中断函数名要对齐启动文件：写 USART1_IRQHandler，自己起名进不来。
  18. 中断里别写太多代码：只读数据、置标志，显示放主循环。
  19. GetRxFlag 读后自动清零：避免同一数据被重复处理。
  20. 本集只支持单字节接收：多字节数据包（帧头/长度/校验）在 P28。
