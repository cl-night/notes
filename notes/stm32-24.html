[8-2] DMA数据转运与DMA+AD多通道 — 学习笔记

一句话结论

DMA 转运配好 DMA_Init 的 11 个成员，每次「失能 → 写计数器 → 使能 → 等 DMA1_FLAG_TC1 → 清标志」。ADC 多通道加扫描和 ADC_DMACmd，通道固定 DMA1_Channel1。

本集定位

  • 模块 8（DMA）的代码课，写两个工程：8-1 DMA数据转运（存储器→存储器，DataA→DataB）、8-2 DMA+AD多通道（ADC 扫描 + DMA，四路自动进数组）。
  • 结构：开场小实验（1:00–9:30，扩展内容）→ 程序一（9:30–40:30）→ 程序二（40:30–53:09）。
  • 理论（DMA 定义、框图、基本结构、请求映像、数据宽度与对齐表57）全在 P23 [8-1]，本集只套用结论，详见 notes/stm32-23-DMA直接存储器存取.md。
  • 覆盖存储器→存储器、外设→存储器两种情况；存储器→外设（串口发送）本集没讲，留作自学；片尾无下集名。

1. 片头与工程准备

  • 接线与 OLED 显示屏工程相同：数据转运全在 STM32 内部进行，外围只加一个 OLED 显示就够了。
  • 复制 OLED 工程 → 改名 8-1 DMA数据转运，删掉原有代码，编译。

2. 扩展小实验：存储器映像的真实验证（1:00–9:30）

  • 目的：验证 P23 讲的存储器映像——定义的数据到底存在哪个地址空间。

2.1 变量：地址在 SRAM 区

  • 定义 uint8_t aa = 0x66;，主函数里用 OLED_ShowHexNum(1, 1, aa, 2) 显示内容，再显示地址。
  • 取地址用 &：&aa 取到的就是地址（不是 aa 的内容）；地址习惯用十六进制表示，要当数字显示得加 (uint32_t) 强转，否则是指针跨级赋值、编译报警告；显示长度给 8（32 位系统的地址都是 32 位）。
  • 现象：第一行 66，第二行地址 2000 0000——20 开头就说明在 SRAM 区。
  • 具体地址由编译器决定：SRAM 区还空着，变量就落在第一个位置 0x20000000。

2.2 常量：加 const 就到 Flash 区

  • const 修饰的只能读、不能写，Flash 也是只能读不能写，所以在 STM32 中用 const 定义的变量存放在 Flash 里。
  • 常量只能在定义时给值，程序里再赋值会编译报错。
  • 现象：地址从 0x20000000 变成 0x08000DF8（屏幕显示 0800 0DF8，08 开头即 Flash）；尾部有偏移，因为 Flash 前面还有程序代码，常量只能安排得靠后。
  • 用途：一大批不需要改的数据（查找表、字库）定义成常量能省 SRAM——OLED_Font.h 的字库数组加 const 就进 Flash；去掉 const 功能不变，但 SRAM 会浪费同样大的空间。

图 2：小实验画面——OLED 显示 66（内容）与 08000DF8（地址，08 开头即 Flash 区），右侧是 PPT 存储器映像表的「用途」列

2.3 外设寄存器地址：&ADC1->DR = 0x4001244C

  • 变量、常量的地址由编译器定、不固定；外设寄存器地址固定，手册里都能查到。
  • 程序里用结构体访问寄存器，要取 ADC1 的 DR 就写 ADC1->DR；把它取地址显示出来得到 4001 244C——40 开头即外设寄存器区。
  • 地址来源：手册第 2 章「存储器映像」查到 ADC1 起始地址 0x40012400，ADC 章节寄存器总表查到 ADC_DR 偏移 0x4C，两者相加 0x40012400 + 0x4C = 0x4001244C。
  • 通用算法：先查外设起始地址，再查寄存器偏移，相加。

图 3：参考手册 2.3 存储器映像表——0x4001 2400～0x4001 27FF 是 ADC1（属 APB2），同表还有 ADC2/ADC3、TIM8、SPI1、USART1 与 GPIOA～G

图 4：main.c 里验证寄存器地址——OLED_ShowHexNum(2, 1, (uint32_t)&ADC1->DR, 8);（第 12 行）

2.4 结构体为什么能访问寄存器

  • ADC1 跳转定义就是 ((ADC_TypeDef *)ADC1_BASE)，也写作 ((ADC_TypeDef *) ADC1_BASE)：左边把 ADC1_BASE 强转成 ADC_TypeDef 类型指针，右边就是 ADC1 的基地址。
  • 基地址链：ADC1_BASE = APB2PERIPH_BASE + 0x2400、APB2PERIPH_BASE = PERIPH_BASE + 0x10000、PERIPH_BASE = 0x40000000，即 0x40000000 + 0x10000 + 0x2400 = 0x40012400，与手册一致；顺带还能看到 SRAM 基地址 0x2000、Flash 基地址 0x0800。
  • 换个写法更直观：PERIPH_BASE(0x40000000) + 0x10000 = APB2 基地址 → +0x2400 = ADC1 基地址。
  • 偏移的实现：结构体成员按 SR、CR1、CR2……依次定义，顺序与手册里寄存器的排列一一对应；结构体指针指向起始地址后，每个成员正好映射到一个寄存器。
  • ADC1->DR 就是「起始地址 + 偏移」；因为是结构体指针，取成员用 ->。
  • 也可以 #define ADC1_DR 0x4001244C，把地址强转成 uint32_t 指针再用 * 取内容，效果完全一样。

3. 程序一：8-1 DMA数据转运

3.1 定义数组与新建 MyDMA 模块

  • 定义 uint8_t DataA[] = {0x01, 0x02, 0x03, 0x04};（源端）与 uint8_t DataB[] = {0, 0, 0, 0};（目的端，不写 0 全局变量默认也是 0）。
  • 任务：初始化 DMA，让它把 DataA 转运到 DataB。
  • DMA 不涉及外围电路，模块可以放在 System 分组，命名 MyDMA（避免与库函数重名）；先写 void MyDMA_Init(void)，后面改成带参数的版本，文件是 MyDMA.c/MyDMA.h。

3.2 编程思路与库函数

  • 步骤照 P23 基本结构图：① RCC 开 DMA 时钟；② DMA_Init 配参数；③ DMA_Cmd 给通道使能；④ 转运完成、计数器清 0 后想再转，先失能 → 写计数器 → 使能。
  • DMA_Init 要配：两个站点的起始地址、数据宽度、地址是否自增、方向、传输计数器、是否自动重装、触发源，另外还有通道优先级；选硬件触发时，别忘了在对应外设里调 XXX_DMACmd 开触发信号输出。
  • dma.h 里重点两个：DMA_SetCurrDataCounter（给传输计数器写数据）、DMA_GetCurrDataCounter（返回计数器当前值，看还剩多少没转运）；其余是老朋友 DMA_DeInit、DMA_Init、DMA_StructInit、DMA_ITConfig，以及获取标志位状态、清除标志位、获取中断状态、清除中断挂起位。

3.3 MyDMA_Init 完整代码与 11 个成员

#include "stm32f10x.h"

uint16_t MyDMA_Size;   /* 留给 MyDMA_Transfer 重新写计数器用 */

void MyDMA_Init(uint32_t AddrA, uint32_t AddrB, uint16_t Size)
{
    MyDMA_Size = Size;

    /* DMA 是 AHB 总线的设备，用 AHB 开启时钟 */
    RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA1, ENABLE);

    DMA_InitTypeDef DMA_InitStructure;
    DMA_InitStructure.DMA_PeripheralBaseAddr = AddrA;                          /* 外设站点起始地址 */
    DMA_InitStructure.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte;    /* 字节（uint8_t） */
    DMA_InitStructure.DMA_PeripheralInc = DMA_PeripheralInc_Enable;            /* 地址自增 */
    DMA_InitStructure.DMA_MemoryBaseAddr = AddrB;                              /* 存储器站点起始地址 */
    DMA_InitStructure.DMA_MemoryDataSize = DMA_MemoryDataSize_Byte;            /* 字节 */
    DMA_InitStructure.DMA_MemoryInc = DMA_MemoryInc_Enable;                    /* 地址自增 */
    DMA_InitStructure.DMA_DIR = DMA_DIR_PeripheralSRC;                         /* 外设站点作为源 */
    DMA_InitStructure.DMA_BufferSize = Size;                                   /* 传输计数器 */
    DMA_InitStructure.DMA_Mode = DMA_Mode_Normal;                              /* 单次，不自动重装 */
    DMA_InitStructure.DMA_M2M = DMA_M2M_Enable;                                /* 软件触发 */
    DMA_InitStructure.DMA_Priority = DMA_Priority_Medium;                      /* 中等优先级 */
    DMA_Init(DMA1_Channel1, &DMA_InitStructure);

    DMA_Cmd(DMA1_Channel1, DISABLE);   /* 先不使能，等 Transfer 调用 */
}
  • 函数原型 MyDMA_Init(uint32_t AddrA, uint32_t AddrB, uint16_t Size)：数组地址由编译器分配、不固定，所以把地址和长度提取成 uint32_t AddrA, uint32_t AddrB, uint16_t Size 三个形参，想转哪个数组就传哪个。
  • 时钟：RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA1)——DMA 是 AHB 设备，完整写法 RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA1, ENABLE);，该参数分「互联型（F105/107）」和「其他设备」两张表，F103 用下面那张选 RCC_AHBPeriph_DMA1。
  • DMA_Init 第一个参数是 DMAy_Channelx：y 选 DMA1/DMA2，x 选通道（DMA1 是 1～7、DMA2 是 1～5），一个参数同时选了 DMA 和通道；这里是存储器到存储器、软件触发，通道任选，给通道 1。
  • 11 个成员：前 6 个是两个站点的起始地址、数据宽度、是否自增；DIR 是方向（PeripheralDST 外设作目的地、PeripheralSRC 外设作源）；BufferSize 是传输计数器（0～65535）；Mode 是是否自动重装（Circular 循环、Normal 正常，注释写明「循环模式不能应用在存储器到存储器」，即自动重装与软件触发不能同时用）；M2M 是触发方式（Enable 软件触发、Disable 硬件触发）；Priority 是通道优先级（VeryHigh/High/Medium/Low）。
  • 程序一的取值：PeripheralBaseAddr = AddrA、PeripheralDataSize/MemoryDataSize = Byte、PeripheralInc/MemoryInc = Enable、DIR = PeripheralSRC、BufferSize = Size、Mode = Normal、M2M = Enable、Priority = Medium。
  • 最后 DMA_Cmd(DMA1_Channel1, DISABLE) 先不使能：转运要同时满足计数器>0、有触发信号、DMA 使能三个条件，此时只差使能，等 Transfer 调用再启动。
  • 地址自增的两个宏（图 5）：#define DMA_PeripheralInc_Enable ((uint32_t)0x00000040)、#define DMA_PeripheralInc_Disable ((uint32_t)0x00000000)，下面还有 IS_DMA_PERIPHERAL_INC_STATE 判断宏与 DMA_memory_incremented_mode 分组。
  • 代码里这些成员的宏名形态（图 6）：DMA_MemoryBaseAddr = AddrB、MemoryDataSize_Byte、MemoryInc_Enable、DMA_DIR_PeripheralSRC、Mode_Normal、M2M_Enable、Priority_Medium，以及此刻还是 DMA_Cmd(DMA1_Channel1, ENABLE); 的使能句。

3.4 MyDMA_Transfer：重复转运

void MyDMA_Transfer(void)
{
    DMA_Cmd(DMA1_Channel1, DISABLE);                             /* 写计数器前必须先失能 */
    DMA_SetCurrDataCounter(DMA1_Channel1, MyDMA_Size);           /* 重新写传输计数器 */
    DMA_Cmd(DMA1_Channel1, ENABLE);                              /* 三个条件重新满足，开始转运 */
    while (DMA_GetFlagStatus(DMA1_FLAG_TC1) == RESET);           /* 等待转运完成 */
    DMA_ClearFlag(DMA1_FLAG_TC1);                                /* 标志位必须手动清除 */
}
  • 为什么要这个函数：初始化后立刻使能就是「初始化即转运一次、然后停」；想再转一次必须重写传输计数器，所以封装 MyDMA_Transfer，调用一次就再启动一次转运。
  • 先失能再写计数器：DMA_SetCurrDataCounter 写之前必须 DMA_Cmd(...DISABLE)（手册规定）。
  • MyDMA_Size：Transfer 里要用 Size，但它和初始化不在一个函数里、不能直接传参，所以定义全局 uint16_t MyDMA_Size;，初始化时存一份。
  • 一句话流程：DMA_Cmd(DMA1_Channel1, DISABLE); → DMA_SetCurrDataCounter(DMA1_Channel1, MyDMA_Size); → DMA_Cmd(DMA1_Channel1, ENABLE); → while (DMA_GetFlagStatus(DMA1_FLAG_TC1) == RESET); → DMA_ClearFlag(DMA1_FLAG_TC1);。
  • 等完成用 DMA_GetFlagStatus：每个通道都有全局、转运完成（TC）、转运过半（HT）、转运错误（TE）4 类标志；这里等 DMA1_FLAG_TC1，用 while 死等，完成后必须用 DMA_ClearFlag 手动清标志。

3.5 主函数、现象与 const 版

#include "stm32f10x.h"
#include "Delay.h"
#include "OLED.h"
#include "MyDMA.h"

uint8_t DataA[] = {0x01, 0x02, 0x03, 0x04};
uint8_t DataB[] = {0, 0, 0, 0};

int main(void)
{
    OLED_Init();
    MyDMA_Init((uint32_t)DataA, (uint32_t)DataB, 4);

    OLED_ShowString(1, 1, "DataA");
    OLED_ShowString(3, 1, "DataB");
    OLED_ShowHexNum(1, 8, (uint32_t)DataA, 8);   /* DataA 的地址 */
    OLED_ShowHexNum(3, 8, (uint32_t)DataB, 8);   /* DataB 的地址 */

    while (1)
    {
        DataA[0]++; DataA[1]++; DataA[2]++; DataA[3]++;   /* 变化源端数据 */

        /* 显示转运前的 DataA（第 2 行）和 DataB（第 4 行） */
        OLED_ShowHexNum(2, 1, DataA[0], 2);  OLED_ShowHexNum(2, 4, DataA[1], 2);
        OLED_ShowHexNum(2, 7, DataA[2], 2);  OLED_ShowHexNum(2, 10, DataA[3], 2);
        OLED_ShowHexNum(4, 1, DataB[0], 2);  OLED_ShowHexNum(4, 4, DataB[1], 2);
        OLED_ShowHexNum(4, 7, DataB[2], 2);  OLED_ShowHexNum(4, 10, DataB[3], 2);

        MyDMA_Transfer();                    /* 调用一次转运一次 */

        /* 再显示一次转运后的 DataA / DataB（位置同上，覆盖显示） */
        OLED_ShowHexNum(2, 1, DataA[0], 2);  OLED_ShowHexNum(2, 4, DataA[1], 2);
        OLED_ShowHexNum(2, 7, DataA[2], 2);  OLED_ShowHexNum(2, 10, DataA[3], 2);
        OLED_ShowHexNum(4, 1, DataB[0], 2);  OLED_ShowHexNum(4, 4, DataB[1], 2);
        OLED_ShowHexNum(4, 7, DataB[2], 2);  OLED_ShowHexNum(4, 10, DataB[3], 2);

        Delay_ms(1000);                      /* 延时 1 秒方便观看 */
    }
}
  • 传参：数组名就是地址，不用取地址符，强转 uint32_t；第三个参数给 4（4 个数据，转运 4 次）。
  • 现象：DataA 地址 2000 0002（即 0x20000002）、数据 01 02 03 04；DataB 地址 2000 0006（即 0x20000006）、数据 00 00 00 00；转运后 DataB 变成 01 02 03 04，源端 DataA 不变。
  • 地址为什么是 20000002 而不是 20000000：模块里的全局变量 MyDMA_Size 被编译器分到 SRAM 开头，占 2 字节，数组地址就往后偏 2 字节——编译器分配的结果，不是 DMA 造成的。
  • 扩展：DataA 前加 const 就能把 Flash 的数据搬到 SRAM，此时下面 DataA[0]++ 那几行必须删掉（等价于 DataA++ 全部作废），否则编译报错；现象是 DataA 地址变 08 开头、DataB 数据与 DataA 一样。

4. 程序二：8-2 DMA+AD多通道

4.1 接线与准备

  • 接线与上一集 AD 多通道一样：PA0 接电位器、PA1～PA3 接三个传感器模块的 AO 输出。
  • 复制上一集的「AD 多通道」工程 → 改名 8-2 DMA+AD多通道，先编译；再把上个工程的 DMA 初始化整段复制到 ADC 使能之前，并把开 DMA 时钟的函数挪到前面。
  • ADC 初始化开头（图 18）：uint16_t AD_Value 数组、void AD_Init(void)、RCC_APB2PeriphClockCmd(ADC1/GPIOA)、RCC_ADCCLKConfig(RCC_PCLK2_Div6);、GPIO_Mode_AIN、GPIO_Pin_0 | GPIO_Pin_1 | GPIO_Pin_2 | GPIO_Pin_3、GPIO_Speed_50MHz。

4.2 ADC 侧：扫描模式 + 4 个通道

  • 流程就是 P23 最后一页的「ADC 扫描模式 + DMA」：先扫描 PA0～PA3 这 4 个通道。
  • 用 4 次 ADC_RegularChannelConfig 把通道 0～3 填到序列 1～4；通道和次序可以任意改，结果存放的顺序也会相应变化。
  • ADC_ScanConvMode = ENABLE（扫描多个通道）、ADC_NbrOfChannel = 4（只看前 4 个位置）。
  • 连续模式这里先用 DISABLE（单次扫描），后面再演示连续扫描。

4.3 DMA 侧参数：与程序一的区别

DMA_Init 成员 程序一（DataA→DataB） 程序二（ADC→数组） 说明
PeripheralBaseAddr AddrA（DataA） (uint32_t)&ADC1->DR 端菜的源头是 ADC_DR（也可写 0x4001244C）

4.4 使能与软件触发流程

    DMA_Cmd(DMA1_Channel1, ENABLE);   /* DMA 先使能 */
    ADC_DMACmd(ADC1, ENABLE);         /* 开启 ADC 的 DMA 请求输出 */
    ADC_Cmd(ADC1, ENABLE);            /* ADC 上电 */
    ADC_ResetCalibration(ADC1);
    while (ADC_GetResetCalibrationStatus(ADC1) == SET);
    ADC_StartCalibration(ADC1);
    while (ADC_GetCalibrationStatus(ADC1) == SET);
  • DMA 先使能也不会立刻工作：三个条件里「计数器不为 0」满足，但「触发源有信号」不满足——这里是硬件触发，ADC 还没启动、不会有触发信号。
  • 所以还要 ADC 触发：单次扫描版把 AD_GetValue 改成 void AD_GetValue(void)，参数和返回值都不需要了。
void AD_GetValue(void)
{
    DMA_Cmd(DMA1_Channel1, DISABLE);                    /* DMA 是单次模式，先失能 */
    DMA_SetCurrDataCounter(DMA1_Channel1, 4);           /* 重新写入传输计数器 */
    DMA_Cmd(DMA1_Channel1, ENABLE);
    ADC_SoftwareStartConvCmd(ADC1, ENABLE);             /* 软件触发 ADC 开始转换 */
    while (DMA_GetFlagStatus(DMA1_FLAG_TC1) == RESET);  /* 等 DMA 转运完成 */
    DMA_ClearFlag(DMA1_FLAG_TC1);
}
  • 要点：ADC 单次、DMA 也单次，所以每次调用前都要重写传输计数器；只等 DMA 完成即可——转运总在转换之后，原来等 ADC 转换完成（EOC）的代码就不需要了。
  • 调用一次 AD_GetValue：ADC 连续扫描 4 个通道，结果依次放进 AD_Value，之后 main 直接读 AD_Value[0]～[3]（AD_Value[0] 是序列 1 即通道 0 的结果）；数组要在头文件里用 extern 声明。
  • 初始化末尾的顺序（图 15）：DMA 参数改完后 DMA_Cmd(DMA1_Channel1, ENABLE); → ADC_DMACmd(ADC1, ENABLE); → ADC_Cmd(ADC1, ENABLE); → 校准四步；AD_GetValue 一开始只写了 void AD_GetValue(void) { ADC_SoftwareStartConvCmd(ADC1, ENABLE); }，之后才补全。

6. 硬件自动化的意义

  • 版本 B 之后硬件外设已经高度自动化：操作都由硬件完成，极大地减轻软件负担，软件什么都不用做、也不用进任何中断。
  • 还能再叠一层：ADC 用单次扫描 + 定时器定时触发，就变成定时器触发 ADC、ADC 触发 DMA，全程不需要程序手动操作。
  • 这是 STM32 的特色：各外设互相连接、互相交织形成网状结构，而不是「一个 CPU 单独控制多个独立外设」——定时器输出可通向 ADC、DAC 或其他定时器，ADC 的触发源可来自定时器或外部中断，DMA 的触发源可来自 ADC、定时器、串口。
  • 本集覆盖存储器→存储器、外设→存储器两种情况；存储器→外设（串口发送一批数据）留给大家自己研究。

坑与易错点

  1. const 数据不能改：DataA 加 const 后 DataA[0]++ 必须删掉，否则编译报错；Flash 可读不可写。
  2. const 地址 08 开头、变量 20 开头：Flash 前有程序代码，常量地址靠后且有偏移。
  3. DMA 是 AHB 设备：开时钟用 RCC_AHBPeriphClockCmd，不是 APB2/APB1。
  4. DMA_Init 第一个参数是 DMAy_Channelx：一个参数同时选 DMA 和通道（DMA1 是 1～7、DMA2 是 1～5）。
  5. 存储器到存储器、软件触发时通道可任选；硬件触发必须用绑定通道（ADC1 → DMA1_Channel1）。
  6. 写传输计数器前必须先失能：DMA_Cmd(DISABLE) → DMA_SetCurrDataCounter → DMA_Cmd(ENABLE)。
  7. TC 标志位必须手动清除：DMA_ClearFlag(DMA1_FLAG_TC1);，否则下次判断会误以为已完成。
  8. 循环模式不能用于存储器到存储器：库函数注释明确写「循环模式不能应用在 M2M 情况下」。
  9. 程序一 M2M = Enable、程序二 M2M = Disable：前者软件触发、后者硬件触发，别抄混。
  10. 程序二必须调用 ADC_DMACmd(ADC1, ENABLE)：不开 ADC 不发 DMA 请求，DMA 永远等不到硬件触发。
  11. 程序二通道固定为 DMA1_Channel1：ADC1 的硬件触发只接通道 1（图22）。
  12. DMA 先使能不会立刻工作：硬件触发模式下 ADC 没启动就没有触发信号，三条件不满足。
  13. 版本 A 要等 DMA 完成而不是等 EOC：转运总在转换之后，等 DMA1_FLAG_TC1 即可。
  14. 版本 B 删掉 AD_GetValue 后别忘了改主循环：直接读 AD_Value[]。
  15. 数组地址偏移不是 DMA 造成的：全局 MyDMA_Size 占了 SRAM 开头 2 字节。
  16. AD_Value 要在头文件 extern 声明，main 才能访问。
  17. 本集没讲 DMA 中断：DMA_ITConfig 只在库函数列表里出现；存储器到外设也留作自学。
  18. DataA/DataB 初始值全 0 可省略不写（全局变量默认 0），但写了更直观。
