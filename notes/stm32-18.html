[6-6] 输入捕获模式测频率 / PWMI模式测频率占空比 — 学习笔记

一句话结论

程序一把 PWM 模块改成「固定 ARR=100-1、用 PSC 调频」，再按六步配好 IC_Init，fx = fc/CCR1；程序二只把第④步换成 TIM_PWMIConfig，占空比 = CCR2/CCR1。

本集定位

  • [6-5] 输入捕获的代码课：捕获原理、ICF 滤波器、CC1S 数据选择器、主从触发的 TS/SMS、测频法/测周法全在 P17，本集只写代码、看 OLED、评估性能。
  • 两个程序：6-6 输入捕获模式测频率（00:00–26:40）、6-7 PWMI模式测频率占空比（26:40–35:26）。
  • 32:40–35:26 是 P17 没有的性能评估（量程下限、上限、晶振误差），按作者经验值写，见第 4 章。
  • 程序一由 P16 的 6-3 PWM驱动LED呼吸灯 复制，程序二由 6-6 复制。
  • 编号对照：视频是 [6-6]，工程目录却叫 6-6 / 6-7，两套编号不是一回事。理论看 notes/stm32-17-TIM输入捕获.md。

1. 两个程序总览

程序 工程目录（复制自哪个工程） 定时器 / 引脚 捕获方式 标准频率 fc 公式 现象
① 输入捕获测频率 6-6 输入捕获模式测频率（复制 6-3 PWM驱动LED呼吸灯） TIM3_CH1 / PA6（PA0 是 PWM 输出，一根线连过来） 单通道（CH1，直连 + 上升沿）+ 从模式 Reset 1MHz（PSC=72-1） fx = fc/CCR1 1001Hz → 修正后 1000Hz
② PWMI 测频率占空比 6-7 PWMI模式测频率占空比（复制程序一） 同左 两通道（CH1 上升沿 + CH2 交叉下降沿，TIM_PWMIConfig） 同左 fx = fc/CCR1、占空比 = CCR2/CCR1 1000Hz / 50%；改参数后 100Hz / 80%
  • 两个程序接线完全相同（都是 PA0 到 PA6 一根线），区别只在 IC.c 里输入捕获单元的配置。
  • 程序二只改「输入捕获初始化」这一段：时钟、GPIO、时基都不动。
  • 共用同一个 PWM 信号源（P16 的 PWM 模块改造而来），所以能自己测自己。

2. 程序一：输入捕获模式测频率（00:00–26:40）

2.1 接线：把 PA0 连到 PA6

  • 测量输入引脚是 PA6（P17 讲过 PA6 = TIM3_CH1），待测 PWM 由 STM32 自己输出到 PA0，一根线连过去就行。
  • 有信号发生器就设成方波输出、高电平 3.3V、低电平 0V，直接接 PA6，别忘了共地。
  • 面包板上实际就是一根飞线：一端接 PA6、另一端接 PA0。

图 1：接线图 6-6 输入捕获模式测频率——一根绿色飞线把 PA0（PWM 输出）与 PA6（TIM3_CH1 输入捕获脚）连起来自测

2.2 复制工程，并改造 PWM 模块

  • 复制 6-3 PWM驱动LED呼吸灯，改名 6-6 输入捕获模式测频率，删掉用不到的显示代码，先编译。
  • 为什么改造：原来频率写死在初始化里，运行时调不方便；PWM 频率 = 72M/(PSC+1)/(ARR+1) 里 PSC、ARR 都能调频。
  • 但 占空比 = CCR/(ARR+1) 只跟 ARR 有关——用 ARR 调频会连占空比一起变，用 PSC 调频不影响占空比。
  • 改造方案：固定 ARR = 100-1（分辨率 1%）、用 PSC 调频，好处是 CCR 的数直接就是占空比百分数。
  • 需要更高分辨率（比如 0.1%）就固定 ARR = 1000-1，此时频率 = 72M/预分频/1000、占空比 = CCR/1000。

新增 PWM_SetPrescaler（加在 PWM 模块最后）：

void PWM_SetPrescaler(uint16_t Prescaler)
{
    TIM_PrescalerConfig(TIM2, Prescaler, TIM_PSCReloadMode_Immediate);
}
  • TIM_PrescalerConfig 就是单独写 PSC 的函数（因为多了重装模式参数，所以叫 Config 不叫 Set）；本程序实际调用 TIM_PrescalerConfig(TIM2, Prescaler, TIM_PSCReloadMode_Immediate)。
  • 第三个参数是重装模式：TIM_PSCReloadMode_Update 在更新事件重装（有缓存器、延迟写入，保证每个周期完整）。
  • TIM_PSCReloadMode_Immediate 立即重装，写入立刻生效，可能会在值改变时切断当前波形，出现一个不完整的周期。
  • 本程序要求不高，选立即生效（Immediate）。

主函数里产生 1kHz / 50% 的待测信号：

PWM_Init();
PWM_SetPrescaler(720 - 1);   //Freq = 72M / (PSC + 1) / 100
PWM_SetCompare1(50);         //Duty = CCR / 100
  • 代公式：72M/(720)/100 = 1kHz、50/100 = 50%，于是 PA0 输出 1kHz、50% 的待测信号。

⑥ 选择触发后执行的操作：选 Reset

2.5 IC_Init 完整代码（程序一最终版）

#include "stm32f10x.h"

void IC_Init(void)
{
    /* ① 时钟：TIM3 是 APB1 外设；GPIOA 在 APB2 */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    /* ② GPIO：PA6 上拉输入（TIM3_CH1） */
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    TIM_InternalClockConfig(TIM3);

    /* ③ 时基单元：ARR 满量程、PSC = 72-1 → fc = 1MHz */
    TIM_TimeBaseInitTypeDef TIM_TimeBaseInitStructure;
    TIM_TimeBaseInitStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseInitStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseInitStructure.TIM_Period = 65536 - 1;   // ARR
    TIM_TimeBaseInitStructure.TIM_Prescaler = 72 - 1;   // PSC
    TIM_TimeBaseInitStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM3, &TIM_TimeBaseInitStructure);

    /* ④ 输入捕获单元：通道1、滤波 0xF、上升沿、不分频、直连 */
    TIM_ICInitTypeDef TIM_ICInitStructure;
    TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
    TIM_ICInitStructure.TIM_ICFilter = 0xF;
    TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
    TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    /* ⑤⑥ 主从触发：触发源 TI1FP1、从模式 Reset（自动清零 CNT） */
    TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1);
    TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset);

    /* 启动定时器 */
    TIM_Cmd(TIM3, ENABLE);
}

uint32_t IC_GetFreq(void)
{
    return 1000000 / (TIM_GetCapture1(TIM3) + 1);   // fc = 1MHz
}

各步骤细节：

  • 定时器换 TIM3：TIM2 已被 PWM 输出占用；TIM3 也是 APB1 外设，所以仍用 RCC_APB1PeriphClockCmd。
  • 引脚：查引脚定义表，TIM3_CH1～CH4 分别是 PA6 / PA7 / PB0 / PB1；用 CH1 即 PA6，模式选 GPIO_Mode_IPU 上拉输入。
  • ARR 给 65536-1：ARR 要设大防止计数溢出，直接给最大值，即 16 位计数器满量程计数（时基就是 ARR = 65536-1、PSC = 72-1）。
  • PSC 给 72-1：决定测周法的标准频率 fc = 72M/(PSC+1) = 72M/72 = 1MHz，也就是 fc = 1MHz；这个值要根据信号频率范围调整。
  • TIM_ICInit 五个成员：TIM_Channel = TIM_Channel_1 选通道、TIM_ICFilter = 0xF（0x0～0xF，越大滤波越好，这里给最大档）、TIM_ICPolarity_Rising、TIM_ICPSC_DIV1、TIM_ICSelection = TIM_ICSelection_DirectTI（TIM_ICSelection_DirectTI 就是直连通道）。
  • 分频器只有 4 档：TIM_ICPSC_DIV1 / DIV2 / DIV4 / DIV8，分频值不能任意指定；要每次触发都有效就选 TIM_ICPSC_DIV1（DIV1）。
  • 滤波器 ≠ 分频器：滤波器计次不改变信号频率（1kHz 滤波后还是 1kHz），分频器对信号计次会改变频率（1kHz 二分频 500Hz、四分频 250Hz）。
  • 主从触发两行：TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1) 选触发源、TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset) 选从模式 Reset；参数只有复位、门控、触发、外部时钟等（编码器模式另有函数配置）。
  • 最后 TIM_Cmd(TIM3, ENABLE) 启动；启动后 CNT 一直自增，有信号来时会按从模式自动清零，不影响测量。

2.6 频率公式：fx = fc / N = 1MHz / CCR1

  • 按测周法 fx = fc/N，而 fc = 72M/(PSC+1) = 72M/72 = 1MHz（即 fc = 72M/72 = 1MHz），N 就是 TIM_GetCapture1 读出的 CCR1。
  • 所以 fx = fc/CCR1 = 1000000/TIM_GetCapture1(TIM3)：读频率就是 1000000 除以 CCR1，返回最新一个周期的频率值，单位 Hz。

2.7 主函数与现象：1001Hz 与 +1 修正

int main(void)
{
    OLED_Init();
    PWM_Init();
    IC_Init();

    OLED_ShowString(1, 1, "Freq:00000Hz");

    PWM_SetPrescaler(720 - 1);   //Freq = 72M / (PSC + 1) / 100
    PWM_SetCompare1(50);         //Duty = CCR / 100

    while (1)
    {
        OLED_ShowNum(1, 6, IC_GetFreq(), 5);
    }
}
  • 链路：PWM 模块把待测信号输出到 PA0 → 导线进入 PA6 → PA6 是 TIM3 的通道 1 → 输入捕获测频率 → 主循环刷新 OLED。
  • 现象：实测 Freq:01001Hz——自己输出自己测，按理没有误差，但它稳定地多 1。
  • 推测：计数刚到 1000Hz 时信号也刚好跳变，这一个数没计到；仍属 ±1 误差范围。
  • 补回来：给计数值 +1，IC_GetFreq 改成 return 1000000 / (TIM_GetCapture1(TIM3) + 1);，重新下载显示 Freq:01000Hz。
  • 注意：这个 +1 只是「自己测自己」的凑整技巧，不是通用做法；换频率、换信号源时「少 1」未必出现，+1 反而可能多算。

3. 程序二：PWMI 模式测频率占空比（26:40–35:26）

3.1 复制工程

  • 复制 6-6 输入捕获模式测频率，改名 6-7 PWMI模式测频率占空比。
  • 时钟、GPIO、时基都不用改，只把输入捕获初始化升级成「两个通道同时捕获同一个引脚」。

3.2 手动配两个通道（过渡演示）

  • 最直接的想法是把通道初始化复制一份：通道 1 保持「直连 + 上升沿」，下面那份改成「通道 2、交叉、下降沿」：
/* 通道1：直连 + 上升沿（捕获整周期） */
TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
TIM_ICInit(TIM3, &TIM_ICInitStructure);

/* 通道2：交叉 + 下降沿（捕获高电平时间） */
TIM_ICInitStructure.TIM_Channel = TIM_Channel_2;
TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_IndirectTI;
TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Falling;
TIM_ICInit(TIM3, &TIM_ICInitStructure);
  • 这样配是可行的，但 ST 专门封装了一个函数，可以一步完成。

3.3 TIM_PWMIConfig：一次配好两个通道

TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
TIM_ICInitStructure.TIM_ICFilter = 0xF;
TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
TIM_PWMIConfig(TIM3, &TIM_ICInitStructure);
  • 只传一个通道的参数（含 TIM_ICSelection），函数内部会自动把另一个通道配成相反的参数：Rising 对 Falling、DirectTI 对 IndirectTI、通道 1 对通道 2。
  • 源码里是一堆 if 判断：传入 Rising 则对方 Falling，传入直连则对方交叉，传入通道 1 则结构体配到 TI1、对方配到 TI2，传入通道 2 则相反。
  • 限制：只支持通道 1 和通道 2，不要传通道 3/4。
  • 执行完这个函数，PWMI 电路就配好了，后面的主从模式、启动定时器都不用改。

图 11：程序二 IC.c 的手动两通道配置（过渡版）——通道 1 TIM_Channel_1 / DirectTI / Rising、通道 2 TIM_Channel_2 / IndirectTI / Falling，两次 TIM_ICInit(TIM3, ...) 都被高亮

图 12：改用 TIM_PWMIConfig(TIM3, &TIM_ICInitStructure)——只配通道 1（TIM_Channel_1 一行高亮）、直连、上升沿，函数内部自动把通道 2 配成相反配置

3.4 IC_GetDuty：占空比 = CCR2/CCR1

  • 高电平的计数值存在 CCR2、整个周期的计数值存在 CCR1，用 CCR2/CCR1 就得到占空比。
  • 比值范围是 0～1，要显示整数就乘 100，返回 0～100 对应 0%～100%。
  • 实测 CCR 总会少一个数，所以两个值各加 1 补回来，写成 IC_GetDuty = (TIM_GetCapture2+1)*100 / (TIM_GetCapture1+1)：
uint32_t IC_GetFreq(void)
{
    return 1000000 / (TIM_GetCapture1(TIM3) + 1);
}

uint32_t IC_GetDuty(void)
{
    return (TIM_GetCapture2(TIM3) + 1) * 100 / (TIM_GetCapture1(TIM3) + 1);
}

图 13：IC_GetDuty 的雏形——正在输入 return TIM_GetCapture2(TIM3) / TIM_GetCapture1(TIM3);（还没加 1、没乘 100）

图 14：IC_GetDuty 最终版——return (TIM_GetCapture2(TIM3) + 1) * 100 / (TIM_GetCapture1(TIM3) + 1);（两个 CCR 各 +1、乘 100 返回 0～100）

3.5 主函数与现象

int main(void)
{
    OLED_Init();
    PWM_Init();
    IC_Init();

    OLED_ShowString(1, 1, "Freq:00000Hz");
    OLED_ShowString(2, 1, "Duty:00%");

    PWM_SetPrescaler(7200 - 1);   //Freq = 72M / (PSC + 1) / 100
    PWM_SetCompare1(80);          //Duty = CCR / 100

    while (1)
    {
        OLED_ShowNum(1, 6, IC_GetFreq(), 5);
        OLED_ShowNum(2, 6, IC_GetDuty(), 2);
    }
}
  • 先显示两行字符串 Freq:00000Hz（第 1 行）和 Duty:00%（第 2 行），主循环分别刷新频率（5 位）和占空比（2 位）。
  • 现象：PSC = 720-1、CCR = 50 时显示 Freq:01000Hz / Duty:50%。
  • 改参数：PWM_SetPrescaler(7200 - 1) → 100Hz，PWM_SetCompare1(80) → 80%，实测 100Hz / 80% 也没问题。

4. 测频率的性能评估（32:40–35:26）

这一段没有代码、也没有 PPT 公式页，是口述的经验值：

4.1 量程下限 ≈ 15Hz

  • fc = 1MHz、计数器最大只能计到 65535，所以能测的最低频率 = 1M/65535 ≈ 15Hz，再低就溢出。
  • 想降低下限：把预分频再加大一点，fc 更低，能支持的最低频率也更低。

4.2 量程上限：由误差要求决定

  • 理论上的上限就是标准频率 1MHz，但这个上限没有意义——信号接近 1MHz 时误差已经非常大。
  • 实际能用多高取决于误差要求，±1 误差可以认为是 1/N：
    • 要求相对误差 1/1000 ⇒ 上限 = 1M/1000 = 1kHz；
    • 要求相对误差 1/100 ⇒ 上限 = 1M/100 = 10kHz。
  • 想提高上限：降低 PSC、提高 fc；频率还要更高就该换测频法（测频法适合高频、测周法适合低频）。

4.3 还有晶振误差

  • 除了 ±1 计数误差，实际测量还有晶振误差：STM32 的晶振不那么准，计次几百、几万次之后误差会累积。
  • 本实验自己测自己，不存在晶振误差，所以数值非常稳定；测别的信号数值可能会抖动，后期可以再做滤波。

5. 两个程序的共同规律

  • 同一套模板：程序二只在程序一基础上改「输入捕获初始化」，时钟 / GPIO / 时基 / 主从触发 / TIM_Cmd / IC_GetFreq 全不动，再加一个 IC_GetDuty。
  • 测频公式始终是 fx = fc/CCR1；占空比只是程序二多读了一个 CCR2。
  • 同一个信号源：都用 P16 的 PWM 模块（PWM_SetPrescaler 调频、PWM_SetCompare1 调占空比），接线都是 PA0→PA6。
  • 读 CCR 只用 TIM_GetCapturex：输入捕获模式下 CCR 只读，输出比较才用 TIM_SetComparex 写。

坑与易错点

  1. 改 PWM 频率要用 PSC，不要用 ARR：占空比 CCR/(ARR+1) 只跟 ARR 有关，改 ARR 会连占空比一起变。
  2. TIM_PrescalerConfig 的重装模式要想一下：_Update 周期完整，_Immediate 立即生效、可能出现不完整周期。
  3. 输入捕获不能用 TIM2：TIM2 已被 PWM 输出占用，要换 TIM3（同为 APB1 外设，开时钟仍用 RCC_APB1PeriphClockCmd）。
  4. ARR 要给满量程 65536-1：测周法靠 CNT 计一个周期，ARR 太小、频率稍低就会溢出。
  5. TIM_ICInit 是 4 个通道共用一个函数：靠 TIM_Channel 选通道；输出比较是每通道一个函数。
  6. 分频器只有 4 档：TIM_ICPSC_DIV1/DIV2/DIV4/DIV8，不能任意指定分频值。
  7. 滤波器 ≠ 分频器：滤波器只滤高频噪声、不改变频率；分频器对信号计次、会改变频率（1kHz 二分频 = 500Hz）。
  8. TIM_ICFilter = 0xF 是最大滤波档：范围 0x0～0xF，越大滤波越强；但 N 越大响应越慢。
  9. 主从触发要两行都配：只配触发源没有从模式、只配从模式没有触发源，都不工作；必须「TI1FP1 + Reset」成对出现。
  10. TIM_SlaveMode_Reset 参数表里没有编码器模式：那几个 Encoder 模式由编码器接口的函数单独配置。
  11. TIM_GetCapture 读的是 CCR，输入捕获时 CCR 只读：不要想用 TIM_SetCompare 去改捕获值。
  12. +1 的修正只是「自己测自己」的凑整：换频率/换信号源时「少 1」不一定出现，+1 可能反而多算。
  13. PWMI 手动两通道只是过渡演示：实际代码用 TIM_PWMIConfig，一步完成、更不容易配错极性。
  14. TIM_PWMIConfig 只支持通道 1 和 2：不要传通道 3/4。
  15. PWMI 里只有一个通道清 CNT：从模式 Reset 由上升沿触发，CCR2 捕获不清 CNT，所以 CCR1 才是整周期。
  16. 两个 CCR 都要 +1 再算占空比：(CCR2+1)*100/(CCR1+1)，只给分子加会偏大。
  17. 量程下限约 15Hz 是 1MHz/65535 算出来的：要测更低就加大 PSC（降 fc），代价是上限也变低。
  18. 「上限 1MHz」没有实际意义：真正上限由误差要求定（1/1000 → 1kHz、1/100 → 10kHz）。
  19. 本集没有示波器：所有现象都是 OLED 显示 + 口述，1001Hz/1000Hz/100Hz/80% 都不是示波器读数。
