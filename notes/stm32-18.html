一句话结论

本集把 [6-5] 的输入捕获理论落成两个工程：程序一（测频率）从 P16 的 6-3 PWM驱动LED呼吸灯 复制——先把 PWM 模块改造成「固定 ARR=100-1、用 PSC 调频率」（因为占空比 CCR/(ARR+1) 只跟 ARR 有关，改 ARR 会连占空比一起变），并新增 PWM_SetPrescaler（内部调 TIM_PrescalerConfig(TIM2, Prescaler, TIM_PSCReloadMode_Immediate)）；再新建 IC.c，按六步写 IC_Init：① 开 RCC 时钟（TIM3 因为 TIM2 被 PWM 占了）② PA6 配 GPIO_Mode_IPU 上拉输入 ③ 时基 ARR = 65536-1、PSC = 72-1 → 标准频率 fc = 72M/72 = 1MHz ④ TIM_ICInit 五成员：TIM_Channel_1、TIM_ICFilter = 0xF、TIM_ICPolarity_Rising、TIM_ICPSC_DIV1、TIM_ICSelection_DirectTI ⑤ TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1) ⑥ TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset)，最后 TIM_Cmd 启动——这一套配完，每次上升沿把 CNT 锁进 CCR1、并由从模式硬件清零 CNT，于是 fx = fc/CCR1 = 1000000/TIM_GetCapture1(TIM3)；实测 1001Hz（比 1000 多 1，属 ±1 计数误差，作者推测是「快到 1000 时信号刚好跳变、这个数没计到」），为了「凑整」在读数里 +1 后显示 1000Hz。程序二（PWMI）由 6-6 复制，只改输入捕获初始化：先手动配「通道 1 直连 + 上升沿、通道 2 交叉 + 下降沿」，再用 ST 封装好的 TIM_PWMIConfig(TIM3, &TIM_ICInitStructure) 一次搞定（它只支持通道 1/2，内部会自动把另一通道配成相反极性/反向选择）；于是 CCR1 = 整周期计数值、CCR2 = 高电平计数值，IC_GetDuty = (TIM_GetCapture2+1)*100 / (TIM_GetCapture1+1) 返回 0～100，现象 1000Hz / 50%，改参数后 100Hz / 80%。最后性能评估：fc = 1MHz、CNT 最大 65535 ⇒ 量程下限 ≈ 1M/65535 ≈ 15Hz（再低要加大 PSC）；上限没有硬边界，由误差要求决定（±1 误差 ≈ 1/N，要求 1/1000 则上限 1kHz、要求 1/100 则 10kHz），再高就该换测频法；实际测量还有晶振误差（本实验自己测自己没有，所以数值很稳）。理论全在 P17 [6-5]。

2. 程序一：输入捕获模式测频率（00:00–26:40）

2.1 接线：把 PA0 连到 PA6

  • 测量信号的输入引脚是 PA6（P17 讲过 PA6 = TIM3_CH1），待测的 PWM 信号也是 STM32 自己生成的、输出引脚是 PA0——所以接线直接用一根线把 PA0 引到 PA6 就行了。
  • 如果手上有信号发生器：把它设置成方波输出，高电平 3.3V、低电平 0V，直接接到 PA6，别忘了共地——这样接线也可以。
  • 面包板上实际就是一根飞线：一端接 PA6，另一端接 PA0。
  • 两个程序的接线都是一样的（都是接一根线，从 PA0 到 PA6）。

图 1：接线图 6-6 输入捕获模式测频率——面包板上的 STM32 最小系统板 + ST-Link + OLED，一根绿色飞线把 PA0（PWM 输出）与 PA6（TIM3_CH1 输入捕获脚）连起来自测；字幕「目前我们这个测量信号的输入引脚是PA6」

2.2 复制工程，并改造 PWM 模块

复制工程：借用之前写好的 PWM 模块来生成待测信号，所以直接复制 6-3 PWM驱动LED呼吸灯 的代码，改名为 6-6 输入捕获模式测频率，删掉之前用不到的显示代码，先编译一下。

为什么要改造 PWM 模块：原来 PWM 的频率是在初始化里写死的，运行时调不方便；而

  • PWM 频率 = 72M/(PSC+1)/(ARR+1)，PSC 和 ARR 都能调频率；
  • 但 占空比 = CCR/(ARR+1)，用 ARR 调频率会同时改变占空比，用 PSC 调频率则不影响占空比，显然更方便。

改造方案：固定 ARR = 100-1（分辨率 1%），用 PSC 调频率；这样还有个好处——CCR 的数值直接就是占空比的百分数（ARR+1 = 100），用起来直观。如果项目需要更高的分辨率（比如 0.1%），就固定 ARR = 1000-1，此时频率 = 72M/预分频/1000、占空比 = CCR/1000。

新增函数 PWM_SetPrescaler（在 PWM 模块最后加）：

void PWM_SetPrescaler(uint16_t Prescaler)
{
    TIM_PrescalerConfig(TIM2, Prescaler, TIM_PSCReloadMode_Immediate);
}
  • 库函数 TIM_PrescalerConfig 就是单独写入 PSC 的函数（因为多了个重装模式参数，所以叫 Config 不叫 Set；本质就是写 PSC）。
  • 第三个参数是重装模式：TIM_PSCReloadMode_Update 是在更新事件重装（有缓存器、延迟写入，保证每个周期完整）；TIM_PSCReloadMode_Immediate 是立即重装——写入的值立刻生效，可能会在值改变时切断当前波形，比如 PWM 一个周期刚过一半就立即生效，就会立刻切断当前周期、开始新的一个周期，频率变化时会出现一个不完整的周期。
  • 本程序要求不高，哪个都行，这里选立即生效（Immediate）。

主函数里产生 1kHz / 50% 的待测信号：

PWM_Init();
PWM_SetPrescaler(720 - 1);   //Freq = 72M / (PSC + 1) / 100
PWM_SetCompare1(50);         //Duty = CCR / 100
  • 代公式：72M/(720)/100 = 1kHz，50/100 = 50%，于是 PA0 输出 1kHz、50% 的待测信号。

2.3 写 IC 代码前先理清六步

对照 P17 的「输入捕获基本结构」图，把电路连成图里的样子需要六步（最后还要 TIM_Cmd 启动、读 CCR 算频率）：

步 做什么
① RCC 开启时钟：把 GPIO 和 TIM 的时钟打开
② GPIO 初始化：配置成输入模式（一般选上拉输入或浮空输入）
③ 配置时基单元：让 CNT 在内部时钟驱动下自增（和之前的代码一样）
④ 配置输入捕获单元：滤波器、极性、直连还是交叉、分频器（用一个结构体统一配）
⑤ 选择从模式的触发源：选 TI1FP1
⑥ 选择触发后执行的操作：选 Reset
⑦ 调用 TIM_Cmd 开启定时器
— 需要读频率时，读 CCR 寄存器、按 fc/N 算

2.5 IC_Init 完整代码（程序一最终版）

#include "stm32f10x.h"

void IC_Init(void)
{
    /* ① 时钟：TIM3 是 APB1 外设；GPIOA 在 APB2 */
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM3, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);

    /* ② GPIO：PA6 上拉输入（TIM3_CH1） */
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU;
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    TIM_InternalClockConfig(TIM3);

    /* ③ 时基单元：ARR 满量程、PSC = 72-1 → fc = 1MHz */
    TIM_TimeBaseInitTypeDef TIM_TimeBaseInitStructure;
    TIM_TimeBaseInitStructure.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseInitStructure.TIM_CounterMode = TIM_CounterMode_Up;
    TIM_TimeBaseInitStructure.TIM_Period = 65536 - 1;   // ARR
    TIM_TimeBaseInitStructure.TIM_Prescaler = 72 - 1;   // PSC
    TIM_TimeBaseInitStructure.TIM_RepetitionCounter = 0;
    TIM_TimeBaseInit(TIM3, &TIM_TimeBaseInitStructure);

    /* ④ 输入捕获单元：通道1、滤波 0xF、上升沿、不分频、直连 */
    TIM_ICInitTypeDef TIM_ICInitStructure;
    TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
    TIM_ICInitStructure.TIM_ICFilter = 0xF;
    TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
    TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
    TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
    TIM_ICInit(TIM3, &TIM_ICInitStructure);

    /* ⑤⑥ 主从触发：触发源 TI1FP1、从模式 Reset（自动清零 CNT） */
    TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1);
    TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset);

    /* 启动定时器 */
    TIM_Cmd(TIM3, ENABLE);
}

uint32_t IC_GetFreq(void)
{
    return 1000000 / (TIM_GetCapture1(TIM3) + 1);   // fc = 1MHz
}

各步骤的细节（视频里都专门讲了）：

  • 定时器为什么换 TIM3：TIM2 已经被 PWM 输出占用了，所以输入捕获换一个定时器——TIM3 也是 APB1 的外设，所以开时钟还是用 RCC_APB1PeriphClockCmd。
  • 引脚怎么定：查引脚定义表，TIM3_CH1～CH4 分别是 PA6 / PA7 / PB0 / PB1；本程序用 CH1，所以是 PA6，GPIO 模式选 GPIO_Mode_IPU 上拉输入。
  • ARR 给 65536-1：根据上一小节的分析，ARR 要设大一些防止计数溢出，这里直接给最大值 65536-1，即 16 位计数器满量程计数。
  • PSC 给 72-1：PSC 决定测周法的标准频率 fc = 72M/预分频 = 72M/72 = 1MHz；这个值要根据你信号频率的分布范围来调整（先给 72-1）。
  • TIM_ICInit 五个成员：TIM_Channel_1 选通道、TIM_ICFilter = 0xF（0x0～0xF，越大滤波效果越好；本程序给最大档、「多给点滤波」）、TIM_ICPolarity_Rising 上升沿触发、TIM_ICPrescaler = TIM_ICPSC_DIV1 不分频、TIM_ICSelection_DirectTI 直连通道。
  • 分频器只有 4 档：TIM_ICPSC_DIV1 / DIV2 / DIV4 / DIV8——分频值不能任意指定，只能选这 4 种；本程序要「每次触发都有效」，选 DIV1（不分频）。
  • 滤波器 ≠ 分频器：两者都是「计次」的东西，但滤波器计次不会改变信号的原有频率（采样频率远高于信号频率，只滤掉高频噪声、让波形更平滑，1kHz 滤波之后仍然是 1kHz）；而分频器是对信号本身计次、会改变频率（1kHz 二分频变 500Hz、四分频变 250Hz）。
  • 主从触发的两行：TIM_SelectInputTrigger(TIM3, TIM_TS_TI1FP1) 选触发源、TIM_SelectSlaveMode(TIM3, TIM_SlaveMode_Reset) 选从模式 Reset。TIM_SelectSlaveMode 的参数只有复位、门控、触发、外部时钟等几种（编码器模式另有函数配置，所以不在此函数的参数里）。
  • 启动后 CNT 一直自增：即使没有信号过来它也会不断自增，不过这没关系——有信号来的时候，它会在从模式的作用下自动清零，不影响测量。

2.6 频率公式：fx = fc / N = 1MHz / CCR1

  • 按照 P17 的测周法：fx = fc/N，而 fc = 72M/(PSC+1) = 72M/72 = 1MHz，N 就是 CCR1 的值（TIM_GetCapture1 读出来的计数值）。
  • 所以读频率函数就是「用 1000000 除以 CCR1 的值」，返回的是最新一个周期的频率值，单位 Hz。

2.7 主函数与现象：1001Hz 与 +1 修正

{
    OLED_Init();

  • 链路：PWM 模块把待测信号输出到 PA0 → 导线进入 PA6 → PA6 是 TIM3 的通道 1 → 通道 1 通过输入捕获测出频率 → 主循环不断刷新 OLED。
  • 现象：实测 Freq:01001Hz——「但是我们输出的是 1kHz，多了一点点」。按理说自己输出、自己测，应该不会有误差，但它很稳定地多了 1。
  • 作者推测：可能是计数刚到 1000Hz 的那个数时、信号也刚好跳变（因为电路结构或者其他什么原因），导致这一个数刚好没计到——不过这也属于 ±1 误差的范畴，误差是符合要求的。
  • 但「总是差那么一点，逼死强迫症」，所以在程序上补回来：给计数值 +1，补一个数——IC_GetFreq 改成 return 1000000 / (TIM_GetCapture1(TIM3) + 1);，重新下载后显示 Freq:01000Hz，「凑个整，现在就舒服多了」。
  • 注意：这个 +1 只是针对「自己测自己」这种特定信号的凑整技巧，不是通用做法——换频率、换信号源时，这个「少 1」未必出现，+1 反而可能多算（见「坑与易错点」）。

3.2 手动配两个通道（过渡演示）

最「简单」的想法就是把通道初始化的部分复制一份：通道 1 保持「直连输入、上升沿触发」，下面那份改成「通道 2、交叉输入、下降沿触发」——正好对应 P17 里「通道 1 直连上升沿捕获周期、通道 2 交叉下降沿捕获高电平」的结构：

/* 通道1：直连 + 上升沿（捕获整周期） */
TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
TIM_ICInit(TIM3, &TIM_ICInitStructure);

/* 通道2：交叉 + 下降沿（捕获高电平时间） */
TIM_ICInitStructure.TIM_Channel = TIM_Channel_2;
TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_IndirectTI;
TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Falling;
TIM_ICInit(TIM3, &TIM_ICInitStructure);
  • 这样配置是可行的、没问题，但 ST 公司「怕我们觉得麻烦」，专门封装了一个函数来一步完成。

3.3 TIM_PWMIConfig：一次配好两个通道

TIM_ICInitStructure.TIM_Channel = TIM_Channel_1;
TIM_ICInitStructure.TIM_ICFilter = 0xF;
TIM_ICInitStructure.TIM_ICPolarity = TIM_ICPolarity_Rising;
TIM_ICInitStructure.TIM_ICPrescaler = TIM_ICPSC_DIV1;
TIM_ICInitStructure.TIM_ICSelection = TIM_ICSelection_DirectTI;
TIM_PWMIConfig(TIM3, &TIM_ICInitStructure);
  • 用这个函数替换掉上面那一大段：只传一个通道的参数，函数内部会自动把剩下的一个通道配置成相反的参数——Rising 对 Falling、DirectTI 对 IndirectTI、通道 1 对通道 2。
  • 作者是「转到定义、分析源码」才知道的：源码里一堆 if 判断——传入 Rising 则对方 Falling、否则对方 Rising；传入直连则对方交叉、否则对方直连；传入通道 1 则结构体配到 TI1、对方配到 TI2，传入通道 2 则相反。
  • 重要限制：这个函数只支持通道 1 和通道 2，不要传通道 3/4。
  • 执行完这个函数，PWMI 电路就配好了；后面主从模式、启动定时器都不需要改。

3.4 IC_GetDuty：占空比 = CCR2/CCR1

  • 根据 P17 的分析：高电平的计数值存在 CCR2 里、整个周期的计数值存在 CCR1 里，用 CCR2/CCR1 就能得到占空比。
  • 但这个比值范围是 0～1（小数），要显示整数就乘 100，返回 0～100 对应 0%～100%。
  • 还是同一个问题：实测 CCR 总会少一个数，所以给两个值各加 1 补回来：
uint32_t IC_GetFreq(void)
{
    return 1000000 / (TIM_GetCapture1(TIM3) + 1);
}

uint32_t IC_GetDuty(void)
{
    return (TIM_GetCapture2(TIM3) + 1) * 100 / (TIM_GetCapture1(TIM3) + 1);
}

4. 测频率的性能评估（32:40–35:26）

这一段没有代码、也没有 PPT 公式页，是作者口述的经验值，但对「这个测频方案能用在哪」很关键。

4.1 量程下限 ≈ 15Hz

  • 目前标准频率 fc = 1MHz，计数器最大只能计到 65535，所以能测的最低频率 = 1M/65535 ≈ 15Hz；信号频率再低，计数器就要溢出了。
  • 想降低下限：把预分频再加大一点——这样标准频率更低，能支持的最低频率也就更低。

4.2 量程上限：由误差要求决定

  • 严格说理论上的上限就是标准频率 1MHz（信号比标准频率还高肯定测不了），但这个上限没有意义——信号接近 1MHz 时误差已经非常大了。
  • 实际能用多高，取决于你对误差的要求：±1 误差可以认为是 1/计数值 N——
    • 要求相对误差 1/1000 ⇒ 上限 = 1M/1000 = 1kHz；
    • 要求相对误差 1/100 ⇒ 上限 = 1M/100 = 10kHz。
  • 想提高上限：把 PSC 降低一点、提高标准频率 fc，上限就会提高；频率还要更高就该考虑测频法了（测频法适合高频、测周法适合低频）——「对于非常高的频率，还是交给测频法来解决吧」。

4.3 还有晶振误差

  • 除了 ±1 计数误差，实际测量时还有晶振误差：STM32 的晶振不是那么准，在计次几百、几万次之后误差会累积，造成一些影响。
  • 本实验是自己测自己，不存在晶振误差，所以数值非常稳定；如果要测别的信号，数值可能会有些抖动，后期可以再做一些滤波处理。

5. 两个程序的共同规律

  • 同一套模板：程序二在程序一基础上只改「输入捕获初始化」这一段——时钟 / GPIO / 时基 / 主从触发 / TIM_Cmd / IC_GetFreq 全部不动，只在第④步换成 PWMI 配置，再加一个 IC_GetDuty。
  • 测频率的公式始终是 fx = fc/CCR1：程序一、程序二都一样；占空比只是程序二多读了一个 CCR2。
  • 同一个信号源：两个程序都用 P16 的 PWM 模块产生测试信号（PWM_SetPrescaler 调频率、PWM_SetCompare1 调占空比），接线都是 PA0→PA6。
  • 读 CCR 只用 TIM_GetCapturex：输入捕获模式下 CCR 是只读的，输出比较才是只写（TIM_SetComparex）。

坑与易错点

  1. 改 PWM 频率要用 PSC，不要用 ARR：占空比 = CCR/(ARR+1) 只跟 ARR 有关——改 ARR 会连占空比一起变；固定 ARR=100-1、用 PSC 调频率，占空比不受影响，而且 CCR 数值直接就是占空比。
  2. TIM_PrescalerConfig 的第三个参数（重装模式）要想一下：_Update 在更新事件重装（周期完整）、_Immediate 立即生效（可能切断当前周期、出现不完整周期）；本程序要求不高选了立即，但对波形连续有要求的场合要用 Update。
  3. 输入捕获不能用 TIM2：TIM2 已经被 PWM 输出占用，要换 TIM3（同为 APB1 外设，开时钟仍用 RCC_APB1PeriphClockCmd）。
  4. ARR 要给满量程 65536-1：测周法靠 CNT 计一个周期的时间，ARR 太小、频率稍低就会溢出，测出来就错了。
  5. TIM_ICInit 是 4 个通道共用一个函数：必须靠结构体 TIM_Channel 选通道；输出比较则是每通道一个函数（TIM_OC1Init～TIM_OC4Init）。
  6. 分频器只有 4 档：TIM_ICPSC_DIV1/DIV2/DIV4/DIV8，不能任意指定分频值。
  7. 滤波器 ≠ 分频器：滤波器只滤高频噪声、不改变信号频率（1kHz 还是 1kHz）；分频器对信号计次、会改变频率（1kHz 二分频 = 500Hz）。
  8. TIM_ICFilter = 0xF 是最大滤波档：参数范围 0x0～0xF，越大滤波越强；信号有毛刺就加大，但采样越慢/N 越大响应越慢。
  9. 主从触发要两行都配：只配 TIM_SelectInputTrigger 没有从模式、只配 TIM_SelectSlaveMode 没有触发源，都不工作；必须是「触发源 TI1FP1 + 从模式 Reset」成对出现。
  10. TIM_SlaveMode_Reset 参数表里没有编码器模式：那几个 Encoder 模式由编码器接口的函数单独配置，所以这里看不到。
  11. TIM_GetCapture 读的是 CCR，输入捕获时 CCR 只读：不要想用 TIM_SetCompare 去改捕获值。
  12. +1 的修正只是针对「自己测自己」的凑整（见存疑）：换频率/换信号源时那个「少 1」不一定出现，+1 可能反而多算；而且修正前后不要混——初版（图 7 阶段）没有 +1，最终版（图 10/图 12）才有。
  13. PWMI 手动两通道只是过渡演示：实际代码用 TIM_PWMIConfig 一步完成；两种写法效果一样，但后者更简洁、更不容易配错极性。
  14. TIM_PWMIConfig 只支持通道 1 和 2：不要传通道 3/4（传了会配不出来）。
  15. PWMI 里只有一个通道清 CNT：从模式 Reset 由上升沿（TI1FP1）触发，CCR2 捕获不会清 CNT——所以 CCR1 才是整周期计数值。
  16. 两个 CCR 都要 +1 再算占空比：(CCR2+1)*100/(CCR1+1)——只给分子加、不给分母加，结果会偏大。
  17. 量程下限约 15Hz 是 1MHz/65535 算出来的：要测更低的频率就加大 PSC（降 fc），但代价是上限也变低。
  18. 「上限 1MHz」没有实际意义：真正能用的上限由误差要求定（1/1000 → 1kHz、1/100 → 10kHz）；想更高就减小 PSC 或改用测频法。
  19. 本集没有示波器：所有现象都是 OLED 显示 + 口述，1001Hz/1000Hz/100Hz/80% 都不是示波器读数。
